# YiboTodo 工程契约与验收

本文是 YiboTodo 的长期工程约定。产品范围见 [PRODUCT.md](PRODUCT.md)，版本路线见 [ROADMAP.md](ROADMAP.md)，数据基线见 [BASELINE.md](BASELINE.md)。不记录逐日实施经过或已被替代的页面方案。

## 架构与目录

- `Catalog/`：活动、冷却、冷却组和客户端规则；所有条目使用稳定 ID。
- `Providers/`：从专业窗口、任务、农场或账号事实采集原始观察；Provider 不直接决定页面文案。
- `Model/`：规范化状态、时间语义、账号快照和统计。
- `Database.lua`：SavedVariables 结构、revision 与迁移。
- `AccountPage.lua`：统一账号页面的业务布局和字段投影。
- `CoreIntegration.lua`：YiboCore API 接入、页面注册与入口生命周期。
- `Tests/`：目录校验、状态、日重置、Provider 观察和回归 smoke tests。

## 目录契约

活动与冷却必须具有不可复用的稳定 ID，并记录资料片、作用域、重置策略、验证状态和规则集。冷却条目引用独立的公共冷却组；共享成员只能产生一个可制作、冷却中或最近恢复结果。失效配方标记 inactive，不能删除或复用历史 ID。

`Catalog/Validator.lua` 必须拒绝重复 ID、缺失冷却组、互相冲突的重置规则和无法解释的目录关系。目录中的外部资料不是正式事实；目标客户端实机记录以 `BASELINE.md` 为准。

## Provider 与状态

Provider 输出原始观察及其来源、采集时间、角色、身份和置信度。模型统一映射为：

| 状态 | 语义 |
|---|---|
| `actionable` | 当前可制作、领取、完成或处理 |
| `completed` | 当前周期已完成 |
| `cooldown` | 已确认仍在等待 |
| `estimated` | 根据已知绝对时间推定，尚未重新观察 |
| `skill-insufficient` | 配方存在但专业技能不足 |
| `in-progress` | 已开始但未达到完成条件 |
| `locked` | 未学习、未解锁或不具资格 |
| `unknown` | 无可靠观察或观察冲突 |
| `not-applicable` | 不适用于该角色 |

未知绝不能投影为完成、零数量或可执行。首次未扫描的专业项目仅能显示待确认；绝对恢复时间到达后可以显示 `estimated`，但实际冷却记录优先。观察型活动未获得全量证据时不得推断全局完成。

## 作用域、快照与页面

活动必须声明 `character` 或 `account` 作用域。账号级项目只在固定账号摘要中出现并统计一次，不能复制到角色行。角色级项目按 Core 角色目录和插件准入条件生成快照。

主窗口、Broker 和小地图预览必须共享同一份账号快照、角色筛选、状态判断和数值格式化。主表按角色呈现待做、可制作、冷却中、最近恢复和行动摘要；详情按活动类型、资料片、专业和冷却组展开。预览仅是字段投影，默认包含所有有效且有业务快照的角色（最多 20 名）。

设置、入口、字段、预览字段与角色排序由 YiboCore 统一工作台保存和渲染；YiboTodo 只注册业务设置、业务页面和摘要数据，不能创建第二套窗口壳或入口管理逻辑。

## 数据库与迁移

SavedVariables 必须保存原始观察、规范化状态所需时间、采集时间、目录版本和 revision；不得把本地化名称作为键。迁移必须幂等、保留用户覆盖、可安全处理缺失或旧字段。缓存缺失、换设备或插件关闭期间发生的行为必须诚实显示为未知或预计状态。

## 日重置与时间

固定时长冷却与服务器每日重置必须使用不同规则。每日活动按国服 07:00 跨日语义验证；跨日、登出、重载和切角色不得产生重复完成或错误可执行状态。显示时间统一使用同一格式化逻辑。

## 测试与发布门槛

每次目录或 Provider 变更至少验证：

1. 目录稳定 ID、冷却组和规则集通过校验；
2. 新、旧 SavedVariables 迁移不丢设置或观察；
3. 可执行、冷却、完成、未知、预计与技能不足状态正确投影；
4. 共享冷却和账号级项目不重复统计；
5. 跨日、跨角色、首次观察和数据陈旧的结果保守且可解释；
6. 主窗口与悬停预览在角色、项目、状态和数量上完全一致；
7. 相关 `Tests/` smoke test 通过，并补充实际游戏内记录。

任一正式项目未通过产品 Change Gate、缺少目标客户端实机确认，或会把未知状态显示为已完成/可执行时，阻断发布。

## 已确认的矩阵实现契约

本节优先于本文中旧的摘要表和字段投影描述。每个活动或公共冷却组必须记录顶层 `monitoringGroupID`、稳定图标身份和组内排序。顶层组与账号矩阵列一一对应：`profession-cooldown`、`farm`、`nomi`、`jewelcrafting-daily`、`cooking-daily`、`fishing-daily`。资料片和专业只能作为组内排序、准入和 Tooltip 信息，不得生成独立列。

主窗口、Broker 和小地图预览必须以同一份快照直接渲染每格全部适用项目图标；Tooltip 仅解释当前图标。禁止 `+N`、隐藏项目、悬停汇总、点击展开、横向滚动或列分页。先按完整单行测量；达到安全宽度后，仅商业冷却单元格可原地换行并增加角色行高，页面使用纵向滚动。

图标优先取任务、奖励或交付物。代理图标必须显式记录、同组不重用、具业务代表性，并可在不改变活动 ID 或设置的前提下替换。不适用项目不显示；适用但未学习、未解锁或技能不足的项目显示其自身图标和对应状态。

任务 Provider 必须区分目标已完成尚未交付的 `in-progress` 与已交付的 `completed`。前者在页面上是原色图标加绿色勾，仍计入待办并优先于未开始项目；`completed` 与 `cooldown` 是灰化图标加绿色勾。未知状态不得作乐观投影。

Todo 的单一业务设置页保存父监控组和子项覆盖；这是业务投影规则，不再与 Core 建立第二套列可见性设置。父组关闭时保留子项选择；子项全关闭时移除该列；新 `verified` 子项继承父组状态，显式子项覆盖优先。Core 仍托管设置窗口壳、页面显示、入口和角色排序。

矩阵相关回归必须额外验证：所有启用子项直接可见；父组全选、部分监控、关闭、恢复和新子项继承正确；待交状态在快照、待办统计、排序和全部入口一致；主窗口与预览的角色、监控组、项目、状态与顺序完全一致。
