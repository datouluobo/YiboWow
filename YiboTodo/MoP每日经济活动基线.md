# YiboTodo 0.2：MoP 每日经济活动基线

这是 0.2 的唯一目录输入台账。它与 `MoP冷却基线.md` 相互独立：后者只维护 0.1 专业冷却，本文件只维护每日经济活动候选。没有 5.5.4 实机记录的候选不得写入正式 Lua 目录，也不得显示为可做、完成或账号共享。

## 当前实施状态

- 阶段 0 已建立只读探针和本台账；尚未取得农场或任务的实机原始记录。
- 当前没有 `active` 的 0.2 活动；因此不得创建 `DailyActivityCatalog_MoP.lua`、`FarmObservation.lua` 或正式 UI 投影。
- `/ytd probe` 会开启并保存 API 能力、可安全调用的农场 API 原始返回、任务日志、事件时间线和服务器时钟到 `YiboTodoDB.diagnostics.lastProbe`；然后在农场或任务场景中操作，最后再执行一次 `/ytd probe` 取得完整时间线。`/ytd probe <任务ID> ...` 额外记录每个指定任务的 `IsQuestFlaggedCompleted` 原始结果。探针不会写活动快照。

## 本地参考实现：BGLite_RoleOverview

已只读检查本机 `BGLite_RoleOverview` 的 MoP “收菜”列。它监听 `UNIT_SPELLCAST_SUCCEEDED`；当玩家施放 `111003`、`116357` 或 `139892`（代码注释为开垦和万能犁）中的任意一个时，就保存 `shoucai` 为当天已完成，并按 07:00 清除。它没有枚举地块、没有读取成熟/空地/异常状态，也没有监听收获完成信号。

## 最后降级路径：本日已进行农场操作

用户已批准将 BGLite 式法术事件记录作为**最后选择**保留：仅当完整的逐地块方案经阶段 0 实机验证确实走不通时，才允许记录“本日已进行农场操作（低保真）”。它不是收菜完成，也不代表全部地块已经处理。

启用前必须同时满足：已确认真实玩家法术 ID 和事件参数；无稳定地块身份/状态 API、任务信号或对象事件可用；设置默认关闭；主表和悬停均明确展示“低保真”。它不得生成 `收获 N`、`播种 N`、`生长 G/T`、`completed` 或任何农场数量统计。

当前状态：`fallback-v0.2.0-implemented`。完整 `16/16` 已证明走不通；经用户批准，v0.2.0 仅将本角色实机观察过的 `111003`、`129757`、`129814`、`129883` 写入低保真“农场操作”记录。它们仅表示发生过操作，不升级为完成、收菜或任何地块状态。地图门控、重复事件与 07:00 的实机验收仍待完成；BGLite 的 `116357`、`139892` 仍仅为本地参考实现候选。

低保真方案已定稿于 [0.2-低保真农场方案](0.2-低保真农场方案.md)。它的任何 spell 规则仍须满足本基线的实机准入；方案文档不是把候选提升为 `active` 的授权。

## 全量状态信号调查

### 1. 动态农场 UI / 模块

待验证：进入农场、选中土地并执行一次合法交互后，是否加载专用 AddOn 或创建名称含 `farm`、`halfhill`、`sunsong` 的全局/UI 框架；以及是否能从中取得完整地块集合。探针会记录 `Blizzard_GarrisonUI` 加载状态和名称含 `farm` / `garrison` / `tiller` / `halfhill` / `pandaria` 的已加载模块。

判定标准：仅“存在模块或框架”不足够；必须能重复读取全部已解锁地块及其状态，才能进入完整方案。

实机结果（2026-08-30）：收获一次后，`Blizzard_GarrisonUI` 仍未加载；仅发现 `HandyNotes_EAPandaria`、`HandyNotes_MistsOfPandariaTreasures` 等第三方地图插件，没有农场专用模块或地块集合。当前判定：**不通过**。这不排除其它全量状态信号，但不再把动态 UI 模块作为当前实现前提。

### 2. 地图任务、隐藏任务或场景全局信号

待验证：当前半山地图的 `C_TaskQuest.GetQuestsForPlayerByMapID`、`C_QuestLog.GetQuestsOnMap` 与 `C_Scenario.GetStepInfo` 是否返回农场有关的任务或可枚举标准；同时记录地图 ID。探针只输出原始返回和可提取任务 ID，不将其当作农场状态。

判定标准：必须存在可重复查询、能覆盖全部地块状态或明确全农场完成的任务/场景信号；仅出现单个任务、地图标记或任务日志刷新不通过。

实机结果（2026-08-30）：当前地图为 `376`；`C_TaskQuest.GetQuestsForPlayerByMapID` 不存在。`C_QuestLog.GetQuestsOnMap` 可用但仅返回任务 `31468`，即当前任务日志中的“黑王子的试炼”，不是农场信号；`C_Scenario.GetStepInfo` 可用但无返回值。当前判定：**不通过**。这些 API 没有返回全农场状态、单地块集合或等价完成信号。

### 3. 16 个地块的稳定位置槽位

待验证：可选中的土壤对象是否能同时提供稳定的实体条目、世界位置和跨重载不变的槽位映射。探针会输出当前目标的 GUID、实体条目与 `UnitPosition` 原值；这一步不假定对象名称就是状态，也不把位置映射当作状态信号。

判定标准：必须能在 16 块已解锁土地上得到互不冲突、跨重载一致的位置槽位，并且后续仍需另有可重复读取的每槽位状态信号。只有位置而没有状态，仍不能实现完整方案。

### 4. 完成任务集合差分（隐藏全局信号）

待验证：`GetQuestsCompleted` 是否可枚举当前角色的完成任务集合，以及收获、播种或开垦后是否产生新增完成任务 ID。探针仅在本次登录会话内保存集合基线，并只输出前后差分；不把全量任务集合写入业务数据。

测试步骤：农场操作前执行 `/ytd probe reset`；不重载、不进行其它任务操作，完成一次农场动作后执行 `/ytd probe`。若新增 ID 出现，需在其它地块状态、跨日与重载后复验它是否是全农场等价信号，而非单次操作或无关任务。

判定标准：仅“某次农场操作新增任务”不足够；该任务必须可重复读取并明确代表全部地块的状态或全农场完成，才可作为完整方案依据。

实机结果（2026-08-30）：在 `/ytd probe reset` 建立基线后完成一次测试操作，后续探针的“完成任务集合新增”和“完成任务集合移除”均为无。期间可观察到法术与任务日志事件，但 `GetQuestsCompleted` 没有可枚举的完成事实变化。地图任务查询随后出现 `31254` 与 `31468` 两项，这不是完成任务集合差分，且没有证明农场全局状态。当前判定：**未发现，按当前可枚举完成任务路径不通过**；这不能逻辑上排除所有不可枚举的隐藏服务器状态，但没有可供插件读取的依据。

## 准入规则

候选只有同时具备稳定身份、直接收益、角色或账号范围、可解释完成信号和跨 07:00 行为的实机记录时，才可改为 `active`。任何缺项继续为 `candidate` 或标为排除；不得通过猜测补齐。
