# YiboTodo 账号矩阵与监控设置方案

> 状态：已确认，实施前置契约。

本方案定义后续 CTM、WLK、TBC 活动扩展进入账号视图时的列、图标、设置和状态投影。产品范围见 [PRODUCT.md](PRODUCT.md)，实机候选与图标基线见 [BASELINE.md](BASELINE.md)，实现约束与验收见 [ENGINEERING.md](ENGINEERING.md)。

## 目标

玩家打开主窗口、Broker 或小地图预览后，应直接看到每个角色的每个已监控项目，马上判断哪个项目已做、待交、可做、冷却、未知或锁定。页面不通过资料片列、专业列、`+N`、悬停汇总或点击展开隐藏项目。

## 主表结构

角色为行，行动类型为固定列：

| 角色 | 商业冷却 | 农场 | 诺米 | 珠宝日常 | 烹饪日常 | 钓鱼日常 |
|---|---|---|---|---|---|---|

- 列顺序固定；不提供拖拽或预设重排。
- 主表列头使用短名：`珠宝`、`烹饪`、`钓鱼`。
- 同一日常列先按状态优先级排序；仅当状态同级时，才按资料片由新到旧排列。
- 商业冷却设置按 WoW 专业册顺序排列：炼金、锻造、附魔、工程、铭文、珠宝、制皮、裁缝；同专业项目连续显示。
- 不在每一列之间新增分隔线：角色列与业务区保持主分隔，日常列通过列头与单元格宽度区分，避免高密度矩阵碎片化。
- 珠宝日常只向 Core 专业快照中拥有珠宝加工（755）的角色投影图标；其他角色保留空单元格。
- 资料片按 CTM、WLK、TBC 作为组内稳定排序；专业只用于冷却列的准入与排序。
- 所有图标自然紧凑排列。不同图标就是不同项目身份，不依赖固定资料片槽位、文字角标或位置编码。
- 图标数量首先按完整单行测量。窗口达到屏幕安全宽度后，商业冷却单元格可原地换行；日常列保留完整直显，页面只使用纵向滚动。
- 不适用项目不显示；适用但未解锁、未学配方或技能不足的项目显示本身图标及锁定状态。

## 图标与状态

每项必须有稳定图标：任务/奖励/交付物的原生图标优先；代理图标必须业务相关、同组唯一、可独立替换。Tooltip 只显示当前图标的名称、资料片、状态、条件和恢复时间。

| 状态 | 投影 | 待办语义 |
|---|---|---|
| `actionable` | 原色图标 | 可立即处理 |
| `in-progress`（任务目标完成、未交） | 原色图标 + 绿色勾 | 仍是待办，优先于未开始 |
| `completed` 或 `cooldown` | 灰化图标 + 绿色勾 | 当前周期已处理，等待 07:00 或 CD 恢复 |
| `unknown` | 弱灰图标 + 问号 | 不作乐观推断 |
| `locked` / `skill-insufficient` | 弱灰图标 + 锁定/技能不足标记 | 不可处理但适用于该角色 |

## 监控设置

Todo 的业务设置页只有一个“活动监控”页面，使用单页分区复选网格。分区与主表列一对一：

1. 商业冷却；
2. 农场；
3. 诺米；
4. 珠宝日常；
5. 烹饪日常；
6. 钓鱼日常。

父组开启即显示对应主表与预览列。子项可单独关闭；父组复选框使用三态：勾选为全选、空心横线为部分选择、空框为关闭。点击部分选择会恢复全选。全部子项关闭时自动移除列。手动关闭父组时保留子项选择，重新开启后恢复。新安装默认启用所有 `verified` 组；新增 `verified` 子项继承父组，用户显式关闭的稳定 ID 不会被重新开启。

设置页不在 Core 和 Todo 之间重复列开关：Core 负责窗口壳、页面开关和入口，Todo 负责业务监控组。子项在足够宽度时自动使用三列，否则回退两列；只有超长的商业冷却区可使用“展开更多”或分页，禁止横向滚动。

## 入口一致性

Broker 与小地图预览完整投影主表：角色范围、列顺序、启用组、项目图标、状态和排序完全一致。关闭任意父组时，所有入口同步移除该列。

# 候选探针接入说明

WLK/CTM/TBC 的未实机确认项目使用“候选探针”状态：业务设置中可见，默认不勾选；启用后才显示对应主表列项目。验证通过后仅将目录条目的验证状态升为正式，不改变列、图标或用户既有开关。
