# YiboTodo 路线图

本文维护 YiboTodo 的版本顺序、里程碑和进入条件。产品边界与准入规则以 [PRODUCT.md](PRODUCT.md) 为准；架构、数据契约和验收方式见 [ENGINEERING.md](ENGINEERING.md)；候选活动、实机记录和资料来源统一维护在 [BASELINE.md](BASELINE.md)。

## 当前状态

| 版本 | 状态 | 已交付或目标 |
|---|---|---|
| 0.1 | 已完成 | MoP 商业技能冷却、共享冷却组、账号摘要、Core 接入与基础设置 |
| 0.2 | 已完成 | MoP 每日经济活动：农场、诺米、半山烹饪日常及经验证的账号每日 |
| 0.3–0.6 | 候选 | CTM、WLK、TBC 与经典旧世的有效冷却或专业每日 |
| 0.7 | 候选 | 周期项目、完整三态设置与长期数据维护能力 |
| 1.0 | 候选 | 稳定版：已验证目录、迁移稳定性与回归覆盖达到发布门槛 |

## 长期路线原则

1. 先扩数据基线和探针，再加入目录、Provider、页面和默认显示。
2. 每个版本只扩大一个可独立验收的活动域；不能以“旧资料片”作为一次性批量收录理由。
3. 候选不等于承诺。未在目标客户端验证身份、范围、完成信号和重置规则的项目不得进入正式目录。
4. 新活动必须沿用稳定 ID、统一状态模型、角色/账号作用域与同一份摘要投影；若现有模型无法表达，先更新产品和工程契约。
5. `BASELINE.md` 中的状态为 `verified` 才可进入默认监控。`candidate`、`external-confirmed` 与 `needs-live-confirmation` 仅用于研究和探针。

## 0.2：MoP 每日经济活动（已完成）

### 目标与范围

在不改变 0.1 冷却模型的前提下，已加入经验证的 MoP 每日经济活动：

- 半山农场的收获、播种、生长和空地观察；
- 诺米课程日常、满阶段固定日常；
- 半山烹饪日常的“同组任一完成即完成”语义；
- 布林顿等可可靠识别、价值明确的账号级每日。

不纳入普通声望日常、暗月马戏团、旧资料片冷却、材料库存、收益估算或自动操作。

### 已完成实施顺序

1. **基线与探针**：补全稳定 ID、解锁条件、作用域、重置信号和 5.5.4 实机结果；未验证项目不写入正式 Lua 目录。
2. **通用每日模型**：实现 `daily-reset` 规则、角色/账号作用域、任务组聚合和 `completed`/`unknown` 的保守投影。
3. **农场观察**：优先采用可验证的全量信号；无法确认所有地块时只显示部分完成或未知，不把单次动作当作全局完成。
4. **任务 Provider**：接入诺米与半山烹饪日常，按活动组而非候选任务数统计。
5. **账号摘要与设置**：将每日活动接入既有快照、预览、角色详情和 Core 设置工作台。
6. **发布验收**：覆盖跨日、跨角色、账号共享、首次观察、缓存迁移和主窗口/悬停一致性。

### 农场的降级边界

当客户端没有可靠的全量农场状态时，最后才允许记录“本日已观察到农场操作”。该信号只能说明单次动作发生过，不能推断 16 块地的收获、播种或生长状态；页面必须标记为低可信度，并保留重新探测路径。

## 后续里程碑

### 下一阶段：账号矩阵与监控设置

先落地 [UI_PLAN.md](UI_PLAN.md)：监控组与主表列一对一、Todo 单页分区监控设置、所有项目图标直显、待交任务第三状态，以及主窗口与悬停的完整一致投影。目录扩展不得绕过这套 UI 与设置契约。

### 0.3：CTM 活动

先验证 CTM 珠宝、烹饪和钓鱼日常；制造候选只验证仍在 MoP Classic 中存在有效冷却的铭文研究与炼金转化。每个日常类别按全局每日活动组处理，不按城市或随机任务重复计数。

### 0.4：WLK 活动

验证达拉然珠宝、烹饪和钓鱼日常，以及独立的铭文研究、炼金转化冷却。锻造、制皮和裁缝不因被称作“专业日常”自动纳入。

### 0.5：TBC 与经典旧世

优先验证沙塔斯烹饪日常与泰罗卡钓鱼日常；经典旧世当前没有符合统一定义的专业日常。制造冷却仅在目标客户端仍有效且具经济价值时单独立项。

### 0.6：扩展冷却目录

按资料片逐组补充经验证的商业技能冷却，持续维护共享关系、重置规则和 inactive 历史身份，避免目录升级破坏既有玩家设置。

### 0.7：长期可维护性

完善三态继承设置、周期与事件窗口、目录维护工具、探针记录流程和数据升级说明。此阶段不改变“专业与经济周期待办”的产品边界。

设置重构完成后，补录 `mop.alchemy.balanced-trillium-ingot`（转化：延极锭）：该转化有几率领悟其它炼金术配方，仍具独立价值；届时先补齐实机记录和准入/展示设置，再决定是否重新纳入正式目录。

### 1.0：稳定版

满足以下条件后再评估稳定版：正式目录均有目标客户端实机记录；跨日、迁移与账号摘要回归通过；未知状态不会被乐观展示；文档、目录、设置和发布包保持一致。

## 变更规则

- 新增或修改范围先更新 `PRODUCT.md` 或本文，再更新 `BASELINE.md`，最后修改代码。
- 每个里程碑采用独立、可验收的提交；发现游戏行为与计划不符时，先修订文档和基线。
- 完成的里程碑仅在本文件保留结论，不保留逐日实施日志；工程实现细节收敛至 `ENGINEERING.md`。
