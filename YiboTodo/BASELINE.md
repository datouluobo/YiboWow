# YiboTodo 内容基线

本文是 YiboTodo 所有候选活动、冷却、实机验证和资料依据的唯一台账。产品准入见 [PRODUCT.md](PRODUCT.md)，版本排期见 [ROADMAP.md](ROADMAP.md)。没有目标客户端实机记录的候选不得进入正式 Lua 目录，也不得默认显示为可做、完成或账号共享。

## 记录规则

| 状态 | 含义 |
|---|---|
| `candidate` | 候选，尚未形成外部或实机结论 |
| `external-confirmed` | 外部资料确认历史身份，未确认目标客户端行为 |
| `needs-live-confirmation` | 必须在 MoP Classic 5.5.4 实机确认 |
| `verified` | 已确认身份、准入、完成/冷却信号与重置规则 |
| `excluded` | 明确不纳入或已确认没有有效冷却 |

每条实机记录至少包含：客户端构建、测试角色与专业/技能、稳定身份（quest/spell/item ID）、前置条件、原始 API/事件/任务日志信号、角色或账号作用域、冷却关系、原始时间值、重置规则、跨日结果和结论。

同一每日活动组的随机候选任务只生成一个待办；制造 CD 是独立活动类型，绝不能伪装成 NPC 每日任务。

## 实机确认清单

- [ ] 记录目标客户端完整构建、测试角色、阵营、等级与专业技能。
- [ ] 确认每个任务的 quest ID、任务池、前置、可接/进行/可交/完成信号和跨日刷新。
- [ ] 确认每日活动的角色/账号/全局组共享范围，防止按城市或候选任务重复统计。
- [ ] 记录每个制造候选的 API 原值、持续时间、共享冷却关系和实际重置方式。
- [ ] 为每个正式项目记录原生或代理图标的来源，确认同组图标可直接区分且不重复。

- [ ] 结论为 `verified` 前，不加入 Lua 目录、默认显示或账号统计。
