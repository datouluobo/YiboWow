# YiboTodo - 账号待办简要版本规划

产品功能、准入标准和长期边界以 [PRODUCT.md](PRODUCT.md) 为准；本文只维护版本范围和实施顺序。当前版本的工程结构、数据契约和验收门槛见 [IMPLEMENTATION.md](IMPLEMENTATION.md)。

## 1. 产品定位

本插件用于汇总账号各角色需要周期处理的专业与经济活动，让玩家快速判断应该登录哪个角色、可以制作什么、还有哪些项目未处理，以及下一项何时恢复或重置。

- 技术名：`YiboTodo`
- 产品名与页面名：`账号待办`
- Slash 命令：`/ytd`（当前工作区未发现占用）
- 目标客户端：熊猫人之谜经典版 `5.5.4`（Interface `50504`）
- Core 依赖：`YiboCore` API v5 或后续兼容版本

### 1.1 命名边界

`YiboTodo - 账号待办` 强调“账号下各角色还有什么需要处理”，不把产品限制为每日重置，也可以容纳固定时长冷却、周常、月度和事件窗口项目。

“待办”不表示追踪所有普通任务。本插件仍只收录具有明确专业或经济价值、稳定完成信号并值得账号级比较的周期项目；普通声望、战斗和通用任务继续排除。

纳入项目必须至少满足一项：

1. 具有真实的专业制造冷却；
2. 直接奖励专业材料、专业货币、配方、技能或专业系统进度；
3. 属于农场、烹饪等明确的每日经济活动。

普通声望日常不因任务要求烹饪、钓鱼、考古或急救就自动纳入。例如云端翔龙的专业主题日常主要服务声望，若不提供专业相关奖励，则不进入默认监控目录。

## 2. 0.1 范围

`0.1` 只监控熊猫人之谜商业技能冷却，不实现日常任务、农场、诺米或烹饪日常。

首版交付：

1. 建立 MoP 商业技能冷却数据基线，逐项记录并实机验证 spellID、结果 itemID、专业、重置方式和共享冷却关系。
2. 建立独立的冷却目录 `CooldownCatalog`。
3. 建立独立的共享冷却组目录 `CooldownGroupCatalog`，共享冷却只计为一个可执行项目。
4. 建立客户端规则集；区分项目来源资料片与其在 `5.5.4` 中的实际冷却规则。
5. 建立可扩展采集器接口；`0.1` 只实现配方冷却采集器，后续可以增加任务、农场和观察型采集器。
6. 建立统一状态模型：`可制作`、`冷却中`、`预计可制作`、`未扫描`、`未学习`、`不适用`。
7. 接入 YiboCore 角色目录、统一账号窗口、Broker/小地图预览和统一设置工作台。
8. 主表提供 `可制作`、`冷却中`、`最近恢复`、`待做项目` 等摘要字段；详情按专业和共享冷却组展开。
9. 设置支持按专业、冷却组和单项显示或隐藏。子项默认继承父组，新增目录项自动继承所属分组设置。

`0.1` 明确不做：

- 农场收菜与播种；
- 农场工作订单；
- 诺米和烹饪日常；
- 普通专业或声望日常；
- 布林顿每日礼物；
- 暗月马戏团专业任务；
- 旧资料片冷却；
- 材料库存、拍卖价格和收益估算；
- 自动制造、完成任务或发送账号数据。

## 3. 目录与扩展契约

每个冷却项目使用稳定 ID，不使用本地化名称作为数据键。目录至少记录：

- `id`
- `introducedIn`
- `professionID`
- `recipeSpellID`
- `resultItemID`
- `cooldownGroupID`
- `resetPolicy`
- `defaultVisibility`
- `ruleset`
- `verificationStatus`
- `verifiedBuild`

共享冷却组独立保存组 ID、显示名、聚合方式和重置规则。冷却项目只引用组 ID，不复制公共规则。

目录更新规则：

1. 新增项目只能追加稳定 ID，不复用旧 ID。
2. 冷却取消或配方失效时标记为 inactive，不直接删除历史定义。
3. Blizzard 修改共享关系或重置方式时更新规则集，不修改项目身份。
4. 启动时校验重复 ID、缺失组、冲突规则和错误成员关系。
5. 目录版本升级不得清空用户的分组或单项显示偏好。

虽然 `0.1` 只有冷却项目，通用活动接口仍预留：

- `provider`：配方冷却、每日任务、农场观察等采集来源；
- `scope`：角色或账号；
- `scheduleKind`：日重置、周重置、固定时长、事件窗口或观察动作；
- `completionMode`：单项、任一完成、全部完成或计数目标。

这些字段在 `0.1` 不产生额外功能，只用于避免后续新增活动时重做数据库和页面模型。

## 4. 未来监控目录

未来功能按“是否有明确的专业或经济收益、是否存在稳定完成信号、是否值得账号级比较”决定是否纳入。不会因为任务使用了某项专业能力就自动监控。

### 4.1 MoP 每日经济活动

- 农场收获、播种、生长状态和空地；
- 诺米：声望未满阶段的任务，以及声望满后每日完成状态；
- 半山烹饪日常与铁掌相关奖励；
- 直接奖励专业材料、专业货币、配方、技能或专业进度的日常。

云端翔龙的烹饪、钓鱼、考古和急救主题日常主要用于阵营声望。除非实机基线确认提供值得独立追踪的专业奖励，否则不纳入默认目录。

### 4.2 账号级特殊每日

- 布林顿 4000 每日礼物；
- 后续其它具有明确账号共享完成状态的经济奖励。

这类活动使用 `scope = "account"`，在账号摘要中只显示一次，不复制到每个角色行，也不能重复计入角色待做数量。

### 4.3 专业与经济相关候选

- 纳特·帕格稀有鱼交付及其它钓鱼日常；
- 阡陌客好友食物或礼物；
- 其它资料片的烹饪、钓鱼、珠宝、铭文等专业日常。

候选项目必须在基线中记录实际奖励、完成范围和终止条件。只奖励普通声望、且没有持续专业或经济价值的项目默认排除或保持隐藏。

### 4.4 周期与事件项目

- 暗月马戏团专业任务；
- 后续出现的专业周常；
- 固定 20 小时、24 小时、多日等非服务器日重置项目；
- 仅在特定日历事件期间开放的专业或经济活动。

暗月马戏团按 `calendar-window` 或对应实际重置规则建档，不伪装成每日任务。事件结束后保留历史状态，但不继续显示为当前待做。

### 4.5 明确排除

- 普通阵营声望日常；
- 世界 Boss、副本和稀有锁定；
- 每日地下城、场景战役和战场首胜；
- 宠物对战日常；
- 职业专属训练日常；
- 仅因“每天可以做”但没有稳定专业或经济目标的普通任务。

## 5. 后续版本

### 0.2：MoP 每日经济活动（规划中）

- 农场收获、播种和生长状态，明确投影是否全部 16 块地处于生长；
- 诺米：五个未满阶段任务、五阶段完成后的固定日常完成状态（不记录声望数值）；
- 半山烹饪日常：六个随机任务组成一组，完成任一个即完成当日任务组；
- 只纳入确实提供专业材料、货币、配方或进度的专业日常；
- 增加布林顿等账号级特殊每日；
- 增加每日任务和观察型采集器。
- 随农场功能发布专业 CD 的技能不足提示：按各冷却组维护的精确技能门槛与 Core 专业等级判定、图标右下角小型禁用标记与技能等级悬停说明。

详细范围、数据基线、Provider 边界、迁移和验收门槛见：[0.2 实施方案](0.2-实施方案.md)；按阶段执行的工作项见：[0.2 实施计划](0.2-实施计划.md)。

### 0.3：大地的裂变冷却

- 不照搬 4.x 原始规则。

### 0.4：巫妖王之怒冷却

### 0.5：燃烧的远征冷却

### 0.7：周期项目、完整设置与数据维护

- 增加暗月马戏团专业任务和事件窗口采集；
- 完善账号级项目、角色级项目和事件项目的统一摘要；
- 完善“必做 / 仅显示 / 隐藏”三态设置；
- 提供按资料片、活动类型、专业、共享冷却组和单项的继承设置；
- 增加目录版本、最后扫描时间和数据可信度说明；
- 完成目录迁移、旧角色数据和异常恢复测试。

### 1.0：稳定版

- 完成 1.x–5.x 商业技能冷却目录；
- MoP 农场、诺米、烹饪、布林顿及符合准入规则的专业日常稳定可用；
- 暗月马戏团等非每日周期项目能够按实际事件窗口正确显示；
- 主窗口、Broker、小地图和设置工作台使用同一账号快照与状态逻辑；
- 完成多角色、跨服务器、日重置、离线到期和版本升级验收。

## 6. 0.1 开工顺序

1. 编写冷却目录、共享冷却组和客户端规则集 schema。
2. 建立 MoP 候选清单并标记 `已验证 / 待验证 / 上游冲突 / 当前无冷却 / 排除`。
3. 编写游戏内探针，验证 API、事件、共享冷却和重置时间。
4. 固化数据基线后再实现 Core 数据域和采集器。
5. 实现账号摘要、详情视图、预览投影和分组显示设置。
6. 完成 2、10、20、21 名角色及重载、离线到期和服务器日重置测试。
