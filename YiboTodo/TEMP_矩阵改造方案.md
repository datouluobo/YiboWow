# YiboTodo 临时矩阵改造方案

> 状态：已实施，待游戏内验收。本文只记录当前已确认的 UI 与数据投影决策，不改变 `PRODUCT.md` 的产品边界。

## 1. 改造目标

账号待办的主页面应让玩家快速找到“当前可以制作的角色和项目”。它不是专业目录，也不是倒计时表。

主页面必须满足：

- 每个角色严格只占一行；
- 不默认各角色拥有相同专业；
- 不重复显示专业名称和专业技能点；
- 制作项目以物品图标为主，状态直接通过图标呈现；
- 账号共享项目不占角色矩阵列。

## 2. 数据边界

### 2.1 专业归属

角色的两项主专业只读取 `YiboCore.DataDomains` 的 `professions` 快照：

- `primaryProfessions[1]` 对应矩阵的“专业槽位 1”；
- `primaryProfessions[2]` 对应矩阵的“专业槽位 2”；
- 快照的 `id` 是专业匹配与项目准入的唯一依据；
- YiboTodo 不保存、不扫描、不推断角色是否拥有某项专业。

YiboTodo 的专业窗口采集器仅收集“已知配方的冷却事实”。它必须以 Core 的当前角色专业快照为前提，不能创建、覆盖或纠正 Core 的专业数据。

### 2.2 项目归位

- 专业冷却项目按其 `professionID` 投影到该角色对应的专业槽位；
- 同一专业的多个独立冷却在同一单元格横向排列；
- 同组冷却只保留一个图标；
- 不属于两项主专业的项目绝不进入该角色行；
- 面向所有角色的角色级项目使用右侧固定列；
- `scope = account` 的项目使用矩阵上方或下方一条账号摘要行，只显示一次。

## 3. 矩阵结构

```text
账号共享：  [布林顿图标]
────────────────────────────────────────────────
角色        专业槽位 1             专业槽位 2       通用项目
天竺雷霆    [贾德]                 [霹雳钢][两仪]   [通用项目]
天竺血月    [活化钢]               [帝王丝]         —
```

### 3.1 固定列

1. `角色`：角色名称；
2. `专业槽位 1`：Core 第一主专业所对应的冷却项目；
3. `专业槽位 2`：Core 第二主专业所对应的冷却项目；
4. `通用项目`：每个角色都可能适用、但不绑定专业的角色级项目；后续每个正式通用项目可增加一列。

角色行高度固定为 38px。项目不增加行数，不展开为文字列表。

### 3.2 溢出与详情

- 单元格图标以 22px 横向排列，图标间距 3px；
- 超出可用宽度时显示 `+N`，不换行；
- 悬停图标或 `+N` 时显示完整项目名、周期语义、当前状态与最后确认时间；
- 主表不显示精确倒计时或恢复时间；
- 初版不在矩阵中内联展开角色详情，避免破坏行数稳定性。

## 4. 图标状态规则

|业务状态|主表图标|悬停状态文字|
|---|---|---|
|`actionable`|原始全彩物品图标|现在制作|
|`cooldown`|同一图标灰化、压暗，并带极小勾形遮罩|本日已制作 / 本周已处理 / 冷却中|
|`estimated`|恢复全彩，并带细虚线外框|预计可做|
|`unknown`|低对比 `?` 占位，不伪造物品状态|待扫描|
|`locked`|默认不占主表图标位|未学习|

状态不能只依赖颜色：灰化项目附带勾形遮罩，预计可做附带虚线外框。完整文字只在悬停中出现。

## 5. 周期规则

### 5.1 每日项目

已确认学会并成功采集过的每日项目，在服务器时间跨过 07:00 后自动进入 `estimated`，主表呈全彩图标和虚线框。

主表和悬停均不显示“未重新扫描”的提示。可信度信息保留给诊断与开发状态，不干扰常规操作。

### 5.2 周常、事件与固定时长

- 周常：以“本周已处理 / 预计可做”表达；
- 日历事件：事件关闭时不进入主表；
- 固定时长：保持灰化冷却图标，详细时间仅在悬停中展示。

## 6. 准入与空状态

- Core 专业快照不可用时，不猜测该角色的专业槽位；
- 已知专业但从未采集该专业冷却时，槽位显示一个 `?`，悬停提示“待扫描”；
- 角色没有对应专业时，该槽位显示 `—`；
- 未学习的单个配方不占主表位置，以免把“目录中存在”误解为“角色有待办”。

## 7. 实施顺序

1. 读取 Core `professions` 数据域，并建立专业 ID 到槽位的投影；
2. 修改快照层，只投影与角色两项专业相符的冷却项目；
3. 以固定行高实现图标矩阵、状态遮罩、`+N` 溢出与悬停；
4. 接入账号共享单行与通用项目列；
5. 验收混合专业、多个冷却、每日 07:00、周常、固定时长、20+ 角色与预览投影。

## 8. 验收样例

- 工程 / 锻造角色：工程项目仅在槽位 1 或 2 的对应专业单元格出现；锻造两种独立锭在另一单元格分别显示；
- 炼金 / 裁缝角色：不显示工程或锻造项目；
- 仅有一项主专业的角色：另一个槽位显示 `—`；
- Core 专业快照未知的角色：不显示伪造专业或项目；
- 每日重置后：已确认项目从灰化转为全彩虚线框，无需打开专业面板；
- 账号共享项目：只在矩阵外的账号摘要行出现一次。
