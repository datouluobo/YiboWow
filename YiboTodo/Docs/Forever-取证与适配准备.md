## 本轮交付与集中测试

新增独立 [YiboProgressForeverProbe 0.1.0](../../_NonRelease/YiboProgressForeverProbe/README.md)，正式业务代码不依赖该探针。一次打开本人专业窗口并执行 `/ypg cooldown`，即可同时取到Crafting扫描准备状态、窗口归属、专业身份、配方ID/信息和专业/法术冷却原始值。通用环境探针没有修改。

首轮不要求角色已拥有冷却配方；有真实对象后，以 `/ypg recipe <ID>` 固定对象做下列对照：

| 样本 | 必须保留的原生事实 | 能回答的问题 |
| --- | --- | --- |
| 制作前 | 本人专业、配方名/ID、已学状态、原生冷却文字、可制造条件 | 对象、归属与可读字段是否匹配 |
| 手动制作后及读数稳定后 | 制作成功事实、原生倒计时、事件与API返回 | 冷却开始信号与短暂零值/延迟 |
| 过一段时间与重载后 | 同一对象倒计时、两套时钟、原生状态 | 剩余秒/起止时间格式与重载时钟边界 |
| 自然到期或跨重置 | 原生状态从不可用转为可用 | 周期/失效规则；未完成前不宣称每日/每周 |
| 另一配方、角色或规则集（仅需共享功能时） | 双方前后值与使用资格 | 同组冷却、账号共享与角色独立范围 |

没有周期对象时，记录“前置条件未满足”，并保留专业诊断样本；不会从nil/false/零值生成完成或可制作状态。营地、Blueprint或Legacy Challenge后续需要各自稳定ID、状态与周期来源，不能复用一次专业采样替代。

## 获得样本后的最小职责边界

- `Forever/`拥有本服API、事件、经核实条目和周期规则；先启用一个明确冷却对象，再扩展目录。采集状态区分未知、可观察、冷却中和已到期；已学、条件满足和可制作数量分别保存。
- Todo拥有观察、完成/到期判断、快照时间、失效与业务SavedVariables。Core只消费需要的专业身份、角色GUID、统一页面/入口和语言；不接管冷却组或周期规则。
- Core的 `profession-profile:1` 可以提供通用专业档案。直接读取原生配方冷却由Todo自己的目标采集器拥有；若将来消费Crafting已提供的配方事实，先定义最小公开能力契约并经Core发现，禁止读Crafting内部对象或存档。
- 状态模型与账号矩阵按实际触及范围审查后共享；现有MoP Provider含本人窗口、名称匹配与每日07:00业务假设，不能仅换TOC引用成为Forever实现。新目标使用独立SavedVariables，Core身份/共享范围未证实时仅当前角色观察。
