# YiboTodo 可点击动作实施方案

> 状态：方案已建立，尚未开始实现。
>
> 范围依据：[可点击动作目录](可点击动作目录.md)。本方案只覆盖当前角色的商业冷却配方图标，不扩展到任务、农场、账号级项目或其它 Todo 项目。

## 1. 目标与非目标

### 目标

1. 当前角色的商业冷却图标在 `actionable` 且动作验证通过时，普通左键直接尝试制作 1 份。
2. 当前角色的不可用商业冷却图标打开对应专业面板，并定位到对应配方；无法可靠定位时只打开专业面板。
3. 其它角色的商业冷却图标保持只读。
4. 点击结果由游戏事件和现有专业快照确认，矩阵、Tooltip、Broker 和小地图预览保持一致。

### 非目标

- 不自动接取、交付或完成任务；
- 不自动寻找 NPC、移动角色或执行世界交互；
- 不制作无冷却的同产物配方；
- 不远程替其它角色制作；
- 不因点击失败而自动重试；
- 不在第一阶段修改 YiboCore 的公共 API，除非验证后确认缺少必要的可选能力。

## 2. 现状与主要差距

- `YiboTodo/AccountPage.lua` 已使用 `Button` 承载图标，但当前只设置图标、状态装饰和 Tooltip，没有动作分派。
- `YiboTodo/Model/Snapshot.lua` 已把商业项目输出为 `professionProjects`，并保留 `recipeSpellID`、状态和冷却信息，但尚未输出直接制作与面板定位所需的动作元数据。
- `YiboTodo/Providers/ProfessionCooldown.lua` 当前按 `recipeSpellID` 观察专业窗口，需要在执行后复用现有事件/快照刷新路径。
- `YiboTodo/CoreIntegration.lua` 已监听 Core 的 `professions` 数据域更新，并通过 `Addon:NotifyChanged()` 刷新页面；不应另建第二套矩阵刷新机制。
- 当前目录字段中的聚合关系需要按动作目录复核：共享冷却只允许用于珠宝和炼金；“华丽毛皮”必须按 20 皮冷却配方作为单配方项目处理。

## 3. 推荐架构

### 3.1 动作分层

新增业务动作模块，建议文件为 `YiboTodo/Actions.lua`，负责：

- 判断当前角色身份；
- 校验项目是否属于商业冷却；
- 校验 `actionStatus` 是否为 `live-verified`；
- 根据项目状态选择 `direct-craft`、`open-and-select-recipe` 或 `open-profession-only`；
- 做短暂防重复点击；
- 记录动作结果，不直接伪造业务完成状态。

`AccountPage.lua` 只负责把项目动作上下文绑定到图标按钮，不承载配方选择规则或 API 细节。

### 3.2 动作上下文

`Snapshot.lua` 输出给商业项目的最小动作上下文建议为：

```lua
action = {
    enabled = isCurrentCharacter and recipe.actionStatus == "live-verified",
    mode = "direct-craft" or "open-and-select-recipe" or "open-profession-only",
    professionID = 171,
    castSpellID = 114780,
    selectRecipeID = nil,
    selectSpellID = 114780,
    cooldownGroupID = "...",
}
```

字段只描述可验证的业务身份；不能把 `estimated`、`unknown` 或专业归属推导成可直接制作。

### 3.3 动作分派

建议接口形态：

```lua
local ok, result = Addon.Actions:Execute(project, character)
```

返回结果至少区分：

- `submitted`：已向游戏提交制作请求；
- `opened-and-selected`：已打开面板并成功定位；
- `opened-profession`：已打开专业面板，但未能定位；
- `not-current-character`；
- `not-actionable`；
- `not-verified`；
- `api-unavailable`；
- `game-rejected`。

动作模块不把 `submitted` 直接转换为 `completed` 或 `cooldown`；后续状态由游戏事件和专业快照确认。

## 4. 游戏 API 验证闸门

在写入正式动作调用前，必须在目标客户端 `5.5.4 / Interface 50504` 逐项确认实际可用 API。方案不预先假定 API 名称或受保护行为。

### 4.1 直接制作

验证：在商业专业面板关闭时，从当前角色的硬件点击事件中尝试使用 `castSpellID` 或目标客户端实际提供的商业制作调用。

必须确认：

- 点击事件中允许提交制作请求；
- 不会自动打开商业面板；
- 一次只提交 1 份；
- 材料不足、未学习、冷却中和技能不足时不会重复提交；
- 成功或失败都能被现有事件/快照路径观察。

若目标客户端不允许无面板制作，则该项目的 `direct-craft` 必须降级为 `open-and-select-recipe`，不得通过模拟按键或非硬件调用绕过限制。

### 4.2 打开并定位配方

验证：根据 `professionID` 打开对应商业面板，再用已验证的配方身份定位项目。

必须确认：

- 可从矩阵点击上下文打开正确专业；
- 已学习的冷却配方可以被可靠定位；
- 共享组能按目录 `order` 选择正确成员；
- 未学习或无法解析的项目会降级为只打开专业面板；
- 不会选中同产物的无冷却配方。

### 4.3 保护与事件

动作调用必须发生在用户硬件点击路径内；任何需要战斗安全、保护函数或面板状态的限制，都以目标客户端实际结果为准。不得使用延时回调继续执行原始点击动作。

## 5. 目录与模型改造

### 5.1 冷却目录字段

在 `Catalog/CooldownCatalog_*.lua` 中为已完成动作验证的项目补充：

```lua
castSpellID = 114780,
selectRecipeID = nil,
selectSpellID = 114780,
actionMode = "direct-craft",
fallbackMode = "open-and-select-recipe",
actionStatus = "pending-live-action-test",
```

字段规则：

- `castSpellID` 只用于直接制作；
- `selectRecipeID` / `selectSpellID` 只用于面板定位；
- 两者相同也要保留语义区分；
- `actionStatus` 独立于 `verificationStatus`；
- 未完成动作实机验证的项目不得填入 `live-verified`。

### 5.2 聚合关系

- 珠宝和炼金可使用共享冷却组；
- “华丽毛皮”只保留 20 皮冷却配方的单配方动作身份；
- 50 皮无冷却配方不进入动作目录、快照动作字段或动作选择器；
- 同产物无冷却配方不得作为共享组成员；
- `Catalog/Validator.lua` 增加动作身份完整性、共享组成员和无冷却配方排除校验。

### 5.3 快照输出

`Model/Snapshot.lua` 在生成商业项目时复制目录动作元数据，并根据当前角色和状态生成最终 `action`：

- 非当前角色：`enabled = false`，`mode = "read-only"`；
- `actionable` 且 `actionStatus = live-verified`：`direct-craft`；
- 非 `actionable` 且可定位：`open-and-select-recipe`；
- 非 `actionable` 且不可定位：`open-profession-only`；
- 动作未验证：不直接制作，可按目录规则仅打开面板或保持只读。

## 6. UI 接入

### `AccountPage.lua`

- 在 `SetIcon()` 或专用绑定函数中保存当前 `project` 和角色上下文；
- 为图标设置 `OnClick`，统一调用 `Addon.Actions:Execute()`；
- 只有当前角色图标显示动作可用反馈；
- `actionable` 的动作按钮与现有高亮边框一致；
- 不可用但可打开面板的图标显示“可打开专业面板”的 Tooltip 提示；
- 其他角色不设置可执行点击，避免视觉上承诺远程操作；
- 图标回收时清理动作上下文和按钮状态，防止对象池复用旧项目。

### Tooltip

在现有项目 Tooltip 中补充动作提示：

- 可直接制作：`左键：制作 1 份`；
- 不可用但可定位：`左键：打开专业面板并定位配方`；
- 无法定位：`左键：打开专业面板`；
- 其他角色：不显示执行提示。

## 7. 事件与刷新

优先复用现有 `Providers/ProfessionCooldown.lua`、`Addon:NotifyChanged()` 和 `DATA_DOMAIN_UPDATED` 路径。必要时补充最小的商业制作成功/失败观察，但不创建与现有快照平行的状态源。

动作后的处理顺序：

1. 按钮进入短暂防重复状态；
2. 直接制作请求返回成功或被游戏拒绝；
3. 监听现有专业/施法/系统反馈事件；
4. 触发专业冷却 Provider 重新采集或等待现有刷新路径；
5. `Addon:NotifyChanged()` 让所有入口使用新快照；
6. 成功时显示冷却状态，失败时恢复按钮并保留原状态。

如果游戏只提供异步专业数据更新，则禁止在点击回调中猜测结果；最多保留短暂“处理中”UI 状态，业务状态仍以快照为准。

## 8. 实施阶段

### 阶段 0：目录审计与 API 探针

- 核对 14 个商业冷却项目的真实聚合关系；
- 补齐珠宝/炼金共享组成员和顺序；
- 修正“华丽毛皮”的单配方关系；
- 为直接制作、面板打开、面板定位分别编写非正式探针记录；
- 确认目标客户端可用 API 和保护限制。

交付物：更新动作目录文档和动作身份字段草案；未通过项目继续保持 `pending-live-action-test`。

### 阶段 1：动作模型与验证代码

- 新增 `Actions.lua`；
- 新增目录字段和 Validator 校验；
- Snapshot 输出动作上下文；
- 不接入 UI，先通过 Lua smoke test 验证选择和降级规则。

### 阶段 2：矩阵图标接入

- AccountPage 绑定点击处理；
- 增加当前角色、状态、共享组和对象池复用测试；
- 增加 Tooltip 动作提示和防重复反馈。

### 阶段 3：事件刷新与入口一致性

- 接入制作结果观察和专业快照刷新；
- 验证主窗口、Broker、小地图预览一致；
- 验证切换角色、关闭面板、重载和跨日行为。

### 阶段 4：逐项开放

- 只把动作实机验证通过的项目标记为 `live-verified`；
- 每次只开放已完成验证的项目；
- 未验证项目继续显示但不直接制作；
- 完成发布前测试清单后再合入正式版本。

## 9. 测试计划

### 静态与 smoke test

- 目录动作字段完整且无重复身份；
- 共享组仅包含允许的珠宝/炼金成员；
- 华丽毛皮只引用 20 皮冷却配方；
- 无冷却同产物配方不会出现在动作选择结果；
- 当前角色与非当前角色的动作权限正确；
- `actionable`、`cooldown`、`estimated`、`unknown`、`skill-insufficient`、未学习状态的动作模式正确；
- 共享组按 `order` 选择成员；
- 防重复点击只影响 UI 保护，不生成业务完成状态。

### 游戏内验证

- 每个 `live-verified` 项目成功直接制作 1 份；
- 每个不可用状态都能打开正确专业面板；
- 可定位项目能选中冷却配方，而不是无冷却同产物配方；
- 材料不足、未学习、技能不足和冷却中不误标完成；
- 直接制作不打开专业面板；
- 失败不自动重试；
- 事件刷新后所有入口状态一致。

## 10. 发布门槛

以下任一条件未满足，不开放对应项目的直接制作：

- 缺少目标客户端实机动作验证；
- 无法区分冷却配方与同产物无冷却配方；
- 无法可靠定位配方；
- 失败后可能重复制作；
- 点击后可能把未确认状态显示为完成或冷却；
- 主窗口与预览入口出现不同动作或状态。
