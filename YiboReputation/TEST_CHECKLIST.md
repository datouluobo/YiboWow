# YiboReputation 新版验收清单

## 主窗口

- [ ] 主窗口只保留账号声望矩阵，不出现“当前角色 / 所有角色”双视图。
- [ ] 声望为行、角色为列；声望列与角色表头固定，滚动时不丢失定位。
- [ ] 资料片和分类可折叠，默认不会展开全部旧资料片。
- [ ] 搜索、`全部 / 已监控`过滤与“全部展开 / 全部折叠”状态正常协作；展开或折叠不得触发整页卡顿。
- [ ] 黑王子、阡陌客、垂钓翁仅显示一层真实主声望；满值 `999 / 1000` 显示“崇拜”。
- [ ] 矩阵角色单元格悬停显示完整角色身份、声望等级/分子分母与数据状态；声望入口使用 YiboReputation 图标。
- [ ] 等级表达式（如 `90`、`85-90`、`>=80`）会只保留符合条件的角色列，清空输入恢复全部等级。
- [ ] 当前角色列可辨认，指向单元格时同行同列均有焦点提示。
- [ ] 主矩阵可通过星标管理最多 10 项快速监控声望。

## 声望数值

- [ ] 保持暴雪声望窗口资料片分类折叠后重载，目录声望仍显示实际等级与进度，不出现批量“? 未扫描”。
- [ ] 采集时临时展开暴雪声望树后，玩家原有折叠状态得到恢复；所有具有稳定 factionID 的非标题行均有数值快照。
- [ ] Core 声望快照为 schema v4，包含 `contractVersion`、`factions` 和逐 factionID 的 `statuses`，不再把资料片/分类文本复制进角色事实。
- [ ] 旧 schema 快照有既存数值时显示过期标记与原值；没有既存值时显示“需重扫”，不得误写成“不适用”。
- [ ] 已注册但客户端本次无法读取的 factionID 显示“不可用”；新契约中确认未出现的未注册项才显示“—”。
- [ ] 目录外声望按稳定 factionID 回退到资料片，并只把暴雪原生标题作为分类提示，不再把“联盟/部落”等标题误判为资料片。
- [ ] schema v1/v2 的列表索引不得生成声望行；只能通过唯一的本地化名称匹配投影到已登记 factionID，并以旧快照标记显示。
- [ ] 资料片归类不得按 factionID 数值区间猜测；目录外记录只能使用 Interface 50504 的原生分组映射，否则明确进入“未归类”。
- [ ] 客户端提供资料片/分类标题的阵营按原生层级归类，未被静态目录收录时也不落入“其它”。
- [ ] 普通声望当前段达到 `999/1000` 时，紧凑矩阵显示“崇拜”而不是 `999`。

- [ ] 普通声望、好友度和诺米课程使用各自正确的等级体系。
- [ ] 崇拜当前段为 `999/1000` 时只显示“崇拜”。
- [ ] 崇拜当前段低于 `999/1000` 时显示实际数值，例如“崇拜 842/1000”。
- [ ] 好友度显示 API 反应名和等级内进度；API 缺失时显示“好友度数据未就绪”。
- [ ] 诺米不显示日常完成状态或伪造声望；课程不确定时显示“课程数据待确认”。
- [ ] 不适用、未扫描、过期和不可用状态可以仅凭文字或图标区分。

## 当前角色悬停

- [ ] 默认展示当前登录角色，不混入其它角色。
- [ ] 声望按资料片折叠，默认一次只展开一个资料片。
- [ ] 折叠资料片仍显示“已满数量 / 有效声望数量”。
- [ ] 指向声望不会向侧面弹出其它角色列表。
- [ ] 点击声望可打开主窗口并定位到对应声望行和当前角色列。
- [ ] 内容过高时只出现纵向滚动，不出现横纵双滚动。

## 监控声望悬停

- [ ] 设置和主矩阵均可管理有序监控列表，上限严格为 10 项。
- [ ] 监控矩阵按“声望为行、角色为列”显示最多 10 项声望和 20 名角色。
- [ ] 10 名以内角色显示详细单元格；11–20 名角色切换为紧凑单元格。
- [ ] 紧凑单元格包含可辨认的等级简称和实际数值，不只依赖颜色。
- [ ] 指向紧凑单元格时，底部固定详情条显示完整等级、分子/分母、百分比和快照时间。
- [ ] 低分辨率时固定当前角色列并分页其它角色，不使用横纵双滚动。
- [ ] 监控列表为空时显示引导和明确操作，不显示空表格。

## Core 接入与一致性

- [ ] 三个表面对同一角色、同一声望显示一致的等级、数值和数据状态。
- [ ] 角色范围、隐藏、排序和当前角色置顶完全采用 Core 上下文。
- [ ] Broker、小地图入口、悬停窗口壳、锚点和关闭生命周期仍由 Core 管理。
- [ ] 插件没有独立设置窗口、入口拖拽、角色删除或缓存管理实现。
- [ ] SavedVariables 迁移后不再依赖旧 `viewMode` 和 `previewColumns`。
