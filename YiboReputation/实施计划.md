# YiboReputation 新版实施方案

## 0. 决策状态

本文档整体取代旧的“双主视图 + 矩阵悬停投影”方案，是后续实现与验收的唯一设计基线。

旧方案中的以下内容全部废弃：

- 主窗口内的“当前角色 / 所有角色”双视图切换。
- 将完整账号矩阵直接缩放成 Broker 或小地图悬停预览。
- 在当前角色声望树中指向某项后，再向侧面弹出其它角色列表。
- 为了复用同一个行渲染器而强制主窗口与悬停使用相同布局。

仓库中现有 Lua 仍是旧方案的阶段性实现。在进入新版开发前，它只能作为数据接口和组件能力参考，不能作为新版 UI 的验收依据。

## 1. 产品目标与界面分工

`YiboReputation` 服务两个不同强度的任务：主动打开主窗口进行完整账号比较，以及在游戏过程中短暂悬停查看重点信息。

| 表面 | 核心问题 | 信息结构 | 复杂度边界 |
| --- | --- | --- | --- |
| 主窗口 | 哪些角色在哪些声望上存在差异？ | 全账号声望矩阵 | 允许横纵滚动、搜索、筛选和折叠 |
| 当前角色悬停 | 当前登录角色的声望情况怎样？ | 按资料片折叠的纵向声望树 | 固定宽度；默认只展开一个资料片 |
| 监控声望悬停 | 我关注的声望在所有角色上分别怎样？ | 最多 10 项声望的紧凑账号矩阵 | 固定最大面积；不得无限扩张 |

三者复用同一份快照、角色准入、状态判断和数值格式化，但不要求复用同一种行列方向或同一个布局渲染器。

## 2. 主窗口：唯一的完整账号矩阵

### 2.1 矩阵方向

主窗口只保留一个正式业务视图：声望为行、角色为列。

```text
声望                    天堂暴风    天堂雷霆       天堂闪光    天堂暴雨
▼ 熊猫人之谜
  黑王子                  崇拜        崇敬 8420/21000  崇拜        尊敬 4820/12000
▼ 阡陌客
  阡陌客                  崇拜        崇拜             崇敬 73%     崇拜
  农夫老方                挚友        朋友 6800/8400    未扫描       —
  诺米                    第4课       挚友             好友 3400/8400 —
▶ 大地的裂变
▶ 巫妖王之怒
```

声望数量远大于角色数量，声望名称也更长，因此把声望放在纵向固定列比照搬 Biaoge 的“角色为行”更适合浏览和比较。

### 2.2 页面结构

主窗口由三部分组成：

1. 顶部工具栏：声望搜索、`全部 / 已监控`过滤、`全部展开 / 全部折叠`。
2. 固定表头：显示角色短名；完整名称、服务器、等级与更新时间在指向时显示。
3. 矩阵内容：资料片、分类、主声望与子声望组成可折叠树。

布局规则：

- 左侧声望列固定，顶部角色表头固定。
- 纵向滚动浏览声望；角色超出安全宽度时只滚动角色列区域。
- 当前角色列使用低饱和青绿色底色强调，不改变文字颜色语义。
- 指向单元格时同时强调所在声望行和角色列。
- 使用轻量行分隔与交替底色，不为每个单元格绘制完整边框。

### 2.3 “全部”的含义

“全部声望”表示所有目录声望均可在同一页面结构中访问，不表示进入页面后全部展开。

- 默认展开当前资料片；旧资料片默认折叠。
- 记住每个资料片和分类的展开状态。
- 搜索命中时临时展开相关父级；清除搜索后恢复原状态。
- `全部`与`已监控`是成对的范围过滤；不再提供“未满”过滤。
- `已监控`只显示加入快速监控列表的声望。
- 目录外但快照中存在的声望归入“其它”。

### 2.4 单元格信息层级

普通详细单元格优先显示等级名称和当前等级内数值。空间充足时可追加百分比，但百分比不能替代实际数值。

普通声望的“崇拜”使用专门规则：

- 当前等级内数值为 `999/1000` 时，只显示“崇拜”。
- 当前等级内数值低于 `999/1000` 时，必须显示实际数值，例如“崇拜 842/1000”。
- 不得仅凭 `standingID == 8` 就隐藏进度。

好友度按好友关系等级和当前关系段显示，例如“朋友 6800/8400”；诺米按可靠的课程或关系等级显示。好友度不得套用普通八级声望格式。

数据状态必须相互区分：

- `—`：该角色不适用此阵营或声望。
- `? 未扫描`：符合条件但尚无快照。
- `时钟图标 + 原值`：快照过期。
- `不可用`：客户端接口当前无法提供数据。

颜色只辅助等级和状态识别；文字或图标必须独立表达含义。

### 2.5 监控入口

每个具体声望行提供星标操作：

- 星标用于加入或移出快速监控列表。
- 已监控项保持可识别的常驻标记；未监控星标只在指向行时突出。
- 最多监控 10 项；达到上限时明确提示，并提供前往设置管理的入口。
- 设置工作台是完整管理和排序入口，主矩阵星标是快速操作入口。

## 3. 悬停模式一：当前角色声望树

### 3.1 用途与默认值

这是默认悬停模式，零配置即可使用。它只回答当前登录角色的问题，不同时展示其它角色。

```text
天堂阴影 · 当前角色

▼ 熊猫人之谜                         8 / 21 已满
  黑王子                     崇拜
  阡陌客                     崇敬 8420/21000
  垂钓翁                     尊敬 4820/12000
  诺米                       第4课 3500/8400

▶ 大地的裂变                         5 / 8 已满
▶ 巫妖王之怒                         7 / 9 已满

点击声望：在主窗口中定位
```

### 3.2 展开与尺寸规则

- 默认展开当前资料片或最近一次主动展开的资料片。
- 默认一次只展开一个资料片，切换时收起前一个。
- 资料片折叠行显示“已满数量 / 有效声望数量”。
- 面板目标宽度为 400–480 UI 单位；高度优先控制在安全屏幕高度的 60% 以内。
- 内容确实超高时才启用纵向滚动；不得出现横向滚动。
- 当前角色没有快照时显示采集说明，不显示空白树。

### 3.3 交互规则

- 指向声望行只显示该项的完整数值、数据时间和特殊类型说明。
- 不向侧面扩展其它角色列表。
- 点击具体声望打开主窗口，并自动展开所属资料片、滚动到目标行和当前角色列。
- 左键入口仍打开主窗口；右键入口仍由 Core 打开统一入口设置。

## 4. 悬停模式二：监控声望账号矩阵

### 4.1 数据范围

- 快速监控列表最多 10 项声望。
- 显示所有有业务快照且符合 Core 角色范围的角色，最多 20 名。
- 声望为行、角色为列，与主矩阵保持相同的比较方向。
- 行顺序采用设置中的监控顺序；角色顺序完全采用 Core 提供的顺序。

```text
监控声望              暴风       雷霆       闪光       暴雨
黑王子                拜         敬 8420    拜         尊 4820
阡陌客                拜         拜         敬 73%     拜
农夫老方              挚         朋 6800    ?          —
诺米                  4课 3500   挚         好 3400    —
```

### 4.2 自适应密度

监控矩阵必须在 10 项声望和 20 名角色的上限下保持面积稳定，因此采用两级密度：

- 角色不超过 10 名：使用详细单元格，显示完整等级与等级内数值。
- 角色为 11–20 名：使用紧凑单元格，显示可辨认的等级简称和当前段实际数值；指向单元格时，在矩阵底部固定详情条显示完整等级、完整分子/分母、百分比和快照时间。

紧凑单元格不是纯颜色热力图。等级简称必须可独立辨认，例如：`拜 / 敬 / 尊 / 友 / 中 / 冷 / 敌 / 仇`；好友度使用对应关系简称。颜色只作为辅助。

崇拜等级仍遵守统一数值规则：

- `999/1000` 显示“拜”或详细模式中的“崇拜”。
- 未到 `999/1000` 时必须保留当前段实际数值；紧凑模式可显示“拜 842”，底部详情条显示“崇拜 842/1000”。

### 4.3 尺寸与低分辨率回退

- 正常目标最大宽度约 1080 UI 单位，最大高度约 520 UI 单位。
- 不因声望名称或角色名称临时向侧面生长。
- 角色表头使用经过消歧的最短名称片段；指向时显示完整名称、服务器和等级。
- 安全屏幕宽度不足时，当前角色列固定，其余角色按页显示；分页优先于横向滚动。
- 最多 10 行监控声望原则上不需要纵向滚动。
- 悬停中不得同时出现横向和纵向滚动。

### 4.4 空状态

监控列表为空时不显示空矩阵，显示“尚未监控声望”，并提供“打开主窗口”和“打开声望设置”两个操作。

## 5. 视觉语言

- 资料片行最强，分类行次之，具体声望行为主要数据层。
- 当前角色使用低饱和选中底色，不使用整列高亮职业色。
- 职业色仅用于角色名或小型身份标记。
- 已监控星标、当前焦点和主要操作统一使用 Yibo 青绿色 `20e070`。
- 等级文字可沿用玩家熟悉的声望色，具体数值采用高对比中性色，避免整张表被“崇拜”紫色淹没。
- 警告色只用于过期、不可用或确实需要注意的状态。
- 展开、折叠和模式切换只使用 150–200ms 的状态过渡；不做装饰性动画。

## 6. 设置工作台

YiboReputation 不创建独立设置窗口。设置继续嵌入 Core 统一工作台。

### 6.1 页面与入口

由 Core 提供页面启用、独立 Broker/小地图入口位置和入口生命周期。

### 6.2 显示与排序

由 Core 提供角色范围、隐藏角色、当前角色置顶和账号排序。业务插件不得自行重排 `context.characters`。

### 6.3 业务设置

按以下顺序提供：

1. `悬停内容`：当前角色 / 监控声望账号对比。
2. `快速监控声望`：最多 10 项，支持搜索、添加、移除和排序。
3. `当前角色悬停默认资料片`：自动 / 指定资料片。
4. `主窗口默认过滤`：全部 / 已监控。
5. `好友度详细值`：等级内进度；可选附加累计进度。

页面展开状态、最近搜索和临时焦点属于视图状态，不作为长期业务设置堆入工作台。

### 6.4 数据与缓存

- 说明声望事实由 YiboCore 保存，本插件只保存视图和监控列表。
- 不提供第二套角色删除、缓存清理或窗口位置管理。

## 7. 数据与格式化契约

所有表面必须调用同一个格式化层，禁止主窗口、当前角色悬停和监控悬停各自解释声望数值。

格式化层至少提供完整、矩阵、紧凑和详情四种格式，并分别处理普通声望、好友度与课程声望。

共享规则：

- 使用稳定 `factionID`，不使用客户端列表索引或本地化名称作为主键。
- `999/1000` 是崇拜满值的显示折叠条件；低于 999 必须保留实际数值。
- 未扫描、不适用、过期、不可用不得合并为同一种空值。
- 阵营限制由目录和角色阵营共同判断。
- 未收录声望归入“其它”，不得静默丢弃。

## 8. Core 接入调整

新版悬停不再是主矩阵的字段投影，因此旧的 `previewColumns` 模型不足以表达业务需求。

- Core 仍负责悬停窗口壳、锚点、安全尺寸、入口设置和关闭生命周期。
- YiboReputation 根据 `settings.hoverMode` 在同一预览容器内选择当前角色树或监控矩阵。
- Core 继续向两种悬停提供统一角色范围与排序上下文。
- 插件共享数据、格式化器、状态颜色和目标定位，但分别实现主矩阵、当前角色树和监控矩阵布局。
- 项目级“悬停必须是主窗口预览列投影”的约定需要改为允许这种明确的任务型例外；在约定正式更新前不得把新版实现视为完成。

## 9. SavedVariables 规划

```text
settings = {
  hoverMode = "current-character" | "monitored",
  monitoredFactionIDs = { ... },        -- 最多 10 项，有序
  defaultExpansion = "auto" | expansionID,
  defaultMatrixFilter = "all" | "incomplete" | "monitored",
  showFriendshipTotal = false,
}
matrixExpanded = { ... }
currentPreviewExpanded = expansionID
matrixFocusFactionID = factionID | nil
```

不再保存旧的主窗口 `viewMode`；旧 `previewColumns` 在迁移后废弃。升级时保留可识别的展开状态与好友度偏好，其余旧视图状态不继续传播。

## 10. 文件调整规划

```text
YiboReputation/
  Bootstrap.lua                    默认值与 SavedVariables 迁移
  CoreIntegration.lua              页面、入口与两种预览路由
  ReputationCatalog.lua            声望目录与阵营限制
  ReputationHierarchy.lua          主矩阵和当前角色树的层级模型
  ReputationFormat.lua             完整、矩阵、紧凑与详情格式
  AccountMatrixView.lua            唯一正式主视图
  CurrentCharacterPreview.lua      当前角色悬停
  MonitoredPreview.lua             10 项监控声望矩阵
  PreviewController.lua            模式、尺寸与焦点交互
  Friendship.lua
  Nomi.lua
  Settings.lua
  Commands.lua
```

旧 `CurrentCharacterView.lua` 已由 `CurrentCharacterPreview.lua` 接管并移除；不得再恢复旧的主页面树视图。

## 11. 实施顺序

1. 更新项目级悬停约定，冻结“数据复用但布局可分离”的例外边界。
2. 重写格式化层，先用测试固定 `999/1000`、未满崇拜、好友度和四种数据状态。
3. 将账号矩阵收敛为唯一正式主视图，完成固定表头、固定声望列、折叠、搜索和过滤。
4. 实现主矩阵星标与最多 10 项监控列表。
5. 将当前角色树迁移为独立悬停视图，删除其它角色侧向飞出逻辑。
6. 实现监控矩阵的两级密度、详情条和低分辨率分页。
7. 调整 Core 预览路由与统一设置工作台。
8. 完成 SavedVariables 迁移，移除旧 `viewMode` 和 `previewColumns` 的运行时依赖。
9. 按主窗口、两种悬停、窄屏和 20 角色上限完成游戏内验收。

## 12. 关键验收标准

- 主窗口不再出现“当前角色 / 所有角色”双视图切换。
- 主窗口能在同一结构中访问全部目录声望，但默认不会全部展开。
- 同一角色、同一声望在三个表面中的等级、实际数值和数据状态完全一致。
- `999/1000` 显示为“崇拜”；`842/1000` 显示为“崇拜 842/1000”，不得隐藏数值。
- 当前角色悬停默认只展开一个资料片，不出现其它角色侧向飞出列表。
- 点击当前角色悬停中的声望能够在主矩阵中准确定位。
- 监控列表支持并严格限制为 10 项；第 11 项不会静默加入。
- 监控悬停在 10 项声望、20 名角色时仍保持在安全面积内，不出现横纵双滚动。
- 监控紧凑单元格同时具有文字简称与实际数值，完整信息可在固定详情条读取，不依赖颜色。
- 当前角色、阵营不适用、未扫描、过期、不可用和好友度数据未就绪均有不同表达。
- 两种悬停仍由 Core 创建、定位和关闭；插件不产生第二套窗口壳、入口或角色排序。
