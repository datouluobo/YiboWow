# Forever 收件人与附件主题 — 2026-11-19

## 实机输入与源码调查

用户截图显示选中账号角色后收件框携带 `-CN1 Realm 8 PvE` 等内部服务器后缀；用户手动删除连字符及其后缀后成功发出邮件。该反馈证明当前样本的原生投递使用完整双名；不把 Core 目录中的 realm 元数据直接当作 Forever 邮件投递地址。

MoP 源码已有 SubjectForAttachments / EnsureSubject：单种物品取首件名称，多种物品附加本地化种类数；只补空白主题，保留非空主题。现有调用集中在快捷联系人与规则寄，普通添加附件的 MAIL_SEND_INFO_UPDATE 未调用它。因此这轮补接共用规则，不据源码推定所有 MoP 原生客户端行为已实测。

## 改动

- 两目标 Compose 提供 NativeRecipient：Forever 只取连字符前的完整双名，MoP 保持原地址。联系人选择、快捷格、规则寄写入及草稿恢复均消费该契约；联系人悬停也展示实际投递地址。存档的标准化地址和角色 GUID 关联不变，不迁移或重写旧联系人、快捷格、规则与历史。
- 共用 Compose 在邮箱会话中、发件页可见时处理 MAIL_SEND_INFO_UPDATE，复用 EnsureSubject 自动补齐空主题。普通拖入、背包装填等均以原生附件更新为准；玩家自填主题不覆盖，空附件空金额不生成主题，关箱/隐藏发件页不编辑草稿。
