# MoP 单封与批量退信方案与验收

创建日期：2026-10-21；最近验收更新：2026-10-22。当前版本：`1.3.0-api1`（包含1.2.25／1.2.26开发迭代）；原1.2.25的已验范围见下文。**1.2.26单独选择拍卖成功邮件时退信禁用、普通邮件与拍卖成功邮件混选退信均已实机通过；对应历史为已收取，实际钱包到账缺少独立证据；其余补修实机及发行检查待完成，未发布**。

## 操作方案

- 收件箱有选中邮件时，在“收取”左侧显示“退信 N”；没有选择或切至附件箱时隐藏。按钮复用现有样式，宽度按当前语言标签计算，底部状态区让出按钮位置，完整反馈可悬停查看。
- N 是涉及的邮件封数。同一封的多个附件、金币勾选去重为一封；部分附件勾选仍表示该信进入整封退信范围，确认框明确提示这一点。原有附件单项收取、部分勾选与全选偏好继续可用。
- 退信必须有正向准入证据：邮件头第12项canReply明确为true/1，且第13项不是GM标记；缺失、false或异常类型均不可退，收取沿用原资格。拍卖识别只是独立排除条件，识别失败不再视为玩家邮件许可。接受确认及每封执行前重新读取。
- 可退资格继续采用当前目标客户端的原生删除／退回判断：`InboxItemCanDelete(index)` 明确为 false/0 才可退回；true/1 的邮件不转成删除操作，接口缺失或结果未知时停止相应退信。打开邮箱、当前角色及新鲜可见快照仍是操作前提。
- 拍卖行邮件在退信资格层排除，保留收件箱的勾选和正常收取。识别使用原生发票类型（seller／buyer／seller_temp_invoice）以及客户端原生拍卖主题模板（成交、到期、取消、竞拍成功／失败、待付款通知），覆盖没有发票的上架到期／取消退件；不硬编码中文主题或发件人。混选在二次确认中列明跳过封数与“拍卖行邮件不参与退信，可正常收取”；只选一封或全部选中拍卖邮件时，退信按钮禁用并使用Core灰色文字；至少含一封当前可退邮件时按钮可用，拍卖邮件在退信时跳过；勾选与收取保持可用。生成计划、接受确认和每封请求前均使用最新读取的资格。旧快照缺少新观测字段时，也不能绕过执行前重读。
- 付款取信的可退判断独立于收取资格；可退的 COD 信可按整封勾选，收取按钮保持禁用。退信直接调用 `ReturnInboxItem`，不走付款或取附件路径。可退的无附件信同样提供整封选择，其它空信沿用既有 X 删除入口。
- **批量退信必须二次确认**：第一次点击“退信 N”只生成本批计划并打开 Core 确认框；玩家再次确认后才开始。每批一次，单封也使用同一确认步骤。文案列明“退回 X 封、跳过 Y 封”、跳过原因，以及整封退回剩余附件、金币和 COD 不付款的说明。取消保留选择且不发请求。
- 确认绑定选择、角色、邮箱会话 generation、全体可见邮件内容与数量；接受时再次验证。切换页面、隐藏或关闭邮箱取消确认；选择／邮件／权限变化时提示重新核对，不自动执行变化后的计划。
- 执行期间收取、删除和重复退信受同一队列互斥保护。更多菜单的暂停停止后续请求；已经发出的单次请求继续核实，不能承诺撤销。成功信清除选择，未执行及跳过的信保留；重复邮件的本地 key 变化按已证明的位置重绑。
- 底部显示执行进度。结束显示成功与跳过封数；暂停显示已成功、待核实和未执行数量及原因。已证明退回的历史使用独立状态“已主动退回”，历史结果筛选可选择该状态；不记录为附件已收取或对方已收到。

## 队列与数据边界

1. 复用 `Mists/Queue.lua` 的互斥、节流、暂停、外部操作检测与邮箱生命周期，增加 `return` 操作。操作计划、位置与确认数据只保存在内存中。
2. 每批按原始邮箱位置倒序执行，每次请求前全量重读并与最新已证明的可见序列、数量核对，再核实当前信的退回资格。一次只发一个请求，至少间隔 0.25 秒，响应慢时沿用队列退避。
3. 每封必须同时取得成功事件、邮箱更新信号、总量减少一封及剩余顺序符合删除目标后的序列，才归档成功并推进。100 封窗口只允许剩余序列后方补入新显现信；新增信不进入本批选择。
4. 退信属于整封移除；新到信、列表插入／重排或其它变化不能按上述证据唯一确认时，继续等本次结果，30 秒后保留待核实并停止后续操作。不会猜测新位置或重发未核实请求。这个保护比附件收取队列的位置恢复更保守。
5. 关闭时未核实请求保存原始邮件、附件、金币和 COD 信息；重开释放旧队列，要求重新核对选择。旧定时器绑定原队列和 pending，不会在重开后继续退信。
6. Mail 仍是邮件快照与历史的所有者，现有扫描／发布事务同步更新账号视图及公开 `mail.items` 消费方。Core 不接管邮件业务数据，未增加跨业务插件绑定。`YiboMailDB`、安装目录和技术名不变；`canReturn`／`auctionMail`／`canReply`／`isGM` 是可重扫的可选观测字段，旧记录未知时不据此发起操作，不重置存档。
