# Mists 收件队列优化与验收

日期：2026-10-21。当前版本：`1.2.24-api1`，包含 1.2.23 优化与本次 AH 补修。状态：代码完成，收件专项离线回归通过；**实机与发行检查待完成，未发布**。

## 问题与边界

用户提供了历史截图：收件状态为“操作后邮箱内容不符”，进度为 11/15。截图只能证明当时队列暂停，不能确认其客户端版本、实际请求结果或当前是否复现。本轮修复针对代码中可确认的设计问题：逐附件扫描全箱、固定 1 秒请求间隔、两次不一致即暂停，以及所有界面错误都暂停队列。

本轮范围为 MoP 的收件扫描和队列，包含邮件／附件两种操作入口。发送、COD 付款及删除空信继续使用各自已有流程。Forever `0.1.0-api1` 的只读收件快照保持既有范围；没有接入自动收取。

## 执行与保护

1. 启动前全量读取可见邮箱，核对所有选中邮件、附件槽、完整物品身份／数量和金币；复制队列私有工作快照。
2. 每次请求前读取当前目标邮件，核对签名、目标槽及其身份／数量或金币；仍检查当前角色、邮箱开放、COD、战斗和背包空间。布局变化时读取完整可见列表，按已知邮件的相对顺序和全部剩余选中邮件恢复位置；只有所有有效排列都给选中邮件同一位置时才继续，不任意替代同内容信件。
3. 一次只发送一个请求。收到 `MAIL_SUCCESS` 后读取目标，确认目标附件／金币发生预期变化；`MAIL_INBOX_UPDATE` 用来唤醒核对，缺少该事件也可由实际内容证据完成确认。仅有更新或内容变化、没有成功事件时不归档为已收取。
4. 普通自动移除通过邮件数量减少和后继邮件身份确认，修正后续计划索引。100 封窗口补入或布局异常时全量复核；新到信和延迟空信移除同时发生时，按完整顺序恢复，排除读数仍可由未执行请求解释的情况。未选邮件的附件／金币变化不单独否定已证明的目标结果。无法证明时继续等待，不猜测目标身份。
5. 短暂旧缓存、附件头和槽位尚未一致、连续更新等情况在 30 秒期限内等待。不会因扫描次数达到两次而暂停，也不会重复发送在途请求。无关 `UI_ERROR_MESSAGE` 仅触发退避；明确 `MAIL_FAILED`、受阻或外部邮箱操作暂停，结果不明保留 pending。
6. 初始请求间隔 0.25 秒，连续成功时逐步降至 0.15 秒；确认耗时参与节奏估算。超过 0.75 秒仍未确认或收到错误反馈时提高间隔，最高 2 秒；已确认的慢请求结束后再等待退避时间。响应等待本身也限制请求速度，不并发发出后续取件。
7. 确认后的变化仍通过现有 Store 快照合并与历史归档一起发布。队列运行期间，目标采样不冒充全箱新扫描：未读邮件保留原采样时间，对外状态保持 stale。整批完成或暂停后安排全量重扫；异常路径实际取得全量数据时使用真实采样时间。
8. 超时／关闭时保留未核实结果；关闭再打开释放旧队列，后续收取需要玩家重新选择。迟到定时器绑定原 pending、原队列和扫描 generation，不继续新队列或关闭后的邮箱操作。

| 邮件头 API 读取次数 | 1395 | 209 |

## 1.2.24 AH 到期退件补修

用户补充截图显示“所选邮件位置或内容已变化”，进度为 8/12，列表中两行未选、四行仍选中。截图不足以确认当时全部事件顺序；代码审查和模拟复现了两个缺口：收空信先保留后消失，以及取件途中有新退件插入前部。此前仅记录当次请求确认时立即移除的索引，后续没有恢复实际位置。

- 每封初始邮件保留队列私有身份和最新期望内容；完整读取后对齐已知邮件相对顺序，允许已确认空行消失、已收到到信信号或数量增加时的新信插入，以及有限可见窗口的尾部暂不可见。仍选中的每封邮件必须在所有有效对齐中具有唯一位置，不能只找第一封同签名邮件。新邮件保持未选中。
- 由目标复读吸收常见的短时空行：首次确认收空后再读一次目标，间隔 0.1 秒；该次过渡通常不需要全箱重扫。空行更晚消失时，按上述对齐更新所有剩余索引。
- 100 封窗口保留被挤出视野的已知邮件，隐藏数量须符合 API 总量，不把仍可见的选中信任意解释为另一个新副本。优先目标暂不可见时，先推进最早到期的可见选中项以腾出窗口，目标恢复后继续优先处理；不自动选取新增邮件。
- 请求进行中的恢复还检查“未变化的请求是否也能解释当前读数”；存在该解释时不确认成功。非预期非空目标不能被当作新到信跳过，也不能用一封看似部分取件结果的新邮件替代目标。
- 私有位置、顺序和新增行标识仅存在于队列中，不进入邮件记录或 SavedVariables，不改变 mail.items／Core 契约、数据身份或最低 Core 要求；本次 Core 接入审查沿用前节结论。

收件专项新增覆盖：8/12 时的两种空行移除延迟、请求 8/12 中插入两封新 AH 信、100 封窗口被新信挤出再恢复、完全相同新旧信的歧义保护、新到信与非预期目标缓存同时发生，以及伪装成部分取件结果的新信。普通 90 附件模拟保持 209 次邮件头读取、首尾请求间隔 13.52 秒。最新输出见 `_NonRelease/MailCollectionOptimization/AH-Results.json`；这些均为离线证据，本次 AH 实机复验待完成。

`AH-Repro.lua` 的对照复现中，旧的“只登记立即移除”规则停在 `paused / 8 / UI.TEXT_0312`，当前实现完成 `complete / 12`；记录见 `AH-Repro-Comparison.json`。旧规则对照使用之前保存的优化前扫描器／队列源码快照，不代表完整的 1.2.23 历史安装包。
