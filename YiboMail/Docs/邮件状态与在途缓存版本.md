# 邮件状态与在途缓存版本（2026-10-29）

需求：Mail 只发布某一角色的就绪／已读等状态时，Vault 不应重新复制其它角色的完整邮箱；真实收发、收件证据或身份目录改变时，仍须重新匹配在途附件。

提供方 YiboMail，消费方 YiboVault，经 Core.Contracts 的 `mail.items` 服务调用。Mists 保持 major1/minor1；Forever 草稿保持 major1/minor0 与原有当前角色／无在途能力范围。最低 Core API13 和既有 business-services:1 不变，无新 Core 接口。

`GetState({characterID})` 保持原有状态、计数、观察时间和角色邮箱 `revision`，增加可选数值字段 `transfersRevision`：

- 角色 revision 随该角色的发布推进，观察／就绪状态按原语义保留。
- transfersRevision 标识全账号真实邮件及在途匹配证据的数据代次；纯状态发布明确 transfersUnchanged=true 时不推进，真实／未明确不变的发布继续推进。它是缓存失效代次，不表示任务完成或数据新鲜度。
- 返回值继续是可独立修改的副本；全局 GetRevision 仍返回全局发布版本，未改含义。

Vault 仅在两个代次均为有效数值、状态与 observedAt 一致、注册身份未变时复用邮箱／在途快照。无 transfersRevision 的旧提供方继续按全局 GetRevision 失效；没有把缺字段解释为零或升级失败。Provider Connect 已处理缺失、不兼容和重新注册；角色目录的更新、导入、ID 迁移和删除会另行清空缓存。来源移除后恢复 Vault 自有独立缓存，状态未知不计为零。

Core 已对请求／结果执行契约隔离复制，Vault 内部直接持有这份消费者私有结果；对外库存查询继续复制，不能修改 Mail 权威数据或 Vault 私有缓存。没有新增业务强依赖或直接跨插件对象访问。

验证：真实 Mail→Core Contracts→Vault 集成、100 次无关状态零邮箱重读、真实在途证据一次重读、目录独立失效、旧字段缺失回退，以及缺失／不兼容／晚注册、数量和副本隔离通过。双方客户端新字节实测及实际内存收益待验；详细记录见 [第三轮修复](../../Docs/性能修复-第三轮-2026-10-29.md)。

2026-10-29 收件专项：在途索引改为先收集有效寄信，集合为空时跳过收件证据构建；有寄信时匹配规则、重复数和时间语义不变，状态版本与独立结果契约不变。55 项当前离线回归通过，见[批量收件记录](../../Docs/Mail-批量收件内存修复-2026-10-29.md)。

2026-10-29 关闭生命周期：真实数据发布立即释放旧派生索引／结果，纯状态仍复用；Mists 关闭邮箱在状态通知后释放派生缓存。它不改变 revision／transfersRevision 或查询结果，关闭后可按需重建，重复查询仍复用，公共副本不被改变。完整业务历史不删除。58 项当前离线回归及连续批次／弱引用验证通过，实机待验，见[会话记录](../../Docs/Mail-连续收件与关闭释放-2026-10-29.md)。
