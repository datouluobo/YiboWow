`WorkspaceSpec` 使用真实 Mail 模型、UI、Core 主题、统一输入、滚动控件和字段查询，模拟 WoW 帧与客户端数据；覆盖跨角色全局范围、COD 变体、0/24/72小时及未知期限、只发件角色、实际收取数量、总览/悬停一致、来源返回、登录内状态、640×480边界及正常宽度单行筛选、25个邮箱角色、滚动位置/锚点恢复、隐藏后的同步与延迟滚动条刷新、角色职业色及图标汇总、分页角色筛选、历史保留确认和稳定旧事件迁移。浏览过程对真实邮件操作 API 的调用被禁止并检查。

`MailRuntimeSpec` 对实际扫描、存储、队列和事件顺序进行模拟，额外验证多步部分收取仅产生原始两封信的发现事件。原生收件测试更新了账号入口和重复邮件的现行基线；保留原生列表执行收取时，同步刷新勾选与菜单状态，使暂停立即可用。运行与 Vault 消费者测试桩补齐了已存在的 Core `NotifyPageChanged` 方法。

输入法回归：`WorkspaceSpec` 模拟五笔 `d → dy → dyt → 矿`，验证组字及期间的数据刷新不回写输入框、不触发中间搜索、不改变光标；提交完成后查询一次。`CoreItemControlsSpec` 覆盖相同值同步、IME 标记晚清除、无用户标记的原生组字事件、组字期间回车/Esc 及隐藏时取消通知。Core `OnChanged` 统一等待组字完成，Mail 仅通过此回调更新查询；周期刷新仅同步外部条件变更。真实五笔/拼音兼容性仍待客户端验收。

附件悬停回归：`WorkspaceSpec` 捕获实际 tooltip 绘制调用，核对每个附件来源一行、同一行内明确标注“邮箱”和“发件人”、附件槽数量、跨服同名角色的服务器信息，以及复用图标时清除旧来源信息。来源行关闭自动换行，保持紧凑高度。

`Tools/Test-LuaSyntax.ps1 -Addon YiboCore,YiboMail` 对两个正式 TOC 加载的 **61 个 Lua 文件**检查通过；`git diff --check` 通过。
