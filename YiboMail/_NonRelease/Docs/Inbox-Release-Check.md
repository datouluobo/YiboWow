## 发布范围

正式 TOC 只加载收件箱、扫描、持久缓存、附件 API 与收取队列共 9 个 Lua 文件。发件辅助、规则、账号主窗口、业务入口和设置页面均不注册；原生发件箱保留。规则、联系人与历史偏好数据不因缩减加载范围而移除。

## 本次修复

- 每次成功扫描后刷新收件控件，避免同内容扫描不发布事件时让勾选和收取按钮停留在禁用状态。
- 邮箱关闭、扫描失败与恢复时发布状态变化通知；重复同内容／同状态扫描保持 revision 不变。API 回调查询到已提交的快照和匹配的 revision；首次扫描失败也返回 `error`。
- 保留邮箱面板显示前到达的更新，并短暂等待面板显示后扫描，避免首次打开时丢失更新。
- 删除当前打开的空信时先清除原生信件索引并关闭信件，避免索引移动后误显示或误删下一封。删除失败或超时解除按钮锁定；再次点击仍重新核对邮件身份与内容。
- 已读样式改为持久保存用户实际打开的记录，不以客户端后台已读标记作为显示依据。左键展开时只读取这一封的正文；右键原生打开后只记录这一封。后台扫描不读取正文，收起操作不重复读取。

## 客户端最终验收

2026-10-03 用户反馈：COD 付款、删除和连续收取均已测试通过。记录以上三项核心操作为已确认；以下清单保留其它专项与兼容性检查内容，未将未单独反馈的边界场景标为已验证。

1. 完整退出再进入游戏，启用 YiboCore 与 YiboMail。首次打开、关闭重开和收发切换均无 Lua 错误；原生发件正常，隐藏功能没有入口。
2. 用一封多附件加金币邮件完成整封及部分勾选收取，再收取多封相同物品；核对实际背包、金币、剩余邮件与 `/yma status`。
3. COD 分别测试取消、确认付款、余额不足；右键原信件附件完整，实际金额与确认框一致。
4. 打开空信后点击 X，确认只删除目标；有金币或物品的邮件不出现删除按钮。
5. 执行中关闭邮箱或造成背包不足，确认暂停且没有重复取件；重开后按剩余内容重新选择。
6. 有 Postal 或邮箱皮肤时检查覆盖层、按钮点击、原生信件与并行操作暂停。未实测的客户端兼容性不能由模拟测试替代。
