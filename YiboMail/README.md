# YiboMail - 邮件助手

![YiboMail 邮件助手](Media/YiboMailIcon-v1-128.png)

当前版本 `0.6-api1` 采用收件箱增强与原生发件基础记录范围，依赖 **YiboCore API v6**。打开游戏邮箱即可使用；无需打开独立主窗口。

## 当前功能

- 接管原生收件箱内容区，顶部同一行放置搜索、类别筛选和关闭按钮；使用统一背景、两行邮件布局、独立勾选区域和列表外滚动条，保留原生收发标签与信件操作。
- 第一行显示发件人与到期时间，第二行显示主题及金币、COD 或退回标记，附件槽数位于条目右下角。左键点击条目展开／收起附件，右键打开／关闭同一封原生信件；中键直接排队收取该信的所有可收附件，不收金币。
- 已读效果只跟随用户左键展开或右键打开信件的动作，按邮件保存；后台扫描和客户端已读标记不改变界面。未打开的邮件保留醒目的发件人与主题，打开后文字变为较暗的灰青色；到期提醒与物品品质颜色保留。
- 无物品、金币或 COD 的空邮件在勾选框位置显示“X”，点击核对邮件身份、内容与客户端删除许可后直接删除，等待列表更新期间禁用重复删除。
- 邮件与附件两种模式支持搜索、类别筛选和排序；“临期／邮箱”排序选择会独立持久化，不受筛选记忆开关影响。附件模式聚合为物品图标，采用与 Vault 一致的细品质边框与图标裁边；物品信息未缓存时使用链接颜色，加载完成后刷新。点击直接收取该物品的可收附件。
- 邮件模式点击“收取”直接执行已勾选项目，无额外预览确认。按钮默认显示“收取”，勾选后显示“收取（x）”；x 是所选附件槽数，不包含金币或堆叠件数。按钮不显示 tooltip。
- “更多”提供全选当前可收项目、清空选择、暂停队列与切换排序。执行期间禁用重复操作；部分勾选显示短横线。
- 收取队列按估算到期时间从早到晚执行；启动前整批核对，执行时逐项按当前邮箱序号重新核对邮件、附件和金额。相同签名邮件使用本轮邮箱序号区分；每次收取后重扫，并按已移除邮件修正后续序号。收空的邮件行立即从当前列表移除，剩余内容则就地更新。COD 和离线角色不进入队列；邮箱关闭、位置或内容变化、背包不足、并行操作或结果不明时暂停。
- COD 邮件右键可打开原生信件；展开后的附件左键触发原生付款确认，右键打开／关闭信件。附件模式中的仅 COD 物品点击时逐封确认付款；金额不足沿用原生提示。
- 保留邮箱扫描、历史记录、缓存生命周期及 `YiboMail.Items` API，供业务数据使用。规则、联系人和已有偏好数据继续保存。

发件箱使用与收件箱一致的深色外壳。收件人右侧“通讯录”提供常用收件人、账号角色、最近邮寄、角色好友、账号好友和公会六类来源，支持覆盖全部六类来源的全局搜索、服务器筛选和按屏幕空间分页；少量结果自动收缩，来源菜单宽 200 UI 单位，悬停或点击来源后名单向右展开（空间不足时向左）；名单宽 200、最高 360 UI 单位。当前收件人可“加入常用”或确认后“移出常用”；“管理”灰显占位，后续接入 Core 邮件设置页。同服角色只显示角色名，跨服显示角色名-服务器。

右侧“快捷寄件栏”保持两列八行 16 个正方形格子，与常用名单分别保存。右键打开菜单，第一项“自定义…”，随后为六类通讯录来源；选人只配置目标格，清空需要确认且保留其它格的位置。空格左键不操作。已配置格左键填入地址；主题或正文有文字且附件非空时，触发现有原生发送按钮，沿用游戏确认与错误提示。原生正文、附件、金额/COD、发送和取消继续使用既有流程。

游戏好友按来源角色保存完整快照。“角色好友”使用当前角色 O 面板好友并排除全部已知账号角色地址；“账号好友”合并其它已读取角色的名单，排除全部已知账号角色地址及当前角色好友地址。账号身份去重包含隐藏角色及当前角色，与 Core 展示准入无关。各角色原始好友快照保持完整。某角色删除好友后，只替换该角色的成员关系；离线角色等待再次登录刷新。发送成功才写入最多 20 位的最近邮寄。Core 删除角色缓存时会同时清理该角色好友快照。旧常用数据保留，只在快捷栏首次初始化时导入最多 16 格；清空后不会重新导入。

实现及游戏内验收项目见 [通讯录实施验收记录](_NonRelease/Docs/Recipients-Implementation-Check.md)。

## 发布范围与代码结构

`YiboMail.toc` 当前只加载：

```text
Namespace.lua
Store.lua
Recipients.lua
RecipientUI.lua
Items.lua
Scanner.lua
ViewModel.lua
Inbox.lua
Queue.lua
Compose.lua
NativeUI.lua
Bootstrap.lua
```

`Inbox.lua` 独立提供收件偏好与可收项目生成，收件箱不再依赖规则模块或主窗口。`Namespace.lua` 开启原生发件基础 UI 与发送事件记录；`sendAssist`、`account`、`settings` 关闭，不注册邮件账号页面、业务入口、设置页面或规则发件 UI。

规则编辑、主窗口、账号缓存页面和设置页面源码仍保留在仓库，但不在当前 TOC 中加载。通讯录和快捷栏共用候选查询，但分别保存常用地址与槽位配置；规则建议/装填 UI 受独立功能标记控制，当前关闭。

当前可单独分发 YiboMail 邮箱版，安装时仍须提供 YiboCore。打包时不包含 `_NonRelease/`；未加载的业务源码不会在游戏中产生页面或入口。

## 安装与验收

插件列表显示名为 `|cff20e070[Yibo]|r YiboMail - 邮件助手`，使用本插件 `Media/YiboMailIcon-v1.tga`（128px、含 Alpha）作为游戏纹理。Core 插件目录与预留业务入口同步使用该资源。当前发布范围的业务入口开关维持既有配置。

Logo v1 提供 `24/32/64/128/512/1024px` 的 PNG 与 TGA；`YiboMailIcon-v1.png` 对应 512px，`YiboMailLogo-v1.png` 对应 1024px，`YiboMailMinimapIcon-v1.png/.tga` 对应 32px。`YiboMailIcon-v1-master.svg` 是可编辑矢量骨架，手绘材质保存在同版本 PNG/TGA 中。

将本目录以同名目录联接或复制到目标客户端 `Interface/AddOns/YiboMail`，启用 YiboMail 与 YiboCore。TOC 加载清单变化后，完整退出并重新进入游戏。

兼容范围包括 YiboMail、YiboCore 与客户端原生邮箱界面共同使用，也可与 NDui 等只美化原生界面、不额外添加邮件功能控件的 UI 皮肤插件共用。Postal 等会增加联系人箭头、按钮、菜单或其它邮件功能控件的插件不承诺兼容；同时启用时，这些新增控件可能被遮挡、无法显示或位置错乱。可按具体报告排查，但不作为正式支持配置或发布验收条件。

1. 打开邮箱，核对邮件数量、两行布局、勾选区域、附件展开与原生信件附件显示。
2. 勾选附件与金币，核对“收取（x）”计数；直接收取并观察进度。测试附件模式跨邮件收取同一物品。
3. 检查“更多”菜单操作与执行中禁用状态，关闭／重开邮箱核对暂停与剩余项。
4. 切换发件箱，核对通讯录的六类来源、搜索、筛选、分页、动态常用增删和菜单边界；右键配置快捷格，检查自定义与来源选人只改该格，左键分别检查仅填写和原生发送确认。切换多个角色验证好友合并与删除，保留邮件草稿和金额/COD。
5. 检查 Core 页面与设置中不出现邮件业务入口，收件箱菜单不出现账号视图入口。

`/yma` 显示使用与诊断提示；`/yma status` 查看邮箱状态；`/yma scan` 仅在已打开且本轮已更新的邮箱中主动扫描。

在仓库根目录运行：

```text
lua YiboMail/_NonRelease/Tests/NativeInboxSpec.lua
lua YiboMail/_NonRelease/Tests/InboxReleaseSpec.lua
lua YiboMail/_NonRelease/Tests/MailRuntimeSpec.lua
lua YiboMail/_NonRelease/Tests/MailAPIConsumerSpec.lua
lua YiboMail/_NonRelease/Tests/RecipientsSpec.lua
lua YiboMail/_NonRelease/Tests/RecipientUISpec.lua
```

第一项复用 Core 勾选框、下拉菜单及实际收取队列，覆盖选择、点击层级、直接收取、整批校验、COD 付款与空信删除。第二项按正式 TOC 加载并执行启动流程，验证收件依赖、页面与事件屏蔽、历史配置保留和诊断命令。第三项验证实际扫描、存储、API 与队列的完整运行流程，包含范围查询、事件一致性、历史状态、错误恢复、重复邮件、100 封边界及多步收取。这些检查使用模拟游戏 API；目标客户端中的付款确认、切页与连续收取仍需游戏内验收。

第四项模拟外部消费者，只通过公开接口检查完整记录字段、只读查询、隐藏角色与未知角色、非法参数、事件订阅和失败状态。

首版发布检查结果见 [发布检查记录](_NonRelease/Docs/Inbox-Release-Check.md)。
