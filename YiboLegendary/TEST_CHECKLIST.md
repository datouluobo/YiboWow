# YiboLegendary（传说之路）首轮游戏内验收

## 安装与基础能力

1. 将 `YiboCore` 和 `YiboLegendary` 同时安装、启用并登录 MoP Classic 目标客户端。
2. 输入 `/yco addons`，确认 `YiboLegendary` 已登记且需要 API 为 3。
3. 输入 `/yle probe`，记录四项结果：`questCompletion`、`questLogIndex`、`questObjectives`、`reputation`。任何“不可用”都应视为兼容性问题，不能据此发布。
4. 鼠标悬停 Core 小地图图标；应显示传说之路的账号预览。左键应打开 Core 账号窗口并进入上次页面或概览。
5. 若安装了提供 `LibDataBroker-1.1` 的插件，数据源列表中应出现“[Yibo] 账号总览”；没有该库时，Core 小地图入口仍应可用。

## 角色测试矩阵

## 声望与多角色总览

1. 使用同时持有收集任务与黑王子声望任务的角色，确认详情同时显示收集目标和“黑王子声望：当前等级 → 目标等级”。
2. 声望达到对应门槛后，确认显示“门槛已满足”，且后续任务能够正常放行。
3. 依次登录至少两个具有不同传说任务进度的角色；任一角色打开详情时，应显示所有已记录角色的独立进度块，当前角色以 `▶` 标记。
4. 切换角色并重登后，确认未登录角色仍显示其最近一次任务与声望快照。
5. 任意角色的“行动”应给出与当前任务对应的具体行为，不应再只显示通用提示。
6. Core 中存在、但尚未保存传说任务快照的角色不应出现在传说之路的悬停或详情列表；登录该角色后才加入列表。

## 高密度账号视图

1. 输入 `/yle` 或左键点击入口，确认打开 Core 统一账号窗口并定位到“传说之路”页；详情显示单行角色表格：角色名-服务器名、章节、当前任务、目标与行动。
2. 中文客户端中，进行中的任务应优先显示任务日志提供的中文任务名；“目标”列仅显示简短的实时任务目标，不应额外占用独立声望列。
3. 未接取但可接取的任务，当前任务和目标列应为空；“行动”列应显示具体接取地点或行为。
4. 当前角色使用背景与 `●` 标记区分；已完成、进行中、可接取和异常状态均同时有文字与颜色标识。
5. 登录并同步 20 个角色后，确认同页完整显示且不滚动；第 21 个角色出现后，确认表头固定、列表可静态滚动且不播放动画。
6. 鼠标悬停任一角色行，确认可看到未截断的任务目标与行动。
7. 未满 90 级的角色不得出现在传说之路的账号视图或悬停列表中。
8. 角色数不超过 20 时，传说之路页面应在 Core 固定窗口中稳定展示；超过可视区域后应保留列头并启用静态滚动。
9. 印记与帝国秘史任务的行动应说明“天神尾王或 10 碎块兑换”，不得暗示必须进入团本。
10. 悬停 Core 小地图或 Broker 入口时，应显示传说之路的正式表格预览；默认只显示“角色、当前任务、目标”，不显示“行动”。
11. 左键入口后，预览应切换为完整账号窗口；离开入口时，未固定的预览应关闭。
12. 在角色列表滚动到中部后触发任务/声望/货币刷新，列表应保持原滚动位置。
13. 即使存在并行目标，仍应保持每个角色一行；并行声望只追加到该行的目标列。

## 发布前必须回填的观察

- 当前客户端实际使用的是 `C_QuestLog.IsQuestFlaggedCompleted` 还是全局 `IsQuestFlaggedCompleted`。
- 任务日志索引 API 的实际可用性；进行中任务是否返回正确的目标文案和数值。
- 黑王子阵营 ID 1359 是否由 `GetFactionInfoByID` 返回正确声望等级。
- 服务器阶段是否会让任务在“前置完成”时仍不可接；确认后将对应阶段条件写成可自动判定的规则，而不是依赖手工 `phaseAvailability`。
- 阵营变更或追赶机制下，历史任务完成记录与当前可接任务是否一致。
