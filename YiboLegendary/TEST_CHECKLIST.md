# YiboLegendary 2.0 游戏内验收清单

## 安装与兼容性

1. 同时启用 `YiboCore` 与 `YiboLegendary`，登录 MoP Classic 5.5.4。
2. 输入 `/yco addons`，确认 `YiboLegendary` 的版本为 `2.0.0` 且需要 Core API v5。
3. 输入 `/yle probe`，确认任务完成、任务日志索引、任务目标、声望和物品数量 API 均按客户端实际情况报告；不可用项不得被渲染为零进度。
4. 输入 `/yle`，确认进入 Core 的“传说之路”页，而非独立窗口。

## 完整页面

1. 左侧目录显示“橙披”“风剑”；选择目标后，右侧标题、路线说明和角色表同步切换。
2. 角色表按“角色、当前检查点、进度、下一步”显示；当前角色只显示 Core 青绿色轮廓，不改变其传说状态。
3. 橙披仍正确显示声望跳过、并行要求、勇气 `0/1600` 基线、阶段未开放和最终完成；90 级第一步显示“异乡的陌生人”，第二步显示“创造传奇”并提示与拉西奥喝一杯，完成后同时接取 C1-02 与 C1-03。
4. 风剑无绑定时显示“关键掉落 0/2 · 本周可刷”；只有一个绑定时显示 `1/2`；材料阶段显示元素锭数量；最终物品存在时显示“已获得 ✓”。
5. 风剑不适用职业显示“不适用 —”，不计入目录的获得率。
6. 完整页不出现横向滚动；角色过多时仅角色表纵向滚动。

## 悬停矩阵与入口

1. 悬停 Core Broker 或小地图入口，显示角色为行、橙披／风剑为列的矩阵。
2. 每个单元格同时有文字、状态符号和颜色；显示获得状态或阶段，以及进度／本周可刷信息。
3. 悬停单元格显示同一快照中的完整检查点和下一步。
4. 宽度不足时仅目标列分页；角色列和目标表头必须与数据单元使用同一切片。
5. 左键入口进入完整页面；右键入口仍由 Core 打开入口设置。

## 测试投影与数据安全

1. 在测试角色执行 `/yle test THUNDERFURY BINDING_LEFT`、`BINDINGS`、`ELEMENTIUM`、`THUNDERAAN`、`COMPLETED`，确认风剑各节点都能显示。
2. 执行 `/yle test THUNDERFURY` 清除投影后，确认恢复真实物品观察结果。
3. 测试投影不得改写 `observedItems` 或已有橙披进度。
4. 在 Core 的角色与排序页删除一个角色缓存，确认只删除该角色的传说快照和测试投影。
5. 切换角色、重登、刷新任务／背包后，非当前角色保持最后同步快照，当前角色按真实 API 更新。

## 发布前回填

- 记录 MoP Classic 中 `GetItemCount` 是否覆盖背包、银行、装备与已获得风剑的历史判定；若不能可靠判定最终武器，增加明确的人工确认节点，不能猜测为未获得。
- 记录风剑关键掉落和元素锭的实际物品 ID、背包观察时机与交任务后的证据保留策略。
- 确认现有橙披任务 ID、声望 API 和任务日志回退逻辑未因目录迁移退化。
