# YiboLegendary 2.0 实施方案：传说之路目录化

> **状态**：规划已确认，尚未实施。
>
> **客户端范围**：仅 `WOW_PROJECT_MISTS_CLASSIC` / Interface `50504`（MoP Classic 5.5.4）。正式服及 5.5.4 之后的内容不进入本期目录；数据结构只预留将来按客户端注册目录包的能力。

## 1. 产品目标与边界

传说之路 2.0 是一个账号级的“传说物品获取路线目录”。它回答两件事：

1. 某个角色是否已经获得某件传说目标；未获得时，当前能推进到哪一步。
2. 在所有可用角色之间，哪名角色最接近完成哪些传说目标。

它不是全物品收藏插件、Boss 掉落数据库或攻略百科。路线说明只保留完成当前检查点所需的信息；详细打法、概率和叙事说明不在主视图堆叠。

### 1.1 目录范围

完整目录的时间边界为经典旧世至 MoP Classic 5.5.4：

| 版本 | 纳入目标 |
| --- | --- |
| 经典旧世 | 雷霆之怒、萨弗拉斯、埃提耶什；黑色其拉作战坦克作为“特殊绝版收藏”。 |
| 燃烧的远征 | 埃辛诺斯战刃、索利达尔。 |
| 巫妖王之怒 | 瓦兰奈尔、影之哀伤。 |
| 大地的裂变 | 巨龙之怒、龙父之牙。 |
| 熊猫人之谜 | 传说披风。 |

- 已绝版目标保留在目录和矩阵中，状态固定为“已绝版”；不能误导玩家为“可开始”或“缺少前置”。
- MoP 传说披风属于当前版本内容，必须继续按可完成路线处理。
- WoD 橙戒及之后的任何传说物不纳入 MoP Classic 目录。
- 蛋刀、索利达尔是直接掉落目标：首版只显示“可刷取的最终 Boss”和是否已获得，不虚构任务进度。

### 1.2 2.0 交付范围

2.0 只正式支持两条路线：

| 目标 | 角色 | 在 2.0 中验证的能力 |
| --- | --- | --- |
| MoP 传说披风 | 既有长任务链 | 章节、并行目标、声望门槛、阶段开放、货币累计、最终奖励。 |
| 雷霆之怒，逐风者的祝福之剑 | 新增掉落／收集链 | 两个独立关键掉落、任务开启、多材料收集、最终召唤事件、最终武器判定。 |

选择风剑不是因为它能在开发期按时做完。两个绑定的随机性不用于决定开发进度；真实每周刷取仅验证客户端采集和持久化。开发与验收使用受限的诊断投影覆盖每个路线节点。

## 2. 统一路线模型

“长任务链、掉落／收集链、直接掉落”是目录的分类，不是三套 UI 或三套角色状态机。每条路线都由同一种节点图组成；不同路线只使用不同节点组合。

```text
传说目标
  └─ 路线节点图（可串行，也可有并行前置）
       ├─ quest       任务完成或任务日志目标
       ├─ bossDrop    某 Boss 的最终掉落或关键掉落
       ├─ itemCount   背包／任务物品／材料的 current/target
       ├─ reputation  声望门槛
       ├─ event       召唤、交付、场景或击杀事件
       └─ manual      客户端无法可靠读取时的明确人工确认
```

每个目标都要定义以下稳定字段；业务逻辑只按 ID 判断，名称只用于本地化展示。

```lua
{
  id = "THUNDERFURY",
  expansion = "CLASSIC",
  routeKind = "collection", -- 只用于筛选和说明，不决定 UI
  finalItemIds = { 19019 },
  availability = "obtainable", -- obtainable / unavailable
  eligibility = { classes = { "WARRIOR", "PALADIN", ... } },
  nodes = {
    { id = "BINDING_LEFT", kind = "bossDrop", bossId = 12098, itemId = 18563 },
    { id = "BINDING_RIGHT", kind = "bossDrop", bossId = 12057, itemId = 18564 },
    { id = "ELEMENTIUM", kind = "itemCount", itemId = 18562, target = 10 },
    { id = "THUNDERAAN", kind = "event", requires = { "BINDING_LEFT", "BINDING_RIGHT", "ELEMENTIUM" } },
  },
  completion = { kind = "item", itemIds = { 19019 } },
}
```

### 2.1 角色—目标统一快照

路线解析器对每个“角色 × 目标”都产出相同的快照，不让调用方识别路线类别：

```lua
{
  targetId = "THUNDERFURY",
  status = "not_started", -- not_started / available / in_progress / obtainable / completed / unavailable / ineligible / unknown
  acquired = false,
  currentNodeIds = { "BINDING_LEFT", "BINDING_RIGHT" },
  stageLabel = "寻找逐风者禁锢之颅",
  progressText = "0/2",
  nextAction = "本周可前往熔火之心击败迦顿男爵与加尔。",
  evidence = {},
  updatedAt = 0,
}
```

规则：

- `completed` 由最终物品、任务完成记录或明确的收藏证据判定；不可由“路线最后一步看似完成”推断。
- `unavailable` 只用于绝版或当前客户端不支持；`unknown` 表示 API／数据不足，绝不等同于未完成。
- `ineligible` 表示角色职业、阵营或前置条件不适用；矩阵保留短横线与原因，不把它计入缺失。
- 多个并行节点会一并进入 `currentNodeIds`。矩阵使用汇总 `progressText`，详情页逐项展开。
- 状态、文本格式化、角色准入和目标准入由同一解析器提供给主页面、悬停、Broker 与小地图入口。

### 2.2 目录与模块边界

新增模块，而不是继续把橙披定义写进单个 `Data.lua`：

```text
YiboLegendary/
  Data.lua                      -- 既有橙披任务定义与 Classic 兼容回退
  Catalog.lua                   -- 目标元数据和路线节点定义
  Model.lua                     -- WoW 事实采集、路线解析与角色目标快照
  UI.lua                        -- 目标目录、路线详情与悬停矩阵
```

YiboCore 继续拥有窗口壳、角色目录、范围选择、字段分页、滚动、Broker、小地图及入口设置；传说之路只注册页面、提供快照和页面内容。不得新建独立窗口壳或第二套悬停系统。

## 3. UI 方案

### 3.1 使用场景

玩家登录某个角色后，先在悬停矩阵判断“谁最接近什么”，再左键进入完整路线，决定本次游玩的角色和副本。完整页优先提供可行动信息；悬停优先提供可比较信息。

使用现有 Core 深色青绿色主题、表格行高与状态色。状态同时使用文本、符号和颜色：不得只以绿色／红色表达完成或受阻。

### 3.2 完整主界面：目录 + 路线详情

完整页面嵌入 YiboCore 账号窗口。Core 已提供固定导航、标题栏、范围切换和关闭操作；业务页不复制这些控制。

```text
┌ 传说之路 ─ 范围由 Core 提供 ──────────────────────────────────────┐
│ [全部] [经典] [TBC] [WLK] [CTM] [MoP]    筛选：可推进 ▾          │
├───────────────┬───────────────────────────────────────────────────┤
│ 传说目标目录  │ 雷霆之怒，逐风者的祝福之剑             [可获取]  │
│ ● 传说披风    │ 经典旧世 · 掉落／收集链 · 适用职业 …             │
│ ○ 雷霆之怒    ├───────────────────────────────────────────────────┤
│ ○ 萨弗拉斯    │ 路线                                                  │
│               │ ① 两个禁锢之颅  0/2  → ② 元素锭 0/10 → ③ 召唤    │
│               │     迦顿 / 加尔        黑翼之巢          桑德兰     │
│               ├───────────────────────────────────────────────────┤
│               │ 角色              当前检查点        进度    下一步 │
│               │ 战士-服务器A      两个禁锢之颅      0/2     熔火之心 │
│               │ 圣骑-服务器B      已获得 ✓          —       —        │
│               │ 法师-服务器A      不适用 —          —       —        │
└───────────────┴───────────────────────────────────────────────────┘
```

具体交互：

- 顶部筛选是紧凑工具栏：版本、可得性和“只看可推进”。筛选不改变 Core 左侧导航的顺序或位置。
- 左侧是可滚动的目标目录，不使用卡片网格。每行显示图标、名称、版本和账号摘要（如“2/8 已获得”）。选中目标以现有 `selected` 背景和强调边框表示。
- 右侧路线区以有向阶段列表展示：串行步骤以箭头连接；并行前置处用同级项目并列，且明确写“均需完成”。节点显示来源、完成状态、数量和限制，不默认展开长攻略。
- 底部角色表只显示对所选目标有业务快照或适用资格的角色；当前角色使用 Core 的青绿色轮廓，而不是改变其业务状态色。
- 主页面先依屏幕安全边界扩展；角色表内容超过安全高度才出现纵向滚动。目标目录与详情不存在横向滚动。
- 选择不同目标只刷新详情与角色表，保留页面范围、目录选择、滚动位置和字段偏好。

### 3.3 悬停：角色／物品矩阵

悬停是主路线快照的紧凑投影，不是另一份文本摘要。行是全部有效角色（最多 20），列是启用的传说目标；不显示没有快照且不满足目标准入条件的角色。

```text
传说之路 · 角色进度
角色              橙披                 风剑
战士-服务器A      第 3 章 · 7/20       0/2 · 本周可刷
圣骑-服务器B      已获得 ✓             已获得 ✓
法师-服务器A      第 1 章 · 声望待达   不适用 —
```

单元格固定两层信息：

1. 第一层是获得状态或阶段，如“已获得 ✓”“第 3 章”“未开始”。
2. 第二层是当前检查点，如“7/20”“0/2 · 本周可刷”“已绝版”。

- 每个单元格的鼠标悬停显示同一快照里的完整 `stageLabel`、所有并行当前节点和 `nextAction`；不额外推断攻略。
- 目标列应先按全部有效角色内容计算自然宽度。完整矩阵达到安全宽度仍无法容纳时，使用 Core 的统一**目标列分页**；角色表头和单元格永远基于相同目标切片。
- 默认矩阵列是目录中已启用的目标。`settings.previewColumns` 迁移为按目标 ID 保存的可见性，而不是把“任务／目标／行动”当成独立列。
- 入口左键打开当前选中目标的完整页；若无已选目标，打开“全部”目录并选中第一个可推进目标。入口右键仍由 Core 打开入口设置。

### 3.4 空、未知与历史状态

| 情况 | 主页面 | 矩阵 |
| --- | --- | --- |
| 尚无任意业务快照 | 教玩家登录相应角色以同步；不显示为零进度。 | 不列该角色。 |
| API 不可读 | 显示“无法读取，执行 `/yle probe` 确认兼容性”。 | `未知 ?`。 |
| 角色不适用 | 展示职业／阵营限制。 | `不适用 —`。 |
| 历史绝版 | 仅展示历史来源与“无法从零开始”。 | `已绝版 ⊘`。 |
| 目录暂未收录 | 不伪装为未完成。 | 默认不出现；设置中注明“后续目录版本加入”。 |

## 4. 诊断与测试

真实进度不能作为测试前置。保留正式 Slash 命令 `/yle`，不添加别名；开发诊断只作为该命令的子命令，并且不占用 Broker、小地图或普通点击交互。

建议子命令：

```text
/yle probe                         检查可用 API
/yle status                        输出当前角色的已解析摘要
/yle test THUNDERFURY BINDING_LEFT
/yle test THUNDERFURY
```

`test` 只写入标注为开发投影的数据，永不覆盖真实采集证据；界面显式显示“测试投影”，发布构建可由开关禁用。它用于验证：

- 风剑：无绑定、单绑定、双绑定、材料部分完成、可召唤、已获得。
- 橙披：锁定、并行项、声望已满足但任务未出现、货币累计、阶段未开放、完成。
- 直接掉落模板：未掉落、可刷取、已获得、绝版。
- 角色准入、删除角色缓存、范围切换、悬停列分页、主页面自然宽度与窄屏安全边界。

## 5. 版本拆分与验收

### 2.0.0：目录底座与风剑

1. 将现有橙披快照接入通用目录／解析器，保持任务定义、兼容回退与已有 SavedVariables 可读。
2. 实现通用节点、角色—目标快照、风剑目录和 API 能力探针。
3. 以本方案的目录 + 路线详情替换现有单路线表；实现悬停角色／物品矩阵。
4. 实现 `/yle test` 的临时投影及覆盖测试。
5. 完成真角色的风剑刷本观察，但不将掉落概率或完成周期写死进判定。

验收标准：

- 橙披现有进度、勇气累计与声望跳过逻辑迁移后显示一致。
- 选择橙披或风剑不会改变 Core 窗口壳、角色范围、入口或滚动行为。
- 同一角色—目标快照在主页面、悬停、Broker 和小地图中给出相同完成状态与当前检查点。
- 风剑的全部模拟节点与真实“无掉落”状态都可渲染，且不会要求真实绑定掉落才能完成测试。
- 主窗口无横向滚动；悬停仅在安全宽度不足时按目标列分页。
