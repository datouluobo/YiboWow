# YiboLegendary 悬停矩阵完整方案

## 1. 文档定位

本文是“传说之路”账号级悬停矩阵的执行方案，定义悬停窗口的信息架构、视觉状态、数据契约、Core 边界、设置行为、分页规则、交互和验收标准。

本文只规划悬停矩阵，不改变传说路线的业务规则、采集器事实来源或 YiboCore 窗口壳职责。

## 2. 产品目标

悬停窗口是账号级橙装实时跟踪面板。玩家应当在一次扫读中回答：

1. 哪些角色与哪些橙装有关。
2. 每件橙装当前是已获得、可推进、进行中、待同步还是其它状态。
3. 对仍在推进的目标，最重要的实时数字是什么。
4. 发现目标后，能否直接进入对应橙装的主页面。

悬停窗口不承担完整路线阅读、任务攻略或人工数据修改。完整检查点、路线节点和下一步行动继续由主页面提供。

## 3. 总体结构

### 3.1 行列定义

- 行：Core 准入后的全部有效角色。
- 列：目录中的全部传说目标。
- 固定列：角色列固定在最左侧。
- 目标列：按目录稳定顺序显示，不因角色状态变化而移动。
- 默认列集合：目录中的全部目标，包括已接入、待接入和历史绝版目标。
- 用户控制：通过 `settings.previewColumns[targetID]` 逐项控制目标列显示/隐藏。

### 3.2 橙装顺序

橙装按游戏内出现时间逆序排列：

- 最新的橙装在前，当前为橙披第一列。
- 更早的橙装依次向后排列。
- MC 橙锤、风剑等早期目标位于后部。
- 顺序由目录定义提供，不能按角色状态、完成数量或可行动性动态重排。

后续新增目标必须在目录中明确稳定排序位置，不能依赖文件加载顺序或注册时机。

## 4. 悬停窗口布局

```text
┌────────────────────────────────────────────────────────┐
│ 传说之路 · 账号进度                         ‹ 目标 1/2 › │
├────────────────────────────────────────────────────────┤
│ ✓ 已获得  ◷ 进行中  ◆ 可刷  … 待同步  — 不适用  ⌁ 绝版 │
├────────────────────────────────────────────────────────┤
│ 角色              [橙披]   [风剑]   [索利达尔]   [橙锤]  │
│ Yibo              ◷800/6000 ◆1/2    ✓ 自动      …待接入 │
│ Yibo-服务器       ✓ 自动   — 不适用 ◆ 可刷      ⌁ 绝版 │
└────────────────────────────────────────────────────────┘
```

### 4.1 角色行头

角色命名完全遵循 YiboCore 统一规则：

- 单服务器范围：只显示角色名。
- 所有服务器范围：显示“角色名-服务器名”。
- 角色名使用职业颜色。
- 当前版本不添加职业图标。
- 不使用角色短名。
- 服务器范围和名称格式由 Core 负责，业务插件只消费格式化后的角色标签。

### 4.2 橙装列头

每个目标列头显示：

- 物品图标。
- 目标短名称。

列头文字提示（Tooltip）补充完整物品名称、版本和路线类型。列头不得截断到无法识别目标的程度。

## 5. 单元格视觉契约

每个“角色 × 橙装”单元格只显示一层紧凑实时投影：

```text
[状态图标] [核心数字或短文本]
```

状态图标和颜色必须同时使用；颜色不能单独承担语义。

### 5.1 状态显示

| 状态 | 常驻示例 | 语义 |
|---|---|---|
| `completed` | `✓ 自动`、`✓ 确认`、`✓ 测试` | 已获得，并显示证据来源 |
| `in_progress` | `◷ 4/10` | 已进入路线，存在实时推进数据 |
| `obtainable` | `◆ 可刷`、`◆ 1/2` | 当前可推进、可刷取或可执行 |
| `pending_sync` | `… 待同步` | 暂时没有足够同步事实 |
| `ineligible` | `— 不适用` | 角色职业、阵营或资格不适用 |
| `unavailable` | `⌁ 绝版` | 不能从零开始获取，仅保留历史语义 |
| `unknown` | `! 无法读取` | 客户端能力或数据读取失败 |
| 待接入占位 | `… 待接入` | 目录已有目标，但采集器尚未接入 |

实际图标材质以 WoW 客户端可稳定渲染的资源为准，不依赖无法保证显示的 Unicode 勾选符。图例、单元格和主页面必须共享同一状态映射。

### 5.2 实时数字格式

格式化器按目标节点类型输出最短、最有行动价值的数据：

- 数值目标：`current/target`，例如 `4/10`、`800/6000`。
- 多个并行目标：用 `·` 压缩并列，例如 `3/10 · 1/10`。
- 关键掉落：显示已拥有数量，例如 `1/2`。
- 直接掉落：显示 `可刷` 或 `未获得`。
- 材料已齐但尚未完成：显示 `材料齐` 或等价短文本。
- 已获得：显示完成状态与证据来源，不重复展示无意义的进度数字。

格式化器不得在矩阵中虚构无法从快照推导的阶段、掉落次数或完成比例。

### 5.3 完成态证据

已获得状态常驻显示证据来源短标：

- `自动`：自动检测最终物品或任务事实。
- `确认`：玩家人工确认。
- `测试`：当前会话中的诊断投影。

证据来源仍以快照中的 `evidence.source` 为准。测试投影只能影响当前会话展示，不得覆盖真实进度或持久化事实。

## 6. Tooltip 规则

单元格文字提示只显示同一快照中的状态与进度摘要：

- 目标完整名称。
- 当前状态。
- 当前核心进度。
- 完成态证据来源短说明。

单元格 Tooltip 不展开完整任务链、所有路线节点、并行节点或下一步行动。需要查看这些内容时，点击单元格进入主页面。

列头 Tooltip 负责目标识别信息；单元格 Tooltip 负责角色在该目标上的实时状态信息，两者不重复维护业务判断。

## 7. 交互行为

### 7.1 单元格左键

左键单元格执行导航：

1. 打开 YiboCore 统一账号主页面。
2. 自动选中该单元格对应的橙装目标。
3. 保留 Core 当前角色范围和排序上下文。
4. 不在悬停窗口内直接修改人工证据或业务数据。

入口左键仍然打开“传说之路”主页面；入口右键仍由 Core 管理入口设置。

### 7.2 状态图例

悬停窗口固定显示一行紧凑状态图例。图例只解释状态图标和颜色，不解释具体路线节点。

## 8. 角色准入与目标准入

### 8.1 角色准入

角色行使用插件现有业务准入结果，并接受 Core 的统一范围和隐藏设置：

- 角色达到插件要求的等级。
- 角色已有传说业务快照或已被插件记录为有效业务角色。
- 角色未被 Core 当前服务器范围、角色隐藏或其它统一筛选排除。
- 角色不因某一件橙装不适用而从整张矩阵移除。

### 8.2 目标准入

目录中的所有目标默认进入目标列集合：

- 已接入目标显示真实角色状态。
- 待接入目标显示“待接入”占位状态。
- 绝版目标显示“绝版”状态。
- 角色不适用的目标显示“不适用”。
- 没有足够数据的目标不得显示为 `0/0` 或普通未获得。

## 9. 数据架构与代码边界

### 9.1 唯一事实来源

主页面、悬停、Broker 和小地图入口都消费同一份角色—目标快照：

```lua
snapshot.targets[targetID] = {
    targetId = "...",
    status = "...",
    acquired = false,
    currentNodeIds = { ... },
    stageLabel = "...",
    progressText = "...",
    nextAction = "...",
    evidence = {
        source = "real|manual|projection",
        updatedAt = 0,
    },
}
```

### 9.2 矩阵派生投影

建议在业务 UI 层增加统一的矩阵投影函数：

```lua
CellProjection = {
    icon = "...",
    color = { r, g, b },
    value = "...",
    status = "...",
    tooltipValue = "...",
}
```

投影函数只做展示压缩，不重新判断业务状态：

- `status`、`acquired` 和原始进度来自快照。
- `icon`、`color` 和 `value`由统一状态/格式化器派生。
- 主页面和悬停不能各自实现一套完成判定。

### 9.3 YiboCore 职责

YiboCore 继续负责：

- 悬停窗口壳和生命周期。
- Broker、小地图入口及入口设置。
- 角色范围、服务器范围、角色隐藏和排序。
- 悬停字段设置入口。
- 安全屏幕边界、自然宽度计算、目标列分页和滚动。
- 当前角色的统一视觉标记。

YiboLegendary 负责：

- 目标目录和稳定排序。
- 角色—目标快照。
- 状态视觉投影和目标短名称。
- 主页面内容与单元格导航目标。

## 10. 设置与 SavedVariables

### 10.1 悬停目标列设置

沿用按目标 ID 保存的可见性：

```lua
settings.previewColumns = {
    CLOAK = true,
    THUNDERFURY = true,
    SORIDAL = true,
    -- 其它目录目标默认 true
}
```

要求：

- 新增目标默认显示。
- 用户隐藏目标后，设置持久化。
- 删除或改名目标时进行 ID 迁移，不以显示名称作为键。
- 目标设置列表使用目录稳定顺序。
- 角色排序、角色范围和入口显示不在本插件页重复设置。

### 10.2 迁移

旧版将业务字段作为悬停列的配置需要迁移到目标 ID：

- `character` 保留为 Core 的固定角色列语义，不作为业务橙装列。
- `CLOAK`、`THUNDERFURY`、`SORIDAL` 等目标 ID 迁移为目标列开关。
- 旧配置缺少的新目录目标默认设为 `true`。
- 迁移后不再把“任务、目标、行动”保存为独立悬停列。

## 11. 尺寸、分页与性能

### 11.1 宽度

目标列先按全部当前可见目标计算自然宽度，内容依据短名称和单元格核心值估算。只有完整矩阵达到屏幕安全宽度仍无法容纳时，才进行目标列分页。

角色列宽由 Core 统一角色标签规则决定。

### 11.2 分页

- 只对目标列分页。
- 角色列在每一页保持固定。
- 表头和数据单元格必须使用相同目标切片。
- 分页控件放入 Core 标题栏，不占用矩阵内容宽度。
- 分页状态按页面和矩阵上下文保存，切换目标范围后自动校正页码。

### 11.3 高度

- 使用紧凑固定行高。
- 状态图例、表头和角色行保持稳定节奏。
- 角色较多时使用 Core 统一纵向滚动。
- 不使用横向滚动替代目标列分页。

### 11.4 刷新

- 快照更新后，主页面和悬停同时刷新。
- 悬停刷新不得创建第二份角色—目标状态。
- 单元格渲染应复用已有控件，避免每次刷新重复创建控件。
- 目标列切换或服务器范围变化时，统一重算自然宽度和分页。

## 12. 实施分阶段

### P1：目录与配置基础

- 为所有目录目标补齐稳定排序元数据。
- 明确目标短名称、图标、路线类型和占位状态。
- 将 `previewColumns` 统一为目标 ID 配置。
- 为新增目标建立默认可见迁移逻辑。

### P2：快照投影

- 建立状态图标、颜色、短标签映射。
- 建立目标类型对应的实时数字格式化器。
- 支持完成态证据来源短标。
- 为待接入、绝版、不适用、待同步和无法读取提供稳定投影。

### P3：悬停矩阵重构

- 重做列头为图标 + 短名称。
- 重做单元格为状态图标 + 核心实时数据。
- 加入固定状态图例。
- 按 Core 规则输出角色行头。
- 为单元格接入主页面导航。

### P4：尺寸与压力测试

- 测试多服务器、长角色名和 20 名角色。
- 测试全部目录目标同时显示。
- 测试目标列分页和分页状态恢复。
- 测试所有状态、并行数字和证据来源组合。
- 验证主页面、悬停、Broker、小地图的状态一致性。

## 13. 验收标准

### 信息正确性

- 所有目录橙装默认出现在悬停矩阵。
- 橙披位于第一列，MC 橙锤/风剑位于早期目标末端。
- 角色准入、服务器范围、角色名格式与 Core 一致。
- 主页面与悬停使用同一状态和同一进度。
- 待接入、绝版、不适用和无法读取不会被渲染为普通零进度。
- 自动获得、玩家确认和测试投影可明确区分。

### 视觉可读性

- 每个单元格都能通过图标、颜色和短文本识别状态。
- 图例与实际状态颜色/图标一致。
- 数值目标显示核心实时数字。
- 多并行目标不会因压缩而丢失必要数字。
- 角色名颜色正确，且不依赖职业图标。
- 列头不会出现无法识别目标的截断。

### 交互与布局

- 左键单元格能打开对应橙装主页面。
- 主页面能正确选中目标。
- 目标列空间不足时只发生目标列分页。
- 表头、单元格和分页目标切片一致。
- 悬停窗口无横向滚动、无截断控件、无隐藏溢出点击区。
- Core 负责的入口、窗口、角色排序和设置壳不被业务插件重复实现。

### 设置

- 用户可以逐项隐藏/显示橙装列。
- 新增目标默认显示。
- 隐藏状态重载后保持。
- 角色过滤和排序仍由 Core 统一控制。

## 14. 后续待定细节

以下内容不影响当前总体架构，可在进入实现前继续逐项确认：

- 各状态最终使用的 WoW 图标材质。
- 数字字号、对齐方式和长数字缩写规则。
- 分页标题的最终中文文案。
- 多并行进度的排序和分隔符细节。
- 状态图例在极窄屏幕下的排布策略。
- 全目录目标较多时的测试数据规模和性能阈值。

这些细节必须在本方案的统一状态投影、Core 分页和目标 ID 契约内解决，不得为单个橙装复制悬停窗口或状态判断。
