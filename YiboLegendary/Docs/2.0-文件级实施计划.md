# YiboLegendary 2.0.0 文件级实施计划

> **执行目标**：在不改动 YiboCore 窗口壳、角色范围、入口和统一设置框架的前提下，完成风剑端到端垂直切片，并将橙披、索利达尔接入同一套“角色 × 目标”快照。
>
> **版本**：2.0.0
>
> **客户端**：MoP Classic 5.5.4 / Interface 50504
>
> **当前状态**：待执行

## 1. 已确认的交付边界

2.0.0 正式显示三个目标：

| 目标 | 路线类型 | 2.0 验证重点 |
|---|---|---|
| 传说披风 | 长任务链 | 章节、并行要求、声望、货币、阶段开放、最终奖励 |
| 雷霆之怒，逐风者的祝福之剑 | 掉落／收集链 | 左右绑定、元素锭、最终事件、职业适用性 |
| 索利达尔，群星之怒 | 直接掉落 | 单一 Boss 掉落、自动证据、人工确认、撤销确认 |

测试投影仅当前会话有效，绝不覆盖真实 SavedVariables。直接掉落的历史获得允许使用人工证据，但必须显示证据来源。

## 2. 执行顺序与依赖

```text
P0 快照契约与证据层
  ↓
P1 风剑采集与解析
  ↓
P2 橙披迁移 + 索利达尔目录
  ↓
P3 主页面与悬停矩阵
  ↓
P4 人工确认与 Core 设置接入
  ↓
P5 静态检查、实机投影验收、真实角色验收
```

不得跳过 P0 直接继续扩展 UI。P3 只能消费统一快照，不能在 `UI.lua` 中按目标 ID 编写路线判断。

## 3. 文件级任务清单

### P0：快照契约与证据层

#### `Model.lua`

- [ ] 定义统一状态枚举：`completed`、`in_progress`、`obtainable`、`pending_sync`、`ineligible`、`unknown`、`unavailable`。
- [ ] 定义统一角色—目标快照字段：

## 5. 发布门槛

2.0.0 只有同时满足以下条件才可更新版本说明和发布包：

1. P0—P4 文件级任务全部完成，或明确标记为不影响正式能力的待办。
2. 风剑、橙披、索利达尔三条路线通过测试投影矩阵。
3. 至少一名真实角色完成风剑无掉落、背包读取和持久化验证。
4. 主页面与悬停矩阵通过自然宽度、分页、滚动和字体显示检查。
5. 人工确认可创建、展示、撤销，并能在缓存清理后消失。
6. 更新 `CHANGELOG.md`、`PRODUCT.md`、`CURSEFORGE_DESCRIPTION.md` 和 `TEST_CHECKLIST.md` 后再标记 2.0.0 完成。

## 6. 后续版本约束

2.1 以后新增目标只能新增目录定义、采集器、节点解析器或本地化文案。只有当统一快照无法表达新路线时，才允许修改快照契约；不得为单个传说物品复制主页面、悬停或入口逻辑。
