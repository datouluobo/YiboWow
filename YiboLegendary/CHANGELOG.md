# YiboLegendary 更新日志

## 2.2.2

- 修复账号矩阵悬停预览中的文本截断：状态图例按标签宽度排布，目标列按表头和角色实际显示内容计算自然宽度，超出屏幕安全范围时使用 Core 分页。
- 未获得目标在矩阵中仅显示“未获得”；英文界面显示“Not acquired”，不附加收集提示。

## 2.2.1

- 明确英文覆盖范围：菜单、矩阵表头、按钮、控件与通用状态／错误提示使用英文；任务步骤、专有名词、路线说明和目标进度保留中文原文。
- 移除任务行动与路线目录中未经可靠英文来源校对的占位译文。

## 2.2.0

- 适配 YiboCore API v13：启动时校验 `localization:1`、`character-name-format:1`、`account-view:2` 与 `account-entry:2`，不兼容时提示升级并停止初始化。
- 注册 YiboLegendary 自有中英文资源，Core 账号语言设置驱动页面标题、摘要、设置说明、启动错误及人工确认。
- 角色名称统一使用 `Characters:FormatName`；人工确认与撤销提示显示真实完整角色身份。
- 入口注册显式声明小地图、Broker、内置信息条均默认关闭；目标主动添加增强继续独立要求 API v12 / `business-item-actions:1`。
- 英文覆盖菜单、矩阵表头、按钮、控件与通用状态／错误提示；任务步骤、专有名词、路线说明和目标进度沿用中文原文，避免缺少可靠英文来源时误译。客户端语言与布局验收待完成。

## 2.0.0

- 将传说之路从单一橙披任务表升级为账号级传说目标目录。
- 保留 MoP 橙披的完整任务、声望和勇气进度，并新增雷霆之怒路线。
- 完整页面改为“目标目录 + 路线说明 + 角色详情”；悬停改为角色／物品矩阵。
- 新增统一角色—目标快照，完整页面、悬停、Broker 和小地图入口共享同一状态。
- 新增 `/yle test THUNDERFURY <节点>` 开发投影；真实掉落不再决定 UI 与状态机测试进度。

- 修复“勇气的试炼”（32476）的货币事件参数未完整传递；累计进度现在优先使用客户端报告的实际获得量。
- 首次识别到已接取的“勇气的试炼”时，立即以当前勇气余额建立基线并显示 `0/1,600`；插件安装或任务接取前的勇气不追溯。
- 修复旧任务日志 API 的返回字段差异导致“勇气的试炼”未被识别为进行中；累计值现直接追加在“目标”列的任务目标后。
- 兼容部分 Classic 客户端的按任务 ID 索引缺失：现代与旧版索引 API 会依次尝试，仍无法返回时扫描当前任务日志。
- “勇气的试炼”的目标列不再依赖任务日志识别；只要它是当前任务，固定显示累计格式 `累计获得勇气点数0/1600`。
- 修复将 `CURRENCY_DISPLAY_UPDATE` 的“获得来源”误当作点数的问题：现在按事件的实际变动量累计，并为中文客户端补充“勇气的试炼”标题扫描兜底。
- “勇气的试炼”只强调已累计数值：当前值以 Core 青绿色及描边粗体显示，说明和目标总数保持常规文本层级。
- 修复部分 Classic 客户端中独立累计数字被裁切的问题：改为同一目标文本内的 Core 青绿色数值标记，不再使用跨字体的覆盖层。
- 修复兼容性识别升级时错误清零已有勇气累计值的问题；重新识别已接取任务会保留进度，并修复此前一次性重置留下的最后获得量。
- 勇气累计目标在当前值前增加空格，提升数字与说明文字之间的可读性。
- 修复传说之路账号表在刚好容纳全部字段时被伪滚动条拆页的问题；“当前任务、目标、行动”在正常窗口同页显示。
- 修复窄窗口字段分页后的末页大面积空白：最后一个可见字段会填满剩余表格宽度。
- 悬停与正式窗口均以页面实际宽度进行字段分页，不再读取滞后的 ScrollFrame 宽度。
- 悬停预览改为按角色、任务、目标与行动的实际内容分别估算列宽；目标和行动不再被等宽压缩，窗口随各列合计需求调整。
