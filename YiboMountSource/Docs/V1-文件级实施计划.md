# YiboMountSource V1 文件级实施计划

> **执行目标**：为 MoP Classic 5.5.4 建立零依赖的坐骑 Aura 来源 Tooltip 垂直切片，先发布可工作的 `0.1.0-alpha`，再完成默认 UI、NDui、双语言和数据校验后发布 `1.0.0`。
>
> **客户端**：MoP Classic 5.5.4 / Interface 50504
>
> **当前状态**：待执行

## 1. 交付边界

V1 只处理自己和当前目标的坐骑 Aura Tooltip：

```text
Aura Tooltip
  ↓
可靠取得 unit + spellID
  ↓
命中本地生成索引
  ↓
读取坐骑实体与主要来源
  ↓
格式化 Locale 路径和条件
  ↓
去重后追加 1～2 条逻辑行
```

V1 不创建窗口、设置、SavedVariables、正式 Slash 命令或 YiboCore 注册。代码只预留目录查询与格式化边界，避免 V2 页面直接依赖 Tooltip 内部实现。

## 2. 执行顺序与依赖

```text
P0 客户端能力探针与最小骨架
  ↓
P1 Schema、验证集与生成器
  ↓
P2 运行时目录与紧凑格式化器
  ↓
P3 Aura Tooltip 接入与去重
  ↓
P4 Alpha 实机验证与发布
  ↓
P5 默认 UI、NDui、双语言与正式 V1
```

不得在 P0 未确认 Tooltip 生命周期和可用字段前写死 Retail API。不得让 `Tooltip.lua` 读取原始 JSON、研究证据或按具体坐骑 ID 拼文案。

## 5. 预留接口契约

V1 预留的是业务服务边界，不是承诺长期兼容的全局 API。内部至少提供：

```lua
Catalog:GetBySpellID(spellID)
Catalog:GetByMountKey(mountKey)
Catalog:IterateMounts()
SourceFormatter:Format(record, locale)
```

约束：

- V2 Core 页面只消费 Catalog 和 Formatter，不读取 `Tooltip.lua` 状态。
- V1 不调用 `YiboCore:RegisterAddon()`，不注册页面。
- V2 接入前检查 Core 的 Public API 与可选依赖加载顺序。
- 如果 Core 当前注册契约只接受强依赖业务插件，应先扩展 Core 的可选集成能力，而不是让独立 Tooltip 退化为 RequiredDeps。
- 对外全局 API 只有在 V2 有真实消费者后才定版。

## 7. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 5.5.4 Tooltip 回调与 Retail 不同 | 无法取得可靠 `spellID` 或 unit | P0 先实机探针，再选 Hook |
| NDui 改变 Tooltip 生命周期 | 标准路径不触发或重复触发 | 正式 V1 专门验收；仅加最小兼容层 |
| Aura 法术 ID 与坐骑召唤法术不一致 | 数据命中失败 | 以实际 Aura `spellID` 建索引并保留多 ID |
| 第三方资料混入 Retail 状态 | 来源或绝版状态错误 | 目标版本资料＋第二来源交叉核验 |
| 结构化条件过多 | 第二逻辑行过长 | 保留关键获取条件并允许自然换行，不拆成长攻略 |
| 未来 Core 页面需要更多字段 | V1 数据重构 | 实体、ID、来源和格式化从第一天分层 |

## 8. 完成定义

`0.1.0-alpha` 完成意味着核心垂直切片已经在 MoP Classic 5.5.4 实机跑通，可以收集反馈；不意味着数据完整或兼容承诺完成。

`1.0.0` 完成意味着验证集、双语言、默认 UI、NDui、生成器和正式发布检查均已通过。V2 Core 页面不属于 V1 完成条件。
