# YiboQuestBlocker v3.0：直接拒绝与自动接任务兼容方案

> 状态：方案设计，尚未实施  
> 目标客户端：WoW MoP Classic / 国服 5.5.4  
> 依赖：YiboCore API v5

---

## 1. 版本与范围

本次更新建议定为 **v3.0.0**，而不是 v2.2。

现有版本的实际主能力是“任务已经被接取后，按规则安全放弃”；v3 的主承诺将变为“优先在接取前直接拒绝，并尽量不中断 Questie、Blitz、Leatrix Plus 等自动接任务插件的连续流程”。这是运行时行为、兼容方式、状态管理和用户预期的重大改变，使用主版本号升级更准确。

v3 不移除现有自动放弃。它从常规路径降级为异常恢复层，用来处理无法直接阻止的特殊 API 路径、加载顺序冲突和客户端限制。

## 2. 产品目标与非目标

### 2.1 目标

- 已屏蔽任务优先不进入任务日志。
- 不要求玩家停用 Questie、Blitz、Leatrix Plus 或其它自动接任务插件。
- 同一 NPC 有多项任务时，跳过被屏蔽任务后尽量继续处理后续允许任务。
- 自动续办不得让原插件重复尝试同一屏蔽任务，不得形成循环。
- 无法可靠兼容时，宁可安全停止续办，也不猜测原插件的自动接取策略。
- 主窗口、Broker 和小地图预览继续复用 YiboCore 统一账号视图与入口。

### 2.2 非目标

- 不接管其它插件的自动接取、自动交付、奖励选择或 Gossip 策略。
- 不修改其它插件的 SavedVariables、私有表或源码。
- 不通过模拟 Esc、重新交互 NPC、反复点击原生按钮来强行恢复流程。
- 不承诺对所有未知自动任务插件实现无感续办。

## 3. 三层处理模型

```text
任务选择层 ──────────> 接取层 ──────────> 接取后恢复层
尽早跳过                最终直接拒绝          安全自动放弃
```

| 层级 | 触发时机 | 正常结果 | 责任 |
|---|---|---|---|
| 任务选择层 | 自动化插件准备从 NPC 列表选择任务 | 被屏蔽任务不进入详情页 | 尽早过滤并管理续办批次 |
| 接取层 | 自动化插件或玩家尝试接取任务 | 直接拒绝，任务不进入日志 | 最终保障 |
| 接取后恢复层 | 已收到任务接取事件但任务命中规则 | 等待安全时机后放弃 | 兼容绕过与异常路径 |

UI 灰显属于可视化投影：帮助玩家理解规则，但不承担安全职责。自动化插件可直接调用任务选择或接取 API，不能仅依赖禁用 NPC 界面按钮来阻止它们。

## 4. 规则与默认设置

现有的全局拒绝与角色独立拒绝继续保留，优先级不变：全局规则优先于角色规则。

新增或明确以下运行设置：

| 设置 | 默认值 | 含义 |
|---|---:|---|
| 直接拒绝已屏蔽任务 | 开启 | 接取层命中规则时拒绝，不正常接取 |
| 与自动接任务插件续办 | 开启（仅已验证适配器） | 被拒绝后尝试继续同一 NPC 的允许任务 |
| 未验证插件续办 | 关闭 | 仅直接拒绝，不替未知插件挑选下一任务 |
| 接取后自动放弃兜底 | 保留现有偏好 | 仅在直接拒绝被绕过时启用 |
| NPC 列表灰显 | 开启 | 标记已屏蔽任务并阻止玩家误点 |
| 诊断记录 | 开启，保留近期有限条目 | 显示直接拒绝、续办、绕过与失败原因 |

“仅本次允许”是可选的玩家交互能力：它只放行当前任务与当前交互批次，不删除长期规则。

## 5. NPC 单次任务批次

### 5.1 批次边界

YQB 不把一次 NPC 对话视为无限流程。每个自动续办批次必须绑定：

- NPC 的唯一身份；
- 当前角色；
- 当前交互批次编号；
- 初始可用任务集合；
- 命中的屏蔽任务集合；
- 已交给原插件的允许任务；
- 当前状态与预期的下一任务；
- 最大允许操作数与超时状态。

目标改变、NPC 对话关闭、角色切换、任务列表无法识别或用户主动取消时，立即结束批次。旧批次的回调不得影响新交互。

### 5.2 理想流程

假设同一 NPC 提供 `A、B、C、D、E`，其中 `B、D` 被屏蔽，原自动化插件愿意自动接取 `A、C、E`：

```text
初始列表：A B C D E
原插件接取 A

返回列表：B C D E
YQB 排除 B、D，交出 C
原插件接取 C

返回列表：B D E
YQB 一次扫描排除 B、D，交出 E
原插件接取 E

批次结束
```

`B` 和 `D` 在内存中被规则筛除，不应反复打开任务详情、拒绝、再回到列表。第二次扫描会再次读取它们以保证当前列表正确，但不会把它们交给原插件处理。

## 6. 完整运行流程

### 6.1 登录与准备

1. 加载规则、已有缓存、设置与近期诊断记录。
2. 检测已安装和已加载的已知自动任务插件。
3. 在所有常规插件完成加载后安装或确认直接拒绝防线；若已知插件按需加载，再在其加载完成后重新确认。
4. 检查当前任务日志。已命中规则的任务不回溯为“直接拒绝”，只按自动放弃兜底设置处理。
5. 在设置页展示适配状态：已验证直接拒绝、已验证续办、仅直接拒绝、未检测到或版本待验证。

### 6.2 NPC 任务列表显示

1. 读取当前可用任务及其 ID。
2. 对命中规则的条目灰显，显示“已屏蔽”及规则范围。
3. 保持原生任务排列和原始数据语义；不隐藏条目、不重排列表、不篡改通用任务列表返回值。
4. 默认情况下，YQB 不抢先选择允许任务，仍由原插件决定它想处理哪些任务。

### 6.3 原插件选择允许任务

1. 原插件选择允许任务。
2. YQB 放行任务选择与接取。
3. 原插件自行完成接取与后续交付逻辑。
4. YQB 只在任务再次触碰屏蔽规则时介入。

### 6.4 原插件选择或接取被屏蔽任务

1. YQB 识别任务命中全局或当前角色规则。
2. 若能在选择层阻止，则阻止进入详情；若任务已进入详情，则在接取层直接拒绝。
3. 记录一次“被屏蔽任务”结果，并创建或更新当前 NPC 批次。
4. 对当前任务仅执行一次拒绝动作；不得重复拒绝同一任务。
5. 等待客户端自然回到同一 NPC 的任务列表。
6. 若回到列表且已知适配器能判断原插件的候选策略，则由适配器在“原插件会接受的候选集合”中排除 YQB 屏蔽任务，交出下一允许任务。
7. YQB 仅负责选择下一候选任务；接取仍由原插件完成。
8. 原插件接取后回到列表时，重复候选筛选，直至没有可处理任务或批次结束。

### 6.5 拒绝后未回到任务列表

1. 拒绝后等待一次有限的界面稳定期和相关事件。
2. 若客户端自然回到任务列表，继续第 6.4 节的续办。
3. 若仍停留在被屏蔽任务详情，或整个 NPC 对话已关闭，记录“未能恢复任务列表”。
4. 终止本批续办，不重复拒绝，不模拟 Esc，不强制关闭或重新打开 NPC 对话。
5. 直接拒绝仍视为成功；仅“自动继续下一任务”失败。

### 6.6 直接拒绝被绕过

1. 若任务已进入日志且命中规则，记录“直接拒绝被绕过”。
2. 若用户开启自动放弃兜底，等待任务交互与确认界面结束。
3. 检查任务是否允许放弃；允许时进入现有的延迟、安全放弃队列。
4. 成功、不可放弃、超时或异常均写入诊断记录，避免反复刷屏。
5. 自动放弃不负责驱动 NPC 续办；它只处理已经接到日志里的异常任务。

## 7. 自动续办的兼容原则

### 7.1 不能使用通用“选下一个未屏蔽任务”替代原插件

原插件可能还会按日常、等级、PvP、重复任务、修饰键、任务预设或其它条件筛选。YQB 若不了解这些条件，直接把一个未屏蔽任务推入详情页，可能让原插件不接取，反而卡住。

因此，续办分为两种等级：

| 级别 | 行为 |
|---|---|
| 已验证适配 | 针对特定插件与版本，确认其候选规则与返回列表行为；只在其候选集合内排除屏蔽任务后续办 |
| 通用兼容 | 仅直接拒绝；不主动代替原插件选择后续任务 |

Questie、Blitz、Leatrix Plus 分别建立适配器和实机验证矩阵。适配器不得依赖修改对方存档或私有状态；版本变化导致规则无法确认时自动降级为通用兼容。

### 7.2 单一控制权与交接

在一个续办批次中，YQB 只在“筛选下一候选”这个短窗口拥有选择控制权。其它时间完全交由原插件。

| 状态 | 选择控制权 | 允许动作 |
|---|---|---|
| 等待原插件 | 原插件 | 正常选择与接取 |
| 正在拒绝 | YQB | 拒绝当前屏蔽任务；不选下一项 |
| 等待任务列表 | 客户端 | 等待自然界面转换 |
| 筛选下一候选 | YQB | 仅交出适配器确认的允许候选 |
| 已交接详情页 | 原插件 | 按其自身逻辑决定是否接取 |
| 已结束 | 无 | 清理状态，恢复普通监听 |

### 7.3 当前实际 AddOns 环境的兼容清单

本清单以 `C:\Program Files (x86)\World of Warcraft\_classic_\Interface\AddOns` 的实际目录为准，并与 `Addon_Maintenance_Log.md`、`Addon_Maintenance_Current.xlsx` 交叉核对。维护清单将 Questie 标为任务辅助、DialogueUI 标为任务界面；源码扫描进一步确认了下列会实际选择、接取或自动交付任务的插件。

| 插件 | 当前代码路径与行为 | v3 定位 | 适配要求 |
|---|---|---|---|
| `Questie` | `Modules/Auto/AutoQuesting.lua` 会选择可用任务，并在任务详情或共享确认时调用接取 | 第一批已验证适配 | 保留其修饰键、NPC 排除、普通/重复/PvP 任务筛选；验证连续任务续办 |
| `!Pig` | `General/Interaction/AutoDialogue.lua` 会遍历 Gossip 可用任务、选择非低级任务，并自动接取、交付和领奖 | 第一批已验证适配 | 其多任务循环会在一个事件中连续请求选择多个任务；YQB 必须把屏蔽任务排除在该批次之外，并验证不会造成重复选择 |
| `NDui` | `Plugins/QuickQuest.lua` 会选择允许任务、自动接取、确认共享任务、交付并自动选奖 | 第一批已验证适配 | 保留其 Shift 暂停、NPC 忽略表、低级任务/追踪设置和奖励选择行为；验证其连续循环与 YQB 批次锁协作 |
| `Leatrix_Plus` | `Leatrix_Plus.lua` 会选择 NPC/Gossip 可用任务，自动接取、确认共享任务和交付 | 第一批已验证适配 | 保留其 `AutomateQuests`、修饰键、NPC 排除和任务条件；验证任务问候与 Gossip 两条路径 |
| `DialogueUI` | 对话框替换插件；仅对内置允许的少量任务、自动接取任务弹窗和控制器模式触发自动接取/选择 | 特殊适配或安全降级 | 它在加载时缓存了接取函数引用，普通的后装全局 guard 可能无法覆盖；需专门适配其公开界面路径并实测，否则只保留接取后兜底放弃 |
| `Blitz` | 当前实际目录未安装，但此前已作为目标兼容插件研究 | 第二批适配 | 保留独立适配器与验收项；用户日后安装时自动检测并先以直接拒绝模式运行 |

以下插件在当前源码扫描中只读取、显示或美化任务数据，未发现实际自动选择或接取任务调用，**不纳入自动接取兼容适配器**：`DataStore_Quests`、`AllTheThings`、任务框体皮肤模块、地图任务标记模块、`Outfitter`、`RurutiaSuite` 等。它们仍需纳入普通 UI 共存测试，但不应占用 v3 的自动化兼容开发成本。

`DialogueUI` 还会替换 NPC 任务界面，因此它即使未启用自动接取，也必须进入“拒绝后是否自然回到任务列表”的 UI 兼容测试。YQB 不得假定默认暴雪任务框体存在或可见。

当前 SavedVariables 中同一插件的自动任务开关会因账号、角色和配置档案而不同；例如 NDui、Questie 与 `!Pig` 均同时存在开启和关闭记录。v3 不得通过离线存档推断“本次一定会自动接取”，而应在运行时根据已加载插件、当前有效设置和实际发生的任务选择/接取调用决定是否启动续办批次。

## 8. 防循环与安全阀

以下规则是续办功能的硬性要求：

1. 同一 NPC 批次内，同一屏蔽任务最多产生一次拒绝记录和一次拒绝动作。
2. 被屏蔽任务加入批次排除集合后，不得再次成为本批次的候选。
3. 每一次“选择下一任务”必须对应明确的状态转换；没有新的任务列表、任务详情或接取结果时，不得再次选择。
4. 交出预期任务期间，任何与预期不符的旧选择请求都不得启动新的递归流程。
5. 最大尝试次数不得超过批次初始候选任务数；到达上限立即终止并记录诊断。
6. NPC、目标、角色、对话状态或批次编号改变，立即废弃旧操作。
7. 用户可以随时取消当前批次；取消后继续执行硬拒绝，但不再自动续办。
8. 超时、未知界面、未知插件版本或适配器无法判断候选资格时，一律降级为“直接拒绝，不续办”。

## 9. 用户可见反馈

### 9.1 NPC 列表

- 已屏蔽任务灰显并带 `⊘ 已屏蔽` 标记。
- 悬停展示规则来源：全局、当前角色或本次临时放行状态。
- 保留任务原顺序，避免误导玩家和破坏外部插件的索引语义。

### 9.2 账号页与设置页

在 YiboCore 的统一设置工作台中，QuestBlocker 仅新增适用的“业务设置”与“数据与缓存”分区：

- 直接拒绝、自动续办、自动放弃兜底与列表灰显开关；
- 已知插件适配状态和版本信息；
- 当前或最近批次的简洁诊断；
- 清理诊断记录的非破坏性操作；
- 清除业务缓存等破坏性动作放在“数据与缓存”末尾并使用确认框。

角色排序、字段显示、入口、小地图、Broker 和悬停预览字段继续由 YiboCore 统一管理，不在插件页重复实现。

### 9.3 结果文案

每次命中应使用以下可区分结果：

| 结果 | 含义 |
|---|---|
| 已在列表跳过 | 未打开任务详情，也未接取 |
| 已直接拒绝 | 打开过详情，但未进入任务日志 |
| 已拒绝并续办 | 已跳过当前任务，自动继续后续允许任务 |
| 已兜底放弃 | 任务先进入日志，后被安全放弃 |
| 自动续办停止 | 直接拒绝成功，但无法安全继续处理同一 NPC |
| 无法自动处理 | 未知路径、任务不可放弃或客户端状态异常 |

## 10. 数据与迁移

现有拒绝规则、角色数据、任务名缓存、预览字段和筛选偏好不应丢失。

新增数据仅包括：

- v3 运行设置；
- 有限条目的近期诊断记录；
- 可安全失效的已知插件适配版本信息。

NPC 批次、拒绝动作锁、预期候选、超时计数等均为纯运行时状态，禁止写入 SavedVariables。升级时将 `schemaVersion` 提升，缺失的新设置使用安全默认值：直接拒绝开启、未知插件续办关闭、自动放弃沿用用户原有偏好。

## 11. 验收矩阵

### 11.1 基础功能

| 场景 | 期望结果 |
|---|---|
| 单个被屏蔽 NPC 任务 | 不进入任务日志；对话按客户端正常行为返回 |
| 手动尝试接取被屏蔽任务 | 直接拒绝并显示规则来源 |
| 全局与角色规则同时存在 | 全局规则优先，显示正确来源 |
| 不在规则中的任务 | 不改变原生或外部插件行为 |
| 特殊路径绕过 | 记录绕过，按设置进入自动放弃兜底 |

### 11.2 连续任务

对同一 NPC 的 `A、B、C、D、E`，屏蔽 `B、D`：

- 已验证适配时预期：接取 `A → C → E`；`B、D` 均不进入任务日志；无重复拒绝、无循环。
- 全部剩余任务被屏蔽时预期：停止续办，保留 NPC 对话，不反复触发。
- 拒绝后无法回到列表时预期：停止续办，不模拟 Esc 或重新交互。

### 11.3 插件组合

每项分别测试“仅该插件”和“与其它自动化插件并存”：

- Questie；
- `!Pig`；
- NDui QuickQuest；
- Blitz；
- Leatrix Plus；
- DialogueUI（分别覆盖仅替换界面、内置自动接取和控制器模式）；
- 未知自动接任务插件（通用兼容降级）；
- 不启用任何自动接任务插件。

覆盖 NPC 任务详情、任务问候列表、Gossip 任务选择、共享任务确认、重复任务、含奖励选择任务、任务已在日志中、NPC 同时为商人或训练师等场景。

## 12. 发布与回滚

1. 先以内部测试版验证“直接拒绝 + 不续办”，确认任务不进入日志。
2. 再逐个开启 Questie、Blitz、Leatrix Plus 的已验证续办适配器。
3. 正式版默认启用直接拒绝；未知插件保持不续办。
4. 若某个适配器在游戏补丁或插件更新后失效，通过适配器版本门槛自动降级，不影响直接拒绝与自动放弃兜底。
5. 用户可关闭直接拒绝，恢复 v2 的“接取后按规则放弃”行为；该开关作为明确的兼容回退，不删除既有数据。

## 13. 发布说明重点

v3 的用户承诺应使用准确措辞：

> YiboQuestBlocker 会优先直接拒绝已屏蔽任务。对已验证兼容的自动接任务插件，它会在跳过屏蔽任务后尽量继续同一 NPC 的其它允许任务；未知或异常路径会安全降级，并保留接取后自动放弃作为兜底。

不得笼统宣称“所有自动任务插件均可无感兼容”或“所有任务均会在接取前阻止”。
