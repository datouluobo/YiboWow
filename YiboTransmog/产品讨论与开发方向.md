# YiboTransmog 幻化助手

2026-11-21 · 技术名与安装目录 `YiboTransmog` · 插件列表显示名 `[Yibo] 幻化助手` · 目标客户端 `Forever`

当前处于产品讨论与取证准备阶段。源码目录和取证探针都已联接到无限服的 `AddOns`。暴雪导出代码的接口核对已完成。2026-11-21 探针 0.1.1 完成 T0 与 T3，2026-11-22 完成 T1 与 T2（结果见「T0／T3 结果」「T1／T2 结果」）。T5 暂缓，T4 已取消；实现和发布验收均未开始。

## 产品方向

`YiboTransmog` 是 Core 中的账号幻化收藏助手。主界面分为「收藏总览」和「追踪清单」，帮助玩家查看已收集多少、还缺哪些外观、接下来可以去哪里获取。物品与任务奖励提示是辅助功能。

## 收藏总览

- **账号收藏数量**按护甲类型、装备部位和武器查看「已收集」数量，不显示总数和百分比（统计口径见下）。点开分类可查看已收集外观及其原生来源类型。
- **外观与来源**按外观计算收藏进度。同一外观只计一次，详情列出不同装备来源，区分「外观未收集」「同外观已拥有」「此来源已收集」。
- **角色适用性**按选中的角色查看获取条件、能否为账号解锁、能否使用该外观。换角色时仍查看同一份账号收藏进度。
- **灰白装备**也有可收藏的外观，纳入收藏统计和待收集清单。无限服符合条件的灰色（粗糙）和白色（普通）装备在拾取时即可解锁外观。 [暴雪无限服幻化说明](https://wow.blizzard.cn/news/24303313/index.html)

**统计口径：方案 C（2026-11-21 用户确认）**。T0 实测，原生总数包含大量本服拿不到的外观（见「T0／T3 结果」），不能作分母。首版只显示已收集数，计数时排除「隐藏外观」（如隐藏头盔，`isHideVisual`）。

| 方案 | 分母来源 | 结论 |
| --- | --- | --- |
| A 原生总数 | `GetCategoryTotal`／`GetCategoryAppearances` | 不采用：总数严重偏大 |
| B 自建目录 | 插件自带本服可获得外观目录 | 不采用：没有原生接口支撑，创建和维护量太大。日后如果出现套装，目录小很多，届时可单独评估套装目录；或出现更省力的生成方式时再议 |
| C 只显示已收集 | 只显示已收集数；缺失外观只来自物品、任务奖励和玩家追踪 | **采用** |

**角色适用性规则**按暴雪公告取值：护甲类型必须一致；60 级以前不能使用高于自身等级的外观，60 级后收藏中的外观解除等级限制，纯外观物品不受等级限制。解锁也有分支：地下城拾取绑定的绿装和蓝装，所有有拾取资格的玩家都获得外观；团队副本史诗只有最终拿到并绑定物品的玩家才解锁。 [暴雪无限服幻化说明](https://wow.blizzard.cn/news/24303313/index.html)

## 追踪清单

玩家可以从物品、任务奖励或已知外观加入追踪，查看还缺哪些、每件的原生来源类型和获取条件。外观入藏后移入已完成。无限服目前没有套装数据（T0），整套追踪等出现套装后再做。

任务来源按**完成该任务可新增的外观**汇总。一个任务能补多件时，清单展示新增数量和各件外观，方便玩家按目标安排路线。

原生接口只给出来源类型（副本首领、任务、商人、世界掉落、制造等），以及副本来源的首领与难度，不给出具体任务、商人或地图。

**来源范围（2026-11-21 用户确认）**：
- 首版只显示原生接口能给出的来源，即来源类型，以及副本来源的首领与难度。
- 原生没有来源信息的外观不展示来源详情，也不靠显示名称推测。
- 不建插件自带的来源目录（与方案 B 同一结论），依赖具体位置的「去哪里获取」和「顺路提示」不在计划内。

## 物品与奖励提示

- **背包、银行和物品 Tooltip**显示该物品对应的外观状态，例如「外观未收集」「同外观已拥有」「此来源已收集」。适用时提示绑定或角色限制，方便玩家判断如何处理物品。
- **拾取与拍卖行**提示该物品是否能补齐缺失外观，帮助玩家决定要不要拾取或购买。
- **多选一任务奖励**按整个任务显示新增外观。按用户在无限服的实测，完成任务时，有可收藏外观的奖励即使未选，或当前角色无法装备，其外观也会解锁。交付界面可以提示「完成此任务可新增 3 个外观」并列出具体外观。选哪件装备由玩家决定，可另显示「卖店价最高」供参考。

**2026-11-21 T3 已证实**：多选一相关全局函数全部可用；交付后，未选的奖励、以及本角色职业无法使用的奖励，外观都会解锁。任务奖励汇总可以按“整个任务新增外观”实现。下面是实测前的原始待确认项，保留备查：
- 多选一相关的全局函数能否使用。暴雪无限服自己的任务界面调用了 `GetNumQuestChoices`、`GetQuestItemInfo`、`GetQuestItemLink` 和 `GetQuestReward(选项)`，大概率可用，但仍以实测为准。
- 交付后未选奖励的外观是否真的解锁。

测试方法见 T3。原生 Tooltip 协调是 Core 的候选能力，Vault 已有物品 Tooltip 追加，本插件会是第二个提供者。实现时先评估收归 Core，再决定是否自己挂钩子。 [Core 多端公共能力方向](../YiboCore/Docs/Core-多端公共能力与界面提升方向.md)

## 幻化显示（不在本插件范围）

2026-11-21 用户确认：是否显示所有角色的幻化外观，要到主城幻化师处对话开启或关闭，不是游戏设置，插件无法代为切换。原「幻化显示偏好」一节（状态显示、快捷切换、场景偏好）整体移出本插件，T4 取消。关闭幻化显示时外观仍会继续收集，收藏功能不受影响。 [暴雪无限服幻化说明](https://wow.blizzard.cn/news/24303313/index.html)

**原生界面的无限服改写**（`Blizzard_Collections/Camelot/Blizzard_Wardrobe.lua`）：

### 取证探针

只读探针 [`YiboTransmogForeverProbe`](../_NonRelease/YiboTransmogForeverProbe/README.md)（`/ytf`）已于 2026-11-21 联接到 Forever 正式客户端，只完成了离线检查，尚未实机运行。它不改筛选、不改外观方案或场景、不写 CVar，也不选择或交付任务。

- `/ytf scan`：身份、显示状态、筛选状态、各分类计数、套装概况。
- `/ytf item 物品ID或链接`：单件物品的外观、来源和同外观的其他来源。也可以先输入 `/ytf item `，再 Shift+点击物品插入链接。
- `/ytf cat 分类ID`：单个分类的外观数、已收集数和来源类型分布。1 头部、4 胸部、16 匕首、23 法杖、25 弓。
- `/ytf bags`：背包里的可装备物品。
- `/ytf quest`：读取已打开任务窗口的奖励；任务交付窗口打开时会自动采样。
- `/ytf verify`：核对最近交付的任务，判断每件奖励是否解锁。交付 3 秒后自动执行一次，之后可手动重复。
- `/ytf report`：复制最近一次样本的摘要。

完整数据在 `/reload` 或正常退出后写入 `WTF/Account/<账号>/SavedVariables/YiboTransmogForeverProbe.lua`。每项测试后把摘要贴回，或告知已退出、可以读取存档。探针是新增目录，第一次使用前需要完整退出游戏再进入。

### T0／T3 结果

2026-11-21，构建 `1.60.1.70959`，探针 0.1.1。角色天堂暴风（德鲁伊 11–12 级，泽风岛），客户端语言 zhCN。原始数据为探针存档样本 1–9。

**T3 任务奖励：已证实「未选也解锁」**

- `questApi` 行中 `GetNumQuestChoices`、`GetNumQuestRewards`、`GetQuestItemInfo`、`GetQuestItemLink`、`GetQuestReward`、`hooksecurefunc`、`C_Timer.After` 全部为 `function`。`GetQuestReward` 后置钩子正常记录到所选序号。
- 任务 92834「十倍奉还」，3 选 1，选第 1 项：

  | 奖励 | 本角色可用 | 交付前 | 交付后 | 结论 |
  | --- | --- | --- | --- | --- |
  | 1 殉道者的护甲（已选） | 是 | 未收集 | 已收集 | unlocked |
  | 2 悲伤腰带 | 是 | 未收集 | 已收集 | unlocked |
  | 3 悔恨苦修带（板甲） | 否，“你的职业无法使用此外观” | 未收集 | 已收集 | unlocked |

  - 汇总为 `unchosenUnlocked 2 / 2`。三条 `TRANSMOG_COLLECTION_SOURCE_ADDED` 在同一时刻到达，交付 3 秒后的核对与约 30 秒后的复核一致。
  - 补充样本：单奖励任务 92840「捕风」的弓（德鲁伊不能用）交付后同样解锁。
- **对状态模型的影响**：职业不能用的那件，交付后「此来源已收集」为 true，但 `appearanceIsCollected` 仍为 false。也就是说，`appearanceIsCollected` 是相对当前角色的判断，不能单独作为“账号已收集”。状态判断需要同时看来源级 `PlayerHasTransmogItemModifiedAppearance` 和外观级字段。

**T0 收藏基线：原生总数不能当分母**

- 头部（分类 1）：原生总数 247 个外观，本角色已收集 3 个。247 个外观共 354 个来源，按来源类型分布为：商人 134、不可收集 122、任务 67、世界掉落 28，另有 3 个类型未知。
- 缺失样本里有大量本服现阶段拿不到的物品，例如安其拉、纳克萨玛斯和 PvP 军衔装备，还有新版本物品。所有缺失外观的 `minIlvl` 都是 2147483647。
- 其他分类的规模类似，例如胸部 443、脚部 374，所以原生总数会让进度长期停在个位百分比。
- **套装**：`GetAllSets` 只返回 1 套，是收集前隐藏的「绿色蜷鳍鱼人连体衣」，`GetFullBaseSetsCounts` 为 0 / 0。无限服目前实际没有套装数据，首版不做套装进度。
- **分类名**：`GetCategoryInfo` 只对部分武器分类返回名称，护甲部位返回 nil。分类名称要用插件自己的本地化文本。
- **物品名**：未缓存的物品返回的名称为空。列出缺失外观时需要先请求物品数据，等加载完成再刷新。
- **头部数量（已核对）**：用户原生界面头部实际为 2（先前的 12 是输入笔误）。探针读到 3，多出的一个是隐藏头盔外观（物品 134110，`isHideVisual`），任务 92834 的奖励是胸甲和腰带，不影响头部。实现时已收集数要排除隐藏外观，才能与原生界面一致。

**显示状态（T0 顺带采集，仅备查）**：`IsTransmogEnabled` 为 true；体验预设为增强（1）。原生场景外观已启用，有「地点」「移动」「天气」「当日时间」4 类，当前 2 套方案，上限 50。T4 已取消，见「幻化显示（不在本插件范围）」。

### T1／T2 结果

2026-11-22，客户端已更新到构建 `1.60.1.71037`，探针 0.1.1，同一角色（德鲁伊 13 级，泽风岛）。原始数据为探针存档样本 34–45。用户正常做任务、打怪时顺带完成，没有专门测试。

**T2 灰白拾取即解锁：已证实**

- 灰色「无力短剑」（物品 1413，来源类型 4 世界掉落）：拾取消息到达后 0.16 秒，就收到 `TRANSMOG_COLLECTION_SOURCE_ADDED`。
- 物品仍在背包里，没有装备，也没有绑定（`bind 0`），而且德鲁伊职业不能使用它，外观照样解锁。

**T1 物品状态：已覆盖**

- 背包 6 件可装备物品读取正常：绿装、灰装、白装都能拿到外观 ID 和来源状态。
- 鱼竿、剥皮小刀、戒指没有外观 ID，属于正常情况，提示时应显示为“无外观”，不要显示成“未收集”。
- 「同外观已拥有、此来源未收集」的样本是任务奖励「至高皮靴」：它的另一个来源 301099 已收集，但交付前 `appearanceIsCollected` 仍为 false。
- **对状态模型的结论**：`appearanceIsCollected` 是相对当前角色的判断，T3 中职业不能用的物品和这里的同外观样本都说明了这一点。账号级的「同外观已拥有」要遍历 `GetAllAppearanceSources`，只要任一来源 `PlayerHasTransmogItemModifiedAppearance` 为 true 即成立；外观级字段只用于说明当前角色能否使用。

**T3 补充**：任务 93835「直面洛苏娜」4 选 1，选第 1 项，结果 `unchosenUnlocked 3 / 3`，包括德鲁伊不能用的双手剑。另一个任务 92640 交付时，同一时刻解锁了 3 件外观，所选的是「守望者的法衣」，但它的奖励样本被 12 个样本上限挤掉了。

**探针 0.1.2**：没有物品奖励的任务不再自动采样，样本上限从 12 提高到 24。

## 代码结构与加载链

即使首发只有 Forever，也按多目标架构组织：共享逻辑放 `Common/`，客户端专用的接口、事件、规则和静态目录放 `Forever/`。日后接入 Mists 或 Retail 时，只新增目标目录和目标清单，不复制共享实现。 [TOC 与运行入口规范 2.1 节](../Docs/多版本目标与发行标识规范.md#21-多目标-toc-与运行入口规则2026-10-26) · [多版本开发规则](../Docs/多版本开发规则.md)

```text
YiboTransmog/
  YiboTransmog.toc            缺目标提示：只加载 Common/TocHint.lua，不声明存档、不初始化
  YiboTransmog_Forever.toc    Forever 目标清单，列出共享文件与 Forever 文件
  Common/
    TocHint.lua               缺目标提示（与 Core 和其他插件的 TocHint 同模式）
    Namespace.lua             插件表、常量、打印与文本取用
    Status.lua                外观状态模型：外观未收集／同外观已拥有／此来源已收集／未知
    Progress.lua              分类已收集数汇总（排除隐藏外观，不计总数）
    Tracking.lua              追踪清单：单件外观目标与完成迁移
    QuestRewards.lua          按任务汇总新增外观
    Store.lua                 存档初始化、schema 校验与迁移，存档名由目标声明
    AccountPage.lua           Core 账号页注册与布局
    Settings.lua              业务设置分区与数据缓存分区
  Forever/
    Target.lua                目标身份、存档名、能力表，最先加载
    Collection.lua            C_TransmogCollection／C_TransmogSets 适配，输出稳定结构
    Sources.lua               来源类型映射、副本掉落读取
    Rules.lua                 本服规则：灰白拾取解锁、60 级等级限制、副本绑定差异
    Bootstrap.lua             身份与 Core 校验、单次初始化、事件注册、Slash 命令
  Locales/  zhCN.lua  enUS.lua
  Media/  Docs/
```

**共享与目标的契约**：`Common/` 只调用目标适配层提供的稳定方法，不直接调用 `C_Transmog*`。最小方法集在实现时按实际需要定稿：
- 物品查外观与来源；
- 来源状态；
- 外观的全部来源；
- 分类列表与计数；
- 套装列表与成员；
- 来源的获取位置；
- 显示状态。

适配层读不到数据时返回明确的未知状态，不返回 0 或 false。

**目标清单要点**：

| 项 | 取值 |

| `## Interface` | `16001`（默认提示清单为 `16001`，日后增加目标时同步） |
| `## Title` | `\|cff20e070[Yibo]\|r YiboTransmog - Transmog Collection`；`Title-zhCN`／`Title-zhTW` 为 `\|cff20e070[Yibo]\|r 幻化助手` |

| Slash 命令 | `/ytm`（2026-11-21 全工作区搜索未被占用，实现时登记到命令清单） |

**初始化顺序**：
1. `Forever/Target.lua` 先校验 `WOW_PROJECT_ID == WOW_PROJECT_CAMELOT`，不匹配就停止，不写库；
2. 检查 Core 已就绪、API 不低于 13，并检查所需能力，能力清单参照 `YiboReputation` 的 Forever 入口在实现时确定；不满足时提示升级 Core 并停止；
3. 再初始化存档，注册账号页、设置、角色清理、入口和事件。

`ADDON_LOADED` 与 `CORE_READY` 都可能触发初始化，必须只生效一次。 [Reputation Forever 入口](../YiboReputation/Forever/Bootstrap.lua)

**覆盖更新**：首发没有旧包，干净安装即首个起点。日后新增目标或改动文件布局时，按规范核对旧 TOC、XML 与间接引用残留。

## Core 接入与数据归属

- **复用 Core**：账号页、统一设置工作台、角色 GUID 与短名、Broker／小地图入口、双语资源（`Core.Locale:Get`，owner 为 `YiboTransmog`）。不自建窗口壳、设置窗口或入口。 [Core 业务页面与入口](../YiboCore/Docs/API-v5-业务插件接入指南.md) · [Core 统一设置](../YiboCore/Docs/API-v6-业务插件增量接入指南.md) · [Core 角色身份](../YiboCore/Docs/API-v11-轻量角色身份.md) · [Core 语言服务](../YiboCore/Docs/API-v13-语言服务.md)
- **收藏状态以原生为准**：外观收藏是账号级数据，每次从原生接口读取，不在存档里另存一份作为权威数据。
- **插件自己保存**：
  - 追踪清单；
  - 业务设置；
  - 各角色用于适用性判断的事实（职业、等级、护甲类型），按 Core 角色 ID 关联；
  - 可重建的派生缓存，标注来源与采集时间。
- **未知状态**：角色未登录采集、物品未缓存、接口不可用时，明确显示「未知」或「未采集」，不当成未收集。
- **悬停摘要**：Broker 与小地图悬停按规范复用账号页快照。悬停默认列在实现时按「收藏进度、追踪剩余」确定，记录在实施方案中。
- **跨插件**：暂无消费方，不定义公开能力契约。Tooltip 协调见上文「物品与奖励提示」。
