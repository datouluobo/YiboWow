# YiboVault 更新日志

## 1.2.4-api1（MoP 发布候选，2026-10-25，未发布）

- 背包和个人银行按通用／专用包分类显示空位，顶部明确总空位；修复空草药包类型识别及银行袋子卸下、装回时的自动刷新。
- 按客户端职责拆分采集与初始化加载链；覆盖旧版后保留的旧采集文件不再执行，角色数据、设置与 SavedVariables 身份不变。
- 入口及插件列表使用现行统一图标；修正设置内容高度上报不足，避免底部缓存操作被内容区裁切。
- 设置页的物品过滤与取消过滤操作复用 Core 统一按钮样式。
- 对外 Items API 保持 v1，最低 Core API13 与所需公共能力不变。MoP 离线检查及客户端剩余验收见发布前检查记录；不据本候选扩大 Forever 支持声明。

## 1.2.3-api1（2026-10-13）

- Tooltip 的邮件在途数量改用专用翼信图标；图标与数量对齐显示，不再重复显示“在途”文字。


## 1.2.2-api1（2026-10-12）

- 消费 Mail 变更通知的可选 `transfersUnchanged` 提示，纯邮箱状态或已读变化仅刷新对应角色，减少批量取件期间的全账号重复查询；真实邮件数据变化、提示缺失或插件生命周期变化仍刷新所有可能受影响角色。
- 保持 mail.items v1.0／v1.1 可选发现与旧提供方兼容；状态优化、混合批次、在途核实和缺失／不兼容／晚注册接口回归通过，客户端待验收。
- 打包脚本统一生成 CurseForge／GitHub 双渠道名称，两个包完整生成后再将旧版本移入 Builds/Archive，保留旧包与失败回滚能力。

## 1.2.1-api1（2026-10-12）

- 安装提供 `mail.items` v1.1 的 YiboMail 时，将可解析到账号角色的成功发件历史投影为收件角色的“在途”邮件物品；匹配收件确认或寄件角色收到的退回邮件后移除在途状态。
- 在途数量单独显示，不计入已持有总量；仓储邮件区域显示在途标记，查询 API 将其放在 `transitRecords`，并通过 `totals.inTransitQuantity` 汇总。
- Mail 未安装或仅提供 v1.0 时，Vault 继续按实际扫描快照工作；不读取 Mail 私有表。

## 1.2.0-api1（2026-10-12）

- 最低 Core API 提高到 13；初始化检查语言、业务 Service、公共名称、输入、物品解析、角色身份与 `account-entry:2` 能力及所需方法。能力缺失时 Vault 停止初始化并提示升级；库存目标增强单独检查 `business-item-actions:1`，不可用时不影响基础 Vault。
- Vault 的页面、设置、Tooltip、状态与错误文本接入 `localization:1`；仓储角色标签与 Tooltip 角色名使用 Core 公共格式化，过滤输入使用 Core 公共输入控件，物品格继续复用 ItemResolver。
- 账号入口声明三个默认关闭通道；账号页面及业务设置继续由 Core 统一框架管理。`vault.items` / `mail.items` 契约与 SavedVariables 所有权未改变。
- 静态语言检查：0 硬编码候选、0 缺失英文、0 未知 key、0 格式参数差异。中英文客户端及入口交互仍待验收。

### AH 上架时效扣减

- 保存本人拍卖的首次观测时间与剩余时间档位上界；服务端时间达到保守到期点后自动从 AH 库存快照移除，并发送既有库存变更通知。
- 仅解决超时后不再计入 AH 数量；不判断售出、退回或其它消失原因。缺少稳定拍卖 ID、服务端时间或时间档位 API 时不自动扣减。

### 库存数量目标

- 物品可添加角色或明确账号范围的数量目标，统计范围支持背包、银行、装备、邮件及这些个人来源合计。
- 公会银行与拍卖上架不纳入本轮个人持有目标；来源未完整扫描时保持待确认。需要 Core API v13 / `business-item-actions:1` 和兼容 TaskHub，客户端待验收。

## 1.1.1-api1（2026-10-09）

- 需要 YiboCore API v9、business-services:1（正式渠道包使用 Core 1.9.0 或更新版本）；经 Core 发现 mail.items，并注册 vault.items 供可选消费方查询。
- Mail 注册后不再在等待／错误路径启动第二套采集；缺失、不兼容、注销时保持独立基础采集。
- 邮件历史及刷新失败后的成功快照继续显示数量，真正未知的来源保留未知，部分可见邮箱保留下限提示。
- 装备事件限定玩家并合并采集；格子物品信息复用 Core 加载。
- 本人拍卖按数量与逐条接口采集，避免批量接口返回空列表导致缺失；首次扫描后的上架、取消等更新继续刷新快照。
- 统一全部库存来源的历史缓存显示：背包、装备、银行、邮件、本人拍卖和公会银行成功快照在登录、重载及刷新失败后继续显示数量并计入合计；未知来源保留 `~`，部分邮箱以 `+` 表示下限。


## 1.1.0-api1

- 新增物品 Tooltip 总开关与服务器范围设置，优化账号库存摘要排版与来源状态展示。
- 新增公会缓存列表、查看、隐藏/恢复和带二次确认的删除操作；隐藏公会仍继续采集，并可在 Vault 中主动查询。
- 改进公会银行缓存、物品查询与库存变更刷新；正常扫描不再向聊天窗口发送通告。
- 保持 `Items` Public API v1，未改变 API 版本。

## 1.0.0-api1

- 发布账号物品仓库：角色背包、装备、个人银行、邮件附件、本人拍卖上架，以及按公会页签缓存的公会银行。
- 在 Core 统一账号页提供角色与公会浏览、物品搜索、容量与空位摘要；原生物品 Tooltip 显示账号库存来源。
- 冻结 `Items` Public API v1：按范围查询物品与扫描状态、读取容量摘要、批量读取个人背包/银行/装备计数，并订阅快照变更事件。
- YiboCurrency 可选使用 Vault 的缓存统计跨角色物品代币；未安装 Currency 不影响 Vault。
- 大量邮件仅能统计客户端当前可见部分时保留部分扫描状态，不把未显示邮件推断为零。
