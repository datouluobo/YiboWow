# YiboVault 更新日志

## 1.1.1-api1（2026-10-09）

- 需要 YiboCore API v9、business-services:1（正式渠道包使用 Core 1.9.0 或更新版本）；经 Core 发现 mail.items，并注册 vault.items 供可选消费方查询。
- Mail 注册后不再在等待／错误路径启动第二套采集；缺失、不兼容、注销时保持独立基础采集。
- 邮件历史及刷新失败后的成功快照继续显示数量，真正未知的来源保留未知，部分可见邮箱保留下限提示。
- 装备事件限定玩家并合并采集；格子物品信息复用 Core 加载。
- 本人拍卖按数量与逐条接口采集，避免批量接口返回空列表导致缺失；首次扫描后的上架、取消等更新继续刷新快照。
- 统一全部库存来源的历史缓存显示：背包、装备、银行、邮件、本人拍卖和公会银行成功快照在登录、重载及刷新失败后继续显示数量并计入合计；未知来源保留 `~`，部分邮箱以 `+` 表示下限。


## 1.1.0-api1

- 新增物品 Tooltip 总开关与服务器范围设置，优化账号库存摘要排版与来源状态展示。
- 新增公会缓存列表、查看、隐藏/恢复和带二次确认的删除操作；隐藏公会仍继续采集，并可在 Vault 中主动查询。
- 改进公会银行缓存、物品查询与库存变更刷新；正常扫描不再向聊天窗口发送通告。
- 保持 `Items` Public API v1，未改变 API 版本。

## 1.0.0-api1

- 发布账号物品仓库：角色背包、装备、个人银行、邮件附件、本人拍卖上架，以及按公会页签缓存的公会银行。
- 在 Core 统一账号页提供角色与公会浏览、物品搜索、容量与空位摘要；原生物品 Tooltip 显示账号库存来源。
- 冻结 `Items` Public API v1：按范围查询物品与扫描状态、读取容量摘要、批量读取个人背包/银行/装备计数，并订阅快照变更事件。
- YiboCurrency 可选使用 Vault 的缓存统计跨角色物品代币；未安装 Currency 不影响 Vault。
- 大量邮件仅能统计客户端当前可见部分时保留部分扫描状态，不把未显示邮件推断为零。
