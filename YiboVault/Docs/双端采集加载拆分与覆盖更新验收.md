## 职责与加载边界

| 文件 | 职责／加载目标 |
| --- | --- |
| `Common/ItemRecords.lua` | 原物品记录构造、完整链接变体键；两端加载 |
| `Common/Collector.lua` | 通用采集错误覆盖状态；两端加载 |
| `Common/CoreIntegration.lua` | Core 最低能力检查、页面／服务／清理注册；两端加载 |
| `Mists/Store.lua` | 原 MoP 数据库初始化与过期状态处理；仅 MoP 加载 |
| `Mists/Collector.lua` | 原 MoP 背包／银行／装备采集与事件处理；仅 MoP 加载 |
| `Forever/Collector.lua` | 无限服目标采集、保存与事件处理；仅 Forever 加载 |

两份 TOC 都不再引用根目录 `Collector.lua`。仓库保留该历史路径的说明文件，不含运行定义；新目标载荷不携带此文件。覆盖用户旧安装后，磁盘上的旧实现仍可存在，但新 TOC 不选择它。无限端不再先定义 MoP 方法再覆盖，不再拥有 `ScanBag`、`ScanBankContainer` 两个 MoP 专用方法。

未涉及的根目录旧业务模块保留迁移库存；本批不扩大到启动壳、所有业务目录或其它插件。插件技术名、安装目录、SavedVariables 表名与 schema 均保持原样：MoP `YiboVaultDB`、Forever `YiboVaultForeverDB`，仍各自 schema 1。未读取或修改玩家实际 WTF。

## Core 公共能力核对

- CAP-003：迁移范围内，MoP 原生容器返回值缺少 itemID 时，通过 Core `ItemResolver:Parse` 解析物品链接；初始化显式检查 Parse 方法。继续使用 API13／`item-resolver:1`，该方法属于已有契约，无新增 Core 能力。原始完整链接负载提取仅用于保留业务 `variantKey`，Core 候选解析不提供该无损键，故继续由 Vault 记录格式负责；它不接受玩家输入、不执行物品选择，也不是并行物品 ID 解析回退。
- CAP-007：迁移采集器和通用错误状态中仅取身份的四处调用使用 `Characters:GetCurrent({ identityOnly = true })`；沿用 `character-identity:1`，缺失能力／方法停止依赖初始化。角色完整档案不再为这些调用构建。
- 原有页面、名称、语言、服务和清理注册仍通过原 Core 接口，契约、所有权和所需版本未变。剩余未触及调用不视为本批已审查。无新增玩家可见文本或 Slash 命令。
