# YiboVault 仓储视图与物品悬停规则

> 仓储页布局依据：[定稿概念图](../Media/YiboVault-Storage-Tooltip-Concept.png)。仓储页与容量展示已获用户确认；物品 Tooltip 的基本显示与数量汇总已有客户端截图验证。下述 Tooltip 排版和设置规则已实现并通过本地 Lua 检查，尚待客户端复核。

## 仓储视图

- 沿用 Core 的窗口壳、页面导航、服务器/角色范围和排序。Vault 只有一个固定仓储页面，搜索框位于右侧内容区顶部；左侧角色列表占满内容高度。
- 左栏先列出每个已有快照公会的一个公会条目，再紧凑列出当前 Core 范围内的角色；不为公会银行页签重复创建左栏行。角色行显示职业着色的名称和服务器，当前登录角色以行尾色块标识，选中态独立显示。搜索时左栏只保留持有匹配物品的对象，右侧只显示所选对象的匹配格子。搜索框在有内容时显示清空按钮；清空后恢复先前选中的对象与储存区。
- 右栏上方显示角色身份，以及分开的随身背包与个人银行空位/总格数。可识别的包名与大小作为组成摘要；公会页签显示自己的容量，不并入角色个人容量。
- 角色详情固定显示“背包、邮件、个人银行、拍卖、装备”五个标签；公会详情固定显示 1–8 页的八个页签按钮，已扫描页使用真实名称。未扫描标签置灰且不可点击，已扫描空页仍可查看。任一视图的标签行保持同一总宽度，按钮按数量等宽平分。背包与银行把各容器合并到同一格子网格，仍保留每条物品记录自己的数量；普通浏览时装备保留槽位顺序，搜索时匹配项紧凑排列。
- 背包、个人银行与公会银行的已知空位合并为一个格子，格子底部显示空位数量；没有可靠空位数据时只显示有物品的格子。装备栏保留槽位顺序。物品格保留自绘品质边框，并裁掉图标贴图边缘，避免双层边框；装备在左下角以淡紫色显示可读取的装等，其它物品在右下角以白色显示堆叠数量，包括单件。物品格按可用宽度换行，列间距随宽度调整以利用右侧空间；内容超出时在右侧区域纵向滚动。
- 当前角色或公会来源为历史快照时，标题标记“上次缓存”；所有角色的最近记录正常展示。不为未采集位置生成零库存。

## 物品 Tooltip

### 范围与数据口径

- 在原生物品 Tooltip 下方追加 Vault 摘要，复用 `Items:Query`、Core 的角色准入与排序；不建立第二份物品缓存或独立悬停窗口。物品格子悬停使用同一扩展内容。
- Vault 业务设置提供物品 Tooltip 的服务器范围选项：`当前服务器`（默认）、`所有服务器`。前者指当前登录角色所在服务器；后者包含 Core 准入的各服务器角色及对应公会。这个选项独立于仓储主页面的 Core 范围切换，不改变主页面当前选择。
- 顶部仅显示 `|cff20e070[Yibo]|r 账号库存` 和该范围内缓存数量合计。合计包含下方列出的角色来源与已成功扫描的公会共享来源，同一公会只计一次。成功保存过的历史快照继续计入，不要求本次登录重新扫描；刷新失败也保留上次成功数量。没有可用快照的来源保持未知；存在未知来源或部分邮箱时合计数字后加 `+` 表示下限，没有任何可用数量时显示 `~`。没有该物品记录的角色和没有可显示页签的公会不显示。

### 持有者行

- 角色行左侧为角色名，右侧为该角色总数及方括号中的来源明细：`角色名    总数[背包图标数量/邮箱图标数量/银行图标数量/装备图标数量/AH图标数量]`。来源固定按 **背包、邮箱、银行、装备、AH** 排列，当前与离线角色遵守相同缓存口径；只显示该物品数量大于零的项。成功快照显示具体数量；有记录但没有成功快照证据的来源显示 `图标~`。没有该物品记录的来源省略，物品转入背包不会让其它来源凭空出现 `~`。行总数只累计方括号内可见数字；存在未知来源或部分邮箱时总数后加 `+`，没有可用数量时显示 `~`。
- 角色名使用职业色；总数和各来源数量统一使用品牌青绿色 `20e070`。来源用可辨认的小图标表达，分隔符与状态说明使用弱化文本色。`当前服务器`范围下使用角色短名；`所有服务器`范围下当前服务器角色仍用短名，其它服务器角色统一显示为`角色名-服务器名`。
- 公会共享库存列在角色之后，每个公会一行。左侧在 `所有服务器` 范围下为 `公会名-服务器名`，在 `当前服务器` 范围下为公会名；右侧为公会总数及页签明细：`公会名-服务器名    总数[P1·材料 20/P2·消耗品 8/…]`。每个明细固定为 `P页码·标签页名称 数量`，按页签编号升序，使用成功扫描时保存的真实名称；旧记录没有可读取名称时写 `未命名`。显示成功扫描且该物品数量大于零的页签，包括历史缓存及刷新失败后保留的成功快照；从未成功扫描的页签省略。没有可显示页签时省略整条公会行。
- 优先保持一名持有者及其总数在同一行。明细超过可用宽度时，整组换至下一行；页签标签、来源图标与其数量始终成组显示，不裁切数字或依赖横向滚动。

### 状态与长度

- 背包、装备、个人银行、邮件、本人拍卖及公会银行统一展示最近成功缓存数量；历史状态和最新扫描失败状态继续保留在查询覆盖信息与主窗口中，不将缓存状态伪装成实时结果。登录、重载和窗口关闭不要求刷新所有角色。真正没有可用快照时保持未知；部分邮箱保留已扫描数量并在角色与账号合计后标 `+`，不推算未显示附件。悬停中不使用独立刷新状态文字。已显示的物品悬停在相关库存修订后重新取数，公会银行当前页签变动也要在全页签扫描期间刷新。
- 按屏幕安全高度收起角色与公会行，角色最多显示 20 名。未展示的持有者分别提示剩余角色或公会数量；合计始终覆盖所选范围内全部已记录持有者。
- 同一物品 Tooltip 刷新不重复追加摘要。现有基本显示与数量汇总已有客户端截图验证；新排版、范围选项、跨服角色后缀及重复悬停生命周期仍需客户端复核。

### 设置入口

- Core 统一设置工作台中的 Vault 业务设置只保留一个`物品总览`导航项，容纳 Tooltip 服务器范围与 Vault 适用的业务、数据设置。Vault 账号页面与业务设置使用同一设置导航目标；通用页面、入口、字段和角色排序仍由 Core 管理。

## Vault 设置与公会缓存管理

- `业务设置`保留物品 Tooltip 的服务器范围，并增加默认开启的 Vault 摘要总开关。关闭后，普通物品与 Vault 物品格的原生 Tooltip 仍可使用，但不追加 Vault 账号库存区块；采集、公共查询和仓储页不受影响。
- `数据与缓存`列出 Vault 实际保存的所有公会快照，按公会名和服务器区分，包括当前 Core 角色目录无法关联的历史记录。每行左侧显示公会身份，右侧依次提供`查看`、`隐藏／恢复`和危险样式的`删除缓存`；较窄宽度下，公会身份移到同一行按钮组上方。点击删除后仍需二次确认。列表最多显示四行，数量与分页紧随列表，分区高度按当页行数收紧。角色缓存仍在 Core 的`角色与排序`中删除。
- 隐藏只作用于选定公会的共享银行快照，不改变该公会成员或其他角色的个人背包、装备、银行、邮件与拍卖数据；不据此推断公会成员构成或所有权。隐藏后继续正常采集并保留快照，但默认仓储列表、物品 Tooltip、公共查询、来源状态与容量汇总均不包含该公会。
- 仓储页提供临时的`显示隐藏公会`开关。开启后，左侧列表和全局物品搜索可显示隐藏公会，并明确标记`已隐藏`；这些物品仍不进入默认账号合计。用户主动浏览隐藏公会的物品格时，Vault Tooltip 可追加该公会的来源明细，并标明它未计入账号合计。
- 公共 API 的显式查询可以读取隐藏公会；默认查询继续排除。无法关联当前角色的历史快照只通过设置页主动打开，默认范围搜索与统计不纳入。
- `删除缓存`删除该公会所有已保存页签、物品与容量快照，并清除隐藏状态；再次访问公会银行时可重新采集。该操作位于对应公会行的最右侧，确认框说明删除范围和不可撤销性。隐藏/恢复和删除后及时刷新仓储页、Tooltip 与查询订阅者。

## 验收边界

- 仓储页与容量展示已获用户确认；容量只使用可读取的客户端快照，不可读取时省略，不能据此推断空位。
- `storage.summary` 公共能力已声明；调用方先检查能力，再按 [API v1 契约](../../Docs/YiboVault-Mail-API-v1-契约.md) 读取容量摘要。
- 邮件附件在打开邮箱并成功扫描后显示；可见邮件少于总数时标明仅统计当前可见邮件，不推算未显示邮件的附件。
