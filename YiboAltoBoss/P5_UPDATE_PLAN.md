# P5（8 月 6 日）更新方案

## 目标

在 P5 开放当天，让玩家能在现有总览中可靠地看到永恒岛新增世界 Boss 的跨角色周常击杀和最近位面信息；不因未确认的测试服数据而产生错误击杀记录。

## 范围与确认门

按 5.4 永恒岛内容预案，候选目标是四天神与奥尔多斯。四天神的**普通掉落资格共享为每角色每周一次**：当周首次击杀任意一位天神才有普通个人拾取机会；奥尔多斯为独立周常拾取。正式服仍以首个可交互单位的 GUID、击杀任务状态和游戏内名称为准。若 8 月 6 日仅开放其中一部分，只启用已确认项目，剩余项目保持关闭，等待实际开放。

| 候选目标 | NPC ID（待正式服复核） | 处理方式 | 上线条件 |
| --- | ---: | --- | --- |
| 玄牛砮皂 | 71954 | 归入“天神（共享周常拾取）” | 可目标、战斗日志 ID 与共享周常锁定一致 |
| 青龙玉珑 | 71953 | 同上 | 同上 |
| 朱鹤赤精 | 71955 | 同上 | 同上 |
| 白虎雪怒 | 71952 | 同上 | 同上 |
| 奥尔多斯 | 72057 | 独立周常 Boss 行 | 实际可进入/可击杀，并确认独立锁定方式 |

因此主面板保留四位天神各自的 Boss 行，但不新增共享状态行。每个角色格使用三态，既保留实际击杀信息，也准确表达共享掉落资格：

| 格子文案 | 含义 | 视觉语义 |
| --- | --- | --- |
| `未击杀` | 本周未击杀该天神，且仍有天神普通拾取资格 | 现有深灰未完成状态 |
| `已击杀` | 本周实际击杀过该天神 | 现有绿色完成状态 |
| `无拾取` | 本周未击杀该天神，但已由另一位天神消耗普通拾取资格 | 低饱和棕灰；不使用完成绿 |

当某角色击杀玉珑时：玉珑显示 `已击杀`，砮皂、赤精、雪怒显示 `无拾取`。`无拾取` 悬停提示应说明“本周已击杀玉珑，天神普通拾取资格已用；仍可参与击杀”。这样主面板不增加任何行，且不会把未实际击杀的 Boss 误写成“已击杀”。若需要服务传说任务，可另存四位天神的历史击杀进度，但不把它混同为周常掉落状态。额外掷骰/徽记的规则须首日单独验证，不能用普通拾取状态推断。

## 实现安排

### 1. 数据层（P5-1）

- 在 `Core.lua` 的 `DEFAULT_BOSSES` 中加入四位独立天神目标及奥尔多斯，归入 `world_boss`，`reset = "weekly"`，排在现有四个世界 Boss 后；四位天神另以 `lootLockoutGroup = "celestials"` 关联共享的普通拾取资格。
- 仅在正式服确认后补入 `WORLD_BOSS_QUEST_IDS`。战斗日志 `UNIT_DIED` / `PARTY_KILL` 应始终可记击杀；任务 ID 只作为重登、跨角色检查的兜底，不能猜填。
- 每位天神保持独立 `key`（如 `celestial_yulon`），以正确记录击杀、位面与刷新；另保存共享锁定组的“首次击杀 Boss / 周重置键”。界面根据该共享锁定组把其余未击杀天神渲染为 `无拾取`。现有 `npcTargets`、GUID 位面提取、周重置和存档迁移可以复用；若要保存传说任务进度，再新增非周常的历史字段。
- 若首日发现同一 NPC ID 在不同场景含义不一致，再增加区域白名单；未发生前不预设限制，以免在“永恒岛”本地化名差异下漏记。

### 2. 界面与配置（P5-2）

- 新 Boss 自动出现在“世界 Boss”区；天神保持四行，不额外增加共享状态行。现有按角色击杀格、位面汇总和 Shift 全服务器视图均应覆盖。
- 首发默认开启；通过现有显示项开关让不参与 P5 的玩家可隐藏它们。
- 版本号升至 `1.5.0`；更新 README 与 CurseForge 文案，明确新增永恒岛周常追踪。

### 3. 首日观测与校准（P5-3）

- 在一个未击杀角色上依次记录：目标 GUID、NPC ID、区域/子区域、战斗日志事件、击杀前后任务状态，以及界面三态。首次击杀一位天神后，该行必须为 `已击杀`，另三行必须为 `无拾取`。
- 退出并重登，验证任务状态能够恢复本周“已击杀”；切换第二个角色，验证角色锁定互不污染。
- 对至少两个位面完成目标观测，检查位面 ID、显示列、6 小时 TTL 和击杀归属是否正确。
- 若奥尔多斯受传说披风/进入条件限制，分别验证“无法接近”和“可击杀”角色；前者不能错误写入击杀。

## 验收标准

- 每个角色每周只有一次“天神”普通掉落资格：首杀天神显示 `已击杀`，其余未杀天神显示 `无拾取`；奥尔多斯独立显示一次，二者不能互相锁定。
- 击杀可由战斗日志即时写入，重登后可由已确认的任务状态正确恢复。
- 跨角色、跨服务器、同 NPC 不同位面数据互不串写。
- 未开放或未确认的候选 Boss 不会默认展示为可用追踪项，也不会写入错误任务锁定。

## 风险与回退

- **最大风险：任务 ID 或锁定规则与旧版本不同。** 首发不依赖未经实测的任务 ID；有问题时移除任务映射，保留可靠的战斗日志记录。
- **奥尔多斯访问条件。** 以实际可击杀性而非预期开放日期决定是否启用。
- **首日位面样本不足。** 位面功能沿用当前通用 GUID 逻辑；先监测、后针对性修复，不在 P5 中扩展复杂的跨玩家同步。
