# 副本目标列合并修复

当前补充：目标列继续按地图ID合并普通列，同时按规范难度归并目标列；已核实的Mists TBC旧3/4身份由同一来源解析为175/176。同角色多个目标使用首领集合并集，实际普通/英雄难度保持区分。投影实现位于Common/TargetProjection.lua，当前LockoutProjectionSpec为20项。详见[搜索与副本身份记录](../../Docs/行动中心-搜索焦点与副本身份一致性.md)。以下保留初次修复的范围与证据。

日期：2026-10-18。状态：代码与模拟验证已完成，客户端待验。

## 原因与行为

`TargetProjection.lua` 原先把行动中心的难度目标列直接追加在普通副本列前面。同一地图因此可能同时出现 `SWP·25人` 与 `SWP`，且只有前者包含目标角色的进度。此问题无需历史数据即可复现。

现在按副本地图 ID 合并两路展示，目标列仍按目标目录 ID 与难度 ID 去重。已存在目标列的副本不再追加普通列；不同目标难度保留各自的列。角色有对应目标时继续显示目标判断，无对应目标时，在该副本原本属于本次主表或悬停列集合的前提下显示同难度普通锁定及详情。仅因目标进入悬停的列继续遵守原有角色准入规则。目标自动展示关闭、来源缺失或目标停用后，普通副本列自然恢复。

合并发生在显示投影中，不迁移或清理 SavedVariables，不修改角色目标、击杀历史或业务快照。普通状态匹配新增可选难度过滤，未指定难度的旧调用保持原行为。

## Core 公共能力复核

本次仅修改 AltoBoss 内部列投影和锁定匹配。继续使用已有 Core 角色 ID 解析、业务契约消费与 owner 语言资源，最低 Core API13 要求不变。未新增跨插件直接访问或公共能力接入变化，迁移台账无需更新。
