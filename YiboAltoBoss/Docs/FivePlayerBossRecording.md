## 实机依据与范围

## 采集与数据

- 原生 ENCOUNTER_END 成功与 BOSS_KILL 继续记录；party、最多五人的实例中按需订阅 COMBAT_LOG_EVENT_UNFILTERED，仅处理 UNIT_DIED。
- Creature GUID 提取 NPC ID，必须命中 DungeonBossCatalog 的副本地图 ID / NPC ID。地图、难度与名称取当次 GetInstanceInfo / 战斗日志；不按显示名称保存业务身份。
- 目录中的 encounter ID 如能在当前客户端 TargetCatalog 的精确地图与难度目录内解析，优先使用该客户端结果。新增统计主键为 instance:<地图>:<难度>:encounter:<ID>；没有已核实 encounter ID 时使用 npc:<ID>。
- 统计保存在 YiboAltoBossDB.characters[charKey].statistics.bosses；包含 name、instanceName、instanceID（地图 ID）、difficultyID、encounterID/npcID、kills、firstAt、lastAt、lastSource。业务所有者仍为 AltoBoss。已有名称键的统计原位补齐元数据，保持累计值，不创建第二份统计。
- 五人本按本角色／地图／难度／本轮／遭遇去重，完成集合与轮次保存在 statistics.dungeonCycles，重载和离开再进入不清空。当前地图内 Creature GUID 的实例范围变化可确认新一轮；第一次绑定范围不重复开轮。成功重置系统消息按当前选择的五人本难度清空对应本轮集合并递增轮次（缺少难度 API 时仅普通难度），失败消息不改变；同一死亡 GUID 仍保留一小时防重复。已采集的英雄本锁定到期时间还可确认下一周期，失效规则直接来自本插件的游戏 API 快照。团本继续使用原有 60 秒去重，不读写五人本轮次。
- 重置与锁定刷新均不清除历史次数。普通本主表从本轮完成集合显示当前进度，悬停保留历史击杀、难度及最近时间；主表与入口投影复用同一状态及 Tooltip 生成器。历史不能用作周期锁定或当前实例的权威进度，TaskHub 的普通本自动周期追踪范围不变。
- 不从离线角色、尸体、空锁定快照补算过去的击杀；客户端未派发/玩家未收到的死亡事件没有历史追补保证。

## 目录来源和边界

DungeonBossCatalog.lua 保存 325 个 NPC 身份、70 个地图的数值事实。来源是本机 DBM-Dungeons r264 的副本分组、SetZone、SetCreatureID 与 SetEncounterID 中的游戏标识，源模块路径随条目保留以便审查。参考项目：[DBM-Dungeons](https://github.com/DeadlyBossMods/DBM-Dungeons)。仅整理数值事实，没有复制执行代码、计时、文案、贴图或控件；正式插件不加载、查询或依赖 DBM。

导入工具位于 _NonRelease/Tools/Import-DungeonBossFacts.py。它按 mists 客户端分支整理事实，剔除多 NPC、复杂死亡处理、特殊完成信号和已知投降遭遇；黑暗深渊、剃刀高地、剃刀沼泽使用 MoP 的原版 NPC。此目录不是全部五人本遭遇完成规则的声明。

多目标、假死、投降和护送等遭遇使用原生成功事件及下述可选 DBM 完成通知，不能把任意一个关联 NPC 死亡视为完成。代表性范围：青龙寺图书馆、魔古山宫殿国王试炼、通灵学院寒心/莉莉安、血色杜兰德/怀特迈恩、冠军试炼、影踪禅院投降首领、时光副本护送。未覆盖且不派发原生完成事件、也无可信 DBM 完成通知的遭遇，须另做实机采样并添加该遭遇明确的完成规则；不得猜测计数。

Encounter Journal 的 creature 条目 ID 与战斗 GUID 的 NPC ID 不应未经验证直接互换；本次不采用该推断构造 Boss 白名单。导入工具更新后必须复审数值事实与特殊遭遇，不能将单 NPC 配置等同于所有阶段均已验证。

## 五人本 DBM 可选补充（2026-10-14）

状态：运行代码与自动化已实施，真实 DBM／游戏客户端验收待完成。只适用 party 且人数上限为 1–5 的副本；团队副本没有 DBM 消费分支，其原生事件、锁定刷新与原有去重保持原行为。

需求是补齐假死、投降、护送等没有简单 NPC 死亡终点的遭遇。外部来源为 DBM 的公开 RegisterCallback / UnregisterCallback API：监听 DBM_Pull、DBM_Kill、DBM_Wipe 和 DBM_TestModStarted。当前兼容依据为本机 DBM-Core 与 DBM-Dungeons r264；以公开方法存在、回调参数类型与客户端目录解析结果检查兼容性。DBM 缺失、未启用、模块缺失、未开始对应追踪或参数无法解析，仅丢失相应补充，原生／单体死亡基础路径继续运行。TOC 不声明 DBM 的 RequiredDeps 或 OptionalDeps，不加载其 Lua、读取其 SavedVariables 或调用其内部判定方法。

DBM 回调提供的模块对象仅作为当前回调负载使用，读取 id / encounterId 两个身份字段；id 属于 DBM／Journal 模块命名空间，不直接当作 DungeonEncounterID。两者必须在当前客户端 TargetCatalog 的精确地图、难度和完整目录中唯一解析到稳定遭遇，显示名使用目录 API 原文。不按 DBM 模块名字硬编码业务分支。两字段指向不同遭遇、目录不完整或不支持该难度时忽略补充。

桥接事实为 Core.Events 上的 YIBOALTOBOSS_DUNGEON_COMPLETED，版本 1。发布方为 AltoBoss 的 DungeonDBM 适配器，消费方为 AltoBoss 五人本记录器；历史数据权威所有者是 AltoBoss。负载为 version=1、source=DBM、characterID（Core.Characters:GetCurrentID 的唯一角色标识）、mapID、difficultyID、run（本角色该地图／难度的轮次）、encounterID、name。使用 Core.Events:FireIsolated 复制负载，订阅方使用 Core.Events:Register/Unregister；不依赖广播顺序，不修改发布方快照。本适配要求已有 Core API13 / localization:1、events:1 与 character-identity:1，没有新增 Core 能力。

开战通知需对应本地五人本，且玩家或同队成员处于战斗；适配器保存该回调的角色／地图／难度及显式重置代次。击杀通知需匹配此前观察到的同一模块开战，角色／地图／难度及显式重置代次一致。进出世界清理未完成的回调上下文，灭团只清理开战状态；DBM 演示通知清理上下文并屏蔽后续 60 秒补充。战斗中首次识别新的实际实例范围可以重新绑定本轮，避免遗漏先于 GUID 到达的开战通知；显式重置后旧开战的延迟击杀被拒绝。

DBM_Kill 只表示一个遭遇完成，不代表整本完成；不据此推断未观察到的其他 Boss、整本进度或周期锁定。不持久化 DBM 模块对象。适配重复初始化不重复注册；DBM-Core 晚加载后通过 ADDON_LOADED 接入，Detach 注销公开回调，Shutdown 同时清理 Core 订阅与游戏事件。

所有来源最终进入同一 RecordEncounterKill；五人本本轮完成集合合并原生、死亡与 DBM 通知，超过原 60 秒窗口的延迟通知仍不重复计数。重置成功后新一轮可重新计数；单体死亡仍独立工作。客户端待验需覆盖有／无 DBM、禁用副本模块、复杂遭遇完成、重置后重打、重载后晚到通知与团本回归。

2026-10-14 自动化结果：InstanceKillsSpec 含真实日志回放共58项通过，覆盖 DBM 缺失／晚加载／接口不兼容／注册回滚、复杂遭遇、延迟重复、灭团、演示、跨角色／难度、世界切换、重置代次与实例范围、重载保存、英雄快照到期和团本隔离。BossGoalsSpec19项与CustomBossGoalsSpec25项通过。实际DBM联动与游戏客户端仍待验收。
