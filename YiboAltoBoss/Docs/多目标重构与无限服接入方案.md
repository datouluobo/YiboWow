# YiboAltoBoss 多目标重构与无限服接入方案

2026-11-20 · 分析与实施准备 · Mists 基线 2.8.6

沿用 YiboCurrency 的目标清单、独立存档和共享实现方式。先在 Mists 拆出世界 Boss、自定义目标和全量副本进度三块，保留现有功能，再让 Forever 复用后两块。Forever 首期可开始接入自定义目标管理和副本进度框架。自动采集按本服证据逐项启用，世界 Boss 及其节日、位面和刷新预测功能留在 Mists。

## 功能和代码归属

| 功能 | 现有实现与耦合 | 重构边界 |
| --- | --- | --- |
| 世界 Boss | `Core.lua` 内置潘达利亚首领、赞达拉战争使者、任务旗标、区域匹配和重置规则，与 `TrackingV3.lua`、`HolidayBoss.lua`、`Mists/Calendar.lua` 和 `AccountPage.lua` 的观察、位面和预测功能相连。`PlannedTargets.lua` 也内置同一批周常旗标。 | 目录、旗标、观察信号、位面语义、节日规则、预测与相关页面归 `Mists/`。现有 MoP 数据、配置、UI 和追踪热路径保留。可以独立复用的目录索引和击杀状态投影放 `Common/`。 |
| 自定义目标 | `Core.lua` 的 NPC ID 增删、用当前目标添加、个人击杀／手动记录、24 小时有效期和删除清理依赖世界 Boss 缓存、GUID 解析、位面观测与事件帧。`Settings.lua` 的管理区混用内置目录，`PlannedTargets.lua` 复用自定义击杀状态。 | `Common/` 管理自定义目录、稳定 `custom:<NPC ID>` 键、手动记录、有效期计算、设置和角色投影。目标层解析当前目标、采集击杀并提供适用策略。Mists 保留现有 24 小时个人记录与位面联动。Forever 可先提供空目录、按 ID 添加／删除、手动记录与账号显示。当前目标添加和自动记录按本服 NPC 身份及归因验证逐项开放。 |
| 全量副本进度 | `InstanceLockouts.lua` 同时做异步锁定扫描、目录、普通本进入次数、首领去重和页面状态。`DungeonRuns.lua` 管普通本轮次，`DungeonDBM.lua` 提供可选补采。`Common/RaidProgress.lua` 处理已配置团本目标的周期证据，并依赖 `PlannedTargets.lua`。`LockoutsPage.lua` 展示账号矩阵并合并选中的行动目标。 | `Common/` 复用副本快照读取、角色 × 副本与难度投影、悬停、详情以及有稳定输入的历史汇总。`Mists/` 和 `Forever/` 各自提供原生读取、事件、身份映射、目录、难度、去重与重置语义。矩阵以本端可识别目录及观察到的副本为来源，独立于行动中心的目标清单。 |

这里的「全量」指进度视图覆盖本端可识别的五人本和团本、各难度以及具备来源的首领进度。界面区分原生锁定、当前轮次与历史计数，显示已观察数据和未知范围。目录覆盖随本端证据扩充。行动中心只投影玩家选中的目标，继续复用同一业务快照。

## 文件拆分与调用方向

| 当前文件 | 实施时的切分点 |
| --- | --- |
| `Core.lua` | 拆出角色与存档访问、自定义目标和状态查询至 `Common/`。实际存档绑定、旧存档整理和启动编排随目标进入 `Mists/` 或 `Forever/`。Mists 的内置目录、位面、战斗／任务／节日监听单独保留。先拆依赖最少的自定义目录，保持现有 `YAB` 调用面以缩小首批 MoP 改动。 |
| `InstanceLockouts.lua`、`DungeonRuns.lua`、`DungeonBossCatalog.lua`、`DungeonDBM.lua` | 锁定请求与响应、字段解析、普通本轮次、进入限制、系统消息、DBM 和内置目录先收拢到 `Mists/`。从 `GetLockoutColumns`、`GetLockoutStatus` 和 `GetLockoutTooltip` 提取依赖快照的共享投影。`Mists/RaidCatalog.lua`、`Mists/RaidEvents.lua`、`Mists/TargetCatalogRuntime.lua` 已有明确目标归属。 |
| `Common/TargetCatalog.lua`、`Common/TargetProjection.lua`、`Common/RaidProgress.lua`、`PlannedTargets.lua`、`Common/GoalTargets.lua` | `Common/` 现有文件仍耦合 MoP 的世界／节日目录、旧角色键、日周重置与已配置目标。先拆目录输入和单项进度读取，再复用稳定的 ID、匹配与合列逻辑。留在 `Common/` 的代码通过本端存档和数据接口获取记录，MoP 旗标、特殊遭遇和周期规则留在 `Mists/`。已有 `boss.target-catalog`、`task.boss-targets`、`action.targets` 等契约沿用 Core 注册与发现，基本功能可以独立运行。 |
| `AccountPage.lua`、`LockoutsPage.lua`、`Settings.lua`、`CoreIntegration.lua`、`Commands.lua`、语言资源 | 共用副本矩阵、自定义目标设置、角色筛选、刷新与 Core 托管入口放 `Common/`。Mists 保留现有标签、偏好键、`alto-boss`／`alto-lockouts`、`yab` 入口和 `/yab`，目标专用子页及诊断随目标加载。Forever 的入口打开已启用的功能页，不显示世界 Boss 标签。共用文案继续使用插件 owner 的双语资源与稳定 ASCII key。 |

采集方向为「目标原生 API／事件 → 目标解释和归一 → AltoBoss 自有快照 → 共享投影 → Core 账号窗口和悬停」。副本数据至少带本端地图与难度身份、采样时间、来源、覆盖状态和已知的首领进度，已证实有过期时间的证据附带失效时间。未采集、读取失败、数据不全和确认无锁定分别表示。跨角色按 Core 角色 ID 关联，Mists 通过 Core 解析既有存档键。手动记录保留来源，展示与消费方可区分自动证据。原生名称用于展示，稳定业务 ID 用于关联与存档。

## Forever 首期

1. **自定义目标**先用本端独立目录接通设置、手动记录和同源悬停。记录显示其更新时间和手动来源。MoP 的 24 小时有效期可作为共享状态计算的现有用例，Forever 的有效期语义由本端显式选择。用当前 NPC 添加核对 `UnitGUID`／`UnitName` 的本服返回，自动击杀另外核对可用事件、当前角色归因与重复信号。位面、刷新预测和 MoP 静态 NPC 目录留待世界 Boss 范围确定后再评估。
2. **全量副本进度**先接共享矩阵与空／未知状态，制作本端副本适配层。`/yaf` 用一次自然副本流程采进入、首领前后、离开与原生锁定对照。先接经证实的进入身份和只读锁定，再增量接通首领、轮次、重置和历史。普通本无原生锁定时按实际采集结果显示，空列表无法推导全员或全首领未打。离线角色只显示已采快照及其时效。

当前可用取证工具是 `YiboAltoBossForeverProbe` 0.1.0，`/yaf`。仓库既有记录只确认部分 API 存在。本机现存探针存档有 4 次会话，未保存业务样本或事件。无须等副本样本才开始拆共享代码或实现手动目标。真实锁定字段、首领完成、有效重置与不同角色的表现按样本补齐。见 [Forever 副本取证记录](Forever-副本取证与适配准备.md)。

## 实施顺序与验收

1. **Mists 行为等价拆分。** 先拆目标身份及启动、世界 Boss 专用目录和规则，再拆自定义目标、锁定采集及投影。沿用 `YiboAltoBossDB`、现有字段和设置。先以真实加载链跑既有回归，再调整 Forever 功能。
2. **双目标加载。** 按规范 2.1 将源码默认 `YiboAltoBoss.toc` 改为缺目标提示，配置 `YiboAltoBoss_Mists.toc`（50504）与 `YiboAltoBoss_Forever.toc`（16001）。两个玩家包的实际加载名均为 `YiboAltoBoss.toc`，技术名、安装目录和 Core 依赖均为现用名称。Forever 新建独立 `YiboAltoBossForeverDB`。目标入口先检查实际项目身份，再检查 Core 就绪、API13 和所用能力版本，最后初始化存档并幂等注册事件、页面、入口和提供者。Forever 门槛按实际调用核对，Mists 的 `calendar-day-query:1` 随节日日历走。目标清单和构建配置在各自业务入口就绪时接入。见 [多目标规范](../../Docs/多版本目标与发行标识规范.md#21-多目标-toc-与运行入口规则2026-10-26)。
3. **候选验证。** 统一构建器与 MoP 整合包检查清单、Interface、引用、目标隔离及 ZIP 内容。核对旧默认 TOC 替换、残留 Lua 与间接引用，覆盖测试从 Mists 2.8.6 起保留旧文件，确认只执行新加载链并读回原存档。Forever 首发验证干净安装与独立存档。两个目标分别验证误目标停在写库前、Core 未就绪／能力不足、重复通知只初始化一次、重载和完整退出恢复。实机另对照可用副本样本、同源悬停及语言模式。

### 重构前基线

- Mists 2.8.6 统一构建器 `ValidateOnly` 通过，当前源码和玩家包加载名均为 `YiboAltoBoss.toc`。当前 TOC 路径没有 XML 引用，根目录的 `GoalTargets.lua`、`TargetCatalog.lua`、`TargetProjection.lua` 未由当前 TOC 加载，迁移时核对开发脚本和测试引用。
- 插件自带 9 组 Lua 5.1 测试通过。任务集成的 `BossGoalsSpec`、`CustomBossGoalsSpec`、`RaidProgressSpec`、`BossSearchIdentitySpec` 通过。`GoalSourcesSpec` 在现有工作树第 274 行的全服默认范围断言失败，预期 `nil`、实际 `true`，收录为拆分前已知基线差异。
- 以上为 Mists 2.8.6 的重构前基线。

## 2026-11-20 实施记录

- **Mists 2.8.7**。世界 Boss、节日与位面、WoW 事件、日周规则、DBM、任务目标的计划源与历史目录移至 `Mists/`。继续使用 `YiboAltoBossDB`、现有页面 ID、配置键、`/yab` 和 Core 目标契约。共享自定义目标增删与有效期、设置编辑器、账号矩阵和锁定状态投影由 `Common/` 提供。MoP 自定义击杀继续使用原有 24 小时规则。
- **Forever 0.1.0**。Core 设置中按 NPC ID 添加或确认移除目标。当前角色在自定义目标表格中左键标记或撤销，标记保存时间与手动来源，并持续到主动撤销。悬停读取同一份记录，历史角色只显示已有记录。副本进度页共用矩阵，当前没有预置副本或已采集数据。采集器接入后可提供稳定的地图与难度键、`observedAt`、覆盖状态，以及按键分组的 `lockouts`、`runs` 与 `history`。仅明确完整且有效的覆盖可给出未锁定状态。当前目标识别、战斗日志、原生锁定、首领与重置事件均留待本服样本。
- **加载和存档**。源码选择 `YiboAltoBoss_Mists.toc`（50504）或 `YiboAltoBoss_Forever.toc`（16001），默认源码 TOC 执行提示。两个玩家包以同名目录及唯一 `YiboAltoBoss.toc` 加载。入口在写库和注册前校验实际项目与 Core 就绪、API13 和能力版本，事件初始化执行一次。Forever 保存至独立 `YiboAltoBossForeverDB` schema 1。新加载链无 XML 引用，旧根目录占位文件无运行代码，旧 2.8.6 的根目录业务 Lua 可保留在覆盖目录中。
- **Core 公共能力**。Forever 复用 Core 名称、身份和账号范围，复用 Core 输入、操作确认、统一设置、入口与同源悬停，并登记角色缓存所有者。业务目录和记录归 AltoBoss。Mists 的目标契约与节日日历维持原有能力门槛。Forever 先提供独立基础功能，行动中心目录和完成提供者未接入。详见 [Core 公共能力台账](../../YiboCore/Docs/Core-公共能力迁移台账.md)。
- **离线验证**。插件原有 9 组测试、目标集成 4 组、矩阵预算 100 项和日历消费者 12 项通过。新增联合验收 30 项，分别加载源码、Mists 2.8.6 保留旧文件覆盖的包，以及干净 Forever 包。两包以统一构建器产出，净包分别含 30／12 个加载 Lua，逐字节核对 TOC 引用和运行文件，并通过 MoP 整合包预检。语言静态报告无 AltoBoss 未知键或格式差异，启动提示使用 Core 不可用时的双语资源。前述 `GoalSourcesSpec` 基线差异仍在，独立 `YiboTaskHub/BossTargetsSpec` 在前置 Todo 角色夹具缺少 `GetAllCached` 时停止。候选包见 [离线构建目录](../../_NonRelease/AltoBossForever/Candidate-20261120/)。
- **客户端待验**。需要完整退出启动核对实际清单，验证 Mists 2.8.6 保留旧文件覆盖与原存档恢复，以及 Forever 干净安装、手动标记、退出恢复、悬停与中英文界面。副本采集另用 `/yaf` 取证。当前两端均为离线候选。
