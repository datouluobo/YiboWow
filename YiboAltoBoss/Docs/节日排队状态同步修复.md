# 节日排队状态同步修复

2026-10-18。代码与模拟验证已完成，客户端待验。

## 反馈与判断边界

用户反馈系统排队图标消失，AltoBoss仍显示“取消排队”；随后补充系统图标也可能存在显示异常。截图不能证明实时队列已经退出，本次不把退队原因归为超时或玩家操作。

代码检查发现 `GetQueueState` 优先使用 `GetLFGQueuedList`，列表命中会直接跳过实时模式查询。现改为以 `GetLFGMode(LE_LFG_CATEGORY_LFD, boss.lfgDungeonID)` 为依据：`queued`、`proposal`、`rolecheck`、`suspended` 保留取消排队状态，其它模式再走原有准入与角色判断。列表或图标缺失不会否定有效实时队列；列表残留也不会覆盖实时空闲状态。实时接口缺失或异常时停止排队操作并使用现有语言资源提示。

刷新增加 `LFG_PROPOSAL_SHOW/UPDATE/DONE/FAILED/SUCCEEDED`、`LFG_ROLE_CHECK_SHOW/HIDE`，保留既有角色、LFG与队列更新事件。事件到达时立即刷新，并合并0.1秒、0.5秒的后续刷新。是否继续排队始终重新读取实时模式，不根据“提议失败”事件推断退队，避免其它队员拒绝后系统重新排队时误清空状态。

API与事件交叉核对[暴雪UI源码镜像的LFGFrame.lua](https://github.com/tekkub/wow-ui-source/blob/live/FrameXML/LFGFrame.lua)。实际怀旧客户端仍需核对确认弹窗超时、别人拒绝后的重新排队，以及系统图标异常时的表现。

## 排队按钮悬停的预估等待时间

2026-10-18追加：排队状态下，行动按钮悬停新增“预估排队时间：…”；每次悬停重新读取当前数据，主表与预览复用相同控件生成逻辑。使用 `GetLFGQueueStats(category, dungeonID)` 第16项 `myWait`，单位秒，与[暴雪队列界面源码](https://raw.githubusercontent.com/tekkub/wow-ui-source/live/FrameXML/QueueStatusFrame.lua)的个人估算来源相同，不作为剩余倒计时或保证入场时间。时间格式复用现有 `FormatDuration`。

仅在实时模式为 `queued` 时读取；统计未就绪、负值、无效数值、接口缺失／异常或返回其它副本时显示“暂未提供”。确认弹窗、角色确认及暂停阶段不使用历史等待估算。新增两对 owner 资源 `QUEUE.ESTIMATED_WAIT`、`QUEUE.WAIT_UNAVAILABLE`，仍由 Core API13语言服务处理；Tooltip壳、定位与关闭继续由Core管理，没有新增公共接口或迁移回退。

HolidayBossSpec现252项通过，新增12项覆盖个人估算字段、零值／负值、不同副本、缺失及错误数据、中英文实际Tooltip渲染和再次悬停重新查询；BossGoals19项通过，Lua语法及语言检查通过。实机待确认：正在排队时悬停行动按钮能显示系统当前估算，系统没有估算时显示明确占位。

同日追加“已排队时间”，紧邻预估时间显示。复用同一次统计查询第17项 `queuedTime`，按暴雪界面相同方式计算 `GetTime() - queuedTime`，不使用服务器Unix时间相减，也不另存本地入队计时。每次悬停重新计算；缺少或无效时间戳显示“暂未提供”，预估未知时仍可独立显示已排队时间。新增 `QUEUE.ELAPSED_WAIT` 一对 owner 中英文资源，Core API13与现有Tooltip托管方式不变。

HolidayBossSpec现261项通过，追加9项检查覆盖入队时间计算、零／未来／缺失时间戳、估算缺失时保留已排队时间、中英文相邻显示和再次悬停更新时间。Lua语法与语言检查通过；真实客户端的两行显示仍待确认。
