# YiboCurrency - 货币管家

当前版本：**1.1.0**。本版统一货币显示与目录管理，设置分为“内置”和“自定义与其它”两页；离线回归通过，实际客户端复验待完成。 请配套使用 **YiboCore 1.12.6 / API13**，启动时检查 `account-surface-budget:2` 及实际方法。

YiboCurrency 1.1.0依赖 **YiboCore 1.12.6 / API13**，并要求 `character-archive-providers:1`、`character-cleanup:2`、`account-dynamic-fields:1` 等实际接入能力。使用 `/ycu` 打开统一账号窗口；`/ycu probe` 输出诊断。缺少必要能力时提示升级并停止初始化。

主表按货币为行、角色为列展示金币、标准货币、节日代币和自定义物品代币。悬停复用同一快照、角色筛选、状态颜色和数值格式化，只展示选中的货币；Core统一设置 → 货币管家 → 业务设置可启用“悬停行列转置”，改为角色为行、货币为列，默认关闭且不改变主窗口方向。主窗口自动按完整角色列展开，达到屏幕安全宽度后先紧凑排列，确实无法容纳才使用Core分页；默认最多20名有效角色。货币设置页通过“内置／自定义与其它”页签统一编辑“主窗口／悬停”两个独立显示选择；主窗口右键或名称旁的悬停勾选可快捷切换悬停显示，自定义项目与内置项目行为一致。Core“显示与入口”读写相同显示状态。自定义物品在“数据与缓存 · 自定义目录”中加入或确认移出，拖入已存在物品只提示重复。

本轮界面与操作规则见[货币目录与显示管理](Docs/货币目录与显示管理-实施与验收.md)；2026-10-19 工作树离线检查完成，游戏客户端复验待完成。

旧主表显隐作为字段默认值保留，Core已有显式选择优先；旧监控选择一次性导入 `settings.previewColumns`。两种选择保持独立，当前均按目录顺序显示。新旧角色名、完整身份和短名由 Core 格式化，中英文界面跟随 Core 会话语言，手动切换重载生效；原生客户端名称和用户自定义文本保持原样。

`~` 表示历史快照或来源不完整。Currency拥有金币、原生货币与随身代币观察，数据保存在 `YiboCurrencyDB.characters`；无Vault时只显示自己的随身计数，不补银行或装备。Vault可用时整次选择其个人库存快照，不混合旧来源；邮件、拍卖和公会共享数量仅作明细。未知不作确认零，历史值不能证明目标完成。

Vault 为可选增强，通过 Core Contracts 发现 `vault.items`，不依赖其加载顺序。缺失、禁用、不兼容或查询失败时基础矩阵仍可用。入口由 Core 管理，小地图、Broker、内置条三个通道默认全部关闭。

原生货币／金币支持指定角色一次达标或持续保持目标，金币单位为铜币。目标增强检查 API13、`business-item-actions:1`、Provider和角色身份能力，不满足时仅停止增强；物品目标由Vault提供，账号货币合计目标不在本轮范围。

Core1.12.4工作树已停止货币业务采集。首次加载配套版本时，Currency通过公开接口逐角色导入旧快照，保留原时间并标为历史；旧Core记录继续冻结保留，不自动清除。新采集只写Currency存档，成功本地数据不被旧值覆盖。Core角色档案金币由Currency公开Provider提供；插件缺失时Core基础档案仍可用。

成功观察24小时后转历史；周进度按客户端重置时间独立失效，未知新周进度不写成0。使用 `/ycu status` 查看导入状态，`/ycu migrate` 重试，`/ycu scan` 重采当前角色，`/ycu probe` 查看诊断。角色缓存清理统一在Core中确认，禁用期间的pending清理会在下次加载处理。

代码与离线验证已完成，真实客户端待验收。详见[货币归属迁移记录](Docs/货币数据归属迁移-实施与验收记录.md)；此前界面接入见[Core API13记录](Docs/Core-API13-实施与验收.md)。Core与Currency需要配套升级。

内置货币独立一页；自定义货币、悬停转置和目录管理集中于另一页。两类货币均可分别勾选主窗口和悬停显示，目录每页最多24项，并按可用高度调整容量。点击自定义名称可选入目录管理控件；移出需要确认。
