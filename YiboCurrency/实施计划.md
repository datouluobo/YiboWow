# YiboCurrency - 货币管家实施计划

## 0. 当前决策

- 插件技术名确定为 `YiboCurrency`。
- 中文产品名确定为“货币管家”；Core 统一账号窗口中的页面标题为“货币总览”。
- 正式 Slash 命令计划使用 `/ycu`；当前工作区未发现占用。
- 本插件只负责多角色货币余额的采集编排、目录和展示，不加入收入支出流水、拍卖估值、资产估值或经济分析。
- `0.1.0` 已创建 `.toc`、SavedVariables、Core 接入、稳定目录、账号矩阵、悬停监控和首批数据基线；尚未创建图标或发布脚本。
- 目录中的“待验证”项不会被伪装成零余额，必须通过 5.5.4 实机探针后再标记为已验证。

## 1. 产品名与页面名

本插件使用两级命名：

- 产品与发布名：`YiboCurrency - 货币管家`
- Core 页面标题：`货币总览`

“货币总览”准确描述页面内容，但不足以承担独立插件的传播名称。“货币管家”用于口头传播和发布展示，并能覆盖标准货币、系统虚拟货币、物品代币、显示隐藏与悬停监控。

“管家”表示整理、展示和管理货币查看偏好，不表示本插件执行购买、兑换、转移、估值或经济分析。

后续命名采用以下边界：

- 页面标题继续直接描述页面任务，例如“货币总览”“声望总览”。
- 发布名称统一采用 `YiboTechnicalName - 中文产品名`。

## 2. 产品边界

YiboCurrency 展示“可以作为余额持有并用于兑换、购买或推进系统的广义货币资源”。首版包含：

1. 金、银、铜。
2. Blizzard 标准货币 ID，包括未出现在当前货币列表中的已知货币。
3. 考古碎片等由独立系统 API 保存的虚拟货币。
4. 以物品形式存在于背包或银行中的兑换代币。
5. 用户按 itemID 添加的自定义物品代币。

明确排除：

- 收入支出流水。
- 拍卖价格、物品估值和账号资产估值。
- 自动购买、兑换、转移或花费。
- 普通制造材料、装备、一次性任务物品和钥匙。
- 其它业务插件的任务、Boss、声望或路线规则。

## 3. 主窗口信息结构

主窗口不提供搜索，不提供“常用 / 已拥有 / 全部”过滤，直接展示所有未被用户隐藏的目录资源。

固定顺序为：

1. 熊猫人之谜
2. 大地的裂变
3. 巫妖王之怒
4. 燃烧的远征
5. 经典旧世（60 年代）
6. 自定义货币
7. 考古
8. 其它与未归类

考古碎片集中放在“考古”分组，按种族显示；不再按其所属资料片分散到多个区域。

每个资料片下再按以下来源分组：

- 常规货币
- 专业与系统货币
- 物品代币

所有资料片默认展开。顶部资料片按钮只负责滚动定位，不改变数据范围。左侧货币列固定，右侧角色列按 Core 顺序显示并在宽度不足时分页；数据区只做纵向滚动。

## 4. 显示、隐藏与悬停监控

主窗口显示和悬停监控是两个独立开关：

- 主窗口默认显示完整目录；用户可以隐藏不需要的单项、子分类或资料片。
- 悬停窗口只显示用户标记为监控的资源。
- 监控数量不设人为上限；超过安全高度后使用纵向滚动。
- 角色列不足时使用分页，避免横纵双滚动。
- 隐藏主窗口行不自动取消悬停监控，取消监控也不隐藏主窗口行。

设置工作台按资料片和来源类型列出完整目录，每项提供“主窗口显示”和“悬停监控”两个开关，并提供整组开关和“恢复全部显示”。

## 5. 资源来源与稳定标识

统一资源键必须包含来源类型，避免不同系统中的相同数字 ID 冲突：

- `money`
- `currency:<currencyID>`
- `archaeology:<raceKey>`
- `item:<itemID>`

标准货币通过稳定 currencyID 直接读取，不能依赖 Blizzard 货币窗口的临时列表索引、折叠状态或“未使用”分类。

考古碎片按考古种族稳定标识保存。物品代币按 itemID 保存，并区分随身数量、银行数量、银行是否完成扫描及历史更新时间。

## 6. 内置物品代币与用户自定义

YiboCurrency 维护从 60 年代到当前版本的内置物品代币目录，但不能保证一次性穷尽所有历史兑换物。为处理遗漏，提供与 AltoBoss 自定义目标相似的自定义 itemID 能力。

用户添加 itemID 时：

1. 读取客户端物品名称和图标并要求确认。
2. 拒绝空值、非法 ID、已存在的内置条目和重复自定义条目。
3. 默认归入“自定义货币”，允许用户选择资料片和来源子分类。
4. 自动统计当前角色随身与可知银行数量。
5. 用户删除自定义定义时停止展示和后续采集，不把其它货币数据一并删除。

内置目录与自定义目录使用同一套行模型、状态、格式化和悬停逻辑。

## 7. 特殊货币数据基线

实施前建立逐项数据基线，不能仅凭名称把历史物品认定为货币。每项至少记录：

- 稳定资源键。
- 中文名称与客户端名称。
- 资料片和来源分类。
- currencyID、itemID 或系统键。
- 数据来源 API。
- 随身、银行或虚拟余额范围。
- 刷新事件。
- 是否允许角色范围合计。
- 在 5.5.4 客户端中的验证结果。

永恒铸币、各考古种族碎片以及各资料片的物品兑换代币作为首批探针对象。

## 8. 数据职责

YiboCore 保存可复用的中性角色事实和快照状态；YiboCurrency 保存目录、显示、隐藏、悬停监控和自定义 itemID 配置。

建议按采集来源拆分 Core 数据域：

- `economy`：金币和标准 currencyID 货币。
- `economy-items`：注册的内置及自定义物品代币。
- `archaeology`：考古碎片及其可用状态。

YiboCurrency 在读取层将这些来源合并成统一账号矩阵，不建立自己的第二套角色目录、窗口壳、入口位置或角色排序。

## 9. 业务插件重复展示原则

Core 统一保存中性事实，但不同业务插件可以为了不同任务展示相同事实，也可以保存与自身业务目标绑定的临时派生进度。

例如 Legendary 的勇气累计只服务特定任务：任务进行时采集和显示；任务完成并交付后停止累计，并从当前任务展示中退出。YiboCurrency 仍可长期显示当前勇气余额和上限，两者不互相替代，也不建立业务插件之间的依赖。
