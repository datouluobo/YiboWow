# 双端目录与表格共享第一批

2026-11-27。Mists 1.1.3 与 Forever 0.1.9 工作树，沿用各目标版本号。

## 共用范围

- 两端使用 `Common/Catalog.lua` 合并目录、生成字段定义并应用主表和悬停的独立选择。金币使用 `money`，原生货币使用 `currency:<ID>`，物品使用 `item:<ID>`。MoP 继续使用本端内置目录，Forever 继续使用本端发现目录。
- 两端主表和悬停使用 `Common/Projection.lua` 读取按角色与字段组织的数值和状态，在单次页面刷新中复用给表格、测量和提示。显式选择的 Forever 原生货币进入悬停，未知、历史和确认零分别显示。范围未确认的发现项不做跨角色合计。
- `Common/AccountPage.lua` 提供共用表格行、行池、滚动内容高度及悬停矩阵。MoP 主矩阵沿用既有账号范围、页内悬停字段操作、转置和目标入口。Forever 主窗口维持当前角色范围，保留金币、会话变化、刷新、随身物品搜索与 Vault 明细，物品区接入共用表格。两端的设置、采集 API、事件与归档数据归属分别沿用既有实现。这一批的范围止于目录和展示重构。

## 加载与存档

| 目标 | 源码 TOC | 单目标包加载名 | Interface | SavedVariables |
| --- | --- | --- | --- | --- |
| Mists | `YiboCurrency_Mists.toc` | `YiboCurrency.toc` | 50504 | `YiboCurrencyDB` |
| Forever | `YiboCurrency_Forever.toc` | `YiboCurrency.toc` | 16001 | `YiboCurrencyForeverDB` |

源码默认 TOC 继续只加载缺目标提示。目标身份校验在写库前执行。两端仍检查 Core 就绪、API13 及所用能力。Forever 显式补查既有的 `account-dynamic-fields:1` 和共用矩阵所需的 Core 方法。初始化沿用各端的单次注册守卫。沿用现有存档格式以及 `previewColumns` 键，无跨目标导入或因本次迁移新增的存档写入。

MoP 旧根路径 `AccountPage.lua`、`Projection.lua`、`Data.lua` 可随覆盖更新保留，新清单只执行 `Common/AccountPage.lua`、`Common/Projection.lua`、`Mists/Data.lua`。Forever 保留 `Forever/AccountPage.lua` 作为目标页面适配，加载共用投影和表格，覆盖时替换同路径文件。核对了两端当前包和本机同版本旧包的 TOC、无 XML 间接加载、双目标共用文件内容及目标专用载荷。

## 证据与待验

- Lua 5.1 语法检查通过。MoP API13 中文／English 各 1102 项，矩阵预算 99 项，迁移 55 项及 TOC／保留专项通过。共享发现和 Vault 集成规格通过。
- Forever 实际目标 TOC 回放通过，覆盖误目标和 Core 方法缺失停写、单次注册、原生货币发现与角色切换、悬停选中字段、历史零、无值、金币选项隔离，以及同 ID 的物品和货币。使用实际 Currency 页面和 Core 表头实现，客户端帧环境为模拟。
- 双端通过统一构建器，临时 ZIP 核对唯一默认 TOC、包内引用及与旧包覆盖后的活动加载图。工作区本地化候选报告已检查，Currency 的源码提示候选仍是既有默认 TOC 文案。货币目录的 `FOREVER.BALANCE` 静态键可在两套语言资源中找到。
- `CoreItemControlsSpec` 的背包解析和 `ScrollBudgetSpec` 的模拟帧 `GetPoint` 在本次改动前的 Currency 加载链上也会失败。本批采信通过的专项与实际包核对。
- 双端游戏内主表和悬停布局、语言模式、干净安装、保留旧文件覆盖、重载与完整退出后的存档恢复待验。Forever 原生货币非空仍需实机样本。本批未发布。
