# 货币数据归属迁移：实施与验收记录

2026-10-15。状态：**代码与离线验证已完成，真实客户端待验收**。版本：Currency0.9.1工作树、Core1.12.4工作树 / API13。按已批准的[方案](货币数据归属迁移方案.md)实施；没有通过工具读取、重写或清理玩家实际SavedVariables，没有提交、推送或发布。

版本安排：按用户要求，TOC与运行时版本保持Currency0.9.1、Core1.12.4，当前为未发布工作树。实机测试通过后再更新正式版本、提交、推送及打包；不能仅按相同版本号判断兼容，必须同时满足新增能力版本与停采集检查。

## 所有权与配套要求

Currency唯一采集并保存金币、原生货币与最小随身代币观察，存于 `YiboCurrencyDB.characters[Core角色ID].native / carriedTokens`；数据schema为1、插件存档version为5。Native负责moneyCopper、各currencyID余额／上限／周状态；carriedTokens只存目录中itemID的随身计数，不保存完整物品库存。

Vault继续拥有背包、银行、装备等库存事实。Currency通过Core发现 `vault.items`，每角色整次读模型选择一个来源；不再把本地或旧Core银行数量拼入Vault。无兼容服务、查询异常或该角色无个人来源快照时，使用Currency自己的随身观察，显示来源不完整。库存覆盖完整只表示Vault已有记录，不推定其为实时采集；来源明细继续由Vault解释。

Core退出货币业务，新增最小通用档案字段Provider适配与通用清理所有者留存。Currency检查Core1.12.4工作树及 `character-archive-providers:1`、`character-cleanup:2` 和实际公开方法；Core版本不足、货币采集器仍注册或CurrencyCatalog仍存在时停止初始化，提示配套升级。Core1.12.4工作树与Currency0.9.1工作树须一起升级；旧Currency依赖已撤下的业务目录能力，不能与新Core当作受支持组合。

## Core停止采集与历史保留

以下模块已从Core TOC撤下，并加停用护栏；源文件保留，不执行物理删除：

- `YiboCore/Data/Domains/Economy.lua`
- `YiboCore/Data/Domains/EconomyItems.lua`
- `YiboCore/Data/Resources/Economy.lua`
- `YiboCore/Runtime/CurrencyCatalog.lua`

Core不再注册economy／economy-items，不再创建CurrencyCatalog，不再监听专用PLAYER_MONEY／CURRENCY_DISPLAY_UPDATE。全仓正式代码复核：其它业务对此二事件使用自己的原生监听；通用Core事件和其它数据域保持。

Core静态character.money字段撤下，由通用 `character-archive.fields` v1.0 Provider提供；字段ID不变，原金币显示选择保留。Core按契约枚举所有提供者，不维护按业务名称的适配分支。缺失Currency时仅没有金币增强，角色身份、等级、装备、专业等档案仍可用。

旧 `domains.economy`、`domains["economy-items"]`、`profile.money`、`profile.currencies` 继续冻结保留。DomainStore:Get可读取旧快照，即使数据域不再注册；导入成功不会删除它们，也没有新旧双写。用户将来主动删除该角色Core缓存，仍按统一确认和所有者清理流程执行，这与迁移后的自动清理不同。

## 导入、采集与时效

Store、Migration、Scanner与ArchiveProvider为Currency所有。初始化先校验Core交接，再初始化存储、处理pending清理和Core别名，然后逐角色导入，注册档案Provider／页面／目标，最后启动本地采集。

导入只通过 `Characters:GetAll({identityOnly=true})`、`GetAliases`、`DataDomains:Get` 读取公开副本。按角色暂存两个缺失分区，全部校验通过后提交；一个分区不合规不会留下半份导入。已成功本地采集值优先，重复执行不覆盖新值或原导入时间；失败、空错误占位及完成标记存在但快照缺失可重试，互不影响其它角色。

当前支持旧域schema1，未知schema、错误状态、非法数值或时间均记失败并保留源记录。原时间、revision和schema保存在provenance；导入值立即标为历史，不能证明目标完成。物品只导入可靠carried，只有total的旧值保持未知，bank／total不成为新库存权威。

Scanner自行监听登录、进入世界、金币、货币、背包和装备变化。一个事件突发只扫描一次；背包事件不查询原生货币，货币／金币事件不扫描代币。随身扫描优先一次遍历背包0～4，不扫描银行；旧客户端count API作为兼容路径。API不可用或异常不写成确认零；瞬时失败最多额外重试3次。

成功观察即使数值不变也更新observedAt，事实revision不因单纯时间变化增加。失败不改写成功观察时间；旧数值保留但状态不冒充有效。新本地快照超过24小时或时间异常时转历史；周数量独立按客户端重置时间失效，重置时间缺失／异常时周进度未知，余额不随跨周被清零。定时失效通知复用Core合并刷新，不扫描游戏数据。

主表、悬停、合计、提示和目标共用读取模型。`~`统一表示历史或来源不完整，`?`表示缺失／未知，确认零继续显示0；目标只使用known原生余额。原生名称、历史名称与自定义文字不改写。

## 角色与缓存生命周期

Store只以Core唯一ID关联。旧legacy ID仅通过Core公开别名修复；两个真实GUID不按同名合并。合并优先本地成功数据，再比较时间；冲突副本保留诊断，等时矛盾标为历史，不用于目标完成。

Core CharacterCleanup能力2保存已登记的动态所有者ID，插件禁用时仍列为pending，待处理记录不因100条软上限被裁掉。Currency注册Inspect／Delete，影响说明包含原生余额和随身代币，不触碰目录、偏好、Vault或其它插件数据；删除诊断快照也属于该角色清理范围。确认列表按技术名排序。

Currency保存被删除ID及旧别名的导入阻止标记，避免冻结Core数据复活。新观察仍可由真实登录产生。旧墓碑回放仅保留墓碑之后有效的本地新采集，直接删除不会被未来时间戳绕过。失败可由Core pending流程重试，重复身份事件不产生删除标记。

## 客户端验收与恢复

安装配套版本后重载，核对当前角色与离线角色：首次导入保留原时间、历史标记正确，当前角色成功重采后恢复确认状态；再次重载不会用旧Core值覆盖新Currency值。用 `/ycu status` 查看记录及失败数，`/ycu migrate` 重试旧数据导入，`/ycu scan` 重采当前角色，`/ycu probe` 查看诊断。

需实机核对：中英文及手动语言、金币花费和货币变化、周重置／无重置API、Vault缺失／禁用／晚就绪与银行／装备覆盖、超过20角色和跨服、角色ID晋升、缓存删除后禁用／再启用及目标一致性。Core角色档案的金币显示选择需能保留，Currency禁用时基础档案保持可用。

旧Core数据没有自动清理计划。恢复时使用已验证的配套版本和正常备份；不把新Currency存档反向双写Core，不自动合并两边不同时间的快照。恢复旧组合会使用旧Core历史／重新采集数据，再升级后仍以已有Currency成功数据优先，需登录相关角色重采确认。
