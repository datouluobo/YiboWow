# 双端货币目标第三批

2026-11-27，Mists 1.1.3 与 Forever 0.1.9 工作树。

## 契约和范围

Currency 继续唯一持有金币和原生货币快照，通过 Core 注册 `action.targets` v1.1，提供方 ID 为 `YiboCurrency:targets`。`GetEntry` 提供货币页面入口，`Normalize` 接收稳定字段 ID、Core 角色 ID、整数阈值和一次达标／持续保持模式，`Evaluate` 返回按目标 ID 索引的任务和来源版本。金币阈值使用铜币。确认的零余额仍是已知值。过期、缺失或当前不可确认的余额使目标保持待同步，不能证明达标。按指定角色评估，物品和账号合计在此契约之外。

余额仍来自各端现有快照，Currency 只把目标状态投影给 Core。行动中心是目标配置与生命周期的消费方，通过 Core 发现提供方，Currency 不读取行动中心存档。可选目标增强要求 API13、`business-item-actions:1`、`business-providers:1`、`character-identity:1` 及相应方法。能力缺失时基础页面和采集仍可用。Core 负责操作绑定及消费服务发现，缺少消费服务时由 Core 提示不可用。当前 YiboTaskHub 0.7.0 的目标为 Mists，Forever 的完整客户端创建与执行链待消费端支持。

## 入口与存档

- MoP 保留主矩阵的金币／原生货币目标操作。Forever 的金币入口位于主窗金币余额，原生货币入口位于「内置」设置中对应的已发现货币行。通过 Core 统一手势和目标操作菜单绑定当前角色，悬停仍是只读预览。
- 两端用同一提供方实现和变更通知，来源代际及 revision 保存在各自插件数据库。Forever 接入可选 `goalSourceEpoch`／`goalRevision`，沿用现有 schema。采集代码与快照结构保持。目标增强能力缺失时不写目标元数据。

两个目标清单都加载 `Common/GoalTargets.lua`。源码默认清单继续只做缺目标提示。原根路径 `GoalTargets.lua` 可随 MoP 覆盖保留，新清单及间接引用均不执行它。客户端身份、Core 就绪／API13 及基础能力在业务写库前检查，目标增强在写入其元数据前检查能力。初始化与提供方均有单次注册守卫。通过统一构建器和临时包核对实际加载名、目标载荷以及保留旧文件覆盖后的活动引用。
