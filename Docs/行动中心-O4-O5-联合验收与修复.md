## 修复与职责

1. Core 先提供扣除窗口壳与安全边界的可用内容高度，悬停计入入口上下空间。新公开契约 [account-surface-budget:1](../YiboCore/Docs/API-v11-视图可用高度.md) 先实现，再由 TASK 显式检查与消费；没有 Core 业务分支。
2. TASK 预览测量与绘制共用 Plan；压缩成每角色一行后只申请已显示行的高度，屏幕容纳不下的角色仍明确计数。摘要省略零计数，保留真实可推进／准备／候选／待核实数；相邻行仍共用分隔线。
3. 已复现邮件失效缓存：MarkMailOpened 发布变化后 Schedule 清空 validAt，中心在延迟扫描前查询得到未知；同内容扫描成功不发变化，未知持续保留。Schedule 现在发布实际失效，CommitScan 恢复有效状态时通知；重复排队只发一次失效，正常有效的无变化扫描仍不广播。查询不发消息，中心不反向调用业务扫描。
4. Mail 保留 expiresAtEstimate 为 validUntil。TASK 通用状态仅在来源期限已到时显示“已过期”，其余失效快照显示“需复核”；关闭邮箱、离线和失败依旧未知。该时间边界用于再次核实，不代表已收取或已完成。

## 客户端复测

已有新增文件加载的本次客户端可 `/reload` 同步修改；首次安装或尚未加载 O4／O5 TOC 新文件须完整退出重进。联接保持指向工作区。

1. 悬停查看密集邮件账号：窗口应贴合角色摘要行，底部不再留大块空白；当前角色与未知数量清楚，空间不足明确提示剩余角色。
2. 打开邮箱等待扫描：当前非付款附件／金币信显示“可收取”，HUD 同步；打开信件或刷新邮箱后等待扫描完成，不能持续停在“待核实”。
3. 收取附件／金币后复核来源与 TASK 一致；关闭邮箱后变为“需复核”，不会把尚未到期的信写成“已过期”。登录摘要仍一次，后续变化只更新展示。
4. 切号、日常交付与重置、设置开关及战斗延迟列表继续按 O4／O5 原清单验收。
