# O3：诺米来源字段映射与验收

日期：2026-10-09。状态：**运行代码与自动化完成，客户端待验收**。Todo 1.1.4，TaskHub 0.1.1；Core 1.10.0 / API v11 保持原连接机制，均未发布。

## 来源与连接

需求：把已有诺米待办接入行动中心，便于使用不同专业的角色验证当前角色和其他角色的今日列表。

- 能力：`action.todo` Provider v1.0；稳定来源 `YiboTodo:nomi`，显示名“诺米日常”。提供方 YiboTodo，消费方 YiboTaskHub；通过 Core.Contracts 注册、枚举和调用。
- 数据唯一所有者：YiboTodo。采集仍由内部 `daily-quest` 完成，判断复用 `Model/Snapshot` 的 `nomiProjects`；TaskHub 不查询来源数据库或重新计算日常规则。
- 基础待办最低 Core API v10；新集成最低 API v11 / business-providers:1。不足时提示升级并停止新集成，基础待办继续工作。没有新增业务插件依赖。
- 参数：`Query({scope={characterIDs={Core角色ID...}}})`。仅显式请求的角色，空数组为空；重复 ID 去重，未知 ID 返回未知覆盖。
- 返回：标准来源 envelope、逐角色 coverage 和 tasks 值副本。只读，无任务执行、制造、数量或分派接口。

## 字段与业务状态

| 输出 | 来源与语义 |
| --- | --- |
| itemKey / businessRef.key | Core 角色 ID + `mop.nomi`；同一角色、同一服务器日只有一份诺米工作，课程变化不另建重复任务 |
| title / summary | 稳定标题“诺米”，已知今日课题附在标题中；摘要使用来源 statusText |
| execution / beneficiary | self / character，均为该角色；专业类型不构成准入条件 |
| sourceState / questID / questKind | 原样保留来源状态与已确认任务身份，不依靠本地化名称关联 |
| state / readiness / reason | actionable → active / actionable / 可处理（仅历史资格时为可接取）；in-progress 或 ready-to-turn-in → active / actionable / 待交付；completed → completed / not-applicable / 今日已完成；unknown → active / unknown / 待核实 |
| temporal | daily；cycleKey 和 nextChangeAt 由来源 Schedule、目录 resetHour 与项目 nextResetAt 提供 |
| freshness / coverage | 有来源确认依据且状态已知为 known；未观察为 not-yet-scanned；已有观察但资格／状态不明为 partial。observedAt 使用项目已有时间，查询不更新观察时间 |
| nextAction | open-page → todo，回到账号待办；实际交互和完成确认仍归来源 |

完成任务仍可存在于来源 Query 中，中心按标准 completed 状态移出两个列表。目标完成但未交付仍显示“待交付”，不能提前认定完成。

监控关闭返回 known-empty。目录或内部日常 Provider 缺失返回 unavailable；已启用但角色项目缺失返回 partial。尚未确认诺米资格的角色显示未知工作，不把未知当零，也不自动认定每个角色具备资格。

## 周期、持久化与生命周期

来源既有规则允许历史重复课程／最终日常交付确立持续资格，次日项目恢复 actionable；一次性谢师礼不确立重复日常资格。历史资格时间不是今日观察时间，继续保留原值；本日有效期由来源给出，不由中心把历史资格误判为过期快照。课题尚未观察时显示可接取，不编造今日课程。

`db.actionNomi` 仅保存独立 sourceEpoch、revision 和派生指纹；`db.actionTodo` 的神纹布元数据保持原位置，增加诺米不重置其来源代际。来源清库后生成新代际，普通重载保留代际。派生任务只缓存于内存，状态仍以日常业务记录为准。

两项真实 Provider 使用同一所有者、不同稳定来源 ID。注册可重复、允许晚注册和注销，通知按来源 revision 合并；查询先提交版本后仍须发送排队通知。中心枚举通用契约，不增加诺米或专业冷却分支。本轮验证两个真实来源来自同一插件；不同业务插件的真实接入仍须后续场景验证。

## 验收范围

自动化覆盖：两个真实来源同时可用；非裁缝角色诺米项目；未知资格；课题变化但身份不变；目标完成待交付；交付移出；次日离线资格重新可接取；监控关闭；显式范围、值副本、独立版本；重复／晚注册、注销、低 Core 版本及多来源筛选。

客户端覆盖：完整退出并重新进入以加载新 TOC 文件，使用 `/yth` 查看；切换“诺米日常”来源，完成一项诺米日常并核对待办／中心一致，登录其他角色检查投影。O4 悬停与提醒仍另行实施。
