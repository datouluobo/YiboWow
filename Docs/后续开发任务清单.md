- Legendary：任务步骤、路线说明、专有名词、目标进度及任务诊断逐项核对可靠英文来源；动态任务名称优先读取真实客户端 API。

## DEV-003：TaskHub 复杂任务链

### 已完成范围

主动添加目标、同一目标库、编辑／暂停／恢复／移除、已支持来源与主列表／悬停／HUD／提醒已实机验收收口。当前任务不是重新实现上述功能。

### 剩余工作

- 一份需求拆分为有前置关系的多条工作，支持多个执行者与受益者。
- 数量分配、部分完成、预留、改派及避免同一库存重复占用。
- 制造、寄出、收取、最终满足的不同证据，以及在途、退回、补做和证据冲突。
- 人工核实、重载恢复、周期／来源失效和来源缺失时保留用户安排。

旧 S2～S5 是复杂模型与文件安排库存；当前主动添加方案以 T0～T6 的已交付结果为基础。重新开工时先核对真实 Core 与来源接口，不按旧文件表批量创建空模块。

### 第一批与完成标准

选择一条真实场景，例如指定角色需要一件可制造产物；首先明确目标数量、执行者、来源事实和最终完成判据。按最小闭环确定是否需要制造查询、库存预留或邮寄证据，逐项补真实能力。正常完成、部分完成、缺来源、重载、数量变化与人工核实均有一致结果后，再增加第二种链路。

依据：[产品与任务模型](行动中心-产品与任务模型方案.md)、[详细模型审查](行动中心-详细模型审查.md)、[文件级计划](行动中心-文件级实施计划.md)、[最小能力契约](行动中心-最小能力契约-v1.md)、[主动添加实施记录](行动中心-主动添加实施与验证.md)。
