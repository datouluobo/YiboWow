# YiboBuilds 装备增强状态规则

状态：修订待确认

孔底座资源状态：待确认（[20/24/32/64px 实尺寸预览](YiboBuilds-孔底座-实尺寸预览.png)；未导出或接入游戏资源）。

适用插件：`YiboBuilds`

本文档定义人偶装备区对装备、宝石孔、常规附魔、专业增强、工程强化、腰带扣和锻造额外孔的状态、视觉、布局与悬停规则。它规定玩家能观察到的结果，不规定具体代码实现。

## 1. 状态模型

装备区把“装备是否存在”“基础孔/强化是否存在”“宝石或附魔是否安装”分开判断。

### 1.1 设备槽状态

| 状态 | 含义 | 显示 |
| --- | --- | --- |
| `empty` | 该部件没有装备 | 槽位保持空白，不显示问号、宝石或附魔 |
| `equipped` | 该部件有装备 | 根据该装备实际存在的孔和增强项继续渲染 |

没有装备和没有数据必须视觉上区分：本规则中未装备就是空白；只有确实发生数据不可用时，才允许显示“数据未准备”类诊断信息，不能用问号冒充。

### 1.2 增强项状态

以下是缺失状态；`installed` 是完成状态，`not-applicable` 是不适用状态。

| 状态 | 含义 | 显示 |
| --- | --- | --- |
| `base-missing` | 当前角色有对应专业/能力，但生成基础增强的动作尚未完成 | 显示明确的“未打腰带扣”“未生成锻造额外孔”“未添加工程强化”等提示 |
| `uninstalled` | 基础孔或附魔位已经存在，但还没有安装宝石/附魔 | 显示具体颜色的空孔，或“未附魔” |
| `installed` | 宝石、附魔或工程强化已经安装 | 显示实际图标和原生 tooltip |
| `not-applicable` | 当前版本、装备类型或角色能力不支持该增强 | 默认不显示增强缺失标记 |

`generated` 不作为独立状态。基础生成的结果就是一个实际可见的孔：孔为空时直接是 `uninstalled`，孔内有宝石时直接是 `installed`。

## 2. 宝石孔

扫描必须保留装备 tooltip 中的完整孔序列，不能只保存已有宝石，也不能压缩掉空孔。

每个实际孔至少保存：

- `socketType`：红、黄、蓝、多彩、棱彩、染煞或其它版本支持的类型；
- `source`：装备原生、腰带扣、锻造额外孔；
- `state`：`uninstalled` 或 `installed`；
- `gemLink`：已镶宝石的链接，空孔为 `nil`。

显示规则：

1. 装备有两个红孔但没有宝石，必须显示两个红色空孔。
2. 一个孔已镶、一个孔为空，两个孔分别显示各自状态。
3. 没有实际孔的装备不显示宝石标记。
4. 空孔必须使用本节定义的空孔底座视觉，不得使用具体宝石物品图标伪装成已镶嵌。
5. 空孔 tooltip 只说明“红色空孔”等自身状态，不打开整件装备 tooltip。
6. 已镶宝石 tooltip 显示该宝石原生 tooltip。

### 2.1 空孔底座视觉

- 底座采用戒指镶嵌式结构：一个内凹孔座，由四个爪托住孔内宝石。空孔时保留四爪与空心凹槽，中心保持暗色或透明，不铺满孔色，也不放宝石图片；一眼能看出“有孔、尚未镶嵌”。
- 当前选定造型为“03 厚重锻造座”，视觉定稿以 [YiboBuilds-孔底座-03选定稿.png](YiboBuilds-孔底座-03选定稿.png) 为准。底座轮廓、颜色、材质明暗、四爪形状与颜色、宝石和排布均按该图原样使用，不再进行二次设计。
- 底座类别同时由轮廓表达：装备原生彩色孔使用圆形或柔和多边形；头部多彩孔使用星形或尖角多边形；锻造腕孔、手孔和腰带扣统一使用方正的锻造轮廓；染煞孔使用带弯月或碎片特征的斜向轮廓。最终轮廓与颜色以选定稿图片为准。
- 镶嵌状态只替换底座中心：空孔为暗色空心凹槽，已镶嵌为实际颜色宝石；宝石可以与孔色不同，宝石颜色不能改变底座类别或底座孔色。
- 底座的尺寸、线宽、背景深度、间距与装备区现有深色面板、细边框及 16px 增强图标协调。白色棱彩边缘在深色背景上必须清晰，但不能用整块高亮白底替代空心中心。不同孔型在亮暗环境下仍应可辨，tooltip 提供文字名称，不只靠颜色识别。
- 同类别空孔使用同一轮廓，不因该孔为空或已镶嵌而改变。孔位类别由轮廓区分，孔色由单一语义色区分，孔位来源由快照数据记录。
- 空孔底座本身是可悬停目标，悬停显示对应孔型的空孔说明。多孔装备的每个底座都有独立命中区域和 tooltip。

### 2.2 棱彩与染煞孔

- 锻造腕部孔、手部孔和腰带扣生成的孔，游戏规则上属于普通棱彩孔：可以镶除染煞外的各种颜色宝石。装备区仍以专属的方正锻造轮廓区别其来源类别，孔色使用单一白色；已镶嵌时显示实际宝石。
- 普通棱彩孔可镶除染煞外的各颜色宝石；染煞宝石只属于染煞孔。染煞孔使用自身独立的空孔颜色和 tooltip，不能显示成白色棱彩孔。
- 一个实际孔只对应一个底座。孔型识别与来源识别不能分别生成两个图标；染煞空孔尤其不得出现两个空孔。

## 3. 腰带

腰带的三个增强维度互相独立：原生宝石孔、腰带扣、工程腰带强化。

### 3.1 原生孔

红、黄、蓝等原生孔按普通宝石孔规则显示，不能因腰带扣或工程强化存在而隐藏。

### 3.2 腰带扣

腰带扣的基础结果就是一个棱彩孔，不单独引入“已生成”状态。

- 腰带没有棱彩孔：若该装备可使用腰带扣，状态为 `base-missing`，提示“未打腰带扣”。
- 腰带有棱彩孔且孔为空：该棱彩孔状态为 `uninstalled`，提示“棱彩空孔”；这同时表示腰带扣已经打上。
- 腰带有棱彩孔且已镶宝石：该棱彩孔状态为 `installed`。
- 腰带扣必须与腰带原生红/黄/蓝孔同时显示。
- 腰带扣生成的空孔使用第 2.1 节的白色棱彩空孔底座，与其它普通棱彩孔的大小、空心中心和边缘样式一致。

### 3.3 工程腰带强化

- 角色具备当前版本工程准入，腰带没有工程强化：`base-missing`，提示“未添加工程腰带强化”。
- 已安装 Nitro Boosts、Frag Belt、Invisibility Field、Grounded Plasma Shield、Cardboard Assassin、Spinal Healing Injector、Watergliding Jets 等：`installed`，显示实际强化名称与强化自身信息。
- 角色不具备工程准入且腰带没有工程强化：`not-applicable`，不显示“未附魔”。
- 已存在工程强化时，即使角色后来失去工程，也按装备实际链接显示已安装效果；是否可再次操作由另一个能力判断负责。
- 工程强化与腰带扣互不覆盖。

### 3.4 工程披风强化

- 工程披风强化（如 Flexweave Underlay、Goblin Glider）与常规披风附魔可以同时存在，必须分别检查和显示。
- 角色具备当前版本工程准入、披风没有工程强化：`base-missing`，提示“未添加披风工程强化”。
- 已安装 Flexweave Underlay、Goblin Glider 等强化时，显示强化本身的名称与信息；不以常规披风附魔状态替代。
- 已存在工程强化时，即使角色后来失去工程，也按装备实际链接显示已安装效果。

### 3.5 工程手套强化

- 手套工程强化与普通手套附魔、锻造额外棱彩孔分别判断、分别显示。
- 当前版本手套工程效果包括 Hand-Mounted Pyro Rocket、Hyperspeed Accelerators、Synapse Springs、Quickflip Deflection Plates、Tazik Shocker、Z50 Mana Gulper、Phase Fingers、Incendiary Fireworks Launcher；对旧版本仍保留在装备上的已安装效果也按实际装备记录识别。
- 有工程准入但未安装手套工程强化：`base-missing`，提示“未添加手套工程强化”；已安装时显示准确效果名称和效果自身信息。
- 手套工程标记不得遮挡锻造额外孔标记；工程强化和普通附魔可同时存在时应独立呈现。

### 3.6 工程强化识别与 tooltip

- 识别以装备链接中的 SpellItemEnchantment 记录 ID、以及该装备原生 tooltip 暴露的强化信息为准；槽位白名单按腰带、披风、手套分别约束，不能仅凭一个披风样例推断其它位置。
- 完整记录 ID、名称和槽位以随插件发布的 5.5.4 工程目录为准；它包含当前熊猫人阶段强化及可继续留存在装备上的旧工程效果。
- 远程武器的 Lord Blastington's Scope of Doom、Mirror Scope 属于工程制作的装备增强，归入工程记录识别；它们不应被腰带/披风/手套槽位规则误收。
- SpellItemEnchantment ID 不是 Spell ID，不得直接传给 `SetSpellByID`，也不得把配方/触发法术当作已安装强化 tooltip。
- 普通附魔与工程强化分别使用随插件发布的版本化目录。目录依据客户端 `SpellItemEnchantment`、`SpellEffect` 数据生成，包含当前版本可应用的永久装备附魔（含低等级记录）以及工程装备强化；运行时读取装备链接中的记录 ID 后，以 `enchant:<recordID>` 打开强化自身的客户端 tooltip。
- 原生装备 tooltip 若提供强化名称/描述，可用于识别和补充信息；悬停本身优先使用强化记录链接，不得回退为整件装备 tooltip 或无关的施法/触发法术 tooltip。
- 当前目录目标版本为 MoP Classic 5.5.4（客户端 build `5.5.4.68042`，Interface `50504`）。更新版本时须重新生成目录并核验普通附魔、工程强化数量及槽位映射；效果法术/使用技能 ID 仅用于辅助识别，不作为强化 tooltip 链接。

## 4. 锻造额外孔

腕部和手部的锻造额外孔与腰带扣采用同一规则：棱彩孔本身就是基础结果，不设置 `generated` 状态。

- 角色具备当前版本锻造准入，但额外棱彩孔不存在：`base-missing`，提示“未生成锻造额外孔”。
- 额外棱彩孔存在且为空：该孔为 `uninstalled`，提示“棱彩空孔”。
- 额外棱彩孔已镶宝石：该孔为 `installed`。
- 装备原生孔和锻造额外孔必须分别保存 `source`，不能把所有棱彩孔混成普通孔。
- 腕部与手部锻造空孔使用第 2.1 节的白色棱彩空孔底座；专业来源不改变孔型、可镶规则或空孔样式。

## 5. 常规附魔

### 5.1 普通可附魔部位

- 当前版本支持该槽位附魔且没有附魔：`uninstalled`，提示“未附魔”。
- 已有附魔：`installed`，悬停显示附魔本身的 tooltip，不显示整件装备 tooltip。
- 当前版本不支持该槽位附魔：`not-applicable`，不显示未附魔标记。
- 未附魔状态悬停时只显示“未附魔”，不能被整件装备说明覆盖。

### 5.2 戒指

- 只有角色满足当前版本附魔专业准入时，戒指才进入附魔检查。
- 有附魔专业但戒指没有附魔：`uninstalled`。
- 没有附魔专业：`not-applicable`。
- 已经存在戒指附魔时，按实际装备显示 `installed`，不因当前是否保留专业而隐藏事实状态。

### 5.3 其他专业施加的附魔

- 制皮腿甲片、护甲增强，裁缝法术线与刺绣，铭文肩部铭文等施加在装备上的效果，按其实际附魔记录进入常规附魔位；已安装时显示效果自身的 tooltip。
- 这些效果的专业归属和技能要求供识别与说明使用。装备上已有的效果按实际记录显示，不因查看时角色的专业变化而消失。
- 产生实际孔位的锻造效果进入上行珠宝孔规则，工程强化进入下行工程位；同一实际效果只归入一个增强项，避免重复图标。

## 6. 人偶装备区增强图标布局

### 6.1 两行与左右镜像

- 每件装备的侧边增强区固定为两行。上行只放实际珠宝孔、已镶宝石，以及与孔位相关的“未打腰带扣”“未生成锻造额外孔”提示；下行放常规附魔和工程强化。两行不得因为某一类图标缺失而互相占位。
- 上行的实际孔按装备上的孔序列从装备向外排列；已镶与空孔混合时保留原序，不把空孔集中到尾部。缺失打孔提示属于待生成孔位的操作提示，排在已有孔位之后；其造型必须与实际空孔底座明显不同，不能伪装成已经存在的孔。
- 下行从装备向外依次是常规附魔、工程强化。常规附魔永远靠近对应装备，工程强化位于远端；某项不适用或不可显示时，另一项仍保持自己的位置，不能跨行或交换次序。
- 左侧装备的增强区向右展开，右侧装备的增强区向左展开，位置和阅读顺序关于人偶镜像。底部武器按各自可用外侧展开，同样遵守上珠宝、下附魔与工程、附魔近装备的顺序。
- 所有增强图标都必须与所属装备保持清楚的视觉关联，不得压到装备图标、人偶、相邻槽位、文字标签或窗口边界；多孔、双附魔和缺失提示同时出现时也应保持两行、独立悬停区域和稳定间距。

### 6.2 图标与悬停

- 珠宝孔、常规附魔和工程强化各自只显示自己的状态与 tooltip。鼠标移到宝石显示宝石 tooltip；移到空孔显示孔型及“空孔”；移到附魔显示附魔本身；移到工程强化显示工程效果本身。
- 提示框不能遮住当前悬停的图标，不能因图标相邻而触发另一项的 tooltip。图标隐藏时不留下可悬停的透明命中区域。
- 已安装与缺失状态沿用装备区统一图标尺度、边框和警示色体系；空孔以空心底座表达“待镶嵌”，附魔与工程以各自图标表达“已安装”或“待添加”。

## 7. 数据优先级和刷新

1. 当前角色页面优先使用最新 `observedEquipment`。
2. 非当前角色页面使用 `confirmedEquipment`；没有确认快照时才使用观测快照。
3. 旧快照缺少完整孔序列或增强状态时，必须在重新扫描后重建，不能从压缩后的宝石列表猜测。
4. 装备变化、专业技能变化、专业配方/能力更新都应触发重新观测。
5. Broker、小地图悬停和主窗口必须复用同一份增强状态快照。

## 8. 验收场景

实现完成后至少验证：

1. 腰带有两个空红孔、没有腰带扣：显示两个红色 `uninstalled` 空孔，并显示“未打腰带扣”。
2. 腰带已打腰带扣但棱彩孔为空：显示一个棱彩 `uninstalled` 空孔，不再显示“未打腰带扣”。
3. 腰带扣棱彩孔已镶宝石：显示棱彩 `installed`，同时保留腰带原生孔状态。
4. 有工程但未装工程腰带强化：显示 `base-missing`；已装则显示实际工程效果。
5. 有锻造但腕/手额外棱彩孔不存在：显示 `base-missing`；孔存在但为空：显示 `uninstalled`。
6. 附魔专业角色的空戒指：显示 `uninstalled`；非附魔专业角色的戒指不显示未附魔。
7. 未装备衬衣、战袍或其它部件：显示空白槽位，不显示问号。
8. 红、黄、蓝、棱彩与染煞空孔并列时，均呈现同一空心底座结构，仅边缘颜色和 tooltip 孔型不同；中心不得由整块彩色图标填满。
9. 腕、手锻造孔及腰带扣空孔均显示白色棱彩底座；可插普通颜色宝石，染煞宝石只在染煞孔内显示。来源记录不额外产生孔图标。
10. 染煞空孔只显示一个底座；已镶染煞宝石后只显示一个实际宝石图标。
11. 一件装备同时有多个宝石孔、常规附魔和工程强化时，上行宝石保持孔序；下行附魔靠装备、工程在远端。左、右装备镜像排布，悬停各图标得到对应增强自身的提示。
12. 腰带或手套需要生成额外孔但尚未生成时，上行显示单独的缺失提示，不能显示为实际空孔；下行的常规附魔和工程强化位置保持稳定。

## 9. 实施与验收边界

装备区的判断与显示应使用同一份增强快照：版本化目录提供记录信息，实际装备与孔序列决定已存在的效果，角色专业和装备适用性决定缺失提示。主界面、悬停和刷新结果都以第 8 节的场景共同验收。

## 10. 目录来源与维护

- 生成脚本：`Tools/Generate-YiboBuildsAugmentCatalog.ps1`。
- 数据来源：Wago Tools 的 `SpellItemEnchantment` 与 `SpellEffect` 客户端表，固定 build `5.5.4.68042`；脚本会下载这两个表并按永久附魔应用效果建立记录目录。
- 普通附魔目录收录客户端中存在且有永久附魔应用效果的 SpellItemEnchantment 记录；低等级记录保留，不按角色当前装备等级裁剪。
- 专业目录按客户端附魔记录的专业 ID 与最低技能等级字段自动归类；覆盖锻造、制皮、炼金术、裁缝、工程学、附魔、珠宝加工和铭文等专业的可施加永久增强，并保留低等级记录。目录同时标记增强类型、记录名称、专业与最低技能等级；运行时展示仍依据装备上的实际增强记录，而不是用角色当前专业推断已安装效果。
- 打孔效果单独收录客户端附魔记录中产生插槽的效果类型。锻造腕部额外孔、手部额外孔和腰带扣分别对应记录 3717、3723、3729/5002；腰带扣与腕/手孔最终仍通过装备上实际棱彩孔序列判定，记录目录用于类型与来源归档，不以角色专业等级伪造孔位。
- 工程目录按客户端工程附魔记录和装备槽位单独生成，覆盖披风、手套、腰带、头部及远程武器瞄准镜；客户端测试记录不纳入可用目录。
- 裁缝刺绣、制皮护甲增强与腿甲片、铭文肩部铭文、锻造额外孔等均使用相同的记录目录与快照来源字段；不能把由专业制造的装备物品误当成施加到装备上的增强记录。
- 目录承担识别、名称和槽位等数据索引；tooltip 由客户端针对当前装备记录 ID 原生解析，并始终指向实际增强记录。
