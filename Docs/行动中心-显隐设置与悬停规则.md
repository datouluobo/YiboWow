# 行动中心显隐设置与悬停规则

2026-10-10 工作树实现，用户批准修改；客户端待验收。

悬停最多覆盖20名符合统一准入、有可展示工作的角色。先预留角色摘要，仅当前角色可以展开；空间不足时按已有工作优先级展示部分明细，页脚显示当前角色剩余工作数。其它角色始终摘要；极小屏幕放不下全部角色时仍明确剩余角色数。当前角色不存在或被Core隐藏时不会把其它角色当作当前角色展开。

## 设置位置与数据所有权

Core 设置工作台 → 行动中心 → 行动中心显示内容。业务插件复用 Core 控件与工作台壳，使用两栏、窄宽度自动堆叠、来源筛选和固定容量分页；长项目名可悬停查看。右侧内容超出安全高度时由 Core 原有工作台滚动设施处理。

- 角色与排序：跳转 Core 的 sorting 设置，角色显隐、准入与排序仍只有这个入口，不保存第二套角色开关。
- 待办监控：跳转 Todo 的业务设置，控制各类日常与冷却是否监控。
- 来源总开关与单项显隐：只改变 TaskHub 主视图、悬停、HUD和登录提醒的展示；保存在 `YiboTaskHubDB.settings.hiddenWork`，默认全部显示，数据库schema3增加可选设置表，无业务数据迁移。稳定键由 providerID 与显示组ID组成，不包含角色名、日期或来源epoch。总开关关闭时子项禁用，再打开保留子项原选择。
- 来源暂时离线时，隐藏条目仍保留标题和来源信息，能从设置恢复。源任务、观察和完成记录不作为第二份权威数据保存。

## action.todo v1 可选展示元数据

能力版本和现有必需字段不变；新增可选字段，旧消费者可忽略，旧来源仍能按整个来源控制显示。

```lua
result.displayGroups = { { id = "稳定业务项目ID", title = "项目标题" } }
task.displayGroup = { id = "稳定业务项目ID", title = "项目标题" }
```

提供方 Todo：profession-cooldown 输出全部 active 冷却组目录，不依赖角色观察或是否监控；nomi 输出诺米目录；activities 复用 Settings:GetMonitoringItems 输出已支持活动目录。项目ID、标题及可用目录由业务来源解释，TaskHub不读Todo对象、数据库或catalog。显示目录不是可执行任务，不代表角色具有专业、任务已采集或可推进。

TaskHub 在设置页通过 Core.Contracts 已有Provider快照读取目录；常规页面继续使用既有缓存，开关变更只刷新展示，不清空来源缓存、不触发采集。没有目录的来源使用总开关；有目录的项目隐藏对所有已准入角色生效。具体首领安排继续使用“刷取目标”管理。
