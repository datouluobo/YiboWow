2026-10-11 Crafting 目标 Provider 升为 action.targets v1.2：Normalize 返回可选 `managesExecutionScope=true`、`needsCharacter` 和 `characterOptions`。TaskHub 在来源管理执行范围时按 needsCharacter 显示指定角色选择器，并使用来源给出的角色候选；未提供这些字段时保持原通用编辑行为。该扩展不引入来源名分支。旧 TaskHub 仍能评估新目标，但配置共享范围需配套本次编辑器。

Crafting 的 any 范围基于 Core professions 已确认的专业归属；专业领域变化通知使目标评估失效并重新取得候选。每角色分别计算制造基线差或公开库存快照，取单个角色最大进度，任一角色独立达标即完成同一 once 目标。制造次数不推断成品件数；产物持有缺库存 Provider 时保持未知。完成判断和计数由 Crafting 持有；TaskHub 只保存目标与完成观察，不另算业务规则。图标默认 holding，名称默认 craft-times，已学角色格默认指定该角色。客户端悬停、共享投影及完成同步待验收。

新装清单为空；来源注册、监控开关、登录和新增角色不创建目标。业务项目中键或 ＋ 添加；Core 常规设置 → 窗口可配置按键和 Ctrl／Alt／Shift。原业务按键被保留，冲突配置会明确拒绝。安全按钮的左／右键不允许复用；非业务按键禁用安全动作回退。

缺少阈值、难度、角色等必要条件时，在 Core 统一窗口的“目标管理”填写。重复提交完整意图定位既有记录，不累加数量；参数变更走明确编辑。✓ 表示同一来源对象／角色已有目标，精确模式与条件仍由来源再校验。目标管理分页显示活动、暂停和已完成记录，提供编辑、暂停／恢复、明确重新执行、确认移除与复制。复制先预览，再按库 revision 重新校验并提交；复制配置，不复制完成历史。Boss 保留原双向批量复制及合并差异预览。

单次完成进入已完成记录；周期目标按来源 cycleKey 保留历史并在来源下一周期恢复；持续目标在确认不足后恢复。未采集、部分覆盖、过期、来源缺失／异常／major 不兼容均保留用户目标并待核实。来源 epoch 变化须明确编辑重新核实。缓存删除不删除目标；Core 角色 ID 迁移更新关联，不按角色显示名重绑。

## 数据迁移与兼容

schema3 → schema4 暂存构建新库，只有全部旧 Boss 计划可解释才提交；保留原目标 ID 关联、角色、难度／首领、暂停、sourceEpoch 与旧库备份 goalMigration.legacyBossTargets。重复初始化不重复导入。旧 Todo／Mail 自动工作、sourceFilter／hiddenWork 等显示偏好不变成目标；业务 SavedVariables 不迁入 Task。

task.boss-targets v1 从通用目标库生成兼容只读公开投影；原 Boss 编辑器是同一库的写适配，不维护第二份权威计划。旧 bossTargets.byCharacter 只作迁移原始数据留存；新操作不回写它。适用 TaskHub 0.5.0 与当前 AltoBoss；未来来源完全消费通用目标后再评估移除兼容投影，须同步消费者和契约，不能提前删接口。

TaskHub 最低 Core API12。九个来源的主动添加增强也检查 API12 / business-item-actions:1，低版本提示升级并停止该增强。明确的兼容例外：来源原有基础功能继续采用既有最低版本；保留原业务实现只为基础功能，并非复制新的目标绑定回退。适用旧 Core；当各来源整体提高最低 Core 版本时移除此分支。Core 不保存业务数据、不按插件名判断目标。

## 设置与 Todo 状态同步补充

添加方式三选一：右上角按钮、中键、Ctrl＋左键；标记可选左下角金色折角／青绿圆点。业务按钮仍由 Core 管理，业务来源仅绑定意图和安全点击回调，Task 管理目标库。旧自定义方式迁移保留，战斗中不允许改方式。

Todo 账号快照与精确目标查询共享专业项目元数据。来源每日重置后的 estimated 显示为“准备 · 预计可用”，confidence 保持 estimated、observedAt 保持原时间；freshness known 表示来源本周期派生准备状态有效，并非真实冷却已扫描。未观察过的配方、未知专业或冲突仍待核实；仅 confirmed 冷却可完成目标。实际专业扫描升级确认状态，制作成功证据不会被同周期滞后零冷却覆盖。Todo 仍拥有观察、重置与业务判断；Task 继续只消费公开契约。
