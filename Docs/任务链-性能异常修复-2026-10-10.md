# 任务链性能异常修复

用户报告 Core 最高约 240 MB / 53 ms，已有诊断截图指向 Todo、AltoBoss、TaskHub 互相放大的刷新与完整角色复制。本记录说明源码修复和本地验证；尚未取得修复后游戏内内存／帧耗时数据。

2026-10-10 客户端反馈：用户确认“性能没问题了”，恢复布局优化。未提供修复后具体 MB／ms 数值，因此只记录性能异常已获用户确认解决。

## 修复范围

- Core 提供 `character-identity:1`，复用 Characters Get / GetCurrent / GetAll 的身份投影选项，跳过 domains，默认完整查询兼容。见 [契约](../YiboCore/Docs/API-v11-轻量角色身份.md)。
- Todo 的特殊活动、诺米、烹饪及旧日常观察以业务字段判断变化。相同状态保留观察时间，不更新修订号，不通知或使主快照失效；实际任务变化与新周期继续刷新。重复交付不会重复广播。旧日常实际变化明确发出通知。
- Todo 每日重置边界扣除服务器时间的秒数，与 GetGameTime 的分钟精度对齐，防止同一边界逐秒漂移、反复改变投影。来源重置语义仍归 Todo。
- Todo 主快照和三个行动来源枚举角色时只读取身份；TaskHub 的目录、受益者、提醒和预览身份读取也使用该能力。
- AltoBoss 奖励／节日观察只在状态或周期变化时刷新。目标行动投影在失效、每日／每周周期变化、目标时效边界到达时重建；查询只截取已有投影，不再次计算全账号。角色更新、迁移、删除与目标服务注册／变化／注销都能失效。
- AltoBoss 按目标服务 registrationRef 和角色范围缓存配置，任务配置变化时清空；最多 24 个范围，避免逐个单元重复跨插件查询。未直接访问 TaskHub 内部数据。
- TaskHub 按 Provider 单独失效，保留无关来源。每个来源最多保留四个最近使用范围，防止提醒与账号／悬停范围交替查询反复覆盖缓存。统一时效计时取全部保留范围的最早边界，只移除已到期条目。
- TaskHub HUD／登录提醒只请求已通过统一角色准入的当前角色；主窗口与悬停继续使用各自账号范围，账号候选按原契约投影。

## 验证

`lua _NonRelease/TaskChainPerformance/PerformanceSpec.lua`：219 项专项断言通过（另外先运行既有134项行动集成、136项目标联动）。

| 场景 | 结果 |
| --- | --- |
| 200 次不变 Boss 观察及查询 | 全账号投影重建 0 次 |
| 200 次同角色配置读取 | 目标配置 Service 查询 0 次 |
| 真正失效后连续读取 | 重建 1 次，后续复用 |
| 200 轮当前／账号范围交替，两个来源 | 每个来源仅初次查询 2 次 |
| 其中一个来源变化 | 该来源再查 1 次，无关来源再查 0 次 |
| HUD 请求范围 | 仅已准入的当前角色 |
| 10,000 条物品的角色，400 次身份查询 | 完整记录深复制 0 次 |
| 200 次时间推进中的相同日常观察 | 通知 0 次；任务实际变化通知 1 次 |
| 200 次相同特殊活动观察 | 通知 0 次 |

现有 Overview、TodoSources、BossTargets、Todo 九个 smoke、Core Contracts／CharacterNames／RuntimePerformance 回归全部通过；四插件加载清单共 104 个 Lua 文件语法检查通过。检查次数与游戏帧耗时不是同一指标，不把本地断言换算为实际 MB／ms。

## 客户端复测

同步更新 Core、Todo、TaskHub、AltoBoss 后 `/reload`。在原先击杀并拾取“恐怖的战利品”的场景，分别测试关闭窗口与打开行动中心／悬停，记录稳定后内存和任务更新时 CPU／长帧。核对实际任务完成、奖励完成、切换角色与重置后状态仍刷新。当前保留已有任务配置与业务数据库，无数据迁移或删除操作。
