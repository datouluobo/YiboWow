# 行动中心：AltoBoss 按角色目标接入方案

日期：2026-10-09；实施更新：2026-10-10。状态：**TaskHub 0.4.0／AltoBoss 2.6.0 已实现运行代码与自动化，客户端待验收，未发布**。实际接口、支持边界与验证见 [运行契约与验收](行动中心-AltoBoss-运行契约与验收.md)。以下保留已确认的产品设计依据；拟定接口以运行契约为准。

## 1. 需求和当前缺口

用户在 Task（YiboTaskHub）中为不同角色配置 Boss／副本刷取目标。Task 保存目标与角色安排，YiboAltoBoss 对照自身业务事实判断进度并生成 action.todo；用户可选择让 Task 目标自动显示在 AltoBoss。只有配置目标的角色才产生对应工作。

当前源码核对结果：

- `Core.lua` 的 display.groups／items 为全局显示选择，不是逐角色刷取计划。
- `CoreIntegration.lua` 的 GetActions 遍历角色与 Boss 列表；不能直接拿这份文本摘要作为行动中心来源。
- `GetBossKillStatus` 在没有当期击杀／锁定记录时会返回 available；角色档案存在不等于已核实该角色当期可获取奖励。
- `InstanceLockouts.lua` 的 lockoutColumns 为悬停固定列偏好；正式副本页面展示完整目录和活动锁定，不代表玩家想刷所有副本。
- 副本扫描已有 difficultyID、逐 Boss killed 和 encounterID，但现有展示查询可按副本匹配任一难度；目标完成判断必须另有精确匹配入口，不能照搬显示匹配。
- AltoBoss 内部已有旧角色键到 Core ID 的解析。新配置与公开输出使用 Core 稳定角色 ID，旧快照只由 AltoBoss 内部适配。

## 2. 建议的最小产品模型

每份刷取计划包含一个稳定目标、适用角色集合、完成条件和来源认可的周期策略。显示范围与任务范围分别保存；关闭一列不取消计划，暂停计划不删除击杀历史。首次升级不自动把现有显示目标全部变成待办；新增角色也不自动加入。

| 项目 | 建议 |
| --- | --- |
| 世界／节日 Boss | 选择目标，勾选需要完成的角色 |
| 副本指定 Boss | 选择副本、难度／人数模式、稳定 encounter，勾选角色 |
| 整本目标 | 选择副本及精确难度，明确须完成的 encounter 集合；缺少完整目录时保持待核实 |
| 执行归属 | 每个选中角色分别完成自己配置的目标 |
| 周期 | 由来源依据目标的真实锁定语义提供，不给所有目标统一套每日／每周 |
| 停止方式 | 暂停或取消计划；周期性任务的本周期完成不取消未来周期 |

示例：角色 A 每周打怒之煞和炮舰；角色 B 只打炮舰；角色 C 只刷某副本指定难度的末王。A 打完怒之煞只完成 A 的对应工作，B、C 不受影响。

Task 主页面提供“行动总览”和“刷取目标”标签页；“刷取目标”承载查看、添加、调整与复制，不将全部编辑控件堆在总览中。Core 继续提供窗口壳与公共导航。配置以当前所选角色为主，双向复制作为常用操作：可以复制给多个角色，也可以从其它角色复制到当前角色。复制完成后各角色独立微调。

Task 的目标配置是唯一权威记录；AltoBoss 保存击杀、奖励锁定与副本进度。Task 目标标签页可以提供分别跳转到来源进度与编辑目标的入口。Core 的角色显示、排序和过滤继续使用原入口。

## 3. 完成条件

“打过一次”“本周期奖励机会已用”“整本通关”和“获得目标掉落”必须明确区分。

建议首版提供刷取机会类目标：世界／节日 Boss 优先采用来源已确认的当期奖励锁定；指定副本 Boss 采用精确难度的 encounter 完成事实；整本采用该目标要求的 encounter 集合全部完成。只有击杀但无法证明奖励锁定时，不把它自动当成奖励机会完成。共享锁定按来源已有组判断，例如四天神，避免同一机会重复催办。

获得坐骑／装备后永久停止属于另一种长期目标。仅配置刷 Boss 不能推断玩家要追求某件掉落，更不能从一次击杀推断已获得。将来需要物品／坐骑条件时，通过 Core 公开能力接入相应数据所有者；当前无此真实契约则由用户暂停目标。

普通可重复副本、手动重置、延长锁定和自定义稀有不自动套用周常模型。首轮核对客户端身份与锁定语义后，分别决定支持范围；无法可靠判断的目标说明原因并保持未知，或暂不允许保存为自动周期目标。

## 4. 状态与时效

| 条件 | 行动中心行为 |
| --- | --- |
| 没有刷取计划／角色未被选中／计划暂停 | 不生成待办 |
| 角色满足已验证资格，当前周期观察确认目标未完成 | 生成可处理任务 |
| 当期奖励／指定 encounter／整本目标已完成 | 输出 completed，默认列表移除 |
| 尚未采集、观察过期、资格或锁定身份不明 | 待核实，说明需上线／扫描，不作为肯定可做提醒 |
| 节日未开放 | 当前行动列表不催办；计划保留，开放后由来源恢复 |
| 本周期共享机会已被使用 | 按完成条件停止奖励机会提醒，保留来源依据 |
| 角色被 Core 隐藏／过滤 | 仅影响中心投影，不改变计划与完成事实 |
| 新周期到来 | 来源重建周期；旧完成记录不算新周期完成；能否直接判定可做取决于来源已验证的持续资格／重置证据 |

世界 Boss 活着、位面状态和预计刷新时间属于额外现场信息，不与角色奖励资格混为一项状态；没有现场观察不等于没有刷取计划，也不能承诺现在能立即击杀。

## 5. 数据所有权与公开契约

- **TaskHub**：保存用户创建的刷取目标、稳定目标 ID、适用 Core 角色 ID、启用／暂停与自动显示偏好；提供目标编辑、双向复制和任务聚合。
- **AltoBoss**：提供业务目标目录，拥有角色资格、精确锁定、采集证据、周期、完成判断和失效；消费 Task 的目标快照，构造只读业务进度与待办。
- **Core**：稳定角色 ID、既有工作台／页面、Provider 注册发现与通知。不接管 Boss 规则。

目标与业务事实分别存储，不将击杀／锁定复制为 Task 的第二份权威数据，也不将目标复制为 AltoBoss 的第二份可编辑计划。AltoBoss 可保留带目标来源及版本的可再生投影缓存。

### 5.1 最小协作链

复用 Core 已有 Contracts Service／Provider，按实际交付实现以下能力；名称为本方案拟定，尚未登记为运行时 API：

| 能力 | 提供方／消费方 | 最小职责 |
| --- | --- | --- |
| `boss.target-catalog` v1 Service | AltoBoss → Task | 只读查询可配置目标、稳定身份、难度／人数、encounter、名称与搜索别名、目录覆盖及可用性 |
| `task.boss-targets` v1 Service | Task → AltoBoss | 按明确 Core 角色范围返回目标快照、启用／暂停、自动显示开关、epoch／revision；仅查询配置，不触发进度查询 |
| `action.todo` v1 Provider | AltoBoss → Task | 目标与源业务事实结合后输出待办和时效 |

两个方向查询的数据分别为目录、目标和业务状态，Task 的目标查询不反向调用 AltoBoss，避免请求递归。初始化先订阅再发现；目标或目录发生实际变化，通过 Core 通知失效，合并后重查。AltoBoss 的进度变化只发布业务待办／进度变更，不把派生展示再次写回目标记录。

Task 不可用时 AltoBoss 自身追踪正常，自动展示投影撤下；AltoBoss 不可用／目录尚未注册／契约不兼容时，Task 保留已存目标，显示来源未就绪，不伪造完成状态。新的双向协作不增加业务插件 TOC 强依赖，也不访问彼此 SavedVariables。最低能力、参数、覆盖状态、错误与通知细节在实现前收敛为实际契约。

建议注册一个真实 `action.todo` v1.0 Provider：`YiboAltoBoss:planned-targets`，复用 API v11 / business-providers:1。公开 Query 仍接收显式 characterIDs。每个角色独立工作使用 execution.mode=self、beneficiary.mode=character。

公开任务的 itemKey 使用稳定计划／角色身份，temporal.cycleKey 使用来源周期。标题提供目标、必要难度／人数和指定 Boss；freshness 保留真实 observedAt、validUntil 和 nextChangeAt。未知不写为零，输出只读副本。身份不使用显示名或列表位置；EJ ID、地图 ID、保存副本 ID 和 encounter ID 须在来源内部建立经验证的对应关系。

同一角色／目标／难度／完成条件的重复配置应合并或拒绝。整本与指定 Boss 同时存在时，按共同 encounter 事实更新两项进度，展示为同一副本下的目标；不能把同一次击杀要求执行两次。首版可在保存配置时禁止重复包含，降低展示与提醒歧义，具体交互待确认。

已存在的 Core Provider 生命周期继续复用：独立持久 epoch／revision、合并变更、幂等注册、注销及晚注册。最低版本不足时明确提示升级 Core，只停止任务集成。查询不执行采集／修改计划，也不调用可能产生写入的旧状态辅助方法。

用户创建的刷取目标属于 Task 自建目标的首个真实场景。首次实现需要对 Task 数据库进行版本化升级，保持既有展示／提醒设置；后续跨插件需求沿用 Task 的用户需求所有权，并按真实场景扩展，不提前构建通用任务链。

## 6. 实施顺序和门槛

1. 落实 Task 内“刷取目标”标签页，保留已确认的逐角色配置与双向复制；按真实目录规模验证界面利用率。
2. 完成 AltoBoss 目标目录、身份／覆盖声明与中英缩写索引，验证难度和 encounter 映射；按业务采集证据明确可配置范围。
3. 在 Task 实现版本化目标存储、目标查询 Service、复制预览／合并与角色清理；发布真实契约和必要验证。
4. 在 AltoBoss 消费目标、补观察覆盖与周期、输出 action.todo，并实现自动显示投影；主表／悬停继续使用相同业务快照。
5. 验证世界／节日、已确认副本指定 Boss 与整本的真实闭环；同步契约、插件说明、产品计划及 CAP-005 台账。普通重复副本另验语义。

验证覆盖：不同角色不同目标、未选角色／新增角色不产生任务、暂停与恢复、共享锁定、错难度不能完成、指定 Boss 完成但整本未完成、重复配置不重复提醒、未知／过期、离线切号、周常／节日日常边界、延长锁定、角色隐藏与删除、API 不足、来源缺失／晚注册／注销。需要真实客户端证据的副本身份和重置必须单列记录，自动化不替代游戏验收。

## 7. 交互原型与待审阅项

用户已确认每个角色分别指定 Boss／副本，并认可可点击原型能完成需求，特别认可双向复制。原型使用示例角色和内存配置；其中角色列表／添加／复制／账号总览的操作流将纳入 Task 的“刷取目标”标签页。

- 角色下拉提供角色身份及目标数，目标列表只展示当前角色已安排内容，分世界／节日 Boss 与副本。
- 添加时选择分类并搜索；世界 Boss 可多选，副本在行内展开难度和指定首领／整本范围。
- 配置副本后折叠为单行摘要，保留调整入口；重复或同难度重叠目标给出提示。
- 复制到其他角色保留目的角色原有安排，先呈现新增／合并／冲突的变化，再确认应用，复制后相互独立。
- 从其它角色复制应在任何当前角色下可用；空角色显示直接操作，已有目标角色也保留入口。账号总览按角色列出目标数与摘要，并进入该角色配置。
- 目标可暂停／恢复或移出计划，模拟变更即时生效；原型不涉及删除真实击杀记录。

已在浏览器验证添加 Boss、调整副本难度／整本范围、复制去重、目的角色修改不影响来源角色；无脚本错误。

### 7.1 界面利用率

Task 的总览与目标管理各自使用完整 Core 内容区，仅在“刷取目标”内显示角色选择、目标数和两个复制入口。主列表紧凑呈现目标、必要难度／Boss 范围、启用状态和操作；编辑时展开当前目标的必要字段。搜索与分类只出现在目标选择上下文，已配置列表按需求提供相应检索。

角色和目标长列表采用 Core 分页／可用高度策略；先在安全高度内利用内容区，再按实际溢出决定纵向滚动，不用固定大留白、双滚动或横向滚动承载配置。中文长名、英文长名、同名跨服务器角色和多首领摘要均须可读；完整信息可通过详情展开查看，操作不依赖悬停。

### 7.2 搜索与目录完整性

- 以稳定业务身份建立目录；每项包含中文名、英文名、经核对的缩写／常用别名，以及所属资料片、副本、难度和 encounter 关系。
- 搜索支持中文、英文和缩写，英文字母忽略大小写，规范空格及分隔符；例如同一冰冠堡垒条目可由“冰冠堡垒”“Icecrown Citadel”“ICC”命中，具体别名以实际目录为准。
- 搜索副本内 Boss 应命中所属副本并提示匹配的 Boss，不要求用户预先知道副本名；缩写碰撞返回全部相关项，显示副本与难度上下文。
- 搜索命中不自动选择难度、人数或完成范围，不把缩写当作业务身份。完整名称永远可访问。
- 选择器使用来源完整、明确覆盖的目录。原型的少量示例不构成正式支持清单；已存目标在目录未就绪时仍显示原引用与可用性，不能因筛选无结果而丢失。
- 尚不能验证的身份、难度或 encounter 明确标注并限制相关操作；目录加载中、来源缺失、已知空结果与不支持分别呈现。

### 7.3 双向复制与数据完整性

从其它角色复制和复制给多个角色使用同一合并规则。默认追加／合并，保留目的角色独有目标；复制只涉及计划配置，不复制击杀／完成记录或当前周期进度。

按稳定目标、角色和精确难度去重。指定 Boss 部分重叠时，保留原有 Boss 并补齐缺少项，不能因为一个 Boss 重叠就跳过整项；整本与指定 Boss 重叠须明确展示目标范围变化。暂停状态差异不得静默覆盖，应在变更预览中说明处理结果。目标选择、去重与合并作为一次完整提交，失败不留下部分角色已复制的中间状态。

校验覆盖：复制后独立修改、双向反复复制、重载、数据版本迁移、同名角色、目录未就绪、跨资料片／难度身份、目标暂停与取消、Core 角色移除及当前来源不可用。搜索与列表筛选只改变展示，不修改隐藏项。

### 7.4 自动在 AltoBoss 显示

Task 的 Core 工作台业务设置增加开关：**“在首领追踪中自动显示刷取目标”**，建议初始开启。开关值由 Task 保存；目标标签页可显示当前开关状态并跳转该设置。

- 开启：AltoBoss 的目标展示纳入 Task 中已启用目标。角色级标记明确哪些角色配置了该目标；列集合可取可见角色目标的并集，但不能因一列出现就将全部角色视为需要完成。
- 手动显示配置与 Task 自动投影分别保留来源，有效展示取并集。副本需保留配置难度／指定 Boss 的精确信息，不让同名副本合并掩盖目标区别。
- 关闭：撤下仅由 Task 自动引入的展示项；AltoBoss 原有手动显示配置及全部业务记录保留。Task 目标和提醒继续生效。
- 暂停／取消目标：及时撤下其自动投影；若仍有其它角色目标或手动展示来源，该项继续显示相应范围。
- 本周期完成：停止 Task 待办提醒，AltoBoss 保留目标完成状态供核对；下一周期依来源规则更新。
- 未安装／禁用／晚注册／版本不兼容：保留目标与偏好，展示未连接状态；兼容能力就绪后自动恢复。开关控制展示，不控制进度判断及 action.todo 输出。

目标编辑与业务状态变化通过 Core 公开契约通知。自动显示投影可重建，并带目标来源及版本；不写入另一插件的手动配置，也不通过显示名称关联角色或目标。

首版世界 Boss 完成条件的奖励机会建议仍须结合真实业务例外核对；副本支持范围以目录和客户端验证结果为准。上述要求为后续实现与验收基线。
