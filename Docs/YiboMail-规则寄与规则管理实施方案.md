# YiboMail 规则寄与规则管理实施方案

> 日期：2026-10-06。
>
> 方案状态：已确认。实施状态：0.11.1 已完成代码接线与自动验证，目标客户端布局、操作能力及事件时序待游戏内验收。
>
> 适用客户端：仓库当前基线为熊猫人之谜经典版，Interface 50504；客户端操作能力须实测。
>
> 本文是规则寄、规则管理及本次快捷寄件扩展的实施基线。相关主题与此前路线图、三阶段方案或联系人方案有差异时，以本文为准。收件箱、账号总览、现有历史和通讯录的其它已确认功能沿用原方案。

## 1. 目标与范围

前期在 Core 设置页建立规则，日常在游戏邮箱的“规则寄”页完成装填和发送。用户通过固定位置的主按钮或快捷联系人，交替点击装填与发送，处理当前角色背包中符合规则的可寄物品。

首版交付：

1. 系统邮箱新增“规则寄”标签，保持邮箱框架和操作位置连续。
2. 指定物品、游戏分类两种规则，分类支持排除物品。
3. 当前角色命中规则、冲突、临时跳过与恢复。
4. 单规则装填、同收件人多规则合装、超容量分封。
5. 主按钮和快捷联系人共用装填／发送状态。
6. 规则寄页面拖放到快捷联系人建立指定物品规则。
7. 发件箱页面拖放到快捷联系人快速寄件，支持客户端能力不足时回退为装填。
8. 规则管理接入 Core 统一设置，发送结果进入现有历史。

首版数量策略为全部寄出；“保留 N 个”安排后续更新。分类采用游戏分类，不建设自定义分类编辑器。每次发送由玩家操作触发，等待本封结果后才能处理下一封。

## 2. 入口与职责

| 位置 | 职责 |
| --- | --- |
| 系统邮箱 → 发件箱 | 手动编辑邮件、通讯录、快捷寄件和拖放快速寄件 |
| 系统邮箱 → 规则寄 | 匹配当前背包、查看规则与异常、装填、核对、逐封发送 |
| Core 设置 → YiboMail → 规则管理标签 | 新建、编辑、启停、筛选规则和维护分类排除列表 |
| Core 主窗口 → 历史记录 | 展示全部发件结果，规则寄沿用现有历史数据与状态 |

规则寄提供“管理规则”入口，跳转 Core 设置的 YiboMail 页面并选中“规则管理”标签。规则维护固定在设置页；无需打开邮箱才能维护。业务控件由 Mail 提供，窗口壳、导航、滚动和位置由 Core 管理。

Core 入口悬停继续服务账号邮件摘要；规则冲突在规则寄的规则区直接呈现。发送成功只表示已发送／在途，送达与退回须沿用实际扫描证据。

## 3. 规则寄页面布局

邮箱标签顺序为“收件箱｜发件箱｜规则寄”。保持现有邮箱的位置、外框尺寸、标题栏、关闭按钮和快捷栏位置。新增标签不得挤压或遮挡原有控件。

页面上方为规则区，下方为附件预览；附件格和底部主按钮与发件箱保持相同位置。通过减少规则区可见行数及内部纵向滚动适配，不为规则寄另建更宽的邮箱窗口。

```text
┌──────────────────────────────────┐  ┌──────────┐
│ 当前角色命中规则     [管理规则] │  │ 快捷栏   │
│ 矿石 → 仓库角色         [跳过] │  │ 命中者   │
│ 布料 → 仓库角色         [跳过] │  │ 突出显示 │
│ ⚠ 指定物品收件人冲突   [处理] │  │          │
├──────────────────────────────────┤  │          │
│ 收件人：仓库角色                │  │          │
│ [附件][附件][附件][附件]        │  │          │
│ 本封数量／格数 · 剩余封数       │  └──────────┘
│ 状态说明       [撤下] [主按钮] │
└──────────────────────────────────┘
```

规则行显示匹配对象、收件人、可寄数量和堆叠数；当前处理行有选中状态。冲突以异常行放在规则区，显示物品与冲突数量，点击查看涉及规则和收件人并进入编辑。异常提示使用图标和文字，不能只靠颜色。

无命中时说明“当前背包没有符合规则的可寄物品”，提供管理入口。信息未加载时显示待识别；不能提前显示为零命中或完成。规则多时保持表头、附件预览和底部操作可见，避免横向滚动。

## 4. 规则定义与设置管理

### 4.1 规则字段

| 字段 | 语义 |
| --- | --- |
| 稳定 ruleID | 规则身份，不使用行号或名称作为键 |
| 匹配类型 | 指定物品／游戏分类 |
| 匹配对象 | itemID，或稳定的游戏分类及子分类标识 |
| 收件人 | 经现有通讯录地址规范化后的完整角色地址 |
| 适用角色 | 全部角色；目标为当前角色时跳过 |
| 分类排除列表 | 按 itemID 保存，仅分类规则适用 |
| 启用状态 | 持久启停，停用保留配置 |

规则与排除列表由 YiboMailDB 保存。收件人总开关独立保存于 `sendRecipientDisabled`，按规范化完整地址关联，默认启用；暂停收件人会阻止其所有规则匹配，但不改写单条规则的启用配置。游戏分类使用稳定标识，名称仅用于本地化显示；不同语言不能改变匹配结果。客户端未提供或尚未加载的分类，不用物品名称猜测。

### 4.2 设置布局

Core 左侧导航仍只保留 YiboMail 业务插件项。右侧 YiboMail 设置内容区使用固定标签条，顺序为“业务设置｜规则管理｜数据与缓存”：

| 标签 | 内容 |
| --- | --- |
| 业务设置 | 适用的收发件业务偏好、通讯录来源和快捷栏业务配置 |
| 规则管理 | 规则列表、新建／编辑、启停、筛选、分类排除和冲突说明 |
| 数据与缓存 | 现有缓存维护及规则删除等需确认的破坏性操作 |

规则管理属于 Mail 业务设置能力，只在右侧内容区作为一个标签呈现，不新增 Core 左侧导航项或独立设置窗口。切换标签保持 Core 导航、页面标题和标签条位置稳定；通用页面、入口、字段及角色排序继续由 Core 的对应页面管理。没有适用内容的分区不显示。

“规则管理”标签左侧为常驻添加／编辑区，右侧为搜索与按收件人分组的规则列表；宽屏时左侧占扣除间距后宽度的 58%，安全宽度不足时上下排列，两区始终可见，不切换编辑页面，不使用横向滚动。左侧直接提供收件人、匹配对象和分类黑名单；唯一主按钮根据选择状态显示“添加规则／保存修改”，“清空”恢复添加状态。物品确认、黑名单添加和明确的“拖放到此”按钮复用 Core ItemPicker。规则统一适用于全部角色。

收件人输入框右侧直接放置“选择收件人”，打开与发件箱共用的通讯录。匹配方式使用“物品／分类”互斥二选一，位于匹配输入同行左侧；物品输入右侧紧接小尺寸“确认物品／拖放到此”按钮，输入后确认、按回车或拖放成功后保留物品 ID。分类模式同一位置提供游戏分类与子分类选择，下方维护当前分类规则的黑名单。

右侧收件人和规则名称采用普通文本。收件人行仅有 ASCII `+ / -` 折叠按钮和独立总开关；折叠仅收起规则，不改变左侧草稿或规则状态。点击带物品／分类图标的规则行载入左侧编辑，单条规则保留启用勾选。搜索命中组自动展开，清空后恢复折叠状态；长列表按完整收件人分组分页。名称显示复用现有 Mail `Recipients:Label()`：同服省略服务器，跨服保留服务器，完整地址仍用于存档、匹配与寄送；Core 公共名称格式化接口另起任务处理，本次不改动 Core。

新建、编辑和分类排除维护均留在该标签内容区。邮箱“管理规则”入口直接选中此标签；冲突行的“处理”入口还应定位相关规则或冲突。定位规则不应直接覆盖尚未保存的编辑草稿，须提供保存、放弃或留在编辑的选择。

分类编辑可选游戏大分类／子分类，排除列表支持拖入、搜索添加与移除，并显示物品名称和图标。分类名称与具体候选范围须在目标客户端核对后形成明确列表，不能宣称当前客户端无法可靠识别的细分类。

收件人阵营内置在资料中，地址仍采用规范化完整角色地址。账号角色的阵营从 Core `Characters:GetAllCached()` 的 `faction` 读取，Core 是账号角色身份事实的权威来源；缺失时等待该角色登录采集。Mail 为外部联系人维护 `recipientFactions[地址键] = { faction, source, updatedAt }`，来源为用户确认或可靠的普通邮件成功证据，不按添加者阵营、名称或发送失败猜测。首版成功证据仅采用附带金币且发送成功的邮件，记录发送时阵营；附件邮件可能存在账号绑定例外，不能据此推断。

阵营已知时无需显示编辑控件；编辑的收件人阵营未知时提供“确认联盟／确认部落”，右键“选择收件人”可修正外部联系人的确认资料。规则寄中只对实际命中的未知阵营规则显示处理入口，点击定位设置中的规则。管理列表对当前角色不适用的收件人显示状态，保留启用配置。

相同匹配对象允许分别配置已知不同阵营的收件人，同阵营或阵营未确认的重复规则仍拒绝。匹配按当前角色阵营过滤对立阵营目标；未知目标参与匹配优先级占位，避免具体规则未确认时向宽泛分类回落。装填及发送前再次校验阵营；Core 身份领域更新和联系人阵营确认使旧计划失效，通过公开 `DATA_DOMAIN_UPDATED` 通知延迟读取已投影角色资料，无需新增 Core 字段或接口。

编辑区下方提供全局黑名单，统一排除物品和发件角色，对所有规则生效。物品支持 ID／名称输入确认与拖放，发件角色支持填写账号中已登录过的角色名及一键加入当前角色；名单以紧凑文本行显示，每页最多六项，逐项移除。全局黑名单独立保存，修改立即生效，规则草稿的清空或保存不影响名单；分类排除仍随对应规则保存。

Mail 在自身 SavedVariables 中保存 `sendBlacklist.items[itemID] = true` 和 `sendBlacklist.senders[Core角色ID] = 完整角色地址`。角色关联使用 Core 稳定 ID，完整地址仅用于显示，角色 ID 变更事件同步迁移关联。旧数据未包含黑名单时初始化为空。

删除规则等破坏性操作位于“数据与缓存”末尾，明确显示对象并确认。导航及业务插件排序沿用 Core 规则；页面、入口、字段和角色排序不在 Mail 业务页重复实现。

## 5. 匹配、排除与冲突

1. 只处理当前登录角色的实际背包物品；离线快照、银行和收件附件不能成为本次装填来源。
2. 先检查启用状态、收件人以及物品信息与可寄条件。
   全局黑名单优先于任何规则：排除发件角色时本次匹配为空；排除物品时跳过其全部背包堆叠，指定物品规则也不能覆盖。名单变更使已装填计划失效，发送或装填过程中等待结果，避免重入或重复寄送。
3. 指定物品规则优先于分类规则；同类分类中更具体的子分类优先于大分类。
4. 分类排除只作用于所属分类规则；物品仍可通过有效的指定物品规则寄出。
5. 被匹配分类明确排除的物品，不向更宽泛分类回落。多个同等具体分类的排除语义必须保持一致，不能让加载或遍历顺序决定结果。
6. 每个背包物品只能归入一个目标。相同优先级指向不同收件人为冲突；相同目标可以去重归并并保留来源 ruleID。
7. 冲突物品不装填，其它明确命中的物品继续处理。设置页与规则区展示同一匹配结果；预览说明冲突而未加入的物品数量。
8. 临时跳过作用于已确定归属的规则，不把物品重新分配给低优先级规则。

保存时阻止明显重复或冲突的配置，并说明已有规则；运行时仍处理已有数据、范围交叠或数据异常产生的冲突。不能用最后保存者或最后加载者静默决定收件人。

## 6. 执行计划与分封

规则匹配输出可寄物品、归属规则、规范收件人、来源背包位置、完整物品链接、数量及异常原因。执行计划是本次邮箱会话的派生数据，不作为第二份物品库存保存。

支持三种执行范围：

- 默认全部：主按钮按稳定顺序处理所有未跳过且无冲突的目标。
- 单条规则：点击规则行，只处理该规则命中的物品。
- 指定联系人：点击快捷联系人，处理归属于此人的全部未跳过且无冲突物品。

同收件人物品可以合装，收件人不同必须分封。容量读取客户端实际附件上限，按整组堆叠确定格数；超出容量拆成多封，不截断剩余物品。首版不为填满邮件格而主动整理背包或合并堆叠。

默认建议顺序为完整收件人地址、ruleID、itemID、背包及槽位；相同输入结果必须稳定。快捷栏优先让玩家自行选择目标。切换执行范围后主按钮继续处理当前范围；范围完成后回到全部剩余范围，并明确显示目标变化。

## 7. 主按钮与快捷联系人状态

主按钮与发件箱发送按钮位置一致。按钮文字、可用状态和快捷联系人动作由同一执行控制器生成。

| 状态 | 主按钮 | 动作 |
| --- | --- | --- |
| 有有效计划、附件为空 | 填入附件 | 装填当前范围第一封 |
| 装填中 | 正在装填 | 禁用，等待实际附件确认 |
| 已核对当前附件 | 发送 | 本次玩家点击触发本封发送 |
| 等待发送结果 | 正在发送 | 禁用，不接受重复发送或装填 |
| 成功且还有剩余 | 填入下一封 | 下一次点击重新核对并装填下一封 |
| 当前范围结束、还有其它目标 | 填入附件 | 显示新的目标，等待下一次点击 |
| 全部完成 | 已完成 | 禁用 |
| 计划失效 | 重新匹配 | 重新计算，随后由下一次点击装填 |
| 失败或结果不明 | 检查邮件 | 停止推进；检查实际草稿与结果后恢复 |

装填和发送每次各消耗一个独立的玩家点击，事件、计时器或结果回调不能自动执行下一次发送。一次点击只能执行它开始时的动作，不能在同一回调中随状态更新继续执行发送。

快捷联系人第一次点击装填，实际装填确认后再次点击同一联系人发送。命中联系人突出显示，当前已装填联系人有选中状态，悬停说明当前动作和剩余物品。主按钮与快捷格可交替使用；点击其它联系人只能切换目标，不能发送上一位联系人的邮件。

快捷栏没有保存的命中收件人仍可通过规则列表和默认主按钮处理，不自动改写快捷格。

## 8. 跳过、草稿与生命周期

设置页停用持久生效；规则区“跳过”仅本次邮箱会话生效。跳过项收起到“本次已跳过”，可以恢复；关闭邮箱后清除跳过状态并重新计算。

装填后跳过、切换规则或联系人时，先撤下本次控制器拥有且尚未被修改的附件；玩家修改过附件时停止并提示核对，不强行整理。手动发件草稿存在时不覆盖收件人、主题、正文、金额或附件，提示先发送、取消或整理当前草稿。

规则寄默认金额为零且不使用 COD；主题生成必要的简明附件摘要，正文为空。原有草稿金额与 COD 状态不能带入规则寄。预览必须显示真实收件人和实际附件；外部手动编辑导致指纹变化时立即取消可发送状态并重新核对。

装填前后核对背包来源、物品链接、数量、目标附件槽及收件人；以实际附件确认装填成功。背包变化只在影响计划时使其失效，正常装填导致物品从背包移入附件不能误报异常。

装填与收件队列互斥。战斗、邮箱关闭、原生锁定或确认提示、鼠标持有其它物品时停止相应操作并说明原因。关闭邮箱清理临时计划和操作状态，实际附件归还以客户端行为为准，重开重新扫描。切换标签保留未发送实际邮件并协调草稿所有权，不复制一份附件状态；所有入口读同一实际邮件。

## 9. 拖放快捷操作

### 9.1 规则寄页：建立规则

拖物品到已配置快捷联系人，显示紧凑确认“将〈物品〉寄给〈联系人〉”，确认后保存指定物品规则并刷新命中。规则按物品身份建立，拖放数量不限制后续匹配数量。保存不移动或发送物品。

已有相同指定规则时定位已有项；收件人不同时显示原地址与新地址并确认修改。鼠标物品必须正确归还，取消及失败不得丢失或移动物品。

### 9.2 发件箱页：快速寄件

拖物品到已配置快捷联系人时，只处理鼠标上这组物品的实际数量，不扩展为背包中所有同物品。

在没有附件、金额、COD、主题和正文草稿的前提下，填入联系人和该组附件；若目标客户端支持在该玩家拖放事件中稳定完成发送，直接发送。若客户端能力限制不支持直接发送，完成装填并等待玩家点击发送。

已有草稿时提示先处理，不混入后直接寄走。拖放目标为空槽时保持现有配置槽位交互，不能把物品误当地址。实际发件调用已发生但结果尚未确认时，只等待结果，不能因为未即时成功又回退或重复发送。

## 10. 数据、历史与架构

规则、排除列表及业务设置归 YiboMailDB。新增版本化规则结构，建议独立保存规则结构版本和规则 revision；会话计划引用 revision，规则变化时失效。

账号角色范围使用 Core 稳定角色 ID，邮寄目标使用通讯录规范地址；两者职责不同，不能用显示短名关联数据。Mail 只依赖 Core 公开接口，不引入其它业务插件依赖或读取其 SavedVariables。

规则寄、快捷点击和拖放直接发送共用现有发送结果采集及历史入口。可在现有历史详情附带操作来源、ruleID 和本封附件摘要；不建立独立规则寄历史表。每次操作只写一份历史，MAIL_SEND_SUCCESS 后才记录为已发送／在途；失败和结果不明遵守现有状态口径，不自动重试。

## 12. 实施顺序与验收

1. 核对客户端分类、第三标签、附件装填与发送调用，以及拖放直接发送能力；必要时使用独立非发布探针。
2. 完成版本化规则模型、匹配优先级、排除与冲突，再接入 Core 设置管理。
3. 完成执行计划、实际附件核对、分封和单次点击状态推进。
4. 接入规则寄上下布局、固定按钮、快捷栏、跳过和异常行。
5. 接入两种拖放语义及直接发送回退，复用现有发送历史。
6. 清理相关残留，完成自动验证、目标客户端验收及文档状态更新。

验收至少覆盖：

- 三标签切换外框稳定；附件预览和发送按钮位置一致；小屏、UI 缩放及长列表可操作。
- Core 的 YiboMail 设置三标签位置稳定，规则新建／编辑／排除维护均在“规则管理”内完成；邮箱管理与冲突处理能直接选中标签并定位，未保存草稿受保护。
- 指定物品、游戏大／子分类、分类排除、指定规则例外、角色范围及同角色目标跳过。
- 同目标去重、不同目标冲突、排除不回落、跳过不转投低优先级；设置与前台结果一致。
- 单规则、联系人合装、默认全部、超容量分封和稳定顺序；未列入快捷栏的目标可处理。
- 主按钮连续点击、快捷联系人连续点击及交替使用；装填／发送期间重复点击不执行，切换联系人不误发。
- 成功推进、失败停止、结果延迟或不明、背包变化、规则修改、外部附件修改和手动草稿保护。
- 临时跳过与恢复、邮箱关闭重开、标签切换、鼠标持物、战斗、收件队列和原生确认提示。
- 规则寄拖放确认／取消／已有规则修改；发件箱拖放实际数量、草稿阻止、直接发送可用及回退路径。
- 所有发送来源只产生一份现有历史；失败不标送达，发送成功不宣称目标已收到。
- 规则数据迁移、信息待加载、不可寄物品及分类缺失；任何未采集信息不得解释为零。

自动测试验证归属、状态推进、API 调用次数和失败恢复；客户端验收确认布局、真实拖放、保护限制、附件归还和事件时序。模拟通过不能替代真实客户端操作验证。
