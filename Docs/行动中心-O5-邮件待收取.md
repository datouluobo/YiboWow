## 最小契约与所有权

- 需求：在当前角色与其他角色列表中查看非付款邮件的附件／金币收取工作。
- 能力 `action.todo` Provider v1.0，来源 `YiboMail:inbox-collection`，显示名“邮件待收取”。提供方和唯一业务数据所有者为 YiboMail，消费方为 YiboTaskHub；连接经 Core.Contracts。
- 方法 `Query({scope={characterIDs={Core角色ID...}}})`，仅输出请求角色，去重；空数组为空，未知角色返回 not-yet-scanned。返回标准 envelope、coverage 和 tasks 的值副本。
- 每封邮件以 Core 角色 ID 与现有 mailKey 形成稳定业务引用，保留 sourceEpoch；不以主题、收件箱位置或显示名关联。同名邮件由 Mail 原有身份匹配负责。
- 仅输出 visibleKeys 中仍 observed、具有附件或金币且 cod=0 的记录。复用 ViewModel:GetMails 的 actionable 与 restriction；纯文本信、付款信、历史／未核实积压不生成可收取任务。
- 当前角色邮箱打开且扫描有效时，已确认的邮件可以为 actionable；部分扫描中已观察邮件也可操作，coverage 保持 partial。离线、关闭邮箱、扫描错误及估计到期均为 unknown，不能提示确定可收取。
- observedAt 沿用邮件观察时间；期限使用来源 expiresAtEstimate，作为下一次核实边界，不按到期推断已收取。期限未知时保持 unknown。查询不采集、不更新观察时间。
- state=active，temporal=persistent；邮件从当前可见快照消失后不再输出，不能据此构造交易／物流完成证据。收取部分附件后按 Mail 的实际身份与新快照更新。
- nextAction 仅在邮件账号页已启用时指向 mail-inbox。没有任务写入、收取或完成操作接口。

## 版本与生命周期

邮件基础功能仍要求 Core API v9 / business-services:1。新增集成单独检查 API v11 / business-providers:1 和实际方法；不足时明确提示升级并停止新集成，邮件基础功能继续运行。TaskHub 不新增 Mail 的 RequiredDeps／OptionalDeps，不读取其 SavedVariables 或实现对象。

来源在自己的数据库 actionTodo 保存 sourceEpoch 和 revision；任务快照保持可再生。注册幂等，先订阅自身邮件变化再注册；初始失败清理订阅。邮件变化经来源内部 Items.Events 合并为 Core 的 Provider 失效通知，revision 标识邮件快照失效，不保证每次都有任务数量变化；读取不反向广播。Shutdown 注销并取消旧排队回调，重注册不会产生重复来源。
