# 无限服与 MoP 功能差异台账

建立日期 2026-11-10。记录两个客户端的功能差异与证据。插件版本、验收和发布状态另见[无限服适配与发布验收台账](无限服适配与发布验收台账.md)。

## 状态和更新规则

2026-11-10 用户明确无限服以现有 MoP 插件为功能与交互基线。开始适配前先定位 MoP 对应入口、行为与数据范围，再核对无限服已经确认的能力。目标差异落在原生数据读取、规则和必要的呈现适配。MoP 没有的功能单独提出，得到用户明确同意后再开发。

- **已确认**：用户明确确认，或同目标的原生界面／实际操作与取证一致。记录证据覆盖的具体范围。
- **局部取证**：已有正向样本，其他职业、等级、规则或操作尚未覆盖。
- **待确认**：当前证据无法判断。保留问题，待自然样本或用户确认。

新增适配前核对对应条目。已确认范围可以开发，功能是否存在或实际规则有疑问时先问用户。API 存在、接口空结果、低等级角色尚未解锁或离线模拟均不足以确认功能。用户明确确认的缺失同样登记。更新时保留条目编号，写清日期、目标客户端、角色条件及证据来源，原始样本继续放在对应插件的验收记录。

| F02 | 天赋解锁、洗点、第二配置 | MoP 的门槛和配置行为按其客户端规则 | **待确认**。无限服截图中第二配置处于锁定，解锁条件、洗点后的事件时序及第二配置的行为待证。 | 自然遇到时用现有探针对照，无需专门洗点或提前解锁。见[天赋取证](../YiboBuilds/Docs/Forever-天赋取证与适配准备.md)。 |

| F08 | 邮箱取件与 Vault 附件联动 | MoP 侧依其邮件事件与插件契约 | **局部取证**。本服附件取件前后数量和最终状态已对照，自动刷新时序待自然样本。 | 按用户约定顺带观察，无特别反馈按正常处理。见[收件与仓储记录](无限服-仓储搜索与收件筛选-2026-11-09.md)。 |
