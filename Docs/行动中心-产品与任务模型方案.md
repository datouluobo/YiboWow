## 0. 当前方案：从业务项目主动添加目标

### 0.1 产品入口与默认行为

TaskHub 是用户目标清单。新用户没有任务；安装、注册来源、开启业务监控、新建角色或切号都不自动创建 Task 目标。用户在业务页面选定对象并添加后，中心才生成对应行动。主列表、悬停、HUD 和登录提醒读取同一份已添加目标投影；空清单提供添加引导，不显示自动推导的工作或空登录提醒。

主页面保留当前角色与其他角色视角；任务按明确执行范围组织。目标管理用于查看、编辑、暂停、恢复、移除及批量复制，具体对象的发现与选择优先留在业务页面。既有“刷取目标”编辑和双向复制可作为同一目标库的专用视图，不再形成独立于通用目标的第二份计划。

### 0.2 统一添加交互

- 默认鼠标中键；Core 统一设置提供鼠标按键及修饰键组合配置，保存一份全局偏好。与已有交互冲突时提示并要求选择可用组合，不能同时执行添加和原有业务操作。
- 只在来源明确声明可添加的项目、单元格或按钮上启用。通用壳、导航、关闭按钮和无业务对象的空白区域不注册添加行为；不全局拦截任意按钮。
- 悬停显示实际手势及“添加到行动中心”；同时提供可见菜单项。原点击行为保留，新增组合只消费明确命中的添加操作。
- 对象、角色及完成条件齐备时直接添加并显示轻量反馈；缺少必要参数时打开紧凑配置面板，只询问缺失项。鼠标手势和菜单使用同一路径。
- 矩阵单元格携带准确角色；只有目标名称或行标题时必须选择角色／账号范围。使用 Core 稳定角色 ID，不依赖当前登录角色、显示名称或表格下标。
- 已添加项目展示标记；再次点击定位既有任务或打开其配置，不增加数量、不重复创建，也不直接删除。编辑、暂停和移除由明确操作完成。
- 批量添加／复制先展示目的角色与变更摘要，复用已有双向复制经验；每个角色后续可独立调整。首个交付无需通用任务链编辑器。

### 0.3 各业务的目标类型

| 来源 | 用户添加的目标 | 来源必须解释的条件 |
| --- | --- | --- |
| Todo | 指定角色的一项冷却、日常或活动 | 资格、周期、就绪和完成；冷却就绪与材料齐全分开 |
| AltoBoss | 指定角色的 Boss／副本 | 精确难度与首领集合，单次或来源认可的重复周期 |
| Vault | 指定物品的数量目标 | 角色或账号范围、仓储来源、阈值、一次达标或持续保持 |
| 声望之路 | 指定角色的某项声望 | 稳定声望对象、目标等级或进度、可证明的完成状态 |
| Crafting | 指定角色制造某产物 | 产物／配方选择、数量、制造次数或成品持有条件；库存增加不直接证明制作 |
| Builds | 某角色某件装备的附魔／珠宝提升 | 装备身份、具体强化要求、适用性与实际应用证据；获得物品不等于应用完成 |

所有业务插件遵循同一接入协议。各插件按实际可表达的对象逐项接入，完整清单见实施计划；没有有效目标的纯操作按钮不制造占位任务。不同任务保留业务参数，不强行统一为“物品＋数量”。

### 0.4 职责与契约边界

| 所有者 | 本阶段职责 |
| --- | --- |
| Core | 通用点击绑定与清理、手势偏好、共享控件与窗口壳、角色身份、既有 Service／Provider 连接；不保存任务或业务规则 |
| TaskHub | 用户目标及约束的持久化、去重、编辑、暂停／移除、完成历史、目标投影与提醒 |
| 业务来源 | 可添加对象、必要参数、目标校验、资格、进度、最终完成、周期、时效、来源页面定位 |

通过 Core 已有 Contracts 注册与调用公开能力。拟复用并细化尚未交付的 `action.demands` 写入和 `action.targets` 描述／评估；现有 `action.todo` v1 保持兼容，只能作为已添加目标的行动依据，来源注册本身不等于用户添加。接口草案与已存在的 Boss 专用 Service 分开记录，不能假定已有通用添加 API。

Task 保存“用户要什么”，来源保存“业务发生了什么”。来源暂缺、不兼容或数据过期时保留目标，标记来源不可用／待核实，不将未知当零或完成；恢复注册后重新验证引用。Task 未安装时，业务页面原有功能正常，添加入口明确提示能力未就绪。

### 0.5 最小持久目标与身份

每个目标保存中心 ID、稳定来源与目标类型、来源业务引用及版本、明确角色／账号范围、用户条件、重复策略、优先级、生命周期、创建／修改时间和必要完成历史。来源快照是带来源、观察时间与失效时间的可再生缓存，不作为第二份权威数据。

来源生成与验证规范化意图身份：至少区分业务对象、角色／账号范围、完成模式、难度或仓储等语义条件。显示文本、当前登录角色、来源注册次数和当前周期不作为持久目标身份。重复请求有幂等键；同一目标重复添加返回既有记录，数量或条件变化进入显式编辑。周期实例另含来源提供的周期 ID，重置不新建另一份用户目标。来源 epoch 只解释数据连续性；变化后重新核实，不静默重绑同编号对象。

### 0.6 生命周期、显示与业务监控

- 单次目标完成后退出默认待办，进入已完成记录；重复点击仍定位原记录，重新执行须明确操作。
- 周期目标保留配置与各周期历史，由来源声明下一周期何时恢复；Task 不另算每日／每周重置。
- 持续数量监控在来源确认不足时恢复待办，达标时停止行动提醒；单次达标目标不随库存减少重新打开。
- 暂停、移除、显示隐藏、业务监控是不同操作。隐藏角色／字段不删除任务；移除任务不关闭来源监控，不删除业务完成记录。
- 在 Task 添加目标不要求用户再到另一处重复选择同一项目。来源对明确目标独立校验与评估，不能直接用来源页面“已监控列表”限制查询。缺少采集时说明需要什么数据；如需开启来源采集，通过来源公开操作并明确告知，不暗改其设置。
- Core 显隐只改变展示，不改变已保存目标的角色归属或账号库存统计范围。既有单项显隐偏好可保留，但不再充当目标创建或主要管理方式。

### 0.7 旧数据迁移与性能约束

保留用户已经明确创建的逐角色 Boss 目标、难度／首领条件、暂停状态及复制后的差异。将它们映射为通用目标时保留稳定关联，原 Boss 视图与 AltoBoss 自动展示引用同一记录，避免双向重复添加。

当前自动汇总的 Todo／Mail 工作，以及旧的显示／隐藏开关，都不是用户添加意图，不自动转成目标。升级说明明确新的清单规则；已有配置留存，不清空来源数据。新装默认空；升级后仅保留可证明由用户主动创建的目标。数据迁移须版本化、可重复执行、失败不覆盖原记录。

空清单跳过业务进度查询；非空清单只查询有关来源、目标与角色。以稳定目标 ID 和范围批量读取，缓存键包含目标集合／配置版本和来源版本／时效；来源变化按影响范围合并失效。普通界面刷新、角色名格式化、显隐开关不触发全账号重算或完整角色记录复制。来源尚不能按目标查询时先补最小契约，不能长期全量扫描后过滤。

行动中心是独立业务插件。既有阶段集中展示已注册来源任务；新阶段仅展示用户已添加目标对应的工作，帮助决定当前角色做什么及还需登录哪些角色。主页面的两个角色视角、只读悬停、HUD 和登录提醒继续复用同一投影。来源拥有业务状态、执行条件与完成判断，中心拥有用户目标并负责组织和展示。

### 1.1 首阶段的两个视角

| 视角 | 内容与判断 |
| --- | --- |
| 当前角色行动 | 当前角色为自己或其他角色执行的工作；分别展示已安排工作、可承接候选和等待／待核实项目，突出来源确认的可推进动作 |
| 其他角色今日任务 | 当前角色之外的有效业务角色按角色分组，显示今日可推进、等待与快照未知的任务；帮助决定下一次登录哪个角色 |

两个视角是同一任务集合的筛选，不保存两份任务。C 为 A 制作宝石时，执行角色是 C，受益角色是 A；该工作按执行者进入 C 的列表，不因 A 受益就把制作动作列为 A 可执行。收取或使用只有来源实际提供相应工作时才列入 A 的行动。

角色范围、显示隐藏和排序复用 Core。来源查询覆盖请求中的明确角色范围，主页面筛选不修改业务快照或来源自己的页面范围。无业务快照的角色不补出空任务行；来源未覆盖与明确无任务分开表达。

### 1.2 工作归属与候选

- 自己的工作、指定执行者的工作、开放承接工作和账号工作均由来源明确声明执行范围；受益角色与执行角色分别提供，未知时保持未知。
- 跨角色工作须已有来源记录及执行安排，或由来源明确返回开放工作和候选资格。中心不根据“某角色缺宝石、另一角色会珠宝”自行生成安排。
- 已指定给 C 的工作不列为 D 的候选；开放工作可在 C、D 的候选区域同时出现，但只有一条任务身份，登录不自动承接。
- 角色统计区分已安排工作与候选机会。账号总数按唯一任务去重，各角色候选数不能直接相加为账号任务数。
- 首阶段在中心查看并跳转来源页面；来源拥有承接、编辑和完成操作。来源没有对应操作入口时仅展示，不提供伪造的完成或承接按钮。

### 1.3 “今日”与数据时效

“今日任务”指当前业务周期内有效、今天值得关注的工作，不统一按本地午夜清空。日常、周常、专业冷却及长期工作由来源给出周期、有效性和下一次变化时间；长期工作仍可作为今天的行动，标注其周期性质。

可推进、准备动作、阻塞和未知由来源判断。冷却就绪不自动证明材料齐全或现在可制作。中心按来源声明的失效时间刷新或标记过期，不另算一套重置规则。离线快照保留观察时间与有效性；未知、未采集、过期和已知无任务分别呈现，过期数据不产生肯定的行动提醒。

完成后的默认行动列表不再提醒该项；周期更新后的新任务由来源给出。中心隐藏或排序只改变展示偏好，不改变来源完成状态。

### 1.4 首阶段最小任务信息

| 信息 | 作用 |
| --- | --- |
| 来源、稳定任务标识与数据代次 | 去重、更新、来源失效和定位；周期任务另含周期标识 |
| 执行范围、指定角色或候选角色 | 生成当前角色与其他角色视角；账号工作保留一份身份 |
| 受益范围与受益角色 | 区分为自己做与为其他角色做；未知时不推断 |
| 标题、行动描述、来源状态与就绪依据 | 表达做什么、是否能推进和阻塞原因 |
| 周期性质、观察时间、有效性与下一变化时间 | 解释今日与离线状态 |
| 来源页面及业务引用 | 回到业务页面操作；不传递私有函数 |
| 物品、数量与进度（按类型） | 来源已有依据时展示，不要求非物品任务填写虚假数量 |

具体字段与返回外壳见 [最小能力契约 v1](行动中心-最小能力契约-v1.md) 的 action.todo。首阶段持久化中心设置；业务快照使用带来源与时效的可再生缓存，默认留内存，重载后重新查询。

### 1.5 首阶段与后续能力

首阶段围绕来源任务聚合和两个角色列表验收，依次扩展悬停、面板及登录提醒。中心自建任务、需求下发、数量预留、自动物流和任务链属于后续能力；下面已确认的模型规则保留，按真实跨角色场景分批实施。完整模型测试不作为两个角色列表的交付前置。

### 1.6 后续持久需求与任务链的已确认规则

| 项目 | 已确认规则 |
| --- | --- |
| 归属 | 独立行动中心拥有用户需求、任务链、分派、数量预留与提醒；Core 提供通用连接和界面基础设施 |
| 组织 | 一份需求可以拆成 N 条任务；多个候选执行者共享需求数量 |
| 部分推进 | 物品任务按已确认可处理数量推进，已产出的部分可先交付；业务要求整步完成的条件另行保留 |
| 补做记录 | 确认供给流失后先寻找其它可用成品，仍有缺口时新增关联的补做任务；原制作事实和完成历史保留，最终需求数量不增加 |
| 分派 | 支持自由承接和指定角色；候选资格与实际承接分开 |
| 默认改派 | 只改派未执行部分；已产物、实际持有角色与原物流保留，交付安排可单独修改 |
| 在途编辑 | 允许修改未来数量与目的地；先展示受影响任务、超量和转交计划，用户确认后保存，已发生的物流事实保持不变 |
| 目标变化 | 目标已满足时自动完成；目标失效时暂停，保留产物和物流记录 |
| 现有成品 | 自动分配明确匹配、可信、可转交且未占用的成品，按剩余缺口安排制造 |
| 材料转交 | 确定制造角色后，自动安排材料转交任务，并跟踪物流 |
| 分配顺序 | 用户优先级优先，同级按创建时间；优先级变化不自动抢占已有预留和在途物品 |
| 提醒 | 默认一次轻量登录摘要加常驻面板；统一设置工作台可选择仅面板或弹出列表，面板显示可独立配置 |
| 异常 | 支持人工校正，保留原因、时间和证据性质 |
| 证据冲突 | 保留人工校正与相冲突的自动证据，标记待核实，仅暂停受影响部分的自动补做和完成推进；不静默覆盖用户安排 |
| 编辑 | 主窗口可编辑任务链和字段；悬停只读展示 |

## 2. 职责与数据所有权

| 所有者 | 权威数据和职责 |
| --- | --- |
| YiboCore | 角色唯一标识与范围、能力注册发现、通用事件、账号窗口、统一设置与入口生命周期 |
| 行动中心 | 首阶段拥有展示／提醒偏好与可再生聚合投影；后续拥有用户意图、需求数量、任务关系、承接与改派、数量预留、工作流状态及人工校正 |
| 来源业务 | 业务目标、候选选择、资格与可执行判断、完成证据、周期与失效语义 |
| Crafting 类提供者 | 已确认配方、产物与材料关系、制造角色资格和快照时效 |
| Vault 类提供者 | 已扫描物品数量、位置、可用性与数据覆盖状态 |
| Mail 类提供者 | 寄出、在途、收取等邮件事实及关联依据 |

首阶段中心保存设置并读取业务稳定引用；查询结果只作带来源与时效的派生视图，不成为第二份业务任务、库存或配方数据库。后续持久需求保存必要的历史证据描述，人工校正只修改中心任务记录。

业务通过 Core 注册与发现的公开契约协作。Core 不按业务插件技术名决定规则，也不保存中心的需求数据。查询采用能力调用与返回；事件描述状态变化，由消费者按需刷新。注册、版本、晚注册、注销与通知合并在 API 阶段具体设计。

中心只对 Core 声明强依赖。首阶段业务来源缺失或不兼容时，相应任务不可查询，失效缓存不继续显示为可执行；其它来源与中心页面继续可用。全部来源不可用时提示暂无可用来源，不能宣称账号没有任务。后续持久需求保留已保存的需求和历史，相关资格、库存或完成判断进入待确认状态，基础编辑和人工管理继续可用。

### 2.1 两种来源

- **来源业务任务（首阶段）**：包括业务即时待办与来源已经保存的跨角色工作；权威状态归来源插件，中心读取、筛选和展示。中心的排版、隐藏或排序偏好不修改来源完成状态。
- **持久用户需求（后续）**：业务按钮或中心编辑器创建；需求与任务链由中心保存，进度依据来源事实和人工校正更新。

同一来源实体的自动待办与持久需求须建立关联，避免当前角色列表重复提示同一工作。关联依据稳定来源键，不按文字标题猜测。

## 3. 后续模型：需求、任务链与任务

### 3.1 需求

需求描述最终目标，保存稳定编号、来源引用、需求角色、目标实体、所选目标与数量、优先级、生命周期和用户约束。

装备提升的目标引用须区分角色、装备对象、槽位及适用构筑上下文；仅物品 ID 或显示名称不足以关联具体目标。引用与目标是否仍适用由来源解释。

一次重复下发同一目标不能自动增加需求量。明确增加数量与重复点击须区分；合并细则在契约阶段确定。

### 3.2 任务链

任务链组织满足需求的各条工作及前置关系。允许并行分支，例如宝石与附魔各自准备；前置关系构成无环依赖图，列表顺序不代替依赖。

物品流转按数量推进：需求三颗、已制作两颗时，可以先寄送、收取和使用这两颗，剩余一颗继续准备。下游处理量受本步骤剩余量、已确认可供本步骤使用的数量及业务条件共同约束；不能仅用前置任务的累计完成量判断当前可用物品，也不能把同一份数量重复放行。

前置条件区分数量流转与业务整步条件。数量流转不要求上游整个任务完成；来源业务确实要求整步完成时，仍须满足该条件。具体可执行条件由适用业务解释。

任务链保存自动规划结果与用户覆盖。用户改派、改数量、改前置等作为明确约束保留；后续重新规划检查其有效性，并更新受影响的自动部分。

### 3.3 任务字段

| 字段 | 含义与编辑规则 |
| --- | --- |
| 稳定编号、所属链、来源 | 用于关联、去重和历史；中心维护 |
| 任务类型 | 制造、寄送、收取、使用或其它业务操作 |
| 物品／业务对象、数量 | 本步骤处理的对象；不要求非物品任务填写虚假物品或数量 |
| 需求角色 | 最终受益角色，可从需求继承 |
| 承接角色 | 本步骤责任角色；为空时由候选角色自由承接 |
| 接收角色 | 转交目的地，可为制造者或中转角色，区别于最终需求角色 |
| 能力条件 | 商业技能、具体配方或其它操作要求，由适用业务提供资格判断 |
| 前置任务 | 可多条；保存前校验引用、循环与后续影响 |
| 完成条件 | 按任务类型选用有定义的条件；来源证据与人工确认分别标识 |
| 计划、已确认完成、剩余数量 | 支持部分完成；完成数量依据事实或明确校正，不能仅由编辑目标数量生成 |
| 优先级、备注 | 默认继承任务链，可覆盖 |
| 生命周期、就绪性、当前阶段 | 分别记录任务进度、可执行依据与物流等展示状态 |
| 物品占用及物流关联 | 引用本需求的数量分配和流转证据；中心维护 |

## 4. 后续模型：状态与阶段

为防止“缺少数据”被解释成“工作未完成”，采用分离的状态维度。以下为产品状态定义，运行时编码待后续确定。

### 4.1 需求生命周期

| 状态 | 进入条件与处理 |
| --- | --- |
| 待处理 | 需求有效，尚未开始处理 |
| 进行中 | 已有准备、制造、物流或使用工作在推进 |
| 已完成 | 来源确认最终目标满足，或用户明确人工确认；制造完成本身不等于最终目标完成 |
| 暂停 | 来源确认目标失效，或用户暂停；停止工作提醒，保留事实与历史 |
| 已取消 | 用户明确取消；释放可释放的未来计划占用，已寄出物品仍保留物流记录 |

来源缺失或数据过期属于待核实依据，不自动把目标判为失效。已完成需求保持完成历史，新的装备需求另建；未完成需求发生供给流失时重算缺口。

### 4.2 任务生命周期与就绪性

- 生命周期：待处理、已承接、处理中、已完成、暂停、已取消。
- 就绪性：可处理、前置未满足（包括可处理数量不足）、缺材料、等待物流、待核实、能力不可用等。
- 当前阶段：例如待寄送、邮寄中、待收取、材料就绪、待使用；由实际工作和证据生成。

登录和常驻提醒读取当前角色可推进的下一步工作，不能仅按生命周期为“待处理”就判定可做。检查资格须同时考虑业务条件、已分派约束、前置关系、物品可用性和时效。

## 5. 后续模型：数量预留与物流

### 5.1 数量守恒

1. 需求数量是最终所需量，不是链上所有步骤数量之和。
2. 制造、寄送、收取、使用引用同一批成品流转，不能各扣占一份库存。
3. 同一来源、物品身份和可用数量不能同时分配给多条需求。预留是中心的计划记录，不会阻止游戏内出售或交易。
4. 支持多来源、部分数量和部分交付；补做只针对确认后的剩余缺口。
5. 材料按具体配方的投入与产出关系计算；成品和原料是不同对象，不能简单相加。无已确认材料关系时不自动生成数量。
6. 制造候选多个时只有一份制造工作。登录不会自动承接；明确承接或指定后才产生面向该制造者的材料转交计划。
7. 需求按已确认计划建立一次数量预留，各阶段引用并移交同一预留；等待前置条件的步骤不重复扣占，也不因自身暂不可执行而释放已有有效预留。例如制造者已确定但缺材料时，可以预留来源角色的材料并安排转交。新分配按优先级与创建时间执行，现有有效预留不被自动抢占；来源不可信或目标不适用时按核实或暂停规则处理。
8. 可自动利用的成品必须匹配所选目标、状态可信、可访问或可转交，且未占用；可转交边界由业务事实确认。

### 5.2 物流状态与异常

| 事实 | 产品处理 |
| --- | --- |
| 成品已确认可供本需求使用 | 停止对应数量的制造提醒，进入交付或使用阶段 |
| 邮寄给目标角色 | 跟踪寄出、在途和收取；在途数量继续覆盖需求，不生成重复制造 |
| 邮寄给自己的中转角色 | 保留最终需求角色和当前目的地，收取后安排下一段转交 |
| 挂 AH | 标记暂不可交付，提示处理；默认保留关联等待撤回、成交或人工决定，防止立即重复制造 |
| 确认出售或转交外部角色 | 释放失去的可用数量，先尝试其它可信成品，再按剩余缺口补做 |
| 物品消失，无法确认去向 | 待核实，暂停针对这部分数量的新制造提醒；不因一次缺失就推断售出 |
| 制造材料已消耗 | 根据确认的制造事实移交投入与产出记录，不把正常消耗判为材料丢失 |
| 数量或目的地发生变化 | 校验受影响步骤，保留已发生事实，并调整剩余工作 |

已发生的制作事实不因成品售出而被抹掉。确认供给流失后先寻找其它可用成品，仍有缺口时新增补做任务，关联原需求、原制作记录、流失原因和本次补做数量。原制作任务保留已完成部分和历史，不因补做重写为尚未制作；原任务未执行的剩余部分继续单独计入制造承诺。主窗口可将原制作和补做任务归组展示。

物品增加、减少或邮箱附件消失本身不充分证明属于某条任务。自动关联必须有足够来源证据；无法确认时允许人工关联和校正，展示其人工性质。

### 5.3 历史、供给与制造承诺

按每个最终目标项分别计算，材料和成品、宝石和附魔等不同目标不能直接合计：

- **最终完成量**：按该目标的最终完成条件确认的数量；制作或收取不直接等于最终完成。
- **当前供给覆盖量**：已分配给本需求且位置可信、适用的成品，包括可信在途数量；同一份物品只有一份当前覆盖。
- **待核实保留量**：去向不明或挂 AH 暂待处理的已关联数量，用于抑制重复准备；不代表肯定可交付。
- **未执行承接量**：已分派、尚未转化为确认成品的制造数量，包含原任务剩余部分及补做任务的未完成承诺。
- **累计步骤事实量**：历史上实际制作、寄送、收取或使用的数量；各步骤分别保存，不能相加成需求完成量或现有供给。

```text
尚需满足量 = max(0, 目标量 - 最终完成量)
待准备量 = max(0, 尚需满足量 - 当前供给覆盖量 - 待核实保留量)
可新承接量 = max(0, 待准备量 - 未执行承接量)
```

覆盖、核实保留和未执行承接中的同一数量互斥；已确认制作将相应承诺移到供给，寄送和收取只更新位置，最终使用后移到最终完成量。供给的可用性和关联依据来自业务事实，中心保存分配意图与任务历史，不另建权威库存。

补做任务只填补仍未覆盖、也未被已有制造承诺承担的数量；新增补做任务或重复刷新不能增加最终目标量、重复分配同一缺口。补做记录保留准备过程，但不抹掉此前确实已经发生的制作。

## 6. 后续模型：主窗口编辑与人工校正

主窗口提供账号需求和当前角色工作两种视角；可新增、拆分、取消任务，改数量、责任角色、接收角色、能力条件、优先级及前置关系。不同类型只显示适用字段。

- 以一次保存校验整组修改，检查数量、引用、循环、冲突和后续影响；校验失败保留草稿并说明原因。
- 显式指定某角色不代替能力确认；不满足条件时显示原因，不生成肯定的可做状态。
- 承接可以释放或改派；默认只转移未执行部分的责任，原角色已制作的产物继续按其实际位置和原交付计划处理。已寄出、已收取、已制作的事实保持原记录，用户可单独修改未来交付安排。
- 部分完成后改派须分开已执行事实与未执行承诺。例如 C 负责三颗、已完成两颗，改派给 D 时撤销 C 剩余一颗的责任并由 D 承接一颗；C 已制作的两颗继续由 C 按原计划交付，不重复生成制造任务。
- 材料尚未寄出时，按新制造者重新检查并调整未来转交计划；已经寄给 C 时保留原目的地，待 C 收取后再安排 C 向新制造者转交。改派后的可执行条件须重新检查，不能仅修改角色字段就推断材料到位或具备资格。
- 更改目标或能力后重新检查匹配和适用性；不能直接把旧宝石换个标签就当作适用的新宝石。
- 提供解除预留、确认去向、重新准备、改派及人工确认等纠错操作。人工修正保存原状态、操作者角色、时间、原因与关联数量。
- 任务与链的取消、清理涉及用户数据，使用明确风险说明和确认；已发生的物流不会随取消而被撤销。
- 自动同步更新任务状态不覆盖用户正在编辑的草稿；保存时检查任务版本和冲突。

### 6.1 在途编辑的影响预览

物流进行中仍允许编辑未来计划。修改需求量、接收角色、物品、配方或关联目标时，保存前展示已发生事实、受影响数量与任务，以及计划停止、保留和新增的后续工作；用户确认后统一保存。预览不执行游戏内寄送、制作或使用操作。

| 修改 | 保存后的处理 |
| --- | --- |
| 改接收角色 | 保留原寄出目的地；按实际收取与可转交条件添加后续转交。实际到货前不显示新角色拥有物品 |
| 减少目标量 | 保留已寄出和已完成事实，停止多余的未执行工作；超量在途物品继续显示真实去向，待到货或返回后再按可用性释放占用 |
| 增加目标量 | 保留原供给和物流，只对新增缺口重新分配成品或安排制造 |
| 目标量低于已完成量 | 保留历史处理量，按新目标判断完成；剩余量不为负，不倒扣已发生事实 |
| 改物品或配方 | 旧产物及物流保留原身份，重新检查是否适用于新目标；不适用或待确认部分不伪装成新物品供给 |
| 编辑时出现新业务事实 | 重新计算影响并提示变化；草稿和新事实均保留，不能按旧草稿覆盖新进度 |

最终需求角色和本段物流接收角色分别编辑与校验。原需求仍由 A 使用而接收角色改为 E 时，E 是中转角色；若最终需求角色或装备目标也变化，须由来源重新检查目标适用性。

### 6.2 重复、迟到与冲突证据

| 情况 | 处理规则 |
| --- | --- |
| 同一证据重复到达 | 只应用一次，补充证据不增加第二次制作、寄出、收取或完成数量 |
| 较早的可比较快照迟到 | 不倒退同一关联对象较新的已确认进度，不撤销较新的人工校正 |
| 背包、邮件等来源同时包含同一批物品 | 根据关联处理一次位置迁移，不把各来源数量直接相加；无法确认关联时待核实 |
| 较新且可靠的业务证据与人工校正真正冲突 | 保留双方记录与依据，标记待核实，由用户核实；不以新证据直接覆盖人工状态或安排 |
| 无法判定证据时序、身份或关联 | 保留不确定性，不推断物品不存在、已售出或目标完成 |

冲突隔离到受影响的任务、物品数量和下游依赖，暂停这部分自动补做和完成推进；其它独立数量、分支和需求继续正常运行。冲突处理沿用人工校正入口，保存处理依据和前后状态，不删除原记录。

例如用户标记某批物品已收取，后续可靠证据显示该批仍在途：界面并列展示人工确认与新证据，提供核实入口；不能自动再制造一批，也不能把人工确认无提示地改为未收取。用户完成核实后再按已确认状态重算剩余工作。

具体证据身份、版本、事实时间、观察时间和人工修正时间在契约阶段定义。不同来源的时间与版本只有满足契约可比较条件时才能用于先后判断。

## 7. 展示与提醒

### 7.1 展示位置

- 主窗口：注册为 Core 统一账号页面，首阶段提供两个角色列表、来源／时效和业务跳转；后续加入中心任务编辑和校正。
- 悬停：只读投影，复用同一快照、状态、数量与过滤规则；左键按入口规范打开主页面。
- 常驻追踪面板：显示当前角色工作与必要的等待信息，保持紧凑。位置、锁定、折叠等具体交互在 UI 阶段设计。

入口悬停默认预览全部有效业务角色（最多 20 名），使用角色分组的任务型只读布局，复用主页面同一快照、角色准入、状态与数值格式；仍由 Core 创建、定位和关闭。任务型例外仅涉及布局，当前角色常驻面板另按当前角色筛选。预览字段按仓库设置规则管理。

常驻追踪面板是新增展示形式，具体通用外壳与生命周期边界在 UI 方案中确定；主窗口、设置壳及入口继续复用 Core。

### 7.2 登录提醒

- 默认在本次登录首次数据就绪后发一次轻量摘要，同时更新常驻面板。
- 用户在 Core 统一设置工作台的中心业务设置中选择：轻量摘要加面板、仅面板、弹出列表；面板显示独立配置。
- 摘要只计入来源确认当前角色可推进的工作；候选机会单独标识，已指定给他人的工作不提醒当前角色执行，未知或过期快照不计为可做。
- 数据未就绪时显示检查状态；后续新增可处理工作通过面板标记提示，不反复发送初始登录摘要。
- 主页面、悬停、面板和提醒使用同一工作投影；角色切换后依据新的当前角色重新生成。

## 8. 场景审查与验收目标

### 8.1 首阶段总览验收

| 场景 | 预期结果 |
| --- | --- |
| 当前 C 有自己的日常与为 A 执行的来源工作 | 当前角色列表同时展示两类工作，执行者和受益者清楚；不推导未提供的下游任务 |
| 同一开放工作有 C、D 两名候选 | 各自候选区域可见，账号唯一工作数为一，登录不自动承接 |
| 来源把工作指定给 C 或确认完成 | D 不再出现该候选；完成项停止行动提醒，两个视角同步更新 |
| 查看其他角色今日任务 | 按有效业务角色分组，展示可推进／等待／未知；不为未采集角色伪造任务或空结果 |
| 日常重置、专业冷却到期、长期工作跨日 | 按来源声明更新周期与有效性，长期工作保持身份，中心不按午夜复制任务 |
| 离线快照过期或部分采集 | 保留状态和观察时间，不把未知当未完成或可执行 |
| 来源缺失、禁用、晚注册、注销、异常或不兼容 | 只影响相应来源；注册恢复后重新查询；空结果与无可用来源不同 |
| 页面切换范围、重载和同源重复通知 | 角色身份与来源范围正确，稳定任务去重，投影重建，刷新不产生循环 |
| 主页面、悬停、HUD 和提醒 | 共用任务集合与判断；角色视角及摘要统计口径一致 |

### 8.2 后续持久需求模型验收

以下是本次文档层面的逻辑审查；运行时测试与游戏验证尚未执行。

2026-10-08 已完成本轮人工场景推演，六项规则已补齐并同步，见 [详细模型审查](行动中心-详细模型审查.md)。本轮规则作为后续契约设计依据；以下场景表作为验收目标，不代表实现已通过。

| 场景 | 预期结果 |
| --- | --- |
| C、D、E 都会所需配方 | 一份可承接任务，多位候选；一人承接后不对其余角色重复安排制造 |
| F 有两颗成品，A 只需一颗 | 自动预留一颗，另一颗仍可供其它需求使用 |
| 两条需求争用一颗成品 | 按优先级、创建时间分配一次，另一条保留缺口 |
| 新需求提高优先级 | 影响新分配，不抢占有效预留及在途物品 |
| C 承接制造，材料在 F | 自动安排 F 向 C 转交，C 收齐后制造；最终需求角色仍为 A |
| 收齐部分材料或交付部分成品 | 只推进已确认数量，剩余部分继续等待或安排 |
| 需求三颗、C 已做好两颗 | 两颗可先交付，另一颗继续制作；前置关系不会把两颗锁到整批完成 |
| C 负责三颗、已做好两颗，剩余改派 D | C 的两颗继续原交付，D 只负责剩余一颗；责任分配原子更新，不出现两人同时承担同一颗 |
| 制造改派 D 时材料已寄给 C | 原 F→C 物流保留；C 收取后再安排 C→D，D 不提前显示材料到位 |
| C 制作后挂 AH | 停止肯定的可交付提示，显示待处理，不立即要求 D 补做 |
| C 确认把成品交易给外部玩家 | 原制作历史保留；确认剩余缺口后才重新安排 |
| 需求一颗，C 制作后确认售出，账号无其它可用成品 | 新增关联的一颗补做任务，原制作记录保留，最终需求仍为一颗；补做已承接后不再重复分配 |
| C 邮寄成品给中转角色 F | 继续跟踪本需求的物流，不把转移当成成品丢失 |
| 成品已寄给 A，A 尚未登录 | 保留在途覆盖，停止重复制造；无法确认收取时不自动完成 |
| A 已收到但未应用到目标装备 | 收取任务完成，需求仍待使用 |
| A 通过其它方式满足原目标 | 来源确认后自动完成需求，处理剩余预留；保留已经寄出的物流 |
| A 换掉目标装备 | 暂停需求和工作提醒，保留产物、物流与编辑记录 |
| 材料或成品去向不明 | 待核实，可人工校正；不把未知当零 |
| Crafting、Vault 或 Mail 缺失、不兼容、晚注册或注销 | 相应增强等待确认；需求保留，恢复来源后按新证据刷新 |
| 来源插件仍在但快照已过期 | 显示数据状态，不产生肯定的可做或已完成判断 |
| 用户编辑邮寄中任务的接收角色 | 保留已寄出的真实目的地，未来转交按新计划安排 |
| 两颗已寄给 A，目标减少到一颗 | 预览并确认调整，保留两颗寄出事实，停止多余未来工作，超量在途物品不提前作为新可用库存分配 |
| 制造因缺材料等待，来源 F 有可信可转交材料 | 确定制造者后可建立一次材料预留并安排转交；寄送、收取、制造不重复扣占该材料 |
| 用户新增循环前置或重复分配 | 保存校验失败，草稿保留，原链仍可查看 |
| 同一寄出或收取证据到达两次 | 只处理一次，完成和供给数量不增加第二次 |
| 人工确认已收取，较新可靠证据显示同批仍在途 | 保留双方记录，标记冲突，只冻结受影响部分的自动推进，等待用户核实 |
| 一条分支出现证据冲突，其它分支事实明确 | 冲突分支及受影响下游待核实，其它独立工作继续展示与推进 |
| 当前角色切换、重载后打开各展示面 | 使用相同任务快照，已保存需求、预留和人工记录保持一致 |
