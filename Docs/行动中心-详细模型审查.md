## 1. 方法与结论

审查按“起始状态 → 实际发生的操作或编辑 → 证据到达 → 数量与责任变化 → 各角色下一步提醒”逐步推演。

每一步检查以下不变量：

1. **需求唯一**：候选者、任务拆分、补做与中转不产生额外最终需求。
2. **数量互斥**：同一份成品只能处于一个当前供给位置或在途状态，不能同时按寄出背包、邮件和收件背包算三次。
3. **历史保留**：实际制作、寄出和收取记录保持其原对象、数量与角色。
4. **补做有界**：只对确认的供给缺口安排新准备工作；去向不明部分保持待核实。
5. **责任明确**：已承接数量只有一个当前责任者，改派不保留两份有效工作分配。
6. **未来可编辑**：修改只调整未来计划；与事实冲突时说明影响，不直接改写事实。
7. **证据可重复处理**：重复或迟到的同一事实不增加第二次完成量，也不覆盖较新的人工校正。
8. **展示一致**：主窗口、悬停、常驻面板与登录提醒使用相同数量及就绪条件。

## 2. 数量口径

以下已同步到产品模型，用于解释数量关系，不是运行时字段或 API 定义。

- **目标量**：最终要满足的数量。
- **最终完成量**：已经按需求完成条件确认的量。装备需求通常指已应用量，不是制作量或收取量。
- **当前供给覆盖量**：已分配给本需求、位置可信且适用的成品量，包含可信在途数量；同一份物品只计算一次。
- **待核实保留量**：此前关联的物品现在去向不明，或挂 AH 暂待处理的量；暂时抑制自动补做，不代表肯定可交付。
- **未执行承接量**：已经分派给某角色、尚未转化为确认成品的制造数量；不是现有库存。
- **累计步骤事实量**：某步骤历史上实际处理的数量，用于审计，不能跨步骤相加成需求完成量。

模型的计算顺序：

```text
尚需满足量 = max(0, 目标量 - 最终完成量)
待准备量 = max(0, 尚需满足量 - 当前供给覆盖量 - 待核实保留量)
可新承接量 = max(0, 待准备量 - 未执行承接量)
```

同一数量不能同时计入覆盖、核实保留和未执行承接。例如制造确认后，相应数量从承接量移到供给覆盖；收取后只更新供给位置；应用后从供给覆盖移到最终完成量。

缺口是供给规划的输入，不代表制造任务在材料和能力上已经可执行。补做前先寻找其它可分配成品；无可信供给时才安排剩余制造数量。

任务中某步骤完成的含义须按类型明确：寄送在可靠寄出证据后记录寄出量；收取在可靠收取证据后记录收取量；最终需求根据来源目标判断。物流事实关联不足时保留待核实。

## 3. 部分完成推演：目标三颗宝石

假设需求允许分批满足，C 已承接制作三颗，所有数量关联均有可靠证据。数量为假想产品案例，不引用实际配方或客户端扫描能力。

| 步骤 | 实际变化 | 最终完成 | 当前供给覆盖 | 核实保留 | 未执行承接 | 可新承接 | 应显示的工作 |
| --- | --- | ---: | ---: | ---: | ---: | ---: | --- |
| 0 | C 承接三颗，尚未制作 | 0 | 0 | 0 | 3 | 0 | C 准备／制造三颗；其他候选不重复承接 |
| 1 | C 已制作两颗 | 0 | 2 | 0 | 1 | 0 | C 可制造剩余一颗；若采用按量放行，两颗可先交付 |
| 2 | C 将其中一颗寄给 A | 0 | 2 | 0 | 1 | 0 | 一颗在 C、一颗在途；不是总共三颗供给 |
| 3 | A 收取并应用该颗 | 1 | 1 | 0 | 1 | 0 | 原寄出量不再次算供给，需求仍需两颗 |
| 4 | C 将手里的一颗确认售出 | 1 | 0 | 0 | 1 | 1 | 原制作两颗的历史保留；新增一颗可承接的补做缺口 |
| 5 | D 承接新增一颗 | 1 | 0 | 0 | 2 | 0 | C 负责原剩余一颗，D 负责补做一颗；总制造承诺两颗 |
| 6 | C、D 各完成一颗 | 1 | 2 | 0 | 0 | 0 | 两颗进入交付阶段 |

判定：用户已确认按数量推进，步骤1的两颗可以提前交付；某些业务必须整步完成的前置条件继续保留。已同步到模型方案 §1、§3.2、§4.2 和场景表。此项为文档规则确认，尚未完成运行时验证。

提醒数量不得把“一颗寄送、一颗收取、一颗应用”展示为需准备三颗。主窗口可以显示多个阶段任务，需求摘要仍按最终缺口计算。

## 4. 补做与未知去向推演

### 4.1 制作完成但供给流失

需求一颗，C 已制作一颗：原制造工作记录已完成，供给覆盖为一。

- 确认售出或交给外部玩家：覆盖变为零；先自动尝试其它可用成品，未找到时生成一颗待准备工作。
- 原制造历史保留，补做用新的工作记录关联同一需求与流失原因；不额外新建最终需求。此记录方式已由用户确认，主窗口可归组展示原制作和补做任务。
- 补做工作已被 D 承接后，后续刷新不能再给 E 分配同一颗。

### 4.2 无法确认去向

此前供给一颗，现在物品消失但去向不明：覆盖转为核实保留一颗，待准备为零。

- 显示“去向待核实”，停止针对这颗的自动补做提醒。
- 用户确认已售出：移除核实保留量，按缺口重新规划。
- 用户确认已寄给 A：关联物流，移回在途供给；不能再记为新增加一颗。
- 挂 AH：保留暂不可交付关联，提示撤回、确认成交或人工选择补做。用户选择补做时解除相应抑制，但保留拍卖去向记录。
- 物品后来返回：根据明确关联更新位置；若已有替代供给覆盖目标，则作为多余可用库存处理，不能抢占或加大原需求。

### 4.3 重复制造事实

同一次制作证据到达两次，累计制作仍为一；已有一颗补做承诺不会因重复事实再次释放或再次补做。证据无法稳定区分时须核实，而不是假定两次制作。

## 5. 改派推演

已确认默认只改派可调整的未执行工作量，已产物继续按实际位置和原交付计划处理；用户可另行修改未来交付安排。实际角色、产物位置和物流事实保持原记录。

| 起始情况 | 用户操作 | 建议结果 |
| --- | --- | --- |
| C 尚未制作，未发生材料物流 | 将三颗全部改派 D | 原 C 的三颗承诺撤销，D 接受三颗；能力与材料条件重新校验 |
| C 已做两颗，剩一颗未制作 | 将剩余改派 D | C 保留两颗产物及制作历史，D 负责一颗；已有两颗由当前位置继续交付 |
| 材料在 F，仅预留尚未寄出 | 将制造 C 改成 D | 在可信且可转交条件下更新未来 F→D 计划，保持材料单次预留 |
| 材料已经寄给 C | 将制造改派 D | 原 F→C 在途事实保留；显示 D 等待，待 C 收取后添加 C→D 转交工作 |
| C 已领取材料，但 D 没有资格 | 指定 D | 保存责任意图时显示资格不符／待确认，不伪造可做；后续补足或改派 |
| C 已制造但尚未寄出 | 将寄送责任改为 D | D 不持有该物品，必须先有 C→D 的转交方案；不能仅改责任人就显示 D 可寄 |

尚未寄出的计划可取消或重新分配；已经寄出的事实、邮件目的地和材料位置不能通过改派撤销。

部分已完成任务可拆为历史部分与剩余工作；两部分有明确关联，数量总计不增加。界面可以归在同一行展开，底层记录形式后续决定。

## 6. 物流中的编辑推演

已确认采用影响预览后保存：先展示真实物流、受影响数量和任务，再由用户确认调整未来计划。以下推演已同步到模型方案 §6.1，运行时验证待实施。

### 6.1 改收件人

起始：C 已把两颗寄给 A。用户希望接收角色变为 E。

建议结果：

1. 原物流仍为 C→A、数量二，保存寄出事实。
2. 未来交付意图改为 E 时，根据实际收件和可转交条件建立 A→E 的后续工作。
3. 目标仍需 A 使用时，说明 E 是中转角色；若同时修改最终需求角色或目标，重新检查来源目标有效性。
4. A 尚未收取时，E 不显示拥有这两颗或可直接使用。

### 6.2 减少需求量

起始：目标三颗，已寄两颗，另有一颗尚未制作；用户改为只需一颗。

- 原寄出两颗的事实不变；未制作的一颗取消未来计划。
- 两颗在途物品中只需一颗覆盖新目标，另一颗列为超出需求的关联物流，不计为新缺口或立即变成可供别处使用的已到货库存。
- 待收取后，再按实际位置和可用性释放多余物品占用；当前需求只要求应用一颗。
- 若目标降低到已完成量以下，原完成事实保留，显示超出新目标的历史处理量，不产生负数。

### 6.3 增加需求量

起始：目标一颗，该颗已在途；用户增加到三颗。

- 保留原一颗的在途覆盖。
- 新增缺口二颗，先寻找成品，再安排制造；原物流不改为三颗。
- 额外材料与任务由新缺口计算，用户的既有分派约束继续接受验证。

### 6.4 改物品或配方

起始：旧宝石已在途，用户将所需物品换成另一种宝石。

- 旧物品事实保持原身份，不改名为新物品。
- 重新检查旧产物是否仍适用于新目标；不能确认则不作为新供给覆盖。
- 显示旧物流如何处理及新目标缺口，保存前向用户展示两部分影响。

### 6.5 取消或暂停在途需求

- 停止该需求的主动工作提醒，保留物流观察记录。
- 在途物品不能瞬间作为发件人或收件人的可用库存重新分配。
- 到货或返回后再按实际位置处理可释放占用；暂停恢复时重新检查目标和证据。
- 不要求用户为已经发生的寄出动作再做一次；目标失效暂停不等于寄出事实撤销。

## 7. 预留与证据专项检查

### 7.1 修正预留时机的歧义

模型方案 §5.1 第7项已依据自动材料转交与单次预留的已确认决策细化为：

> 需求按已确认计划建立一次数量预留，各阶段引用并移交该预留；等待前置条件的步骤不重复建立占用，也不因自身暂不可执行而释放已有效预留。来源不可信或目标不适用时按核实或暂停规则处理。

例如制造需要 F 的材料：C 已承接后，可以预留 F 的材料并启动寄送；不能因为制造暂时缺材料就拒绝预留。收取、制造和后续应用不能分别再扣占一次该材料或成品。

### 7.2 来源重叠

寄出背包旧快照仍有一颗，Mail 已确认在途一颗时，只能作为同一供给的一次位置迁移。缺少明确关联时进入核实，不能简单把两个来源相加。

Mail 尚未确认收取但收件背包已确认相应物品时，仍需验证关联，不能同时保留邮件覆盖和新增背包覆盖。

### 7.3 人工校正与迟到证据

已确认冲突处理采用保留记录并待核实：仅暂停受影响数量、任务和下游依赖的自动补做与完成推进，由用户核实；其它独立工作继续运行。

用户确认“已寄出”后到达同一寄出证据：补充或核实该记录，不再增加寄出量。

用户确认“已售出”后到达一份更早的背包快照：不能恢复可用库存。若到达更新且相互冲突的事实，则显示冲突并提供校正入口，不能静默取消用户安排。

用户确认“已收取”后，较新可靠证据显示同批物品仍在途：保留双方记录并标记待核实，不直接改写人工进度，也不新增制造。重复证据只处理一次，同一对象较早的可比较快照不倒退较新进度。

审计记录应说明事实时间、观察时间、修正时间和依据性质。具体证据标识、版本与时序能力由 API 阶段确认；无法提供时使用待核实流程。

### 7.4 编辑草稿冲突

用户编辑目标数量时发生一次真实寄出：保存前重新计算影响，保留草稿与原寄出事实，提示变化，不按旧草稿覆盖新状态。业务发生动作不因编辑器未保存而丢失。
