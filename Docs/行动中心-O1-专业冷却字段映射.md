# 行动中心 O1：专业冷却字段映射

日期：2026-10-09。状态：源码映射已核对；Core Provider 自动化通过；YiboTodo 公开输出与 TaskHub 页面已在 [O2](行动中心-O2-实施与验证记录.md) 实现并通过集成验证，游戏内尚未验收。

## 首项真实来源

选择已纳入监控时的 **神纹布**：groupID `mop.tailoring.celestial-cloth`，activityID `profession.cooldown.mop.tailoring.celestial-cloth`。当前来源目录声明裁缝 197、技能 600、配方 143011、产物 98619，resetKind=daily-07／resetHour=7。依据 [冷却组目录](../YiboTodo/Catalog/CooldownGroupCatalog.lua) 和 [配方目录](../YiboTodo/Catalog/CooldownCatalog_MoP.lua)，属于工作区规则，不能推定其他客户端相同。

输出由 YiboTodo 的 ActionTodo 适配器生成，复用 [Model/Snapshot](../YiboTodo/Model/Snapshot.lua) 中对应角色的 activities[groupID]，以及 [State](../YiboTodo/Model/State.lua)、[Schedule](../YiboTodo/Model/Schedule.lua) 的判断。通过 Core 注册 `action.todo` v1.0 Provider `YiboTodo:profession-cooldown`，TaskHub 只调用 Query({scope})；不读取业务全局或 SavedVariables。

## 字段映射

| action.todo 字段 | 来源与处理 |
| --- | --- |
| itemKey／businessRef.key | 来源内角色 ID 与 groupID 的稳定组合；周期另用 cycleKey，重载不产生新 task ID |
| providerID／sourceEpoch／revision | 描述符给出 providerID；O2 在 YiboTodoDB.actionTodo 保存 epoch／revision 与可再生指纹元数据，投影变化提交后合并通知；不用登录次数或单角色 record.revision 代替查询版本 |
| title／summary | activity.label 与来源状态说明，保留业务状态和置信度 |
| execution | self，characterID 使用 Core 角色 ID；本项工作由该角色为自己执行 |
| beneficiary | character，与执行角色一致；本项不产生为其他角色制作的安排 |
| state | 有效监控项目 active；单纯 cooldown 不推断为 completed，来源尚未证明的最终工作不由中心标记完成 |
| readiness | 按下表解释来源状态和下一动作；不把来源 UI 的“可制作”标签直接作为材料就绪证明 |
| temporal | kind=daily；cycleKey 由来源 Schedule:ServerDay 解释，nextChangeAt／有效截止由来源的日常重置或状态转换时间给出，中心不另算 07:00 |
| freshness | 保留 activity.observedAt、confidence、来源覆盖与时间依据；缺观察不能用查询生成时间补成新观测 |
| nextAction | 已有 Core 注册页面 todo；需要观察时提示查看／打开自己的专业界面，中心只跳转页面，不自动开专业窗口或执行制作 |
| item／quantity／progress | 可提供 itemID=98619 的目录信息；现有快照不证明产出数量、材料齐全或累计制作量，省略无依据数量和进度 |

## 来源状态与行动含义

| Snapshot 状态／依据 | 总览行为 |
| --- | --- |
| actionable + confirmed | 冷却条件已确认可用；提供查看业务页面、核对材料的 preparation 动作，不宣称已可直接制作 |
| actionable + profession | 仅职业／技能依据，readiness=unknown，提示打开自己的专业界面核实；没有观察时间时报告 not-yet-scanned |
| cooldown + confirmed | readiness=blocked，说明冷却中及来源 readyAt；正常周期等待不表示任务已完成 |
| estimated | 保留预计状态，当前冷却是否可用需再次观察；readiness=unknown，不计为确定可制作 |
| skill-insufficient | readiness=blocked，显示来源技能条件；不生成肯定制造提示 |
| unknown | 未观察为 readiness=unknown；现有模型以 unknown + recipe-unlearned 表达已确认未学习，适配器保留原因并标 blocked；冲突为 partial + unknown。跨重置的观察统一 stale + unknown；未知不当成数量零 |
| locked／not-applicable 或未监控 | 按来源准入排除；只有监控设置／职业范围确实已知时，对该查询范围声明 known-empty |

现有 Provider 中 craftable 来源于专业列表难度字段，表达技能是否满足，不是材料足够。来源返回准备动作时仍保留未知／过期的状态与观察时间，登录摘要不把它计为肯定可执行。未来若增加真实材料或执行依据，由来源扩展解释。

## 查询、时效与范围

Query 使用显式 Core characterIDs，覆盖仅针对本项监控范围。来源使用自己的监控开关与角色专业准入，不使用来源页面的临时范围；来源未采集、部分或未知专业不能声明没有任务。对应项目缺失时依据准入与覆盖分别返回 known-empty 或 not-yet-scanned／partial，不能只靠数组长度判断。

每日 cycleKey、到期后的估计与状态重建由来源 Schedule／Snapshot 解释。TaskHub 收到状态变化或下一变化时间后重新 Query；两个角色列表引用同一条记录。中心不保存一份独立冷却数据库，不根据物品数量差推断制作完成。

角色 ID 变更由来源迁移自有引用，中心清理旧投影并重新查询；只用于展示的名称由 Core 格式化。暂停监控后本项退出当前输出，中心只是失效投影，不删除来源业务历史。

## O2 验收输入

使用真实来源模块验证：确认零冷却、冷却中、重置后 estimated、职业已知但无观察、未学习／技能不足、监控关闭、离线角色与角色 ID 变更。核对来源页面与中心源状态、角色、观察时间和周期一致，同时明确中心就绪含义。

跨角色执行、开放候选和账号工作使用独立投影测试覆盖通用契约；本项没有这些真实安排，不能据此宣称已实现下发或改派。第二个真实来源在 O3 选择并记录其所有权与字段映射。
