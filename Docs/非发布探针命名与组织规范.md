# 非发布探针命名与组织规范

本文规定 YiboWow 工作区内游戏运行探针的命名、目录、加载与归档方式。探针用于开发验证、客户端能力观察和受控诊断，不属于玩家发行功能。

## 目录与 TOC

- 每个可在游戏中加载的探针都放在仓库根目录 `_NonRelease/<AddonName>/`，不得放在业务插件目录、插件内 `_NonRelease/`、构建快照或发布归档中。
- `<AddonName>` 使用 `Yibo` 前缀并以 `Probe` 结尾；中间按“业务/系统 + 目标（可选）+ 具体用途（可选）”组成，例如 `YiboCoreRetailTocProbe`、`YiboBeastPathsMistsPetProbe`。
- 探针目录名必须与默认清单 `<AddonName>.toc` 完全一致。只有一个目标实现时只创建该默认清单；确需多个已验证目标时，沿用仓库多目标规则建立 `<AddonName>_<Target>.toc` 并由默认清单作缺目标提示，不创建没有实现的目标清单。
- 不把日期、临时批次号、客户端 build 或修订号放进稳定目录名。它们写入 README、样本文件名或证据元数据；历史冻结副本可保留原名。
- 同一探针的 Lua、静态样本、README 和必要工具放在该探针目录内。离线测试夹具若不需要游戏加载，按其所属测试/验证分类存放，不伪装成插件目录。

## Slash 命令

- 需要手动触发的探针使用唯一的小写三字母 Slash 命令，格式 `/y??`；不得占用业务插件命令或保留旧别名。
- 命令登记在 `Docs/Yibo系列插件命令清单.md` 的“独立探针命令”表。新增或变更前搜索全工作区 `SLASH_*`，确认源码中无冲突，并同步该表。
- 探针/诊断不得占用 Broker、小地图、主窗口或其它常规入口。

## 加载与存放

- 游戏中需要运行时，才把探针目录以同名 Junction 联接到目标客户端 `Interface/AddOns/<AddonName>`；联接来源必须指向仓库根 `_NonRelease/<AddonName>`。
- 联接必须记录客户端路径、源路径、目标用途及建立日期。客户端不可用时保留源码，不新建或假定联接存在；客户端恢复后先核验其产品身份、Interface、TOC 后缀选择，再建立链接。
- 探针不得进入正式玩家包。不得通过插件运行时删文件、故意报错或加载过期清单完成目标选择。
- 探针默认使用自己的 SavedVariables，不写业务插件 SavedVariables。确需读取被测插件内部状态时，优先使用已声明的公开能力；任何开发期内部耦合必须单独记录原因、依赖版本和失效行为，不能默认为跨插件架构许可。
- 从正式插件加载链抽离探针时，必须检查初始化顺序、业务命令、事件订阅、存档、TOC 间接引用、构建包文件引用及旧目录链接；拆分完成后不得留下悬空 TOC 项或重复注册。

## 名称例子与迁移

新探针采用上述规则。现有名称如 `YiboCoreForeverR4` 等历史探针不因命名规范发布而自动改名；改名时须一并更新同名 TOC、链接、构建/测试引用、证据和文档。不得为整齐而破坏仍有效的历史证据。
