状态：本次修复及适用离线回归通过；客户端 CPU、长帧、回收后占用及新字节存档恢复待验，未判定可发布。基于已有未提交工作树继续修改，当前 main，未提交、推送或发布。

## 发现与修复

生产改动仅涉及 `YiboCore/Data/DomainStore.lua`、`Data/Profile.lua`、`Runtime/DataDomains.lua`，不包含本轮开始前已有的身份目录、账号视图及领域输入复制优化。

| 路径 | 问题 | 本次处理 |
| --- | --- | --- |
| `DomainStore:GetState` | 为返回状态字符串而通过 Get 深复制整个领域 | 直接读取状态值，不返回内部数据引用 |
| `DataDomains` → `DomainStore:Commit` | 每次采集都构建调用方不会使用的返回快照；即使内容未变也复制 | 内部采集通过私有 CommitCollectedDomain 复用同一个提交实现，跳过返回快照；公开 Commit 保持原返回值及副本隔离 |
| `Profile` 领域通知 | 没有 ProjectLegacy 的领域更新也读取完整领域副本 | 先判断是否存在投影函数；真实投影仍取得隔离副本，旧档案通知及合并行为保留 |
| `Profile` 旧采集器 | 只要存在旧采集器，每个事件都先读完整角色；事件不匹配也分配 | 匹配事件后才读取身份定位权威记录，继续向采集器提供原有可写记录和时间戳 |

数据确实改变时，提交仍复制输入取得所有权；公共 Get、Commit、无变化 Commit 的返回结果仍与存储隔离。失败／过期／不可用状态继续保留最后成功数据。没有删业务数据、修改历史保留策略或取消消费者需要的隔离。

## 职责、目标与发行边界

完整职责单元是共享领域提交／状态查询及旧档案兼容桥。无新增客户端 API、客户端专用规则或静态目录，稳定逻辑继续共享，适用 Core Mists／Retail／Forever。Core 自身复用身份查询，公开 API13、能力版本及业务插件最低要求保持；未新增公共能力、未改变业务接入状态，因此不更新公共能力迁移台账条目。没有把业务规则或业务 SavedVariables 纳入 Core。

清单和实际加载名保持：源码 `YiboCore_Mists.toc`／`YiboCore_Mainline.toc`／`YiboCore_Forever.toc`，对应玩家包为 `YiboCore.toc`；默认源码提示、TOC／XML／间接引用及初始化入口未变。误目标写库保护、Core 就绪与最低能力检查、单次初始化均沿用现有实现，不因离线性能测试登记为新实机通过。内部采集提交仍在 Core 已初始化及角色存在后执行。

技术名、安装目录、各目标 SavedVariables 身份和 schema 不变；本次工具没有读取或修改实际 WTF。生产文件原路径覆盖，没有新增旧残留路径参与加载；统一构建的目标、Interface、引用与内容校验通过，未生成发行包。旧文件保留覆盖与干净安装的已有相同机制证据可复用，但本轮新字节的实际采集、旧档案展示、reload／完整退出恢复与性能需客户端验证。Forever 不外推 Mists／Retail 证据。
