## 历史页耗时原因与修改

原布局对每条历史调用完整显示格式化，重复测量所有列；对方角色名称格式化还会逐次读取并复制 Core 角色目录。3411 条数据会放大这些开销。

现在隐藏行只计算附件和金额所需高度，并在本轮布局中缓存相同文字的测量；完整显示字符串仅用于可见行。空搜索不再构建每条记录的搜索文本，当前时间按查询获取一次，非空搜索的角色显示名按角色获取一次。所有历史仍由 Mail 保存，查询结果未缩减。

## Core 公共能力复核

- 继续使用 Core Theme 的 MeasureText、按钮、下拉、共享输入／物品选择器、账号窗口与滚动能力，无新增 Core 接口；基础门槛保持 API13 / localization:1。
- 字段分组增加插件内部稳定 groupID，不再以中文显示名称关联业务列；提供给 Core 的分组标题仍本地化。
- 原生寄信地址、主题、正文、金额与到付控件保留游戏对象和交互脚本，仅调整位置与皮肤。
- 本轮账号搜索及规则输入继续使用已有 Core 公共输入；NativeUI／RecipientUI／MailUI 旧自建输入的剩余范围沿用 CAP-002，不能据本轮尺寸修复认定全部基础输入迁移完成。
