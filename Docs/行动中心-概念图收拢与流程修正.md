## 本轮行为

- 主窗口保持共用表头、当前角色在上、其他角色在下。待核实项按 Core 角色 ID、来源、来源 epoch、候选属性和受益角色分组；至少两项时折叠成“待核实工作 · N 项”。同一分组一键展开／收起，点击整行同样可展开。已确认工作逐条显示。
- 分组只是展示投影：不生成新业务任务、不合并物品数量、不更改执行安排、时效或来源状态，不落库。顶部账号统计和分区统计基于原始工作，候选按原身份去重；分页按展示行计算。
- 来源改为 Core 下拉选择，增加全部／可推进与准备／待核实／等待状态筛选。两者应用于主表及悬停，当前角色 HUD 与登录提醒继续独立读取完整准入范围。
- HUD“列表”和登录弹出列表模式清除来源／状态筛选，使用 Core SetPageScope 切回全服并回到第一页，使当前角色真实工作可见。直接查看主页面仍保留自己的筛选。
- 悬停先保证有效角色摘要，再用剩余行展示已确认工作的薄标题和明细；未知角色显示角色名、工作数量、来源数及状态数量。标题不再串联全部邮件主题；极小空间仍明确剩余角色数。行详情限制为 8 项，剩余数量指向主窗口。
- 主表、悬停和 HUD 共用工作图标与状态标记。复用已有 WoW 纹理，状态以 `>` 可推进／准备、`@` 候选、`~` 等待、`?` 未知与文字／颜色共同区分。工作图标来自来源声明，物品图标由 Core ItemResolver 加载，未就绪时使用通用任务图标。
- 角色名复用 Core FormatName 的 short／sameRealm 策略，同服省略服务器，跨服继续显示；详情保留 original／full 身份。主表移除状态单元格的完整观察时间，完整时间与业务原因继续在详情显示。字号保持 Core body／assist，相邻行共用底部单线。

## 最小契约与公共能力审查

`action.todo` v1.0 增加可选显示元数据 `icon`：正整数 WoW 纹理 ID 或不含富文本分隔符的非空纹理路径。字段缺失使用通用图标；非法字段按无效来源结果处理。提供者拥有图标选择，中心仅渲染；Mail 从自身附件快照提供 texture，没有读取其他业务对象。

既有 `item.itemID` 可用于显示图标，中心通过 Core ItemResolver:GetInfo／Request 获取，不读取物品业务库存；同一物品只排队一次，加载完成由 Core 页面刷新与 Displays 合并更新。消费者显式检查 API11、item-resolver:1 及方法；能力或方法缺失提示升级并停止初始化，无并行本地加载器。

本轮未新增 Core 运行接口。CAP-001 调整名称显示策略仍全部通过公共 FormatName；CAP-003 新增 ItemResolver 接入；CAP-004 复用 Core 下拉、页面、范围与高度预算；CAP-005 沿用通用 Provider 和可选显示字段，不增加来源技术名分支。CAP-002／006 无新增适用调用。台账保留部分接入，等待修订后的客户端验证。
