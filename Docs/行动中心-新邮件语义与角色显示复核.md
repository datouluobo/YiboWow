## 角色显示与同类调用

0.3.0 已调用 `Characters:FormatName`，不存在没有接入名称格式化的问题；实际遗漏是用普通 FontString 绘制角色，绕过了 Core 的共享角色显示控件，缺少职业色与统一完整身份提示。本轮主表执行角色、跨角色受益者、悬停角色标题／压缩摘要改用 `CreateMatrixHeader`／`SetCharacterHeader`。HUD 不展示角色名，其详情仍复用公共格式化。

TASK 为角色行的紧凑列表，使用共享控件的单行模式，名称仍显式按 `short/sameRealm` 格式化；没有把全服角色列矩阵的两行表头强行塞进 28px 任务行。身份提示由 Core 生成，任务详情的执行者及跨角色受益者使用 `original/full`。没有新增 Core API；初始化明确检查已有共享方法，缺失提示升级并停止。

同类复核发现主表／悬停还在本地选择交替行底色，本轮收拢为 `GetDataRowColor`。任务就绪高亮属于中心自身展示策略，使用 Core 既有 `successSurface`；来源、数量及完成判断仍由业务所有者提供。来源下拉、字段、设置、准入、高度预算、物品解析已接入现有公开能力；本轮没有文本输入／物品选择器或低频操作引导，CAP-002／006 不适用。迁移进度已同步公共能力台账，未审查模块不推定已完成。

## 邮件来源的当前契约

- 需求：提醒查看新邮件，保留用户把附件留在邮箱备用的选择。当前真实来源共三个：Todo 的诺米、神纹布，以及 Mail 的新邮件；不增加 TASK 对具体业务名的分支。
- `action.todo` Provider v1.0，稳定来源 ID 继续为 `YiboMail:inbox-collection`，显示名改为“新邮件”。提供方与确认状态所有者为 Mail，消费方为 TaskHub，连接经 Core.Contracts。历史技术 ID 不表示用户必须收取。
- 方法与 envelope 保持原契约：`Query({scope={characterIDs={...}}})`；按 Core 角色 ID 限定范围，返回值副本，空范围为空，未知／未采集不等于空邮箱。没有收取、任务写入或完成操作接口。
- 每角色最多输出一个“新邮件 · N 封”查看工作；纯文本、付款信也可提示查看，绝不提示自动付款或强制收取。仅统计当前 observed、未主动查看且未确认处理的邮件。主题摘要最多三封，数量表示信件数而非附件或工作需求量。
- 主动查看信件或展开附件时，复用 Mail 的 `MarkMailOpened`，保存 `noticeHandled`；仅渲染收件列表、打开 TASK、后台查询或扫描不确认处理。重载后仍生效。已处理附件继续由原 mail.items 库存接口提供，不从邮箱删除、不修改物品数量。
- 升级首次将已有缓存设为已处理基线，不修改原 `openedByUser` 已读外观。首次观察客户端已经读过的信也不提醒；后续背景扫描导致的客户端 read flag 变化不视为用户操作。
- 部分收取的已验证队列余量继承已处理；同内容重复邮件无法辨明具体剩余副本时不重新催收存量。库存记录与未核实历史仍按 Mail 原规则保留。
- Mail 监听 `UPDATE_PENDING_MAIL`、`PLAYER_LOGIN`、`PLAYER_ENTERING_WORLD` 的 `HasNewMail` 原生事实。邮箱外先显示“新邮件 · 待查看”，不捏造数量或附件；真实扫描后更新为未看信件数。相同原生信号不重复通知，扫描后黏住的 true 不重新建立提醒；后续 false→true 代表下一次到信。
- Mail 保存通知批次 ID，查看部分信件／重扫维持同批身份；全部确认后下一批有新身份，支持中心新增工作标记。sourceEpoch／revision 沿用来源持久元数据；派生任务不存成第二份权威数据。
- 邮箱打开且扫描有效时可提示“待查看”；部分扫描只统计已观察部分。离线、关闭邮箱、错误、估计到期仍待核实。当前角色刚收到的原生新邮件事实可提示查看，覆盖率仍保留未采集／陈旧状态，不升级整个邮箱的可信度。观察时间及到期均来自 Mail，查询不采集、不广播。
- mail.items v1.0／Items API v1 不变，Vault 继续获得已看未取附件。Mail 基础最低 Core API9；可选 action.todo 仍检查 API11 / business-providers:1，不足仅停止新集成并提示升级。来源缺失、晚注册、注销、不兼容继续由通用消费路径处理。
- “其它任务需要的邮件附件”留在后续真实需求与物流契约接入；当前没有需求关联能力，不能从物品存量推断必须收取。

## UI 层级

主窗口保留当前角色与其他角色两个区；区内依次显示可推进／准备、候选、等待、待核实，同级保留 Core 角色顺序。悬停当前角色优先，其后有可推进工作的角色先显示；摘要容量继续覆盖最多 20 名有效角色。

统计以语义颜色区分状态，总工作量降为辅助信息；可推进行使用轻量绿色底色，状态同时保留文字与标记。来源、“自己”和待核实标题使用辅助文字色，角色使用职业色。保持原字号、单行高度、共享分隔线，不靠增加卡片或空行制造层级。
