# 副本目录与 Hub 内添加流程

后续的搜索焦点与原生难度身份统一见[补充记录](行动中心-搜索焦点与副本身份一致性.md)；当前目录夹具为458项，TBC目录与客户端锁定统一使用175/176身份。

日期：2026-10-25。工作树基线：TaskHub 0.6.1、AltoBoss Mists 2.8.3。状态：**代码与专项离线验证完成，真实客户端待复测**。未提升版本、提交、推送或发布。

## 当前行为

AltoBoss 提供副本目录和角色业务进度，Hub 保存目标。AltoBoss 注册兼容的 action.targets 来源后，Hub 的添加目标菜单和目标列表显示“首领或副本”；点击直接进入 Hub 内部目录，完成角色、搜索、副本、难度、整本/尾王/指定首领和保存。来源缺失、禁用、注销或主版本不兼容时隐藏对应添加入口，既有目标保留；晚注册后恢复。其它业务来源继续使用各自的声明入口。

21 个旧团本使用 Mists 维护目录，共135个遭遇条目，首次进入或形成锁定之前即可选择。太阳之井明确列出六个首领，尾王稳定身份为 raid:580:kil（基尔加丹）。卡拉赞歌剧院为一个遭遇，兼容三种剧目名称；Ulduar 的主线尾王明确为尤格-萨隆，卡拉赞为玛克扎尔王子，安其拉神殿为克苏恩，均不依赖目录末项。其它地下城手册实例保持完整客户端目录；目录只有 JournalEncounterID 时使用 journal-encounter:<ID>，不冒充 DungeonEncounterID。

尾王由目录显式声明 finalEncounterID，已维护的后续团本使用明确的末战名称映射；未声明时仍可指定首领。保存转为精确 encounterIDs 集合。单难度副本自动选择唯一有效难度，多难度要求明确选择；切换难度清空旧首领选择；空集合无法保存。

角色锁定仅作为进度证据，不能定义目录完整性和尾王。旧 targetLegacyDirectories 保留作既有 ID 的兼容映射，不再决定可选范围或缩减目录；不会清理玩家存档。已有误存目标可以直接编辑为“仅尾王：基尔加丹”，保留目标 ID、历史和状态。无法从已保存的精确首领集合推定用户当初使用了何种快捷选项，因此不批量改写玩家的首领选择。

整本仍要求全部声明首领完成，指定集合仅判断所选首领。完整目录不代表完整击杀证据；缺少相应锁定首领记录时为未知，不能补算击杀或错误判定完成。进度证据不完整的客户端仍需实机采样，目录专项不构成该客户端全部副本自动进度验收通过。

## 契约与所有权

沿用 Core.Contracts 的 boss.target-catalog 与 action.targets。来源 GetEntry 增加可选 targetType="boss" 元数据，Hub 据此路由到已有内部选择页，不按提供方技术名绑定业务对象。Normalize 的 multiselect、clears、needsConfiguration/fields/reason 契约沿用前次扩展，未完成草稿不持久化。

AltoBoss 拥有目录、合法难度、尾王、周期和完成判断；Hub 拥有用户计划。未新增 Core 业务规则、跨业务强依赖、第二份权威业务数据或读取其它插件的 SavedVariables。双方应同时更新以获得新的入口和目录行为。

CAP-004 复用 Core 搜索输入、单选、多选、分页及分组控件；CAP-008 继续使用公开 Contracts；CAP-009 新文案和目录显示名称均有 owner 中英文资源，语言由 Core 管理。最低 API13 与已有能力版本不变，现有多选方法检查保留，无本地控件回退。

## 迁移与加载

新增 Mists/RaidCatalog.lua 保存目标专用目录与名称资源；Mists/TargetCatalogRuntime.lua 负责 Blizzard 手册加载、tier/instance/difficulty 选择与恢复、API 返回适配及旧身份匹配。Common/TargetCatalog.lua 负责稳定目录组合、别名与查询。原 TargetCatalog.lua 为无执行逻辑的残留兼容文件。

Hub 的完整目标选择职责移到 Common/TargetsPage.lua，通用编辑器继续位于 Common/GoalEditor.lua。两个 TOC 与实际测试引用同步更新；旧根路径不在新加载链上，残留文件不会重复创建/注册。技术名、安装目录、SavedVariables 和 schema 不变。影响范围为当前 Mists；Forever 没有因此获得正式副本业务实现。
