### 0.4 迁移、验收与性能门槛

1. 新装、来源注册、业务监控开启、切号及新增角色不自动添加目标；无目标不查询业务进度、不发空提醒。
2. 中键、设置后的组合键和可见菜单同一路径；按钮原点击仍有效；行复用、解绑、重复注册不串角色／对象、不叠加回调。
3. 角色矩阵单元格直接传稳定角色 ID；行标题缺角色时配置；账号范围显式保存，不随当前角色或显示过滤变化。
4. 添加必要参数、重复点击、重试、编辑冲突、失败回滚、重载恢复；数量改变不通过重复点击隐式累加。
5. 单次完成、周期重置、持续监控回落分别处理；来源缺失、晚注册、注销、异常、不兼容、epoch 变化和过期数据保留目标并准确提示。
6. 主列表、悬停、HUD、提醒基于同一已添加目标集合；隐藏角色不删除任务，隐藏库存角色不偷偷改变已保存统计口径。
7. Boss 旧计划、难度／首领、暂停和目的角色差异保留；迁移重复运行不重复；失败保留原库；原编辑、复制、AltoBoss 自动展示均引用同一目标。
8. 自动来源行和旧显隐设置不自动变成目标；升级提示清楚，旧设置保留；Task 移除目标不修改来源监控或业务事实。
9. Todo 精确目标不因页面未勾监控而消失；缺采集返回未知及明确引导。Vault 部分覆盖不冒充总数，Crafting 无制作事实不以库存差完成，Builds 已有道具不等于已应用。
10. 按来源批量评估显式目标，只失效相关缓存；20 角色多目标、连续任务日志与背包事件压力下，复核查询次数、复制量、长帧与内存。既有性能与布局检查继续保留，不能仅用旧测试代替新路径验证。

各阶段分别记录自动化和客户端证据；文档完成不标记运行能力完成。迁移台账已更新 CAP-008 与本轮相关能力；发布、提交未执行。

## 1. 既有交付顺序和完成标准（历史）

首阶段以一项真实来源任务完成输出、连接和展示，再接入第二个来源验证通用性，随后扩展展示与提醒。Core 扩展先于业务接入，但其最小边界由真实来源与中心消费者确定。每阶段只注册已交付且有真实消费方的能力；尚未具备的契约保持文档状态。

| 阶段 | 交付结果 | 进入下一阶段的依据 |
| --- | --- | --- |
| O1 真实契约与 Core 连接 | 已完成源码字段映射与 Core Provider 自动化验证；首项为神纹布冷却 | API v11 / business-providers:1 已提供；连接兼容回归通过；客户端待 O2 接入验收 |
| O2 首个来源与最小页面 | 已实现神纹布输出与两个角色列表；70 项集成、待办及 Core 回归通过 | 自动化覆盖来源一致性、缺失／晚注册／不兼容、范围与周期；游戏内状态、切号及布局待验收 |
| O3 多来源与角色投影 | 已接入诺米第二真实来源；133 项集成覆盖两来源、角色与周期 | 中心无业务技术名分支，两个真实来源同属 Todo；客户端及真实跨业务安排仍待验收／后续接入 |
| O4 展示与提醒 | 0.2.0 已实现只读账号悬停、当前角色面板、登录摘要及统一设置 | 四个展示面共用投影；219 项检查通过，新增 Core 角色准入通知；客户端待验收 |
| O5 跨业务来源 | Mail 1.2.3-api1 输出非付款附件／金币邮件待收取，TASK 无新适配分支 | 新增 46 项、合计 265 项通过；API9 基础功能保留，新增来源客户端待验收 |
| S2 后续持久需求与模型 | 先按实际场景交付独立任务持久化，再增加数量、任务链和人工校正 | 按交付范围验证去重、重载和模型不变量 |
| S3 后续 Builds 下发 | 提升页面创建一份宝石需求，来源判断最终目标 | 重试去重、装备身份和累计完成验证通过 |
| S4 后续制造与库存 | 查询候选制造者、成品和材料，分派并生成缺口工作 | 配方材料／产出有依据，物品不重复占用 |
| S5 后续邮件与证据 | 材料／成品转交、收取、补做和冲突核实 | 自动证据和人工核实边界完成客户端验证 |

O1～O5 是当前实施范围，S2～S5 保留后续模型与业务文件安排，不作为任务总览的交付前置。首阶段来源任务由来源管理，中心持久化展示／提醒设置，默认不持久化可再生任务快照。只有实际需求出现时创建对应模块。

首个总览流程：**来源已有一项纳入监控的专业冷却 → 通过 action.todo 输出 → 中心按执行角色投影 → 登录／切号查看两个列表 → 来源完成或周期变化 → 中心查询并同步展示**。冷却就绪与当前可制作分开，来源只声明其能证明的动作。

后续跨角色流程：**Builds 发现 A 缺宝石 → 创建需求 → 查询成品和候选制造者 → 分派 C → F 转交材料 → C 制作并交付 → A 收取并应用 → Builds 确认目标满足**。这个流程仍须交付真实下发、业务资格与证据；合成输入验证跨角色投影不能当作流程已实现。

### 5.2 数据和事务

- 独立 ID 用于需求、链、任务、分配和人工记录；角色关联复用 Core ID。registrationRef 仅留内存；持久来源引用使用 capability、providerID、sourceEpoch、key。
- 单根需求保存目标数量。已制作历史、当前可用供给、最终满足量分别记录；补做只增加关联任务，不增加根需求数量。
- 材料和成品按各自物品／配方规则核算。材料消耗和成品产出由 production 解释，不能将两种数量直接相加；一次材料占用在寄送、收取、制造准备阶段间转移。
- 编辑时在副本中验证前置无环、数量、角色、证据关联和预留，再一次替换受影响记录、更新去重索引与 revision，最后通知。保存前校验旧 revision，旧草稿不能覆盖新事实。
- 影响预览完成后至用户确认期间如收到新证据，旧预览失效，重新生成后再提交。用户确认针对当前影响，不能沿用过期结果。
- 修改目标、角色、数量或优先级只调整未来计划；已寄出角色、数量、目的地和历史不随草稿改变。有效预留和在途供给不被新优先级抢占。
- 对人工判断和可靠事实的真实冲突，保留双方并隔离受影响数量及下游；重复事实不重新计量。人工操作不能改写库存或配方来源。
- 角色删除进入 Core 的影响预览；中心报告需求、分配与历史影响。仍被需求引用的角色变为待核实，不因目录缺失释放在途量；显示隐藏不触发数据删除。
- 初期迁移仅为实际 schema 变化增加；恢复失败保留原数据并停下受影响功能，不自动清空用户需求。

Builds 已要求 API v10 / account-view:2，新增下发集成不能降低既有最低要求；Service 调用另检查 business-services:1，目标 Provider 按实际扩展版本检查。其他业务模块同样保留自己的基础初始化要求，缺少新连接只停止新增增强功能并提示升级。通用版本检查、插件登记元数据和模块边界须记录一致。

现有 mail.items v1.0 的方法为 GetState({characterID})、GetByCharacter({characterID,options})、GetRevision()，并未提供草案中的 Query。返回结构沿用原附件协议；providerID 可由描述符获取，持久 sourceEpoch／originRef 尚须增量设计和验证，不假定现有结果已携带。兼容字段增加与方法扩展按业务契约版本声明，不能静默替换 v1.0 方法。

Vault 的本地邮件简版采集是既有业务来源。Mail 已注册但数据未采集、partial、stale 或 error 时沿用当前服务契约的覆盖和可信观测语义，不能仅因查询不完整就切回旧来源或认为为空；Mail 缺失／禁用／注销／不兼容时，Vault 的独立采集继续可用。中心只查询统一库存投影，不另外把 Mail 附件叠加为库存。现有 vault.items 可作为只读基础，但 action.inventory 所需资格和持久关联仍须交付。

制作、寄出、收取是不同事实，最终满足仍由目标所有者确认。寄给账号中转角色推进原物流；确认外部转交先寻找其它有效供给，再按实际缺口建立补做任务。AH 上架只影响可交付性，不能当作售出证据。

每个证据来源仅注册自己已验证的事实类型。现有 Mail eventID 配合持久 epoch 才能形成稳定事实 ID。相同物品和数量不证明同一批次；客户端无法提供可靠关联时显示候选，人工确认后保留审计。需要额外操作关联机制时先补足实际契约，不提前创建空绑定接口。

客户端至少验证：正常寄出／失败／取消，分拆附件，部分收取，寄给中转号，退回，两封同内容邮件，重载和历史清理。制作事件、库存去向和最终镶嵌分别核对原业务视图与中心数量。

## 10. 来源扩展与操作边界

O5 已扩展真实来源，当前 Mail 1.2.6-api1 通过 `YiboMail/ActionTodo.lua` 输出每角色一条新邮件查看提醒，查看信件／展开附件后默认处理；邮箱存量继续由邮件库存 Service 提供。Bootstrap 在既有 Service 注册后初始化；TASK 按通用 Provider 契约消费。MailSourceSpec 当前 80 项，累计 359 项通过；契约、所有权、最低版本与客户端验收见 [当前复核](行动中心-新邮件语义与角色显示复核.md)。邮件基础 API 保持 v1，Core 仍为 API v11。

每个新来源先明确一项实际任务的语义，再同时完善输出、连接和消费验收。输出可以是自己的即时待办或已存在的跨角色工作；资格查询、库存快照等只有事实时，不强制包装为任务，也不由中心自动组织出用户尚未创建的需求。

农场等观察型投影保留来源置信度，不能包装为确切完成证据。需要中心创建或改派工作的场景进入后续 S2；需要自动制造与物流进入 S3～S5。扩展时按实际业务能力维护各自进出口，不预建全套空接口。
