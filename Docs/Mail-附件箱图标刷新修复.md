# Mail 附件箱图标刷新修复

日期：2026-10-14。版本：1.2.15-api1。状态：代码与自动化完成；用户确认游戏名称异常在重载后恢复正常，其它边界场景仍按下方清单复测。

## 附件箱整体不可用：缺少发件人名称

客户端反馈 `/yma status` 为 `error · 4/4`，`/yma scan` 报 `header-unavailable:index=2:sender=nil:subject=string:days=number`。第 2 封邮件仅缺少发件人名称，原扫描器把它作为整封邮件头未就绪，拒绝提交整箱快照，导致其余普通邮件的附件也无法取件。

- 读取时接受缺少发件人名称的邮件，存档以空字符串保留未知值；名称显示通过既有 Mail owner 中英文资源显示“未知／Unknown”，不把本地化文字写入地址或签名。
- 主题和剩余时间仍须有效，非字符串发件人仍被拒绝；附件身份、数量和总数检查继续执行。取件前仍复核邮件签名；发件人信息变化后旧身份失效。
- `AttachmentReadinessSpec` 联动真实 Store、Items、Scanner、ViewModel、NativeUI 和 Queue，复现 4 封邮件、110 个材料／6 组附件、3 件装备、其中空信缺少发件人的场景；确认图标恢复可用及 110 个材料成功收取。另覆盖未知发件人的附件取件、无效邮件头阻止操作、错误恢复和关闭重开。
- 同轮复现连续邮箱更新不断取消延迟扫描的问题，调度改为合并到已排定的扫描，开始读取时使用最新 generation；关闭邮箱取消旧请求，异步身份校验继续保留。
- Mail 全部 12 个 Spec、修改 Lua 的语法及 diff 空白检查通过。本地化报告已查看：Mail 为 0 硬编码候选、0 缺英文／未知 key／格式参数差异。
- Core 公共能力复核：未知名称显示继续使用既有 owner Core.Locale；角色格式化、身份、UI 和消息接入范围及最低 API13 不变，无新增公共能力或迁移状态变化。扫描调度和邮件可读性归 Mail 所有。

2026-10-14 用户确认游戏问题在重载后恢复正常。截图中同服材料信与跨服 BOA 信均曾缺少名称，原生信件详情也显示“未知”；重载后恢复。仅记录本次反馈的恢复结果，其它取件及异常边界继续按清单验收。

## 已复现的刷新路径

- `Scanner:Schedule()` 收到邮箱更新后立即清空 `validAt`，公开状态变为 stale；扫描延迟提交期间，附件箱将所有暂不可取件的图标去色，提交后恢复。内容未变化也会发生灰显切换。
- `NativeUI:RefreshInbox()` 每次先隐藏全部附件图标再重显，并重复设置相同纹理。背包变化和发件附件变化此前也会刷新附件箱，放大这一过程。

以上为代码及模拟事件可复现的原因；真实客户端的全部闪烁来源仍需复测确认。

## 修复范围

- 附件图标保持挂载，只在分组消失、筛选移除或离开附件箱时隐藏；相同纹理与去色状态不重复设置。
- Scanner 以内部 `refreshPending` 标识本次打开邮箱已成功扫描后的短暂复查。仅同一物品分组可保留此前的可用颜色；公开 `GetState` 仍立即变为 stale，图标点击与队列校验仍停止取件。
- 扫描提交、扫描错误和关闭邮箱均清除标识；首次打开、重新打开、永久过期或错误不借用旧会话的显示状态。复用到另一分组时重新计算颜色。
- 背包变化、发件附件更新和发件成功只刷新发件区域；邮箱更新、取件结果与失败继续刷新收件区。批量取件仍沿用挂载图标及页脚进度更新。
- 本次仅调整 Mail 扫描与显示生命周期。Core Characters、ItemResolver、UITheme 与账号页继续使用既有公开接口，最低 API13 不变；无新增公共能力或迁移状态变化，迁移台账无需更新。未新增玩家可见文本。

## 自动验证与客户端复测

`NativeInboxSpec` 统计图标隐藏、纹理设置、去色次数，覆盖重复刷新、短暂复查、禁止取件、复用、错误与过期、分组移除、页面切换及背包／发件事件路由。`MailRuntimeSpec` 使用真实 Scanner、Store、ViewModel 和取件队列，覆盖事件连续到达、stale／known／error 转换、关闭重开与取件安全；既有 30 封／90 附件批量收取验证仍保持 180 次发布、1 次完整终态刷新。

NativeInboxSpec、MailRuntimeSpec、RuleSendUISpec、RecipientUISpec 四组回归通过；修改的 Lua 语法与 diff 空白检查通过。本地化报告已查看，Mail 为 0 硬编码候选、0 缺英文／未知 key／格式参数差异。

发布启动模拟已在 2026-10-14 更新并跑通：`InboxReleaseSpec` 使用 API13 基础能力、真实 Core Capabilities／Locale、稳定字段 groupID 和当前公开方法；覆盖可选增强缺失／晚注册／注销恢复，以及 76 个中英文版本、能力和方法不兼容的升级提示与停止场景。Mail 全部 11 个 Spec 通过。详见 `YiboMail/_NonRelease/Docs/Inbox-Release-Check.md` 的当前发布测试记录。

客户端 `/reload` 后打开附件箱，核对无操作时、收到邮件、自动标记已读、背包变化与发件附件变化时图标是否稳定；再验证单次／批量取件、到付邮件、切页、筛选、关闭重开和读取失败时的图标与交互。模拟帧检查不能代替客户端视觉验收。
