## 当前三标签结构

邮件设置仍为 Core 设置中的单个业务入口。内部三个标签固定顺序：**发件、收件、缓存管理**。标签高 34，宽分别 112、112、144，间距 12；位置固定在页面说明下方。分区内容从纵坐标 176 开始。

切换时保留发件草稿、规则筛选与页码及未保存的收件偏好，标签切换本身不提交、不清空。关闭整个设置工作台也不得自动保存未确认内容。

## 规则定义

规则只有两个必填条件：**物品、收件人**。

- 物品最终保存物品 ID。名字、背包和拖放都用于选择同一物品身份。
- 收件人最终保存完整的“角色名-服务器”。手工未填写服务器时，补当前登录角色所在服务器。
- 启停是可选状态，默认启用。
- 发件建议按客户端每封最多 12 个附件分封，按背包可寄送整叠匹配。旧数量上限字段不进入本轮新设计；实施时保证旧记录仍可读取，旧上限不再限制装填。
- 同一物品保持一个目标收件人，重复创建时定位既有规则供编辑。
- 最终发送沿用玩家点击原生发送的动作。

## 度量口径

使用 WoW 逻辑 UI 单位，按 UI Scale = 1 绘制。Core 标题 18、分区和按钮 16、正文及输入 14、副信息 12。

图中文字宽度以微软雅黑预估；实施时用 Core 的 `MeasureText` 与游戏字体复核，并保留光栅容差。

输入框、下拉、按钮统一高 34；按钮文字两侧各至少 12。输入文字可用宽度为控件宽度减 24，下拉为宽度减 44（含箭头）。字段标签独立占 20 高，标签与控件至少隔 8。

## 物品：保留四种添加方式

| 方式 | 行为 |
|---|---|
| 物品 ID | 输入正整数，读取名称和游戏图标后确认选定 |
| 名字 | 搜索已知物品集合：背包、邮件快照、已有规则的物品；从候选中明确选择 |
| 背包 | 下拉可寄送物品，按 ID 去重；可搜索和分页 |
| 拖放 | 把物品拖到 40 × 40 图标区；只读取身份，不移动或寄出物品 |

名字搜索不承诺遍历游戏全部物品；无候选时提示使用 ID、背包或拖放。相同名称对应不同 ID 时显示 ID、图标和完整链接供确认，未选定候选不能保存。

所有方式共用已选物品状态。切换输入方式保留当前物品；只有选择新的明确物品后才替换。

|---|---|---|
| 四种方式按钮 | 88 / 72 / 72 / 96 × 34 | 间隔各 12；总和 364 |
| 查询输入 | 264 × 34 | 文字区 240；模式决定输入提示与校验 |
| 查询按钮 | 88 × 34 | 与输入间隔 12 |
| 已选 / 拖放图标 | 40 × 40 | 正式界面读取游戏物品图标，图中为示意 |
| 物品名 | 312 × 20 | 字号 16；长名称省略，悬停完整链接 |
| 物品 ID / 状态 | 312 × 18 | 字号 12；确认选定或等待信息 |
| 查询候选 / 背包下拉 | 364 × 34 | 文字区 320；每页最多 6 项，支持分页 |
| 物品字段标签 | 364 × 20 | 显示“物品 *” |

## 收件人：统一地址输入

下拉名单包含：

1. Core 缓存的账号内其它角色，排除当前登录角色的自动候选。
2. 已有规则里的收件人，包括不在账号角色或收藏联系人中的地址。
3. 手工收藏联系人。

按规范完整地址去重，合并来源标记。名单支持名字搜索及每页最多 6 项分页；旧规则中的收件人仍可复用，不因角色隐藏或联系人删除而丢失。

| 控件 | 宽 × 高 | 行为 |
|---|---|---|
| 收件人标签 | 364 × 20 | 显示“收件人 *” |
| 来源名单下拉 | 364 × 34 | 文字区 320，显示名字、服务器及来源 |
| 地址输入 | 364 × 34 | 可只输入角色名，也可输入完整名字-服务器 |
| 地址解析结果 | 364 × 18 | 字号 12；显示将要保存的完整地址 |

下拉与手工输入共用同一个地址字段：选择名单项立即填入输入框；输入框修改时下拉显示手工地址。服务器缺省只在当前角色服务器已知时补全；未知时要求填写服务器，不能猜测。

保存时规范化地址，不重复添加联系人。跨服地址完整保留，不强行改为当前服务器。

## 缓存与联系人管理

缓存常驻区只显示“已确认历史期限 / 待核实期限”及 88 × 34 管理按钮。管理时在 Core 右侧业务内容中展示：

- 保留天数编辑与保存。
- 当前缓存概况、角色缓存管理的 Core 入口。
- 分区末尾的清理过期历史操作及确认。
- 返回规则编辑的明确按钮，恢复原草稿。

规则删除在编辑已有规则时的管理操作末尾提供，明确对象并确认。联系人删除在联系人管理分区末尾，说明规则地址保留。常驻列表和普通表单不混排三个危险按钮。

## 窄屏与屏幕边界

业务宽度不足 1000 时，默认列表占满业务区。点击新增 / 编辑在同一内容区显示完整表单，提供返回列表；保留列表筛选、页码与选中规则。

物品方式按钮、输入和标签保持完整语义组；宽度不足 364 时按钮按两行分组，输入与查询上下排列。列表宽度不足 660 时改为 76 高两行规则行，并重新计算页容量。

由 Core 在安全屏幕高度内调整窗口；确实超出时使用 Core 的统一纵向滚动。导航、页面标题和底部状态持续可见，不加入列表内部第二条滚动条。
