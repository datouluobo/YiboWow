## 目标与探针边界

从 1 级新角色的真实能力出发，逐步取得身份、保存、基础 API 与业务数据的证据，为后续 Core 和业务插件适配确定最小范围。现有 Mists 实机验收与无限目标分别记录。

已建立独立非发布探针 `_NonRelease/YiboForeverProbe`，目录名与 TOC 同名；全工作区搜索 Slash 注册后选用 `/yfp`，无旧别名。TOC `16001` 已由游戏内 GetBuildInfo 核实。白名单、事件、存档、命令与验证边界见[探针说明](../_NonRelease/YiboForeverProbe/README.md)。

探针优先独立读取原生 API，避免把尚未完成无限适配的 Core 当作启动条件。目标 Core 可用后，再验证角色 ID、规则集范围、页面与保存契约。采样由明确命令或适用原生事件触发；不自动接／放弃任务、学习技能、移动物品、发送邮件、付款或删除存档。

未来探针的只读调用必须有明确用途和参数白名单；接口存在性检查与实际调用分开。记录缺失、异常、不可读取的返回值和受限场景，不为了得到非空结果调用业务变更接口。事件按目标支持情况登记，避免高频事件重复全量扫描；手动报告与有限样本优先。

## 证据与状态

函数存在、函数调用成功、观察到有效数据、业务语义验证通过分别记录。每个检查项同时保留状态、原始结果类型与数量、错误、角色条件和下次触发条件。

| 状态 | 使用条件 | 后续动作 |
| --- | --- | --- |
| 环境尚不可用 | 客户端未安装、不可登录或探针尚未加载 | 先满足P1／P2条件，不记为API失败 |
| 待采样 | 尚未执行该检查 | 达到阶段条件后采样 |
| 条件未满足 | 未学习专业、无坐骑、未解锁系统、尚未访问目标界面等 | 记录具体前置，解锁后再测 |
| API 可调用／语义待验证 | 方法存在且可调用，但只有空结果或不足以证明业务含义 | 有真实对象后做正向与对照样本 |
| 已观察／待复测 | 已取得有效对象或事件，尚未覆盖持久化／变化 | 按该项清单复测 |
| 已验证 | 当前构建与记录条件下完成预期检查 | 保留覆盖范围，构建变化时评估重测 |
| 调用异常 | 报错、权限限制或返回结构异常 | 保存错误和调用条件，定位后重试 |
| 当前构建不支持 | 有明确能力／客户端证据证明不支持 | 记录证据和影响，不从空数据推导 |

1 级角色没有专业、收藏、邮件、锁定或货币时，空结果只能描述该样本的现状；不能据此确认账号无数据、接口不支持或后续功能无价值。确认完整空集合须有该 API 在该场景的覆盖证据。

缺少API与当前场景不可用也分别记录。仅在前置条件具备并取得目标构建证据后，才确认“不支持”；模拟环境中的缺函数或报错不能代替该结论。

## 身份、范围与存档规则

- 采样记录实际可读的稳定身份字段及其来源；显示名、双名、服务器名或列表位置用于展示，不能直接成为正式跨插件关联键。
- 目标识别、角色身份、账号共享、规则集分别保存验证状态。规则集字段不可读时明确标未知，保持样本隔离；同名角色或相同物品ID不构成可合并依据。
- 探针拥有自己的诊断样本与有限历史，使用局部样本引用；正式Core角色ID与业务SavedVariables在目标适配阶段按公开契约接入。既有Mists快照及用户设置保持原范围。
- 先验证同一角色重载、退出再登录后的样本恢复，再取得跨角色／规则集的对照。第二个空角色只能帮助核对身份，不能独立证明共享库存或收藏语义。
- 所有时间保留来源；无法取得时间时标缺失，不写假定时间或用本次登录时间覆盖业务观察时间。客户端更新前后的样本按构建关联，若发生删档则另外记录环境变化；旧事实保留历史身份，不自动并入新进度。
- 单次样本、跨角色对照、真实周期与更新回归分别计入覆盖。存档迁移和清理若产生真实需求，再单独给出范围与验证方式。

## 首批适配选择规则

先解决Core身份、范围、保存与基础页面的真实差异，再选择一个已有正向样本的业务来源完成闭环。初期优先评估新角色能自然取得的背包／装备等事实；Vault或Builds是否适合作为首个来源，依据实际API、对象与所需最小改动决定，不预先固定为全仓库迁移顺序。

专业、邮件、坐骑、声望、首领与周期按各自样本条件进入；TaskHub至少等待一个已验证的来源与完成契约。AutoOpen／QuestBlocker的读取与状态采样可以独立安排，自动操作需要对应目标的另行验证。三项既有延期工作仍见[后续任务清单](后续开发任务清单.md)，与本轮无限规则准备分别排期。
