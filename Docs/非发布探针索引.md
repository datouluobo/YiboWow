# 非发布探针索引

本页是创建、复用和临时部署游戏内探针前的唯一查询入口。先按用途查现有探针；功能相同则直接复用，功能相近则先评估扩展或复用，不重复造轮子。新增探针后同步登记本页和独立探针命令清单。

## 命名与源码位置

- 可加载探针源码统一放在仓库根目录 `_NonRelease/<探针名>/`，目录名与默认 TOC 名完全相同。游戏客户端 AddOns 目录只在需要实机采样时临时创建同名 Junction；工作完成后断开，源码和证据保留在仓库。
- 新探针统一命名为 `Yibo<业务或系统><目标><用途>Probe`。目标仅在探针确实专用于某个客户端时写入名称；跨目标实现使用同一个稳定探针名和经过验证的目标 TOC。名称不包含日期、build、阶段号或临时批次。
- 每个探针登记用途、适用目标、命令、复用关系和当前状态。历史目录名为保留既有证据、引用或存档兼容而暂不改名的例外；新增探针不得沿用例外格式。
- 离线测试夹具、发布快照、取样指引和诊断报告不是可加载探针，按其主题保存在 `_NonRelease/` 对应分类目录，不为它们创建游戏目录 Junction。

## 重新部署流程

1. 先查本索引和对应探针 README／产品文档；确认是否已有相同或相近采样能力、当前缺口及所需客户端目标。
2. 复用时验证当前源码和 TOC 适用于目标客户端，完整退出客户端后才建立同名 Junction：`Interface/AddOns/<探针名>` → 仓库 `_NonRelease/<探针名>`。不要把发布包解压到源码联接目录。
3. 建立前核验客户端产品身份、Interface、清单选择规则和实际路径；依赖 Core 的探针还须按代码要求检查 Core 就绪与能力版本。只在本索引记录实际部署和断开日期，不把建立 Junction 当作实机通过。
4. 完成采样后断开探针 Junction，保留源码和独立 SavedVariables；如仍需后续采样，记录原因与待验项。
5. 没有可复用探针时，按本页统一名称、目录、TOC、Slash 冲突检查和只读／存档约束创建；同步本索引与 `Docs/Yibo系列插件命令清单.md`。
