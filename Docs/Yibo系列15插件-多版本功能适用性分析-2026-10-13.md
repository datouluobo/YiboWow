# Yibo 系列 15 插件：多版本功能适用性分析

> 文档状态更新（2026-10-16）：本文是2026-10-13的适用性分析快照，当前Mists功能验收已收口，见[状态总览](仓库当前状态总览.md)。文中版本与日程仅代表当时资料；无限开测时间待确认，实际能力按[首次验证计划](无限公测首次验证计划.md)分阶段取得证据。

分析日期：2026-10-13（北京时间）。

本文评估当前仓库实际功能在六个游戏目标中的用途、内容对应关系与适配边界，不是安装兼容认证。依据为各插件 TOC、README、当前目录与关键采集代码，以及文末官方资料。本次未运行六种客户端，也未改动运行代码、TOC 或发行配置。

## 1. 结论与阅读方式

Yibo 的账号管理、资源查询、进度展示与目标组织方式在多数版本都成立；差异主要落在内容目录、角色/账号范围、业务规则和客户端 API。不能把“内容存在”“功能有用”“当前代码能运行”合并成同一个结论。

- **通**：核心功能与业务思路直接适用，仍须做目标客户端 API、界面与实机适配。
- **换**：功能有用，但必须更换或重新核验本服目录、结构、范围或规则。
- **限**：当前功能只有部分内容或较窄用途成立，不代表完全没有价值。
- **无**：当前业务内容没有对应对象；重新开发另一种业务不能算当前功能兼容。
- **待**：官方资料不足以确认具体内容或可观测能力；可复用框架，暂不承诺相应功能。

“通”不表示现有安装包可以直接安装。“换”也不代表必须重写整个插件。表中无限服为官方公布设计下的产品适用性判断，Beta 实际开放内容、API 与持久化行为仍需另测。

## 2. 当前代码目标与支持证据

| 范围 | 仓库现状 | 可据此得出的结论 |
|---|---|---|
| 除 BeastPaths 外的 14 个插件 | 根 TOC 均声明 Interface 50504 | 目前以熊猫人怀旧服为开发目标；不能据此宣称支持其它五种客户端 |
| YiboBeastPaths | Mists TOC 50400；Mainline/默认 TOC 120007；运行时有 flavor 识别 | 已有正式服和熊猫人实现入口；Mists TOC 版本与其它插件不一致，须在目标 build 核验 |
| BeastPaths 正式服验证 | 既有审计记录有部分路线初测，锦绣谷相位等仍需覆盖；1.7.0 README 标注验收待完成 | 是已有实现和部分验证，不能扩大成全部路线、全部相位完成验收 |
| 70、60、时光、无限 | 未见这些目标的独立 TOC 与完整目标适配/验收记录 | 本次统一记为“尚未证实当前包兼容”，不是断言每个文件必然报错 |
| 最新工作树 | Crafting、TaskHub 等文档明确保留未发布或客户端待验收项 | MoP 是现有基线，也不能把所有工作树新增功能都记成已正式验收 |

Core 的通用界面与连接机制不等于现有采集层已经跨版本。例如 Core 专精采集使用 GetSpecialization；Builds 读取六层三选一天赋和六个雕文位；Vault 的拍卖采集使用 C_AuctionHouse。存在 API 探测或 pcall，只能证明部分失败处理，不能证明其它客户端业务语义正确。

AutoOpen、BeastPaths、Mounts 的 Core 集成是可选增强。其余业务插件现有 TOC 对 Core 声明强依赖；这些插件迁移前须先具备相应目标的 Core。

## 5. 各插件保留什么、调整什么、哪里最有用

| 插件 | 可以保留的核心 | 各版本关键调整与实际价值 |
|---|---|---|
| Core | 窗口、设置、入口、角色排序、公开契约与快照状态 | 所有版本都是系列底座。正式服区分战团共享与角色独立状态；无限重做规则集/双名/账号范围适配。不能把“所有角色可查看”推导为“所有角色可交易或代做” |
| AltoBoss | 首领/副本目标、历史、锁定展示、跨角色比较 | 正式服可用于当前锁定及旧本刷坐骑；70/60 用本服团本与世界首领；时光重点适配单难度25人和乱序开放；无限建立新地下城/团本目录。MoP 奖励周锁、位面观察、普通本次数与真实遭遇完成信号要分别处理 |
| AutoOpen | 允许列表、安全暂停、队列、逐项失败隔离 | 版本越多、奖励包越多，便利性越高。60 的对象较少但并非无用。不得把 MoP 的蚌、袋子和绑定确认来源原样当作其它目标的安全目录；需要手动打开的容器继续交给玩家 |
| BeastPaths | 路线渲染、世界/小地图投影 | 现有10只宠物在 MoP 最贴合，正式服为历史宠物收集。70/60/时光/无限没有当前潘达利亚路线业务；若未来增加本服稀有宠物，属于另建内容与验证，不能仅改 TOC 即宣称支持 |
| Builds | 装备/增强快照、账号对比、操作面板概念 | 正式服用现代天赋/配置与增强体系；70/60 用点数树；60 不应展示 MoP 式宝石/雕文需求；时光使用80级天赋/雕文与重铸装备规则；无限核验改造点数树、装备属性及可读能力。不能把固定双槽、六层天赋或六雕文当通用结构 |
| Crafting | 谁学会了哪个配方、哪个角色能制造、三态证据 | 70/60/时光有很强的账号专业分工价值；无限新增配方与营地设施也适合。正式服“已学配方”与“能做出指定品质”是两个问题，当前插件只提供前者基础；质量、专业专精、订单等须明确扩展后才可承诺 |
| Currency | 金币、代币余额、来源覆盖与阈值 | 70 可关注荣誉/竞技场及实际开放徽章；60 主要是金币与物品代币，不硬塞勇气/征服/考古；时光建立秩序纹章等本服目录；正式服区分可转移与不可转移、共享与角色余额。无限不要把传承点数直接当普通消费货币 |
| Legendary | 阶段/检查点、物品/任务证据、最终目标 | MoP 橙披是完整核心。正式服保留仍可获得旧橙装的收藏用途，但原橙披任务线已移除。70 保留旧世及开放阶段的TBC路线；60 保留旧世路线。时光需重做传说武器获取/升级模型，并考虑本服新增装备。无限目前只确认框架可用，具体路线未证实 |
| Mail | 到期风险、离线快照、收取队列、联系人与规则寄送 | 无共享仓库的版本，专业小号间邮寄尤其有用；正式服战团银行降低部分搬运需求，但不会消除交易邮件/到期风险。无限按双名和规则集核验地址与邮寄资格，不能从可见角色推出可寄送。操作仍需要游戏允许的邮箱场景 |
| Mounts | 在看到坐骑时回答来源和获取条件 | 全版本均有需求，差别在数量与来源。70/60 核验坐骑物品、法术与收藏入口，不假定有同等 Mount Journal；正式服重核已移除、活动和难度来源；时光同名旧本掉落已变；无限建立独立新目录。现插件是 Tooltip 信息增强，不能写成已实现的完整账号坐骑任务管理器 |
| QuestBlocker | 全局/角色规则、暂停、矩阵管理 | 适合使用自动接任务工具或反复做不想接任务的玩家；纯手动接任务时价值相对有限。所有版本都要核验任务分类、任务ID、第三方工具与保护调用；新内容丰富的无限宜先保守启用，避免错误拦截关键职业/解锁任务 |
| Reputation | 声望状态、等级目标、账号比较 | 70 的钥匙/附魔/配方门槛、60 的阵营/配方、时光的本服兑换都适合。正式服按实际声望区分战团共享、角色独立与特殊等级；共享声望应只保留一个事实视图，不能重复计为多个角色的工作。无限使用本服新增阵营和传承挑战关联，前提是来源提供契约 |
| TaskHub | 主动添加、目标生命周期、展示与提醒、来源失效处理 | 可以组织任何目标版本已有的库存、配方、声望、首领等来源。不同服只是可添加目标集合不同；无限传承、正式服新的周常等是后续接入候选，不是当前已实现能力。缺来源保持不可用/待核实，不复制来源的权威状态 |
| Todo | 冷却/周期状态、活动目录、观测与未知语义 | MoP内容最完整；70可新增本服裁缝/炼金冷却与日常；60可关注月布、转化、筛盐等有限生产周期；时光采用经核验的WLK及本服目录；正式服保留有收益旧项目并新增本版本周期；无限营地设施的已公布共享冷却是适配候选，须先验证可观测性 |
| Vault | 物品快照、位置来源、只读查询、库存目标 | 70/60材料小号与个人银行最有用；60不提供原生公会银行的位置应禁用，公会银行小号仍是角色库存；正式服新增战团银行等共享位置必须去重，适配现代银行/AH；无限按规则集和真实共享范围处理，不混算不可互通资源 |

正式服共享范围依据[战团说明](https://worldofwarcraft.blizzard.com/en-gb/news/24061008/the-war-within-warbands-preview)与[战团银行及货币说明](https://worldofwarcraft.blizzard.com/en-gb/news/24115313)。无限双名与规则集依据[官方规则集文章](https://wow.blizzard.cn/news/24302070/index.html)及[经典服官方新闻入口](https://wow.blizzard.cn/classic/news/index.html)。无限专业/营地的候选方向依据[官方深度解析](https://wow.blizzard.cn/news/24303313/)；未来接入建议是本文推断。

## 7. 优先适配建议

以下是根据现有功能、内容稳定性与协作依赖作出的工程建议，不是用户已批准的开发计划。

| 目标 | 优先方向 | 原因 |
|---|---|---|
| 正式服 | Core → Vault/Mail → Builds/Crafting → Mounts/AltoBoss → 其它来源/TaskHub | 通用需求充足；先解决战团共享范围与现代API，再承载目标。BeastPaths单独补齐已有实现验收 |
| 熊猫人90 | 收尾当前各插件与Core API13的实机验收 | 已有内容最完整，宜先形成可靠发布基线 |
| TBC周年70 | Core → Vault/Mail → Builds/Crafting/Reputation → AltoBoss/Currency/Legendary/Todo → TaskHub | 专业小号、英雄本/团本、声望门槛、材料邮寄与阶段橙装用途明确 |
| 经典60 | Core → Vault/Mail → Crafting/Builds/Reputation/AltoBoss → 精简Currency/Todo/Legendary → TaskHub | 核心是小号资源与旧世进度；保持少量有用内容，不制造空模块 |
| 时光80 | Core → AltoBoss/Legendary/Currency/Builds → Vault/Mail/Crafting/Reputation/Todo → TaskHub | 规则差异集中在团本、橙装升级、重铸装备和新货币，独立目录收益最大 |

AutoOpen、QuestBlocker 可独立做目标验证后提供；不必等待所有业务迁移。BeastPaths暂只维护MoP与正式服。TaskHub可早期接入首个已完成来源，表中顺序不表示必须等全部来源完成才有价值。

按仓库已确认的[多版本开发规则](多版本开发规则.md)，复用稳定模型与界面，把API与数据目录按目标隔离、独立分包；不复制六套完整源码，也不能只改Interface数字。新增目标名称与发行配置仍按正式实施时的仓库规则确认。

## 8. 实机验证必须回答的问题

1. 目标客户端是否正确加载TOC、初始化Core与业务页，当前角色身份是否稳定。
2. 当前与离线快照是否有正确时间、覆盖与失效状态，未知没有被写成0或已完成。
3. 角色独立、账号共享、公会共享与规则集隔离是否正确，统计是否重复，角色可见与交易资格是否分开。
4. 目标目录、开放阶段、职业/等级资格、实际难度、冷却/重置与奖励规则是否一致。
5. 保护操作、战斗锁定、邮件节流与新客户端受限数据是否按能力降级；AltoBoss战斗日志、Mounts光环/单位读取等需要特别核验。
6. 关联来源缺失、晚注册、不兼容与注销后，TaskHub等消费方是否仍保持基本功能和未知语义。

正式服已有广泛插件权限调整，依据[至暗之夜前夕说明](https://wow.blizzard.cn/news/24244455/index.html)。本文没有足够官方API资料证明无限的限制逐条与正式服相同，因此无限记为单独待测，不能把网上概括替代客户端能力证据。

普通旧世与专家/自强不要混为一列：自强可能禁止交易、邮件、AH等，应按实际规则停用对应功能，而非认定整个Mail/Vault产品无价值。依据[周年与专家模式官方介绍](https://wow.blizzard.cn/news/24156594/index.html)。无限的专家模式尚非首发开放，收藏/传承共享有单向边界，依据[规则集说明](https://wow.blizzard.cn/news/24302070/index.html)与[传承说明](https://wow.blizzard.cn/news/24307383/index.html)。
