# YiboMail Broker 与小地图悬停规划

> 日期：2026-10-05。
> 状态：已实施；悬停摘要融合附件、金币、期限警示和更新状态，待客户端验收。
> 实施范围：悬停警示＋登录时一次主动提醒；到期提醒是必需项。
> 已确认默认列及顺序：角色、邮件数、附件数、可收金币、最早到期、更新状态。

## 目标与现状

玩家短暂悬停即可判断哪个角色有邮件、附件和可收金币，多久到期，以及数据来自哪次扫描；临期与到期风险通过摘要顶部提示条突出显示。

实施前的正式 TOC 未加载账号页和缓存浏览文件，`FEATURES.account` 关闭。扫描器已有到期时间和覆盖状态；本次把已保存摘要接入 Core 页面与预览，并将角色准入限定为成功收件箱扫描的快照。

账号页与预览沿用 Core 的表格、字体、角色标识、范围和排序，不新增图标资产或独立窗口壳。

## 悬停显示内容

采用角色为行的紧凑账号表。角色名依职业着色，服务器名用辅助色显示。Broker 与小地图显示完全相同的内容，默认展示所选账号/服务器范围内全部有效角色，最多 20 名，使用 Core 的隐藏、短名、置顶及排序规则。

| 默认字段 | 示例 | 用途与口径 |
| --- | --- | --- |
| 角色 | 小牧师 · 莫格莱尼 | 角色名依职业着色；服务器名用中性色，跨服范围保留服务器信息。 |
| 邮件数 | 12；或 18/24 | 完整快照显示当前邮件数；部分扫描显示已扫描/总数。离线数量是上次扫描值。 |
| 附件数 | 18 | 汇总邮件中的物品附件格数，每格计 1、不累加格内堆叠数量；仅统计当前有效快照，不计已确认收空邮件。 |
| 可收金币 | 42.8 金 | 汇总无需 COD 付款的邮件金币；COD 金额不计为可收金币。 |
| 最早到期 | 约 2.4 天 | 取有效邮件中最近的未来期限；7天内使用警示色，3天内使用紧急色；已到估算期限时显示待核实数。 |
| 更新状态 | 10-05 08:20；部分 · 10-05 08:20；读取失败 · 10-05 08:20 | 显示最后成功扫描时间，必要时标明部分扫描或本次读取失败；悬停角色行可查看完整覆盖和未扫描数量。待核实积压由可选扩展列显示。 |

Broker 与小地图使用 Core 的统一标题栏及服务器范围选择。悬停摘要显示到期提示条和默认六列表格，与主窗口账号总览共用渲染器。数据行高 24 UI 单位；表格列按表头与当前角色数据的最大文本宽度自适应，悬停窗口按列宽总和紧凑收缩。沿用 Core 的字段投影机制；默认字段保存于 Mail 的 `settings.previewColumns`，由 Core“显示与入口”统一提供设置；到期提醒、COD 邮件和待核实缓存为可选扩展预览列。

角色行保持 Core 顺序，不为了临期风险单独重排悬停角色。期限排序用于主页面的邮件明细。超过 20 名时明确显示预览覆盖数量，完整页面仍可访问全部有效角色。

邮件发件人、主题、附件和完整收取操作由 Core 邮件页面呈现；悬停仅提供账号概览和到期判断。

## 到期提示与颜色

以扫描保存的 `expiresAtEstimate` 减当前时间计算。最早到期单元格与摘要顶部提示条使用 7天/3天阈值；登录聊天提醒继续沿用收件箱的 24小时/3天风险分级。边界如下：

| 剩余时间 | 显示 | 提醒语义 |
| --- | --- | --- |
| 大于 7天 | 常规色，约 N天 | 普通待取邮件。 |
| 大于 3天且不超过 7天 | 黄色，约 N天 | 摘要提示条提示 7天内有邮件到期。 |
| 大于 0且不超过 3天 | 红色，约 N天 | 摘要提示条提示 3天内有邮件到期。 |
| 小于或等于 0 | 红色，待核实 N封 | 仅说明缓存已到估算期限；提示重新打开邮箱核对，不宣称邮件已消失或物品已丢失。 |
| 缺少有效期限 | 期限未知 | 不将缺失时间解释为已到期；该记录不加入有期限统计。 |

风险覆盖普通、退回、COD、金币、附件及空信，按邮件封数统计。最近有效扫描中的空邮箱显示邮件 0、无临期邮件、最早到期“—”；其离线状态仍标注上次扫描时间。

倒计时在悬停打开时重新计算，预览保持打开时定期刷新，跨过提醒阈值即可改变状态；无需重新打开邮箱。没有扫描依据的邮件与未暴露邮件无法计算期限。

## 登录主动提醒

已确认提供登录时一次提醒。建议使用一条聊天提示，不弹窗；等 Core 角色目录、用户过滤和 Mail 缓存准备完成后汇总，避免插件初始化阶段漏掉离线角色。

示例：`[Yibo] 邮件：小牧师紧急2封（最早约6小时）；小猎人临期3封。按上次扫描估算，打开邮件页查看。`

- 默认提醒范围与邮件账号页的所选范围和角色准入一致；筛选排除的角色不偷偷进入提醒。若预览超过 20名，登录摘要检查该范围全部有效角色，不受预览行数上限影响。
- 只在存在临期、紧急或到期待核实记录时输出。以已扫描数据为依据；部分扫描角色明确带“另有未扫描邮件”。
- 信息较多时先列紧急及到期待核实角色，再列临期角色；一条摘要容纳不下时保留最紧急角色与其余角色数量，完整详情在账号页查看。
- 每次登录最多一条。建议对相同风险集合和同一风险等级做账号级当日去重，避免切角色或重载重复输出；出现新增风险邮件或风险等级升级时，下一次登录可重新提醒。去重不以扫描 revision 或精确到期时间作为唯一依据，避免重扫造成误重复。
- 普通过图、邮箱更新和打开悬停不触发登录提示。悬停警示独立实时更新，不受聊天提醒去重影响。
- 登录提醒开关放入 Core 承载的 Mail“业务设置”；默认开启。首版固定 3天/24小时阈值，与收件箱一致。

相同风险在同一服务器日期内去重；新增风险记录或风险等级上升后允许再次提醒。

## 快照与状态约束

- 只纳入具备成功收件箱扫描依据的角色，允许完整、已知空、部分以及这些状态的历史快照。只有发件记录、没有成功收件箱扫描的角色不出现在悬停中。
- 当前摘要以有效 `visibleKeys` 投影为基础，复用收件列表对已确认收空邮件的隐藏规则；已归档收取记录不进入待取数量或到期风险。
- `unverified` 积压记录不混入确定的当前邮件、附件、金币及临期数。账号页提供待核实数量与明细，悬停更新状态在存在积压时给出简短提示。
- 离线、邮箱关闭、扫描失败不抹除最后成功扫描；显示“上次扫描/估算”。已到估算期限的缓存不因倒计时而自动删除。
- 部分扫描的到期风险仅覆盖已扫描邮件；未扫描邮件不能描述为无风险。邮件数必须说明 `已扫描/总数`。
- 无有效角色时由 Core 显示最小空状态：“打开邮箱完成一次扫描后，可查看账号邮件与到期提醒。”不生成无数据角色行或零值假记录。

## 入口与实现顺序

Core 创建、定位和关闭预览，管理 Broker/小地图及入口设置。独立 Mail 入口沿用 Core 的用户选择，新安装默认不自动开启。左键打开 Core 邮件主页面；右键打开入口设置。悬停仅预览，收件操作仍在游戏邮箱中执行。

1. 在 Mail 建立统一角色摘要、邮件准入、期限分桶和格式化函数，供账号页、悬停与登录提醒调用。
2. 接入 Core 邮件主页面及预览，用同一摘要渲染账号总览，再由主页面提供临期邮件明细；启用入口所需的加载文件，不连带开放规则发件功能。
3. 接入 Core 字段、入口配置和 Mail 业务设置，保存预览列及登录提醒偏好。
4. 接入登录提醒和持久化去重，补齐时间变化与扫描事件刷新。

Core 的表格、范围与预览约定承载实现；Mail 收件箱的登录提醒继续使用 24小时/3天风险分级，悬停摘要使用 7天/3天颜色提示。客户端仍需核对布局、状态文字、色彩对比和入口交互。

## 验收重点

- Broker、小地图、账号页、登录提醒对同一快照的数量、风险与范围一致。
- 7天、3天、0 的边界正确；保持预览打开可跨级刷新。
- 多角色、短名、隐藏、跨服、20名以上角色的覆盖与完整访问正确。
- 完整空邮箱、部分扫描、失败后保留历史、未扫描角色、仅发件历史角色分别正确表达。
- 收取后不重复提醒；COD、退回、空信、重复签名邮件按封计算且不被静默合并。
- 登录只输出一次；相同风险切角色/重载去重；新增风险和升级能够再次提醒；预览不被去重抑制。
- 左键打开统一主页、右键打开入口设置，所有位置共用 Core 生命周期；当前原生收发件功能保持可用。
