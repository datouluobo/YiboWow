# Mail 通知刷新与初始占用（2026-10-29）

本轮重点是收件通知、账号摘要、在途查询及登录常驻占用。完整 records、history、原信、附件、未知字段与事件顺序保留，不清理历史、不改变 schema 或保留策略，也不增加强制全量 GC。

## 改动

- Mail 自有账号页、原生界面和待办失效订阅使用无负载信号，避免为不读取 payload 的回调复制相同数据。普通订阅与 Core Contracts 的隔离副本契约保持；只有运行中队列已安排权威进度刷新时跳过重复原生刷新，暂停、错误、普通观察继续刷新。
- 账号摘要按 owner coverage/revision、当前时间及记录集合复用原始统计；显示结果仍隔离，并逐次读取实时错误状态及当前角色。旧未版本化快照保持重新扫描。缓存弱引用记录集合，关闭后不因闲置摘要保留被替换的旧邮箱。
- Core API13 新增 character-identity-cache:1，GetAllCached(identityOnly) 复用只读身份目录。Core 在通知前由 owner 失效，Mail 依目录数组身份重建在途目录与指纹，不依赖监听顺序。数据代次仍决定在途证据失效；关闭邮箱释放 Mail 派生目录，公共查询结果仍隔离。
- 收件人、视图、待办与迁移中的只读目录枚举接入同一能力，避免每次在途地址解析重新投影。当前角色仍使用独立身份读取。原生请求前／成功后核实未减少。
- 初始化合并所有字段完全相同的只读附件数组，索引只在初始化期间存在。不同元数据不合并；缺失字段不写 nil，避免 Lua5.1 无效 hash 扩容。公开返回值和历史输入仍隔离。

## 离线证据

NotificationPipelineSpec：100封邮件、每封12附件，3个角色在每次发布查询在途，并让账号摘要执行三次投影。对比冻结的本轮前 Store／Items／AccountPage，固定其余环境。暂停 GC 测量累计分配，结束后恢复回收；不代表游戏峰值或FPS。

只读磁盘样本：较大存档31角色、1978条记录、7774条历史，字段指纹及条数前后相同，原文件SHA不变。恢复数组共享后29161→23340个唯一表，复用7647个数组；同进程存档组件13.825→13.494MB，独立进程13.701→13.369MB。新增登录收益约0.33MB，尚不能宣称游戏26MB基线大幅下降；必要历史仍需常驻。没有读取其它业务存档，也没有写入游戏WTF。

73／73回归通过，373个加载引用Lua语法通过；语言报告Mail硬编码候选为0，缺英文／格式差异为0，6项未知key均属未触及的AutoOpen。

回归入口：_NonRelease/MailPerformance20261029/audit.py。新增覆盖信号隔离、目录 owner 失效／改名、关闭释放、摘要时间／版本／实时错误、旧记录集合弱引用、数组所有字段一致、原生运行／暂停刷新，以及完整收件通知链。新测试最初因夹具缺 date 和寄信框拖拽API失败，补齐时间API并隔离未测寄信创建；生产环境未据此增加回退。

## 目标、公共能力与加载审查

Core共享 Characters 影响 Mists／Retail／Forever；Mail共享状态、存档、视图逻辑影响 Mists 与 Forever草稿。客户专用API仍位于原 Mists Scanner／Queue 等适配模块；此次仅调整关闭派生缓存参数，没有新增客户端专用职责或目录迁移。

Mail Mists 和 Forever 初始化都要求 Core API13、character-identity-cache:1 及既有能力；Mists继续检查 character-identity:2／account-identity-context:1，Forever保留既有 character-identity:1。缺能力提示升级，在业务写库前停止，无本地回退。Core新增能力及Mail消费者应同步更新。CAP-007／004／005／009 审查见公共能力台账。

清单和实际加载名保持：Core源码 YiboCore_Mists.toc／YiboCore_Mainline.toc／YiboCore_Forever.toc，玩家包 YiboCore.toc；Mail Mists既有单目标 YiboMail.toc，Forever草稿 YiboMail_Forever.toc。未改TOC/XML/引用、实际目标保护、单次初始化、事件入口注册方式、SavedVariables身份或覆盖更新加载链。旧文件覆盖与恢复沿用既有机制证据，新能力与新运行字节仍待客户端验证。

统一构建器仅执行 ValidateOnly，不生成或发布安装包。Core三个目标和Mail Mists均已通过目标、Interface、引用及包内容校验；Mail Forever没有发行配置，只登记离线Smoke，不能据此宣称可发布。
