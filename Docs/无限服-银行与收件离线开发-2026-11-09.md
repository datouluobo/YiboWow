## Vault 银行及加载边界

- 原生镜像将 `BAG_UPDATE` 声明为带容器 ID 的事件，`BAG_CONTAINER_UPDATE` 和 `BAG_UPDATE_DELAYED` 未声明容器 ID。Forever 仅用角色银行页的 `BAG_UPDATE` 或既有银行专用事件确认首个全空读取，仍支持手动刷新。无容器 ID 的背包更新继续触发扫描。角色银行每个已购页都必须有正容量。真实客户端事件时序待验。[Forever 原生容器事件定义](https://raw.githubusercontent.com/Gethe/wow-ui-source/forever/Interface/AddOns/Blizzard_APIDocumentationGenerated/ContainerDocumentation.lua)
- 源码清单为 `YiboVault_Forever.toc`，单目标包映射为唯一的 `YiboVault.toc`。修改了 Forever 事件注册及版本，未增删加载引用。保留 `YiboVault` 安装目录、`YiboVaultForeverDB` 和 schema 1。Mists 保留既有 `YiboVault.toc` 与 `YiboVaultDB`，无银行代码改动；共享语言表仅新增 Forever 状态。
- Forever 初始化先校验实际客户端，再检查 Core 就绪、最低 API13、localization:1、account-surface-budget:2、account-character-admission:1 及既有能力。业务初始化成功后注册事件，重复调用先由 `initialized` 守卫返回。模拟验证目标误装和旧 Core 停在写库前、重复初始化不增加订阅、两个存档表隔离。银行采集继续复用 Core 身份，页面继续复用 Core 账号窗口与预览，没有新的 Core 公共契约。
- 解包已核对清单、运行字节和资源。三个候选均为各插件的首个 Forever 发行范围，旧 Forever 正式包覆盖场景不适用。源码目录中可能保留同名 `*_Forever.toc` 并由客户端优先选择，候选包须在独立安装目录验收。干净安装、真实落盘、关闭后查看旧快照与完整退出恢复仍待客户端。客户端正常加载及语言验收以实测为准。
