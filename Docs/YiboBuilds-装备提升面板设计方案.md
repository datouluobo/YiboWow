# YiboBuilds 装备提升面板设计方案

状态：已按实机反馈调整右侧视图切换；实现中，待 MoP Classic 再次验收。

## 1. 定位与布局

装备提升面板是当前角色单件装备的操作入口。点击装备格即可打开；继续点击另一件装备时，面板切换到新装备。面板替换右侧天赋／雕文内容区，关闭后恢复天赋／雕文；人偶与装备区始终可见。本方案统一覆盖宝石镶嵌与更换、附魔卷轴、专业配方及装备额外孔。

装备格、装备名称、孔位标记、宝石图标、附魔标记、工程标记、底部武器格和顶部“原型 / 幻化”控件保持原位、原尺寸、原命中区域及原 tooltip。面板的绘制与鼠标命中仅在右侧内容区；打开面板时可给被选中的装备格增加一圈选中描边，但不移动其原有增强图标。

右侧面板采用固定标题与选中装备行，内容纵向滚动。内容增加时只滚动面板内部，不改变装备区尺寸。若右侧内容区已折叠，点击装备格自动展开并显示提升面板；点击关闭按钮或再次点击已选装备格恢复天赋／雕文。按该装备实际适用的类别排列：宝石孔、附魔与背包增强物品、专业提升。没有适用内容的类别不显示。可直接执行的背包宝石与附魔候选使用完整卡片、物品图标、青绿色边框与操作标识；悬停时增强底色与边框，已选择的宝石显示持续选中态。仅能制作的候选继续显示为次级操作，避免误认为能立即施加。

## 2. 候选来源与展示条件

只展示对**这件装备**有意义的提升，现有增强状态与候选动作分开呈现。现有状态沿用装备快照；候选须针对当前角色实时判定。

| 来源 | 展示条件 | 面板内容 |
| --- | --- | --- |
| 宝石 | 装备有实际孔位 | 按真实孔序显示孔型、现有宝石、匹配的背包候选及数量；已镶孔同样可选择替换。珠宝加工已学切割配方产生的匹配宝石标为“可制作” |
| 附魔配方 | 当前角色仍拥有附魔专业，已学会该配方，目标部位与装备满足配方要求 | 配方名称、已学会标识、当前安装状态；材料在点击使用时核对 |
| 背包卷轴及增强物品 | 当前角色背包内存在，且物品可用于该装备部位 | 物品名称、数量、适用目标；与同效果配方合并到一个效果条目下展示不同来源 |
| 工程 | 当前角色拥有工程专业，已学会相应强化，装备部位符合要求 | 可用工程强化及当前安装状态 |
| 锻造 | 当前角色拥有锻造专业，已学会对应额外孔等操作，装备部位符合要求 | 对应专业操作；已有实际孔时显示现状，避免把同一孔重复列为“待打孔” |
| 制皮、铭文、裁缝 | 当前角色拥有相应专业，已学会配方，装备部位符合要求 | 对应腿甲片、肩部铭文、披风刺绣等实际适用动作 |

“已学会”必须来自当前角色的配方事实，不能仅因版本化目录收录某效果就认为已学会。已装备但当前角色不再具有专业能力的增强仍显示为现有状态，不因此生成可执行候选。背包卷轴与直接施放配方是两种来源：即使没有附魔专业，只要卷轴本身允许当前角色使用，仍可作为背包候选出现。

专业配方**已学会且产物或效果适用于当前装备时就保留在候选列表**。点击该项时检查材料、专业等级、装备条件、角色状态及客户端执行条件；材料不足则显示所缺材料及数量，保持面板和当前选择，不发起施加。候选列表不预先因材料缺失而消失。配方要区分“直接对装备施加”和“先制作宝石、腰带扣、腿甲片、法术线等物品，再使用产物”两条路径；后一类明确标为“可制作”，制作完成后重新检查背包与目标装备。

### 按装备逐层筛选

候选须依次通过：**当前版本允许新施加 → 效果或物品明确适用当前装备槽位 → 具体装备的类别、子类、物品等级和其它目标条件成立 → 当前角色已学配方且具备专业能力，或背包确有可用物品 → 现有增强位允许新增或替换**。额外等级、职业、专业专属和唯一装备限制也参与判断。材料只决定点击后的执行反馈，不决定已学配方是否列出。已有宝石及已安装效果的事实展示独立于候选筛选。

**宝石通则：**下表所有部位都只依据该件物品的真实孔序列显示孔位；无实际孔时无宝石候选。背包成品宝石和当前角色已学会的珠宝加工切割配方分别作为“可直接镶嵌”和“可制作后镶嵌”来源。候选须匹配孔型及宝石自身使用限制。

### 完整装备栏位矩阵

下表逐一覆盖当前界面显示的 18 个装备栏位。“可列”仅表示进入进一步目标校验的增强类别，并不代表任意同类配方、卷轴或物品都能用于该件装备。已学配方必须带有实际可用的应用法术或可制作产物；只有附魔效果记录而没有施加来源，不生成候选。

| 栏位 | 可列的非宝石提升来源 | 必须再核对的边界 |
| --- | --- | --- |
| 头部 | 无 | 本面板不提供头部附魔或工程新施加候选；实际已有的旧效果继续按装备事实显示 |
| 颈部 | 无 | 仅显示真实孔与宝石 |
| 肩部 | 肩部铭文/肩部增强物品；已学铭文专业肩部配方；适用的背包肩部物品 | 铭文专业专属效果与通用消耗品分别核验，目标必须是肩部 |
| 背部（披风） | 披风附魔或卷轴；已学裁缝刺绣；已学且当前可施加的工程披风强化 | 常规附魔/刺绣与工程强化分别核验其增强位；配方目标必须是披风 |
| 胸部 | 胸部附魔或卷轴；可用于胸部的背包护甲增强物品 | 按该物品的目标类型核验，不能把其它护甲片泛化到胸部 |
| 衬衣 | 无 | 仅展示装备事实，不列主动提升候选 |
| 战袍 | 无 | 仅展示装备事实，不列主动提升候选 |
| 腕部 | 护腕附魔或卷轴；已学制皮护腕强化；已学锻造护腕额外孔 | 锻造动作仅在额外孔尚未存在且目标符合要求时列出；制皮效果检查专业专属条件 |
| 手部 | 手套附魔或卷轴；已学工程手套强化；已学锻造手套额外孔 | 常规附魔、工程强化、额外孔分属各自状态；已有额外孔时只显示孔状态 |
| 腰部 | 背包腰带扣或已学配方对应的可制作腰带扣；已学工程腰带强化 | 腰带扣只针对腰带；已有扣生成的孔时显示真实棱彩孔；工程与扣独立 |
| 腿部 | 适用的背包腿甲片、法术线及其它腿部增强物品；已学制皮/裁缝配方的可制作产物 | 制作产物与直接施加分开；目标必须是腿部且符合护甲/物品限制 |
| 脚部 | 靴子附魔或卷轴；明确可用于脚部的背包增强物品 | 按物品目标要求核验；腰带工程强化不得误入脚部 |
| 戒指 1 | 当前角色已学且可自行施加的戒指附魔 | 校验当前附魔专业与所需技能；普通装备附魔卷轴不泛化到戒指 |
| 戒指 2 | 当前角色已学且可自行施加的戒指附魔 | 与戒指 1 独立检查当前装备和已安装状态 |
| 饰品 1 | 无 | 仅显示真实孔与装备事实 |
| 饰品 2 | 无 | 仅显示真实孔与装备事实 |
| 主手 | 适用该物品子类的武器附魔或卷轴；主手装备实际为弓、枪、弩等远程武器时，适用的瞄准镜/工程产物 | 先读装备类别与子类，再区分近战武器、远程武器及特殊物品；瞄准镜不能用于普通近战武器 |
| 副手 | 副手是武器时适用的武器附魔或卷轴；副手是盾牌时适用的盾牌附魔或卷轴 | 对副手物品的具体类别与子类分别判定；一般副手物品不继承武器/盾牌候选 |

该矩阵是**候选上限**。`EnchantCatalog`、`ProfessionCatalog`、`EngineeringCatalog`、`SocketEffectCatalog` 含有已安装或历史记录，不能直接当成当前角色的可施加清单；其中工程目录还保留头部旧效果。候选需要额外的“施加配方/背包物品 → 目标槽位与物品类型 → 当前版本可用性”映射。没有足够目标数据时，应显示已安装事实并暂缓产生操作候选，避免给出错误按钮。

### 专业与候选状态

附魔、工程、锻造、制皮、铭文、裁缝和珠宝加工各自按上表与真实配方目标筛选。炼金、采矿、采药、剥皮等专业的被动收益或可装备成品不属于“对当前装备施加提升”；它们不会仅因角色拥有该专业而出现在面板。若这些专业制作出的某个**背包物品**确实带有可用于当前装备的使用效果，仍按该物品本身的目标规则判定。

| 候选状态 | 面板行为 |
| --- | --- |
| 背包有可直接施加的成品 | 显示物品和数量；点击时再次检查背包位置、目标和使用限制 |
| 已学直接施加配方 | 显示“已学配方”；点击时检查材料，缺材料则列出缺口 |
| 已学制作配方、产物可施加 | 显示“可制作”；先完成制作，再重新验证产物和目标并进入使用步骤 |
| 已安装且允许替换 | 显示现有效果与替换后的效果；宝石逐孔单次确认 |
| 已安装且当前无法再施加 | 只显示事实状态和原因，不生成重复打孔、重复扣孔等动作 |
| 目标不符、版本不支持或施加来源不明 | 不进入操作候选；装备已有的效果仍按事实显示 |

## 3. 操作流程

### 打开与切换

左键点击装备格打开面板，标题行显示装备原生图标、名称及当前增强摘要。悬停装备格和周边孔位、附魔标记仍调用原有 tooltip。切换角色、构筑槽位或装备时清理待选操作；非当前角色和当前未穿戴的历史/确认快照只显示提升状态，不提供执行按钮。

### 宝石：单孔、单次确认

逐孔显示现有宝石和匹配的背包宝石。背包候选使用实际图标、名称与数量；选中后高亮并标明“待应用”，面板底部出现“应用宝石 / 取消”。空孔的操作为“镶嵌此孔”，已镶孔的操作为“更换此孔”。选中某孔的一颗候选宝石后，只为**该孔**建立游戏认可的待镶嵌状态；点击面板中的“应用宝石”提交，确认成功并读取新的装备事实后，才允许处理下一孔。更换前展示旧宝石与新宝石，并说明旧宝石的处理结果。每次操作只提交当前孔的一颗宝石。原生镶嵌窗口保持客户端事务但在操作期间隐藏。

普通颜色、多彩、棱彩和染煞孔按客户端实际规则过滤，同时检查宝石自身的专业、装备唯一数量等使用限制；同一颗背包宝石不能被多个待处理孔同时视为可用。无匹配宝石时仍显示孔位与“背包中无匹配宝石”。空孔继续使用现有空心底座，已镶宝石使用实际物品图标和 tooltip。

### 附魔、背包物品与专业增强

点击候选先显示该效果的来源及它将覆盖或新增的增强位。若背包已有卷轴或增强物品，优先提供该物品的使用路径；已学配方提供专业施放路径。确认后由提升面板直接对当前装备格提交目标，不再要求玩家在人物面板点第二次。背包卷轴拖放到装备格是同一规则下的快捷入口，仅在目标合法时高亮并交给客户端允许的物品使用流程。常规附魔、工程强化、额外孔和专业专属附魔分别核对目标类型。

点击执行时再核对材料、背包物品、目标装备和当前专业状态。若材料不足，展示缺少的材料与数量；若目标不匹配或游戏拒绝操作，展示客户端返回的具体原因。成功后重新扫描实际装备链接与孔序，刷新装备侧边标记和面板。确认快照依旧遵循既有“玩家确认构筑装备”的机制，不由一次增强操作暗中覆盖。

## 4. 视觉与空间验收

1. 面板打开、滚动、提示材料和切换装备时，左右装备格及每个珠宝、附魔、工程标记的位置和独立 tooltip 都不变；面板鼠标层不吞掉它们的悬停与点击。
2. 面板完整位于右侧天赋／雕文内容区；人偶、主手、副手和所有增强图标完整可见、可悬停、可点击。
3. 点击任一装备后，只看到该件装备适用且已学会的专业提升，以及背包中适用于该件装备的卷轴、增强物品和匹配宝石；头部无附魔、工程候选，非腰带无腰带扣候选。
4. 一个装备有多个孔时，逐孔单独确认；已镶宝石可更换，更换前显示新旧宝石，完成一孔后重新读取装备再处理下一孔。
5. 已学配方缺材料时仍可找到；点击后显示缺口，原有装备状态保持不变。
6. 离线角色、其他角色与未穿戴的确认装备不会出现可执行操作。
7. 按完整栏位矩阵逐栏验收：头、颈、衬衣、战袍、两件饰品只出现实际孔对应的宝石操作；肩、披风、胸、腕、手、腰、腿、脚和双戒指各自只出现目标允许的增强来源。
8. 主手分别用近战武器与弓/枪/弩验收，副手分别用武器、盾牌和一般副手物品验收；瞄准镜、武器附魔、盾牌附魔各自只进入合适的物品子类。
9. 腰带扣、腿甲片、法术线、肩部物品、卷轴和切割宝石分别测试背包成品与已学制作配方两条来源；配方只产生物品时，界面先提示制作，再使用产物。

## 5. 实现前实机验证

目标客户端为仓库 `.toc` 指定的 MoP Classic `50504`。面板负责汇集候选、展示待应用状态、提交单孔宝石与直接指定附魔目标；实际施加调用客户端允许的镶嵌和物品目标接口。仍须在该客户端实机验收替换确认、专业材料反馈，以及战斗或受保护状态下的限制。

概念图中的物品、宝石和专业图标是示意，实施时使用客户端真实图标和原生 tooltip。

## 6. 当前实施记录

- 点击装备格可在右侧天赋／雕文内容区打开单件装备面板；关闭后恢复原视图，角色或构筑槽位变化时清理当前选择。
- 已镶宝石优先按物品 ID 实时读取图标，并以快照图标回退；空孔继续使用空心底座。
- 当前穿戴装备的宝石、附魔、工程、腰带扣及锻造孔状态沿用装备快照；非当前穿戴只读。
- 宝石从背包实际物品和当前角色已学切割配方生成候选；背包候选显示图标、选中态和数量，面板提供应用与取消。客户端原生镶嵌窗口在待应用期间隐藏，面板按钮调用客户端提交接口。
- 附魔与装备增强候选使用 `SpellEquippedItems` 的目标掩码，并结合背包物品、已学配方及当前专业判断；腰带扣和锻造孔只在基础孔缺失时列出。
- 可制作产物由 `Item`、`SpellEffect` 和 `SkillLineAbility` 客户端表建立配方来源；制作后由背包事件刷新候选。
- 工程学强化使用 `SpellEffect` 的实际施加法术和 `SpellEquippedItems` 的目标约束；头部历史效果不生成新候选，瞄准镜按主手远程武器子类筛选。
- 背包增强物品可拖到目标装备格；拖放复用面板候选与目标校验。面板候选确认后直接把当前装备格交给客户端作为施加目标，无需打开人物面板。镶嵌成功事件触发装备重扫。
- 已学施加与制作配方在点击时按客户端 `SpellReagents` 材料表和当前背包数量检查缺口；能够读到专业窗口配方时仍保留接口回退。
- 可执行按钮仅对当前角色当前构筑的实穿扫描开放；确认快照仅显示事实。Lua 语法、目录加载和关键目标掩码断言已通过。
- 客户端安装版本为 `5.5.4.69934`；本面板新增目标映射与制作来源由该版本客户端表生成。原有增强效果目录仍来自 `5.5.4.68042`，须实机核对面板内镶嵌提交、直接指定附魔目标与专业材料反馈。

实施 `YiboCrafting：专业、配方与可制造角色` 时，由它向 Builds 提供角色专业等级、已学配方、配方产物及材料需求的查询 API。Builds 的装备提升面板改为通过该 API 判断当前角色的“已学”和“可制作”来源；装备孔序、目标装备适配、背包现货和原生施加流程仍由 Builds 对当前装备实时核对。

跨角色配方信息只用于说明哪个角色可以制作，不为非当前角色或历史装备提供执行按钮。接入时再确定 API 名称、数据新鲜度及插件缺席时的回退行为；当前实现继续使用客户端实时专业/配方接口与版本化候选目录，不把它误认为 YiboCrafting 已接入。
