## 实施边界

- 主页面与悬停复用 Snapshot、Core 角色准入、来源筛选、工作标题／数量、受益者和状态格式。悬停使用已确认的任务型分组例外，由 Core 创建、定位、关闭；只读，不提供来源操作按钮。
- 默认最多 20 名有来源工作快照的有效角色。空间充足时逐角色列工作；空间不足时折叠成每角色一行摘要，悬停该行查看明细。达到屏幕边界仍放不下时明确显示剩余角色数，入口左键打开完整主页面；不增加纵向滚动。
- 常驻面板与登录摘要共享当前角色投影，遵循 Core 隐藏角色和页面等级准入；不受主页面来源筛选或服务器范围影响。可处理、准备与候选分别计数，未知／过期不当作可做。
- 默认一次轻量登录摘要加常驻面板。统一设置可选择仅面板或有可推进工作时打开主列表；晚到数据更新面板，不重复登录摘要。新确认工作以面板数量提示，不创建重复任务。
- 悬停字段放入 Core“显示与入口”的统一字段配置，保存在 settings.previewColumns；主表字段由 Core 保存。面板显隐、锁定、容量和提醒模式属于业务设置，仅提供 Core 工作台内的控件。
- 面板复用 Core UITheme。Core 现有拖动／位置代码只服务主窗口，没有可公开复用的通用 HUD 位置接口；本次用 WoW Frame 的拖动和屏幕夹取保存面板自己的位置，不访问 Core 私有函数，也不新增无消费者的通用机制。
- 最低要求为 API v11 / business-providers:1、account-view:2、character-name-format:1，以及本次实际新增的 account-character-admission:1；检查所需公开方法，版本或能力不足停止初始化并提示升级。

Core 原有隐藏／默认页面等级筛选只刷新窗口，不能及时通知窗口外面板；因此本次先在 Core 发出最小的准入变化事实，再由 Displays 订阅，不通过私有方法 hook 或轮询发现。正式 [API v11 准入通知](../YiboCore/Docs/API-v11-角色准入通知.md) 说明负载、失败、版本和清理。Core 1.10.0 / API v11 尚未发布，本项为该工作树的非破坏性增量；旧版 account-view:2 行为保持兼容。

## 文件安排

Presentation.lua 统一字段、格式、统计和当前角色准入；Preview.lua 为 Core 页面内只读布局；HUD.lua 为当前角色只读面板；Reminders.lua 为本次登录摘要；Displays.lua 合并来源失效后的面板／提醒刷新；Settings.lua 为 Core 工作台内业务控件。Database 迁移仅添加自有显示偏好和位置，不保存来源任务。

Contracts 的失效通知继续经 Core，中心只更新自己的展示，不发回来源业务。预览、面板和摘要的读取不新增游戏状态扫描。来源缺失、异常和未知状态保留，完成任务由 Snapshot 移出；重新确认任务或新周期才进入新工作标记。
