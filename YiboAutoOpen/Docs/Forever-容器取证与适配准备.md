# Forever 容器取证与适配准备

日期：2026-10-23。状态：取证工具代码完成，业务实现待真实容器及操作证据。尚无Forever正式TOC、版本或允许目录。

按[适配计划](../../Docs/Yibo系列-无限服适用性与适配顺序-2026-10-19.md)，AutoOpen在有真实容器样本后可提前。既有环境样本只有炉石等普通物品，不能证明任何对象适合自动打开；MoP允许目录不直接迁移。

本轮复用独立[天赋与容器探针](../../_NonRelease/YiboBuildsForeverProbe/README.md)的 `/ybf bags`、`/ybf item <袋> <槽>` 与report，以同一套有界报告实现记录物品ID、提示、数量、锁定/冷却、战斗/施法/载具状态和前后位置。只读接口采用固定白名单，使用/拾取/确认接口仅盘点存在性，拒绝调用。

集中实机取一个玩家本来准备打开的真实容器，保留原生提示和采样，正常手动打开后记录数量/位置变化与拾取、绑定或保护确认，再采一次。没有对象时登记前置条件未满足。首批只为经过对照的itemID建立本服目录；单项失败恢复、安全暂停与确认流程分别实机验证，保护动作不能用接口存在性替代许可。

正式实施时以实际涉及的打开队列/安全暂停职责为边界，将MoP专用API、事件和目录归Mists，本服内容归Forever，稳定队列算法按需共享。误装须在建库前停止，存档保持目标隔离。需要Core公开能力时先检查现有操作确认、物品解析、语言和设置能力及最低版本；原本独立的功能不为占位引入Core。本轮没有正式业务运行diff和Core调用变化，不触发未改动旧模块迁移。

取证工具43项离线检查通过；客户端采样与容器业务均待。工具不会执行打开，不构成AutoOpen Forever开发完成、实机通过或可发布。

## 2026-11-17 空目录适配决策与实施检查

用户确认 Forever 不内置容器样本，初次使用时目录为空，玩家自行添加物品。该决定移除了等待样本才能实现目录管理的前置条件；它不证明任意物品可安全自动使用，也不代替本服真实容器、保护动作与失败恢复的实机验收。

当前代码仍为 Mists 单目标：`YiboAutoOpen.toc` 直接加载共享实现，`Catalog.lua` 含 MoP 默认物品和手动限制，`Database.lua` 固定读写 `YiboAutoOpenDB`，启动时立即注册事件及可选 Core 设置。不能简单增加 Forever TOC 并复用这些文件，否则可能导入错误目录或在客户端身份、Core 就绪检查前写库及注册入口。

实施需将目标目录和背包/安全差异拆到目标层；Forever 默认目录、迁移列表及 MoP 专属限制均为空，使用独立 `YiboAutoOpenForeverDB`，不读取或迁移 MoP 存档。保留玩家自定义的目录及删除结果；空目录不触发任何使用动作。允许添加不等于保证该物品可自动开启，保护拦截、失败隔离和重试行为必须保守处理。源目录改用 Mists、Forever 目标清单与默认提示，玩家包只加载所选目标；启动须先检查实际客户端身份、Core API 13、localization:1 和就绪，成功后才写库、注册设置和业务事件，并保证重复就绪通知幂等。还须按本次触及的玩家界面和命令区域完成中英文资源迁移，检查 Core 公共能力与构建引用。

待验证：两目标离线回归及统一构建；误目标和 Core 缺失/过旧不写库；空目录、添加/删除与存档隔离；保留旧 TOC/XML/Lua 的覆盖更新；客户端完整退出启动、设置与语言、目录恢复。真实容器出现后再验证安全条件、打开结果、保护拦截及失败恢复；没有这些证据不能宣告完整实机通过或可发布。当前仅完成方案核对，尚无 Forever 运行代码或版本。

## 2026-11-17 语言与 Core 公共能力收尾（Forever 0.1.1 / Mists 1.2.6）

本节替代 0.1.0 的语言/Core“未完成”状态。命令、设置控件/状态、删除确认、队列安全/失败提示、绑定取消、物品占位名称及来源标签均使用稳定 ASCII key 的中英文资源。Core owner 为 YiboAutoOpen，语言由 Core 会话决定；动态原生物品名称与玩家保存的别名不改写。默认来源标签存稳定 key；历史别名原样保留。默认提示TOC的独立中英文诊断不依赖Core；业务无新增独立语言设置。

适用能力契约：Core API13，localization:1、basic-input:1、item-resolver:1。Forever 写库前同时验证 Core 就绪与方法存在，能力不足提示升级并停止启动；无本地业务回退。Settings 的四类输入（空位、物品、对象ID、别名）复用 UITheme:CreateInput，提交通过 OnSubmit/OnFocus，保留Core IME与焦点处理；无新增Core接口。共享 ItemResolver 通过 Core.ItemResolver:Parse 查询ID/链接/精确名称，候选来自本插件目录及Core背包读取，0项返回not_found、多项返回ambiguous；GetInfo/Request用于显示和显式名称刷新，原生异步事件只触发本页刷新。没有跨业务插件数据读取、Provider或角色身份关联需求。

Mists沿用既有独立运行兼容边界：Core缺失/未就绪/解析能力不足时，基础命令使用Mists/LegacyResolver.lua；设置页要求Core就绪、API13及上述能力，能力满足时共享解析与设置直接消费Core。该例外仅维护现有Mists独立功能，Forever不加载该文件；未来取消Mists独立模式时移除。Core公共能力迁移状态须按目标区分，不能将兼容边界误记为Forever回退。

验证：既有17组规范通过；Forever目标21项断言通过；实际Core Input.lua和Runtime/ItemResolver.lua联合测试，Forever235项、Mists229项通过，覆盖中英文资源存在/格式一致、设置构建、ID/名称与无效ID、添加/删除、别名保留、IME提交保护、单次设置注册和能力不足停止。目标TOC及版本、包引用/内容、Lua5.1由统一构建器核对。本地化脚本已改用桌面随附Python成功运行，YAO未知key/格式不一致均为0；唯一中文候选为Common/TocHint.lua中的独立双语启动诊断，已审查。固定尺寸和英文真实排版仍需客户端核对，模拟帧不作为视觉验收。

加载与存档：源码为Mists/Forever目标TOC，默认TOC只提示；玩家包仍输出YiboAutoOpen.toc。技术名、安装目录、Mists的YiboAutoOpenDB及Forever的YiboAutoOpenForeverDB保持。默认Forever目录、迁移和MoP专属限制为空；仅用户添加物品进入目录。目标与Core检查早于写库；初始化/登录扫描/设置注册幂等。无XML间接引用。0.1.0到0.1.1保留旧文件覆盖的包加载离线回放通过范围以联合测试结果为准；客户端清单选择沿用已支持Forever机制证据，实际打开、安全暂停、绑定确认、退出恢复和覆盖启动仍待样本实机。代码及离线验证完成不等于实机通过或可发布；未安装到游戏、未上传发布。
