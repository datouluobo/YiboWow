## 逐步流程

每次只切换一个客户端，先确认另一个客户端已完整退出。新 TOC 需要完整退出再启动才能重新发现。两个探针目录均已在对应游戏进程关闭时安全联接，且没有替换现有 YBP、Core 或旧诊断目录。

### 第一步：Retail 基线

连接 Retail 探针目录，启用 YiboCore 与 YiboBeastPathsRetailPetProbe，完整启动正式服并登录猎人。先不要打开兽栏，输入：

```text
/yrx report
```

确认输出 project=1、Core 未报不可用，发回所有 `[YBP Retail Probe]` 行。用户可运行 `/yrx scan` 重新取样。先收基线后我再给下一步，不要求一次做完所有场景。

### 后续 Retail 取样（每次按引导进行）

打开原生兽栏后立即 `/yrx scan`；等待约 2 秒再次 scan；切换原生兽栏页／过滤或排序后再 scan；若当前角色自然拥有兽王额外宠物，另外记录该状态；移动一只已有宠物后，在移动中、稳定后分别采样；关闭兽栏后立即和延迟采样；随后 `/reload` 并取样，最后才完整退出重登验证。每步保留相应命令和时间顺序，不能用未发生的额外槽状态作推断。

### Mists 取样

待 Retail 当前可达场景取完并确认客户端完整退出后，再连接 Mists 探针。首条命令为 `/ymx report`，先核 build/project=19 与当前 Mists/Core 版本。依序比较兽栏关闭基线、打开立即读、等待后读、各页尾槽、移动中与稳定后、关闭、reload、完整退出恢复。若登录当前猎人不方便访问兽栏，先记录不可访问，不用理论候选范围替代实测。

### 返回信息

每一步只发对应目标探针的 `[YBP ... Probe]` 输出和简短界面观察（兽栏是否打开、原生界面显示宠物数量、切换了哪一页、是否执行移动）。聊天输出刻意不含宠物名；如需核对原生列表明细，后续再单独提供不含玩家身份的摘要。不要贴 SavedVariables 原文。
