## 2026-10-23 客户端反馈

- 用户报告扫描 #317（兽栏关闭）与 #320（兽栏打开）均为随身 3、兽栏 63、缺外观 0、读取错误 0。打开时 API 数量也为 3／63，扫描覆盖 1–205，末槽位 205 有数据。本机存档最近样本同为 3／63、缺外观 0、错误 0、兽栏关闭。证明该角色样本下有正向读取，不外推所有状态的完整性。
- 两只宠物名字分别为“变色噩兆”“魁麟噩兆”，报告索引 151、152，外观 ID 同为 `45427`；截图中均呈蓝色外观。仅凭名称和相同 ID 不能认定不同颜色，也不能证明变色机制或四色可分辨。
- 四色统计的零值来自尚未建立颜色映射，不代表该角色没有噩兆。
- 当前需要玩家在兽栏中点选后用 `/yhp selected` 核对名字，再用 `/yhp color <颜色>` 记录目视色彩。若同一 ID 收到不同颜色，标为冲突并停止自动匹配；保留原始诊断观察继续研究。

### 点选截图与颜色异常补充

- 两张新增截图显示 `/yhp selected` 分别输出“变色噩兆”（151）与“魁麟噩兆”（152），均为 `45427`、读取 `ok/ok`，与兽栏模型预览标题对应。原生点选到正确宠物已验证；截图没有执行颜色标注，不能把颜色命令记为已验。
- 用户反馈其中一只抓到时会变色，现在不再变色。将其作为用户观察保留，不能从宠物名字或当前 ID 还原驯服前颜色，也不能仅凭这两次读数推断 API 无法区分所有四色。
- [Petopia 的噩兆资料](https://www.wow-petopia.com/npc.php?id=50843)列出四种外观；对应紫晶、碧玉／红铜、翡翠和蓝色。该外观目录与目标客户端驯服后的保存行为分开验证。
- [暴雪官方论坛的 Mists Classic 玩家缺陷报告](https://us.forums.blizzard.com/en/wow/t/mop-classic-portent-hunter-pet-color-shifting-after-tame/2145770)自 2025-08 起有多名玩家报告驯服后变色、重登后固定成蓝／铜色，2026-03 与 2026-08 仍有后续反馈。这是玩家一手报告，不是暴雪开发者确认或修复公告；与本次现象吻合，但具体成因待确认。访问日期：2026-10-23。
- 当前可用事实为两只宠物显示相同蓝色外观、API 同为 `45427`。原始颜色与变色原因保持未知，四色自动完成判断及颜色驱动的路线隐藏继续待验；不把一只曾发生变色的宠物计为拥有全部颜色。

## 进入正式开发的条件

确认目标构建的槽位范围、何时可取得完整随身与兽栏数据、各颜色外观 ID 的实际稳定性。若来源只能确认外观，则正式功能须明确按外观拥有情况判断；不能把外观一致升级为指定稀有捕获证据。未覆盖颜色或未证明完整扫描的范围继续待确认。
