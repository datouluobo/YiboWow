## DEV-002：离线宠物查看

2026-10-28 暂停 P0-02：Retail 已取登录、开关窗、过滤／排序、reload 与完整退出重登样本；Mists 70579 已取登录、开窗、延迟复读及关窗后 reload 样本，搜索受 NDui_Plus 报错影响。原始结论、差异及待测项保留在[P0-02 指引](../../_NonRelease/YiboBeastPathsPetProbe-P0-02/README.md)。完整性、跨组移动等仍待核，业务代码未改；后续恢复时接续已有证据。四色与来源匹配仍归 DEV-005。

### 已确认要求

- 地图路线继续独立运行；离线兽栏是依赖 Core 的可选增强。Core 缺失、API／能力不足时明确提示，不影响原有路线。
- 兽栏初始化检查实际客户端、Core 就绪、最低 API 与实际所需能力；支持 Core 晚就绪，重复通知不重复建库或注册。
- 跨服务器展示本客户端本地已采集兽栏快照的全部猎人角色；没有兽栏快照的角色不展示，不能仅因 Core 目录存在该猎人就加入页面。
- 同时展示随身宠物与兽栏宠物，分组保存采集时间和可用状态。某部分暂时不可读时，保留上次快照并提示；读取失败不当作空栏，不清空历史。
- 以 Core 的角色唯一 ID 关联记录，复用名称、排序、范围、隐藏与清理公共机制。Core 不保存宠物业务数据。
- YBP 拥有采集、快照、迁移、失效和业务准入；窗口、设置和入口由 Core 管理。主视图与适用的悬停预览使用同一业务快照，语言使用 owner 中英文资源。
- 现有 YBP 技术名、安装目录及各目标 SavedVariables 身份保持稳定。新宠物 schema、完整扫描条件、字段与采集触发在业务实施方案中根据真实 API 证据设计。

### 开工前证据与设计任务

1. 分别核对 Retail／Mists 的打开前、打开后、延迟读取、关闭、切页、移动宠物、改名及重载行为，确认随身／兽栏完整读取条件与确认为空的依据。
2. 核对现有 `_NonRelease/YiboBeastPathsPetProbe/` 样本；这是 Mists 证据，不外推为 Retail API 已验证。新增非发布探针遵守根目录 `_NonRelease/` 规范。
3. 固定 Core 已提供且已验证的公共契约及最终最低版本，补依赖缺失／旧版／缺能力的中英文提示；不为兽栏创建第二套本地窗口或语言回退。
4. 明确部分扫描、上次成功时间、本次失败状态和完整快照的保存规则。宠物跨分组移动时处理不同采集时间造成的陈旧记录，不能把异步旧记录拼成已证明完整的当前清单。
5. 以完整职责单元完成新增功能涉及的目标适配、加载链、存档及覆盖更新审查，沿用统一 TOC 与构建规则；既有维护例外仅按已记录范围处理。

### 验收门槛

先离线验证快照提交／保留、目标身份保护、Core 版本检查、晚就绪与幂等注册，再实机核对原生宠物列表、跨服务器多猎人、无兽栏快照角色排除、时间／状态、移动宠物及部分读取。确认完整空栏才可替换为已知空快照，失败不能清除历史。

分别验证 reload、完整退出恢复、干净安装与保留旧文件覆盖；覆盖旧设置／路线存档保留、双语与手动语言、Core 缺失／旧版时原有路线正常。按实际实现目标分别登记，不能从单端或单组截图推定整插件完成。此阶段不要求路线拥有标记通过验收。

## DEV-005：路线“已拥有”状态

目标：在离线快照可靠后，将已采集宠物与 YBP 路线对象关联，为路线提供拥有状态。具体角色范围、标记／筛选交互和颜色呈现，在本阶段开工时确定。

- 业务匹配由 YBP 负责，不将宠物身份或拥有规则迁入 Core。
- 必须验证改名、随身／兽栏移动、外观变体和多角色快照时效；缺失、陈旧或部分采集证据不能直接显示为未拥有。
- 原 DEV-002 的噩兆四色研究保留在本阶段作为身份匹配证据任务：采集实际外观 ID，验证颜色对应及稳定性；未持有样本保持待确认，不要求为测试放生或重抓宠物。
- 外观一致不独立证明原始 NPC 来源；名字、图标或家族名不作为可靠来源身份。仅按真实证据声明可识别范围，若某种匹配不能证明则保留未知。
- 完成标准是已声明对象的可靠匹配、未知／失败语义和主视图／路线的一致性通过验证；四色样本不足项单独列出，不能把拥有功能可用等同四色全部识别通过。
