# YBP 1.9.0：维护面板迁入设置页

日期：2026-11-14。范围：Retail／Mists 的共享维护 UI 及关联玩家入口；不是离线兽栏视觉方案的实现。

## 行为与职责

维护面板直接嵌入 Core → 设置 → 隐兽寻踪 → 业务设置，保留路线校准、融合工作台、脚印管理和导出四页签。原设置页的跳转按钮与状态占位被完整面板替换；主窗口不再创建「兽栏／维护」双标签或维护子页面。`/ybp debug`、地图维护按钮继续调用同一维护入口，现在打开 YBP 设置页；`/ybp stable` 仍打开兽栏主页面。

复用既有 `settings.CreateSettingsPanel` 及 Core 的 `createSection`／`refreshPanel` 宿主契约。维护内容本身不再创建整页滚动框；只有 Core 设置内容区滚动，导出文本编辑器的内部文本滚动保留。页签变化将实际高度回报宿主；重复进入、刷新和缩放复用同一批控件，离开设置页清理导出焦点与维护确认框。顺带修复导出按钮没有绑定实际文本输入框的问题，切换导出类别和全选使用同一输入框。

## 加载、依赖与迁移审查

- 适用目标仅 Retail／Mists，版本仍为 1.9.0；技术名、安装目录均为 `YiboBeastPaths`。源码与已批准 universal 包沿用 `YiboBeastPaths_Mainline.toc`／`YiboBeastPaths_Mists.toc`，实际加载清单取决于客户端已验证后缀选择；默认 `YiboBeastPaths.toc` 继续仅提示缺目标。没有 TOC、XML 或构建引用增删。
- 继续在目标入口核验实际 project，维护文件要求 `YBP_TARGET_OK`，初始化检查 Retail／Mists 身份；本轮不扩大客户端支持。路线继续独立加载；Core 是已记录的可选增强边界，不将整个路线插件改为强依赖。
- Core API13、就绪及既有能力门槛保留，兽栏关联入口补查公开 `AccountView:ShowSettings`；不再要求已移除的外层 `CreateBusinessTabs`。维护适配器在已注册时也重新核验 Core 就绪与能力，不凭本地注册标记绕过保护。
- 页面仍是同一 owner 的唯一设置来源；旧的独立维护页面注册路径移除。无兽栏模块的独立维护加载仅注册独立设置内容，不创建主页面。重复登录／CORE_READY 不重复注册。
- 本轮迁移单元是共享维护设置托管与关联入口，不涉及客户端专用 API／事件或静态业务目录，继续保留共享 `Maintenance/`，不复制到两个目标。未触及的路线业务与旧校准器实现保持维护例外。
- `YiboBeastPathsDB`／`YiboBeastPathsDebugDB` 名称、schema、业务数据归属不变，不重置或跨目标导入。UI 页签仍由原维护存档保存。
- 覆盖兼容：复用原有目标清单与同路径文件，没有新旧并行加载点；残留旧文件不被新增引用。当前测试使用源码 Junction，不冒充旧包保留文件覆盖验收；既有 universal 包覆盖与 WTF 恢复待验范围不因此改变。
- 本次 Core 公共能力审查：CAP-002 输入、CAP-004 托管页面／统一设置、CAP-009 owner 双语继续复用；没有新增本地语言或窗口壳。CAP-001／007／010 的身份、快照和清理行为不改。整插件剩余接入及发行状态不扩大。
