# 野生宠物外观拥有提示：后续开发方向

日期：2026-10-29。状态：**方向记录，待可行性验证和后续排期**。本文不改变现有开发顺序；离线宠物快照及路线拥有状态的进度以[版本任务清单](离线兽栏与拥有状态-版本任务清单.md)为准。

## 目标与范围

玩家悬停可驯服野兽或其单位框体时，在单位提示中显示账号已采集宠物是否有相同外观，并在可用时显示对应角色及随身、兽栏位置。该功能覆盖实际遇到的野兽，按外观 ID 实时比对，不以建立完整宠物目录为前提。

拟作为 YiboBeastPaths 的独立功能模块，提供独立开关，与潘达利亚路线及离线宠物查看共用 YBP 拥有的宠物快照。YBP 负责采集与业务判断，Core 提供角色身份及已有的公共框架能力。路线继续独立运行；依赖缺失时外观增强不可用，不影响路线。具体目标客户端、依赖版本及设置接入在实施时分别确认。

## 用户可见语义

- **已拥有相同外观**：有可靠的当前或已保存快照与目标外观匹配；展示来源角色和位置时注明快照时效。跨角色结果属于最近采集到的状态，并非对离线角色实时核验。
- **未找到相同外观**：仅在所选角色范围内的相关随身和兽栏快照均满足已验证的完整性与时效条件，且目标外观可可靠读取时显示；明确结果所覆盖的角色范围。
- **数据待更新或无法判断**：目标 ID 读取失败、采集不完整、快照缺失或过期时使用；已有正向匹配可展示，同时提示其他来源尚未完整检查。

相同外观不代表来源于同一个 NPC。宠物可改名，名称不能作为可靠身份；野兽和驯服后的外观也可能发生变化。噩兆四色及其驯服后的变化需要单独验证，不能从当前两个相同 ID 的样本推断全部颜色。

## 可行性验证

现有 Mists 探针已取得随身、兽栏样本及两只兽栏噩兆的外观 ID；野外单位的 ID 读取、与驯服后 ID 的对应关系及完整采集条件尚未证明。Retail 与 Mists 分别验证，不互相外推。

1. 检查各目标客户端支持的单位提示、可驯服判断和外观读取接口；评估模型控件加载单位后获取显示 ID 的方法，记录实际返回及失败条件，不预设其可用。
2. 对同一野兽分别悬停世界实体和目标／单位框体，核对取得的单位、显示 ID、加载时序和提示刷新；覆盖切换目标、快速移动鼠标、无效目标及其他插件的提示框。
3. 以已拥有的样本核对野外与随身／兽栏 ID，覆盖普通宠物、同外观不同 NPC、改名、跨组移动、不同颜色及噩兆；记录无法对应或可能变化的情况。
4. 验证快照完整性、时效和多角色范围，以及首次未采集、部分读取、旧数据、重新登录与角色切换。失败不能当作空栏或未拥有。
5. 确认可驯服判定的可靠边界；无法判定时不将目标直接标为可驯服。测试响应速度和重复悬停的开销，避免过期异步结果显示在新目标上。

探针放在仓库约定的非发布目录；记录客户端版本、实际结果与未覆盖情况。可行性成立后，再制定实现与验收方案。

## 与路线拥有状态的关系

悬停比对依赖当前可见目标的外观；地图路线在目标不在视野内时仍需依据可靠的路线对象与外观关联数据判断。两者可以复用快照，但关联证据、未知状态和验收分别记录。外观一致不足以证明稀有 NPC 来源，不能据此无条件隐藏其路线。

## 待决定

- 外观提示默认开关、角色范围及过期阈值。
- 提示中角色、位置和采集时间的呈现方式，以及多角色命中时的展示上限。
- 各目标客户端的可驯服识别方式、模型加载限制和允许进入正式功能的证据。
- 若未来扩展为独立图鉴、搜索和收藏进度，再评估是否拆分插件；当前不预设拆分。
