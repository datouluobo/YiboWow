# 1.9 离线兽栏主窗口重构

状态：代码完成，客户端验证进行中；设计目标为已确认的组合效果图 v2。Retail、Mists 使用同一只读页面，随身和兽栏同页分区，支持角色、家族与名称筛选、槽位选择和右侧详情；悬停继续使用同一账号快照的摘要投影。

外观使用快照的可选 `displayID`：Retail 从 `PetInfo.displayID` 读取；Mists 在已占用槽位调用 `C_PlayerInfo.GetPetStableCreatureDisplayInfoID`。缺失、异常或旧记录无该字段时显示外观未知，不用共享图标或名称猜测。显示模型只复用视口附近的控件；切换或滚动不会写业务存档。存档 schema 及身份未改变，新增字段按现有快照复制规则保存，未确认观察仍标示未确认。

来源地图不是兽栏 API 给出的驯服地点。Retail 采集到有效 `creatureID` 且与本插件路线目录 NPC 唯一匹配时，详情标注“路线目录”并使用 `C_Map.GetMapInfo` 的客户端名称；没有身份、目录匹配冲突或地图名称不可用时显示未知。Mists 当前兽栏读数无可证明的 NPC 身份，显示未知。该字段不代表玩家实际驯服地点，也不按昵称、家族、图标或外观 ID 推断。

Core 接入沿用 API 13 及既有能力检查：角色目录和显示名、统一窗口、滚动框、输入、下拉、语言与入口均使用 Core 公开能力；模型显示为游戏原生 `PlayerModel`。未新增 Core API 或跨业务插件访问。业务语言新增中英文资源，目标专用读取仍分别位于 Retail 与 Mists；共享渲染位于 Common。TOC、XML、技术名、安装目录与 SavedVariables 身份未改，既有 YBP Universal 双目标包例外继续适用。误目标保护及单次注册沿用目标入口、Core 门禁和既有测试；无需新增旧路径加载链。
