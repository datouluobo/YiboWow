# YiboBeastPaths 1.4 实施任务清单

## 文档定位

本文用于把 `RouteFusionPlan-v1.4.md` 拆成可执行的实施清单。

目标是：

- 明确 `1.4` 必须完成的工作
- 明确哪些任务可以并行
- 明确哪些任务应延后到 `1.4.x` 或 `1.5`

---

## 总体推进顺序

建议按以下阶段推进：

1. 建立数据层骨架
2. 建立参考工作层数据迁移链路
3. 建立真实脚印采集链路
4. 建立融合重算链路
5. 建立大地图显示链路
6. 建立小地图显示链路
7. 建立调试面板
8. 建立导出与固化链路
9. 做逐条路线验证

---

## P0：1.4 首版必须完成

这些任务属于 `1.4` 的硬要求，不建议下放。

### 任务 1：建立正式数据文件骨架

目标：

- 建立 `真实脚印层`
- 建立 `参考工作层`
- 建立 `最终融合路径层`
- 预留 `参考点层` 与 `参考源层`

建议文件：

- `FootprintAnchors.lua`
- `ReferenceRoutes.lua`
- `ResolvedRoutes.lua`
- `ReferenceRoutePoints.lua`
- `ReferenceRouteSources.lua`
- `RouteDisplayMeta.lua`

验收标准：

- 文件职责边界明确
- 不与现有 `CuratedRoutes.lua` / `RouteTransforms.lua` 混淆
- 可以作为后续开发正式入口

### 任务 2：定义数据结构

目标：

- 明确每层数据的表结构
- 明确字段命名与可选字段

至少要定义：

- 真实脚印点字段
- 参考工作层点/段字段
- 融合路径字段
- 显示元数据字段

验收标准：

- 能支撑后续录点、重算、导出
- 字段能表达启用/禁用、备注、来源、区段主导状态

### 任务 3：把当前已调好的大图路径结果转成参考工作层

目标：

- 走偏 `路线 A`
- 以当前已调好的结果作为 `1.4` 首版参考主路线

具体要求：

- 不要求从原始图片重做
- 不要求先补齐 `参考点层`
- 重点是拿到“可计算、可显示、可融合”的参考工作层数据

验收标准：

- 无真实脚印时，参考工作层可单独支撑路线显示
- 当前已有大图效果不会因为迁移而明显退化

### 任务 4：建立真实脚印采集能力

目标：

- 在调试模式中记录当前脚印坐标
- 将脚印点正式落到真实脚印层

至少要支持：

- 记录当前点
- 删除最后一个点
- 清空当前宠物点
- 查看当前宠物点列表
- 启用/禁用单点

验收标准：

- 脚印点可持久保存
- 改动后能触发地图刷新或可手动重算

### 任务 5：建立融合计算入口

目标：

- 以“真实脚印层 + 参考工作层”生成最终融合路径层

首版要求：

- 可以先做较保守的融合实现
- 优先保证结果稳定、连续、可预览
- 不强求一开始就做最复杂算法

验收标准：

- 无脚印时结果等于参考工作层
- 有脚印时结果会按局部受到影响
- 不会把整条路线整体拉坏

### 任务 6：建立自动/手动重算机制

目标：

- 融合层不是一次性产物
- 支持调试过程中反复重算

至少要支持：

- 新增脚印后重算
- 删除脚印后重算
- 启用/禁用脚印后重算
- 参考工作层调整后重算
- 手动按钮重算当前宠物
- 手动按钮重算当前地图

验收标准：

- 逻辑稳定
- 不需要 `/reload` 才能看到结果

### 任务 7：建立大地图正式显示链路

目标：

- 默认显示最终融合路径层
- 叠加显示真实脚印点

要求：

- 主观观感必须仍是一条连续路线
- 不能显示成点串珠
- 真实脚印点要独立可见

验收标准：

- 用户一眼能区分主线与实测点
- 地图上能直观看见脚印对路线的修正价值

### 任务 8：建立小地图正式显示链路

目标：

- 小地图改为默认基于最终融合路径层显示

要求：

- 保留首尾往返双向近邻结构
- 不错误合并成单线
- 附近真实脚印点显示要克制

验收标准：

- 小地图具备可用导航效果
- 双向近邻路径显示正确

### 任务 9：建立调试面板首版

目标：

- 形成完整的录点、预览、重算、对比工作流

`1.4` 首版最少应包含：

- 基础信息区
- 层显示控制区
- 脚印采集区
- 脚印点列表区
- 参考工作层与重算区

验收标准：

- 能在游戏内完成“录点 -> 看图 -> 重算 -> 预览”
- 不依赖外部手改文件才能验证效果

### 任务 10：建立三层显示切换

目标：

- 调试模式中可勾选多层同时显示

至少要支持：

- 真实脚印层
- 参考工作层
- 最终融合路径层

并提供：

- `全开`
- `仅最终层`
- `重置默认显示`

验收标准：

- 能快速对比三层关系
- 能直观看出融合结果是否合理

## P1：建议在 1.4 内完成

这些任务不是绝对阻塞，但很建议进入 `1.4` 正式版本。

### 任务 11：建立即时预览链路

目标：

- 调试时修改参考工作层后，大地图即时看到最终融合路径变化

验收标准：

- 不必保存正式数据后才能看效果
- 临时调试态也能驱动融合层预览

### 任务 12：建立导出与固化能力

目标：

- 将调试结果稳定导出为正式数据片段

至少建议支持：

- 导出当前宠物真实脚印层
- 导出当前宠物最终融合路径
- 导出当前地图全部改动
- 生成 Lua 片段

验收标准：

- 导出结构可直接审阅
- 便于后续写回正式文件

### 任务 13：建立显示细节调试项

目标：

- 辅助处理小地图重叠、大地图点密度等视觉问题

建议支持：

- 点大小
- 点透明度
- 路径线宽
- 小地图近邻双线增强开关

验收标准：

- 能帮助快速定位视觉异常
- 不必频繁改代码常量才能试效果

### 任务 14：建立区段状态表达

目标：

- 让融合结果具备“参考主导 / 融合过渡 / 实测主导”区段语义

验收标准：

- 至少在数据层可表达
- 最好在调试模式中可查看

## 串行依赖建议

以下依赖顺序建议尽量保持。

1. 先做数据文件骨架与数据结构
2. 再做参考工作层迁移
3. 再做真实脚印采集
4. 再做融合计算与重算
5. 再做大地图主显示
6. 再做小地图主显示
7. 再做调试面板整合
8. 最后做导出与逐条验证

---

## 风险点

### 风险 1：参考工作层迁移后效果退化

应对：

- 优先逐条比对当前大图效果
- 不要一次性全量替换后再统一排错

### 风险 2：小地图双向近邻结构被错误合并

应对：

- 提前挑出首尾往返明显的路线做专项验证

### 风险 3：自动重算导致调试性能或体验问题

应对：

- 必须提供手动重算按钮
- 必须提供自动重算开关

### 风险 4：数据层职责再次混淆

应对：

- 明确真源只有真实脚印层和参考工作层
- 融合层是结果，不反向变成唯一源

---

## 最小可用版本定义

若要定义 `1.4` 的最小可用版本，应至少满足：

1. 有正式真实脚印层
2. 有正式参考工作层
3. 有可重算的最终融合路径层
4. 大地图默认显示“最终融合路径 + 真实脚印点”
5. 小地图默认显示最终融合路径
6. 调试面板可录点、删点、切换三层显示、触发重算
7. 无真实脚印时路线仍可正常显示
8. 小地图能正确显示双向近邻路径
