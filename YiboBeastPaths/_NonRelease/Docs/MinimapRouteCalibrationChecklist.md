## 当前结论

- 四风谷 `50812` 已有成功样例，说明“小地图渲染链路本身可用”。
- 但 `50812` 调准，不代表其它 `petID` 会自动一起调准。
- 当前应按“每条宠物路线单独校准”推进，而不是继续按“统一全局修正”推进。

---

## 判断规则

每条路线后续都按下面三类之一归档：

1. `只调 RouteTransforms.lua`
   世界地图和小地图一起偏，且偏法基本一致。
2. `只调 CuratedRoutes.lua`
   世界地图大体正确，但小地图局部折线明显不贴实际巡逻路径。
3. `两者都要调`
   世界地图整体有偏，小地图局部折线也不准，或两边偏法明显不同。

## 现阶段判断依据

### 0. 清单可直接记录用户实测状态

- 后续你在游戏里发来的“哪条小地图偏了 / 哪条已经对了 / 哪个脚印名已确认”，都可以直接回写进这张表。
- 不必等完整复查一轮再补，先把现状记进去更稳。

### 1. 四风谷不能代表全部路线

- 当前实现中，世界地图和小地图都按 `petID` 分开读数据。
- `RouteTransforms.lua` 本身就是逐条路线独立参数，不存在“一条修好，全局一起修好”的机制。
- `CuratedRoutes.lua` 也是逐条路线独立点线，不同宠物之间不会自动共享校准结果。

### 2. 大多数小地图路线点并非实测点

当前 `CuratedRoutes.lua` 中：

- `50812` 来源是：`Extracted from Sneaky Sams reference image for Patrannache`
- 其它多条路线来源是：`Auto-traced from overlay ...`

这说明大部分小地图折线仍是从参考图或 overlay 反推出来的，不应默认视为已准确落在游戏实际巡逻路径上。

### 3. 同图宠物适合成组检查

建议按地图分组推进，减少来回切图成本：

- 昆莱山：`50811`、`50816`
- 卡桑琅丛林：`50817`、`66522`
- 翡翠林：`50821`、`50822`
- 单独地图：`50812`、`50813`、`50818`、`50820`

## 推荐检查顺序

1. 用 `50812` 作为正确对照，确认当前客户端和当前构建下小地图显示仍然正常。
2. 先复查已完成一轮校准但仍需继续实测确认的 `P0`：
   `50813` → `50818` → `50820`
3. 再按同图成组复查已完成一轮校准的 `P1`：
   `50811` + `50816`
   `50817` + `66522`
   `50821` + `50822`
4. 每查完一条，就把该条改写成：
   - 世界地图：正确 / 偏
   - 小地图：正确 / 偏
   - 修正范围：`RouteTransforms.lua` / `CuratedRoutes.lua` / 两者都要
