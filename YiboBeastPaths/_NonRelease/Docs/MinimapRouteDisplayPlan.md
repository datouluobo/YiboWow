# YiboBeastPaths 小地图路线显示方案

## 目标

在不影响现有世界地图路线覆盖图功能的前提下，为插件新增小地图路线显示能力。

小地图路线的目标不是把整张大地图的巡逻路线缩略塞进小地图，而是只显示当前小地图可视范围内真实进入视野的路径线段。

该能力需要满足以下体验目标：

1. 只要路线真实进入当前小地图显示范围，就显示。
2. 只显示当前小地图可视范围内的部分，超出边界的部分自然不显示。
3. 当前范围内的所有有效线段都显示，包括回环、分支、多段。
4. 如果当前范围内同时出现两只或多只宠物的路线，则全部显示。
5. 路线表现为细线，可带轻微柔光，但整体观感必须克制。
6. 路线必须跟随小地图的真实缩放、旋转和玩家移动实时变化。

## 效果定义

### 1. 显示原则

小地图路线只按“当前小地图可视范围”判定显示，不按整张区域地图判定。

这意味着：

1. 玩家进入某张地图后，如果某条路线并未进入当前小地图范围，则不显示。
2. 如果某条路线的一部分进入了小地图范围，则显示进入范围内的那一段。
3. 如果路线横穿当前小地图视野，则会看到一条从边缘进入、再从边缘离开的连续线段。
4. 如果路线只擦过小地图一角，则只显示角落中的一小段。

### 2. 多段与分支

路径的显示边界只由“是否进入当前小地图范围”决定。

因此：

1. 同一只宠物的多段路线只要在范围内，都应显示。
2. 同一只宠物的分支、回环、相邻线段只要在范围内，都应显示。
3. 不做人为裁剪，不隐藏所谓“次要岔路”。

### 3. 多宠物同时显示

如果当前小地图范围内同时包含两只或多只宠物的路径，则全部显示。

该行为不依赖当前选中宠物，不依赖最近目标，不依赖手动切换。

显示规则如下：

1. 只要该宠物在当前地图存在对应路线数据，并且路线进入当前小地图范围，就显示。
2. 不限制同屏显示数量。
3. 各宠物路线允许在小地图中同时存在和重叠。

### 4. 视觉风格

小地图路线采用细线表现，而非大面积覆盖图，也不是一串离散点。

视觉要求如下：

1. 主体是一条清晰但偏细的线。
2. 允许有非常轻微的柔光或描边，以保证在线条经过复杂地形底图时仍可辨认。
3. 发光必须克制，不能做成高亮荧光导航条。
4. 线条整体应优先保证“清楚但不抢眼”。

### 5. 边界表现

路线在小地图上的显示边界只由小地图当前可视范围决定。

因此：

1. 进入可视范围的线段显示。
2. 超出可视范围的线段不显示。
3. 不额外添加边缘箭头、延伸提示或强制补全效果。
4. 线条在边缘处自然裁切即可。

### 6. 缩放与旋转

路线必须跟随小地图真实状态变化，而不是贴一张固定纹理。

这意味着：

1. 小地图缩放变化时，路线显示范围与线段位置同步变化。
2. 小地图旋转时，路线也同步旋转。
3. 玩家移动时，路线相对于玩家位置平滑滑动。
4. 最终观感应接近同类导航插件的原生动态显示方式。

## 总体设计方向

### 1. 世界地图与小地图分离

世界地图与小地图使用两条独立渲染链路：

1. 世界地图继续沿用当前覆盖图贴图方案。
2. 小地图单独采用路径点数据进行线段渲染。

这样做的原因是：

1. 当前世界地图方案已经成熟，不应为小地图需求推翻。
2. 小地图更适合绘制局部动态线段，不适合直接复用整图贴片。
3. 两条链路职责清晰，后续调试和扩展更稳定。

### 2. 小地图使用点线路径数据

小地图显示不使用 `RouteOverlays.lua` 中的整图资源，而使用 `CuratedRoutes.lua` 中的点线数据。

原因如下：

1. 小地图需要基于玩家当前位置实时裁切可见线段。
2. 小地图需要随缩放和旋转动态重算位置。
3. 整张区域覆盖图无法自然适配小地图的局部显示需求。

### 3. 小地图渲染内容

小地图渲染的不是“整条路线缩略图”，而是“当前视野内的路径片段”。

因此：

1. 显示内容按当前小地图范围实时决定。
2. 玩家视野移动时，进入视野的线段出现，离开视野的线段消失。
3. 最终视觉上看到的是一条或多条穿过当前小地图的局部路线细线。

## 数据职责划分

### `RouteOverlays.lua`

用途：

1. 继续仅服务世界地图覆盖图显示。
2. 保存每条宠物的整图覆盖资源信息。

小地图不依赖该文件中的贴图资源进行线条绘制。

### `CuratedRoutes.lua`

用途：

1. 作为小地图路线显示的核心数据源。
2. 保存每只宠物的多段路径点数据。
3. 每条路径由 `segments` 构成，每段由顺序点构成。

小地图功能的覆盖范围取决于该文件的数据完整度。

当前结论：

1. 只要某只宠物没有完整 `segments` 数据，就无法按本方案在小地图上显示真实路线细线。
2. 因此后续若要实现全宠物支持，必须持续补齐该文件中的路径数据。

### `Data.lua`

用途：

1. 继续提供宠物基本信息。
2. 提供 `petID` 对应的地图归属信息。

### 其它说明

世界地图现有能力与小地图新增能力不冲突，二者可以共存：

1. 世界地图看全局。
2. 小地图看当前视野局部。

## 渲染表现方向

### 1. 线条形态

小地图采用细线而非点串。

原因如下：

1. 用户已明确希望表现为细线。
2. 细线更接近同类导航插件的路线感。
3. 对于当前路径数据结构，线段式渲染更能完整体现分支与回环。

### 2. 显示范围

显示范围定义为“小地图当前实际可视区域”，而不是“玩家附近一定半径的固定值”。

因此：

1. 小地图缩放越大，可见路线范围越小。
2. 小地图缩放越小，可见路线范围越大。
3. 不人为再套一层独立显示半径。

### 3. 同屏内容

小地图中允许同时出现：

1. 同一只宠物的多段路线。
2. 同一只宠物的多个分支。
3. 多只宠物的路径同时进入当前范围后的叠加显示。

## 跟随原则

小地图路线必须与以下状态同步：

1. 玩家当前位置
2. 小地图缩放等级
3. 小地图旋转状态
4. 当前所在地图

只要上述任一状态变化，路线显示结果都应与之同步更新。

最终目标是让路线看起来像真实存在于地图空间中的路径，而不是固定贴在界面上的装饰层。

## 用户已确认的最终效果

截至本方案文档形成时，已确认如下设计结论：

1. 小地图路线显示为细线。
2. 细线允许有少量发光，但必须克制。
3. 当前小地图范围内的所有有效线段都显示。
4. 包括分支、回环、多段在内，只要进入范围就显示。
5. 如果同时有两只宠物的路线进入当前小地图范围，也要同时显示。
6. 显示边界只以是否进入当前小地图范围为准。
7. 路线必须跟随实际缩放与旋转变化。
8. 边界处采用自然裁切，不增加额外提示表现。

## 后续实现约束

本方案不直接规定具体代码实现细节，但在实际开发时必须遵守以下原则：

1. 不破坏现有世界地图路线覆盖图功能。
2. 不把世界地图整图贴片直接搬到小地图。
3. 小地图路线数据优先以 `CuratedRoutes.lua` 为准。
4. 实现应支持多路线同时显示。
5. 实现应支持小地图真实缩放、旋转和动态移动。

## 实施前提

实现该能力的最大前置条件不是界面，而是数据完整度。

当前如果只有部分宠物具备完整点线路径数据，则小地图也只能先支持这些宠物。

因此后续工作会自然分成两部分：

1. 小地图路线显示框架本身。
2. 各宠物 `CuratedRoutes` 数据的持续补全。

## 实现设计

本节开始进入具体实现层，目标是为后续开发提供直接可执行的结构化设计。

## 实现边界

本次小地图路线能力的实现边界定义如下：

1. 只新增小地图路线显示，不改动世界地图路线显示结果。
2. 不重做现有覆盖图校准逻辑。
3. 不新增与用户确认结果相冲突的“只显示最近宠物”或“只显示选中宠物”逻辑。
4. 不把整张路径覆盖图压缩后贴到小地图。
5. 不使用 `websocket` 类连接或外部运行时依赖，继续基于当前插件本地 Lua 实现。

## 模块拆分

建议将小地图能力拆成四层：

1. 数据层
2. 坐标换算层
3. 小地图渲染层
4. 刷新调度层

### 1. 数据层

职责：

1. 从 `CuratedRoutes.lua` 读取每只宠物的 `mapID`、颜色、`segments`。
2. 对每段路径点进行基础合法性检查。
3. 提供统一的数据遍历接口给后续坐标和渲染层使用。

建议输出的数据结构应尽量稳定，避免渲染层直接操作原始表。

### 2. 坐标换算层

职责：

1. 将 `CuratedRoutes.lua` 中的地图归一化坐标转换为世界坐标。
2. 按当前玩家位置和小地图状态，把世界坐标换算成小地图局部屏幕坐标。
3. 判断路径点和路径段是否进入当前小地图可视范围。

这层是整个方案的核心。

### 3. 小地图渲染层

职责：

1. 管理小地图路线用到的 frame 与 texture。
2. 把“可见路径段列表”转换成实际显示的细线。
3. 控制线条颜色、透明度、轻微柔光和层级。

### 4. 刷新调度层

职责：

1. 在玩家移动、切图、小地图缩放变化、旋转变化时触发刷新。
2. 控制刷新频率。
3. 避免每帧创建和销毁 UI 对象。

## 文件组织建议

为了最大限度减少对现有结构的冲击，建议采用以下组织方式：

1. 保持 [Renderer.lua](E:/Program/YiboBeastPaths/Renderer.lua) 继续负责世界地图。
2. 新增独立文件，例如 `MinimapRenderer.lua`，专门处理小地图路线。
3. 如需要，可再新增一个轻量数据辅助文件，例如 `MinimapRouteUtils.lua`，用于坐标与路径预处理。

推荐优先方案：

1. `Core.lua`
   负责初始化、事件注册、总开关协同。
2. `Renderer.lua`
   保持现有世界地图职责。
3. `MinimapRenderer.lua`
   新增，小地图渲染主逻辑。

这样后续定位问题时，世界地图和小地图互不干扰。

## 为什么不直接使用 HereBeDragons-Pins 画整条线

仓库已包含 `HereBeDragons` 与 `HereBeDragons-Pins`，它们非常适合做以下事情：

1. 获取玩家当前地图与世界坐标。
2. 在小地图上放置点位图标。
3. 处理小地图缩放、旋转、边缘浮动等基础地理行为。

但 `HereBeDragons-Pins` 的直接能力更偏向“图标 pin”，不适合直接承担整条折线的绘制。

原因如下：

1. 它擅长的是点位挂载，不是多段连续线条拼接。
2. 如果强行把路径拆成大量 pin 点，会让小地图路线变成点串，不符合当前已确认的细线目标。
3. 线条需要控制角度、长度、连续性、柔边和裁切，这些都更适合我们自己管理 texture 段。

因此建议：

1. `HereBeDragons` 负责坐标换算基础能力。
2. 小地图的“线段渲染”由插件自己的 `MinimapRenderer` 负责。

## 数据格式规范

`CuratedRoutes.lua` 作为小地图路径主数据源，需要明确格式规范，避免后续补数据时出现风格漂移。

每只宠物建议保持如下字段：

1. `mapID`
2. `color`
3. `source`
4. `segments`

其中 `segments` 规范如下：

1. `segments` 必须是数组。
2. 每个 `segment` 必须包含 `points`。
3. `points` 至少包含两个点。
4. 每个点必须是 `{ x = number, y = number }`。
5. `x/y` 使用当前地图归一化坐标，取值范围原则上为 `0.0 ~ 1.0`。
6. `loop` 为可选，用于表达该段是否闭环。

建议后续补数据时继续沿用现有格式，不额外引入新的坐标系。

## 预处理方案

为了避免每次刷新都从最原始数据开始计算，建议在插件初始化后或首次使用时进行一次小地图路线预处理。

预处理内容建议包括：

1. 遍历 `CuratedRoutes.lua`。
2. 校验每只宠物的 `mapID` 与 `segments` 结构。
3. 将所有点先转成可复用的世界坐标缓存。
4. 将点序列预拆分成线段序列。

预处理后的每个线段建议具备：

1. `petID`
2. `mapID`
3. `segmentIndex`
4. `pointIndex`
5. 起点地图坐标
6. 终点地图坐标
7. 起点世界坐标
8. 终点世界坐标
9. 颜色信息

这样做的好处是刷新时只需要做“可见性判断 + 屏幕投影 + UI 更新”。

## 坐标换算设计

### 1. 原始输入

原始路径点来自 `CuratedRoutes.lua` 的地图归一化坐标。

例如：

1. `mapID = 376`
2. `x = 0.661`
3. `y = 0.709`

### 2. 世界坐标缓存

建议通过 `HereBeDragons:GetWorldCoordinatesFromZone(x, y, uiMapID)` 将每个点转换为世界坐标，并缓存：

1. `worldX`
2. `worldY`
3. `instanceID`

这样后续刷新时不必重复做同样的地图到世界坐标换算。

### 3. 小地图局部坐标

每次刷新时，需要基于以下信息重新计算：

1. 玩家当前世界坐标
2. 玩家当前所在实例或地图
3. 小地图当前缩放
4. 小地图当前旋转状态
5. 小地图尺寸和形状

最终目标是把每条世界线段映射到小地图局部坐标系中。

### 4. 可见性判定

可见性判定必须以“线段是否进入当前小地图视野”作为标准，而不是只看端点。

建议按如下顺序判断：

1. 如果线段所在地图不等于当前玩家地图，则跳过。
2. 如果线段两个端点都远离当前小地图范围，并且线段整体也不与当前小地图区域相交，则跳过。
3. 如果线段有任意部分与当前小地图区域相交，则保留用于绘制。

这里要特别注意：

1. 不能只通过“端点是否在圈内”判断，否则会漏掉横穿小地图边界的长线段。
2. 线段与小地图边界的相交测试应作为基础能力存在。

## 小地图渲染结构

### 1. 渲染单元

小地图的基础渲染单元建议定义为“单条线段 frame”。

每个可见线段对应一个小型 frame，frame 内至少包含：

1. 主线 texture
2. 可选柔光 texture

其中：

1. 主线 texture 负责主体颜色和透明度。
2. 柔光 texture 负责极轻的边缘提亮。

### 2. 线段表现

每条线段通过以下参数驱动：

1. 中心点
2. 长度
3. 角度
4. 颜色
5. 透明度
6. 宽度

建议采用一张可横向拉伸的细线纹理，通过旋转和缩放表现任意方向线段。

### 3. 裁切策略

用户已明确边界表现为自然裁切，因此实现上应满足：

1. 进入小地图范围的部分显示。
2. 超出范围的部分不显示。

实现时可以有两种路线：

1. 先做几何裁切，再绘制裁切后的线段。
2. 让线段绘制在小地图容器内，并配合 mask 或父级裁切显示。

设计建议：

1. 优先保证视觉正确。
2. 如果单纯依靠父级裁切会导致旋转长线超出边界显示异常，则需要补充几何裁切。

### 4. 层级策略

建议为小地图路线使用稳定层级，不做动态浮动。

推荐原则：

1. 所有小地图路线位于小地图底图之上。
2. 所有小地图路线位于玩家箭头、任务关键图标之下，或至少不明显压制其阅读。
3. 多宠物之间按稳定顺序渲染即可。

## 刷新机制

### 1. 刷新触发源

小地图路线显示至少需要响应以下变化：

1. `PLAYER_ENTERING_WORLD`
2. `ZONE_CHANGED`
3. `ZONE_CHANGED_NEW_AREA`
4. `ZONE_CHANGED_INDOORS`
5. `MINIMAP_UPDATE_ZOOM`
6. 小地图旋转状态变化
7. 玩家移动导致的位置变化

### 2. 刷新模式

建议采用“事件驱动 + 轻量轮询”的组合方式。

原因如下：

1. 切图、缩放等事件非常明确，适合事件驱动。
2. 玩家持续移动时，小地图路线仍需平滑更新，因此仍需要一定频率的位置刷新。

推荐做法：

1. 事件触发时立刻做一次完整刷新。
2. 平时通过 `OnUpdate` 或定时器进行低成本位置刷新。
3. 不需要像世界地图那样无条件高频全量刷新。

### 3. 刷新频率建议

建议将小地图路线刷新频率限制在“足够顺滑但不过度频繁”的范围。

设计目标：

1. 移动时视觉连续。
2. 不对小地图 UI 造成明显性能压力。

实现时可预留参数，例如：

1. 最短刷新间隔
2. 玩家位置变化阈值
3. 朝向变化阈值

## 复用与对象池

由于小地图路线会频繁进出视野，不建议每次刷新都新建或销毁 frame。

建议建立线段对象池：

1. 需要显示时，从池中取出 frame。
2. 不再可见时，仅隐藏并回收，不销毁。
3. 下次复用相同结构 frame。

对象池至少需要管理：

1. 已激活线段 frame
2. 空闲线段 frame
3. 当前刷新周期实际使用数量

这样能显著降低 UI 抖动和 GC 压力。

2. 在总开关变更时，同时刷新世界地图与小地图。

## 风险与注意事项

### 1. 当前最大风险：数据不完整

现阶段世界地图能显示全部宠物，依赖的是覆盖图资源。

但小地图要显示真实局部细线，依赖的是点线路径数据。

因此：

1. 当前如果 `CuratedRoutes.lua` 只有个别宠物完整，小地图能力就只能先覆盖这些宠物。

### 2. 裁切精度风险

如果只靠粗略“点在不在范围内”判断，可能出现：

1. 横穿边界的线段丢失
2. 边缘闪烁
3. 长线段显示不完整

因此必须把“线段与视野边界相交”的判断作为正式能力。

### 3. 性能风险

如果刷新逻辑设计不当，可能出现：

1. 小地图高速移动时频繁重建 UI
2. 多段路径场景下不必要的全量重算

因此必须：

1. 做预处理缓存
2. 做对象池复用
3. 做受控刷新
