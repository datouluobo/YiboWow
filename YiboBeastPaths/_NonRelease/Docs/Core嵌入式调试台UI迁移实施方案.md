# YiboBeastPaths Core 嵌入式调试台 UI 迁移实施方案

状态：已确认，待实施
适用首期：Mists Classic
目标版本：待排期

## 1. 目标

将 YiboBeastPaths 现有的路线校准调试台迁入 YiboCore 的统一窗口，作为唯一的维护工作台。迁移完成后不再创建、显示或维护独立顶层调试窗口。

首期只保证 Mists Classic 的 Core 内嵌工作台可用。Retail 保持既有路线显示能力，不注册该调试业务页，直到 Core 的 Retail 兼容性被单独确认。

## 2. 已确认的决策

| 编号 | 决策 | 结论 |
| --- | --- | --- |
| D1 | Core 依赖关系 | YiboBeastPaths 发布版保持独立；YiboCore 是可选接入。 |
| D2 | 缺少 Core 时的行为 | 不创建旧独立调试窗；仅提示调试功能需要 YiboCore API v6。 |
| D3 | Core 中的界面位置 | 完整调试台注册为 Core 业务页；设置页仅提供偏好和维护数据操作。 |
| D4 | 调试代码发布边界 | 调试代码可以随正式 BeastPaths 发布，但只能在 Core 内嵌工作台中访问。 |
| D5 | 首期客户端范围 | 仅 Mists Classic 实现、验证和验收。 |
| D6 | 默认访问策略 | 业务页默认隐藏；必须在 BeastPaths 设置中显式开启“路线维护模式”。 |

## 3. 非目标

- 不将 YiboBeastPaths 的路线、融合、脚印或调试数据库迁入 `YiboCoreDB`。
- 不为 Retail 同步实现或承诺 Core 调试页。
- 不保留 `TTRDebugPanel`、可拖拽独立窗口、独立窗口尺寸/位置存档或独立关闭按钮作为兼容回退。
- 不将账号矩阵、Broker、小地图入口或角色快照机制引入 BeastPaths；该页面是地图维护工具，不是账号视图。

## 4. 目标架构

```text
YiboBeastPaths（始终可独立加载）
├─ 正式路线显示、世界地图按钮、小地图覆盖层
├─ 业务数据：YiboBeastPathsDB / YiboBeastPathsDebugDB
└─ Core 适配层（仅满足全部条件时启用）
   ├─ 客户端：Mists Classic
   ├─ YiboCore 已加载且 API >= 6
   ├─ 注册 BeastPaths 设置面板
   └─ 路线维护模式已开启
      └─ 注册并显示 Core 业务页：路线维护
         ├─ 路线校准
         ├─ 融合工作台
         ├─ 脚印管理
         └─ 导出

其余情况
└─ 不创建任何独立调试窗口
```

Core 负责窗口壳、左侧导航、页面尺寸、安全高度、纵向滚动、关闭和战斗状态下的隐藏。BeastPaths 继续负责地图上下文、宠物/路线选择、数据写入、重算、地图重绘、脚印管理与导出内容。

## 5. 加载与注册约定

1. BeastPaths 的 toc 声明 `## OptionalDeps: YiboCore`，不得声明 `## RequiredDeps: YiboCore`。
2. 新建 Core 适配层，延迟等待 BeastPaths 和 Core 的 `ADDON_LOADED` 生命周期完成后再判断是否注册。
3. 适配层首先验证：
   - `ns.IS_MISTS == true`；
   - `_G.YiboCore` 存在；
   - `YiboCore:CheckAPIVersion(6)` 成功。
4. 任一条件不满足时，不创建窗口；Slash 命令或设置页入口只能给出明确、一次性的不可用原因。
5. 适配层使用 `Core:RegisterAddon("YiboBeastPaths", { requiredAPI = 6 })` 注册插件归属，再注册设置面板与业务页。
6. 注册必须幂等：重复的 `ADDON_LOADED`、页面刷新或维护模式切换不得重复占用页面、设置或资源 ID。

## 6. 页面与设置职责

### 6.1 Core 业务页：路线维护

页面是完整调试工作台的唯一承载位置。首期采用四个稳定工作面，不以独立浮窗的绝对坐标布局复刻旧界面：

| 工作面 | 保留的业务能力 |
| --- | --- |
| 路线校准 | 当前地图与宠物选择、路线变换、节点变换、小地图变换、重置与即时地图重绘。 |
| 融合工作台 | 图层显示、自动/手动重算、显示预设、融合与显示细节调整。 |
| 脚印管理 | 录制、撤销、清空、逐点启用/禁用、删除和分页查看。 |
| 导出 | 当前参数、脚印、融合结果和本图变更的可复制 Lua 片段。 |

页面必须使用 Core 提供的内容容器、主题、按钮和纵向滚动能力。内容按可用宽度自动换行或分栏；不得要求横向滚动，不能把标签、说明和控件拆散到不可理解的位置。

### 6.2 Core 设置页：YiboBeastPaths

首期仅提供以下最小内容：

- “路线维护模式”开关，默认关闭；
- 开启后会允许修改本地路线维护数据的风险说明；
- 当前可用性状态：客户端、Core API、业务页是否已启用；
- 前往/打开路线维护业务页的操作。

后续可在此页增加低频显示偏好和调试数据维护，但不得将高频校准、录点、重算或导出搬回设置页。

## 7. 数据与安全边界

- `YiboBeastPathsDB` 与 `YiboBeastPathsDebugDB` 继续由 BeastPaths 独占。
- 维护模式只决定 UI 是否可访问，不得在关闭时删除、迁移或重置任何已有调试数据。
- 清空脚印、删除单点、重置变换等破坏性操作须位于相应工作面的末尾，使用明确风险文案和确认框。
- 所有变更后的唯一刷新链路保持为 BeastPaths 的现有业务方法：更新数据 -> 重算（按设置）-> 刷新世界地图 -> 刷新小地图 -> 刷新当前 Core 页面。

## 8. UI 迁移策略

现有 `DebugCalibrator.lua` 的路线计算、调试数据库访问、导出器和地图刷新 API 是可复用的业务层；其独立窗口壳和绝对坐标 UI 不是可复用的视图层。

迁移时按以下边界拆分：

| 处理方式 | 内容 |
| --- | --- |
| 保留并抽取为业务 API | `InitDebugDB`、选中宠物状态、变换读写、脚印 CRUD、融合重算、显示设置、导出文本生成。 |
| 迁入 Core 页面 | 标签切换、状态摘要、控件创建、内容测量、纵向滚动、控件刷新。 |
| 删除 | `TTRDebugPanel`、位置/尺寸保存、拖拽、缩放手柄、独立关闭按钮、`ShowDebugPanel` / `HideDebugPanel` 的窗口实现。 |

`RefreshDebugPanel()` 应重构为不依赖顶层 `panel` 的页面刷新入口。例如由业务层发布状态变化，再由 Core 页在显示时刷新；地图刷新钩子不得每帧强制重建全部页面控件。

## 9. 实施阶段

### 阶段 1：接入骨架

1. 在 Mists 开发环境确认 YiboCore API v6 的加载顺序与可用性。
2. 增加可选依赖声明与 Core 适配层。
3. 注册最小 BeastPaths 设置面板和默认隐藏的业务页。
4. 实现维护模式开关、可用性提示、业务页显示/隐藏与幂等注册。

验收：关闭维护模式时没有业务页；开启后只有一个 Core 窗口入口；缺少 Core 时没有独立窗口。

### 阶段 2：业务逻辑脱离独立窗口

1. 将调试数据库初始化和所有业务操作从 UI 构建函数中分离。
2. 为当前地图、选中宠物、变换、图层、脚印和导出建立无 UI 依赖的读取与写入接口。
3. 保持既有保存结构和导出文本兼容。

验收：不创建旧面板时，路线重绘、重算、脚印与导出 API 均可单独工作。

### 阶段 3：Core 业务页迁移

1. 依次实现“路线校准”“融合工作台”“脚印管理”“导出”四个工作面。
2. 所有布局使用 Core 容器和统一纵向滚动；根据安全高度进行分段组织。
3. 为当前地图不可用、无路线、无选中宠物和无脚印提供明确空状态。

验收：每项旧调试台能力都能在 Core 业务页完成，且没有横向滚动、裁切控件或重叠元素。

### 阶段 4：移除旧壳与回归验证

1. 删除独立窗口创建、拖拽、缩放、位置尺寸保存和旧窗口 Slash 打开行为。
2. 将旧调试 Slash 命令调整为：打开 Core 的 BeastPaths 设置或维护页；Core 不可用时给出原因。
3. 进行完整 Mists Classic 手工验证。

验收：全局不存在 `TTRDebugPanel`；任何入口均不会产生第二个调试窗。

## 10. Mists Classic 验收清单

- BeastPaths 未安装/未启用 Core 时，正常路线显示不受影响，调试入口只提示缺少条件。
- Core API 低于 6 时，不半初始化、不留下空白导航项。
- 路线维护模式默认关闭，Core 左侧导航不显示维护业务页。
- 开启维护模式后，Core 内只有一个 BeastPaths 工作台入口；关闭后页面被隐藏且数据保留。
- 世界地图切换时，页面准确更新当前地图、可选宠物和状态摘要。
- 校准、图层切换、录点、删点、清空、重算均立即刷新对应地图/小地图覆盖层。
- 导出的当前参数、脚印、融合结果和本图改动与现有格式一致且可复制。
- 页面在安全屏幕高度内优先自适应；确有溢出时仅内容区纵向滚动，导航、标题和关闭操作始终可见。
- 进入战斗时 Core 按既有安全策略隐藏页面；脱战后可正常恢复。
- 不创建 `TTRDebugPanel`，不保存或读取旧独立窗口位置、大小。

## 11. 后续决策（不属于首期）

- Core 的 Retail 正式支持与 BeastPaths Retail 调试页启用条件。
- 是否将路线维护模式细分为只读浏览和可写维护两级权限。
- BeastPaths 常规显示偏好、调试数据库清理与恢复策略的完整设置页设计。
- 是否为高级用户提供受控的正式调试页说明与导出工作流文档。
