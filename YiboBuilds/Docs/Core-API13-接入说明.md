# Core API13 接入说明

2026-10-15，状态：代码与离线验证已完成；用户已反馈本次 Core 适配正常。基线为工作区 Core1.12.4 / API13；Builds 保持1.4.2工作树版本，尚未发版。

## 最小边界与失败行为

Builds 保有 YiboBuildsDB、装备／天赋／雕文采集、增强适用性和目标完成判断。Core 提供账号页面与入口、角色目录、名称格式化、语言资源查询、清理所有者和目标 Provider 连接，不读取 Builds 数据库。

初始化要求 API13，以及 localization:1、character-name-format:1、character-identity:1、account-view:2、account-entry:2、characters:1、character-cleanup:2、business-providers:1、business-item-actions:1。同时检查 Core 已就绪及实际公共对象。TOC 保持 RequiredDeps: YiboCore。版本号之外必须通过能力检查；不兼容时输出双语升级提示，停止页面、目标及事件采集初始化，不注册本地替代界面。已有 API12 目标增强分支合并到统一初始化要求。

资源在 Bootstrap 之后、业务模块之前注册，使用插件 owner YiboBuilds。Core 在自身 ADDON_LOADED 完成会话语言初始化后，依赖插件才读取资源。启动阶段语言服务不可用时，唯一固定双语升级提示是有意保留的启动通道。

## 已接入区域与数据契约

- 页面注册、设置说明、首次模型提示、角色范围标题、字段、悬停、装备与雕文界面、确认／状态／失败提示、目标 Provider、Slash 输出及专业标签使用244组中英文 ASCII key。中文与英文参数保持一致，确认句子与天赋／雕文字段使用完整插值。
- 主表角色行与预览 CharacterLabel 使用 Characters:FormatName；紧凑名称采用 short，全服务器视图采用 full 服务器策略。失败时只显示未知角色占位；业务关联始终使用 Core 角色ID。
- 主窗口与悬停继续消费同一构筑快照，保留默认最多20名有快照的有效角色，Core负责排序、范围与屏幕边界。未启用不限角色预览或新增字段分组，因此不引入相关能力要求。入口继续由 Core 管理三通道选择，默认关闭业务独立入口。
- GetPreviewFields 返回副本；SetPreviewFieldVisible 只接受已声明字段ID，未知ID不写入设置。字段选择仍由 settings.previewColumns 持久保存。
- 新采集的自有占位使用 nameKey；旧快照占位仅在显示时映射，不批量改写历史记录。WoW API 名称与既有客户端DB2目录名称保持原文。原生 Tooltip 匹配词不使用会话语言，以免中文客户端手动选择英文时识别失败。历史专精、专业及雕文准入标签保留兼容语义，不作为身份关联键。
- action.targets Provider 的来源仍是 YiboBuilds:targets，版本1.1；装备实例身份、孔位及强化ID不变。角色不存在、装备实例未知与缺少快照继续返回未知／部分就绪；仅实际应用且装备实例吻合才完成。目标提示按会话语言生成；消费方缺失时基础构筑仍可运行。
- character-cleanup:2 的 Inspect 返回双语影响摘要，Delete 同时清理角色ID与 Core 提供的别名集合。直接删除清除全部快照；延后回放只保留删除时间之后且不晚于当前时间的有效新观察，移除旧装备观察和旧确认，过期槽位整体移除。清理后使页面与目标派生结果失效。Core 保存所有者和pending生命周期，Builds自行执行数据库变更。

## 既有附魔候选问题修复（2026-10-15）

用户确认 Core 适配正常后，反馈背包一张卷轴出现多个不同属性数值候选。根因是 EnchantCatalog 通过 SpellEffect 建立的 itemID→enchantID 关系为一对多：74719关联4430（+170急速）、5058（+14急速）、5094（+8急速）。此前候选只检查物品存在与装备部位适用，三个记录全部获得同一背包来源。

AccountPage 现在通过 C_Item.GetItemSpell／GetItemSpell 的实际使用法术与 source.spellID 比对，筛选背包卷轴及可制作卷轴来源；一次候选构建按物品ID暂存查询结果，下一次刷新重查。实际法术未知且目录存在多个映射时不猜测数值；唯一映射保留兼容行为。已学直接施法、不同卷轴及各自数量不受影响。原生效果目录保留全部记录，用于已有装备快照与目标实际应用识别。

EquipmentAugmentSpec 先复现单卷轴三条候选失败，再验证手套急速、护腕精通、四条智力记录、实际法术优先、未知身份、旧API、不同卷轴／数量、可制作与已学直接附魔。离线回归通过；此项修复的游戏内候选显示待用户复测。Core公共能力审查：涉及插件自身物品→效果映射，复用现有Core语言、页面刷新和已接入能力；未新增Core接口或最低版本要求，台账无新增迁移范围。
