# Forever 当前角色装备最小适配与验收

日期：2026-10-20。Forever 0.1.0／Interface16001；客户端已有探针基线1.60.1.70374／WOW_PROJECT_CAMELOT=18。本轮代码完成，**全部待实机验证，尚不可发布**。

## 范围与所有权

独立 `YiboBuilds_Forever.toc` 只加载Forever目录；MoP仍为1.5.0，原装备、天赋、雕文与增强模块保持原有路径。当前版只读当前角色已穿戴装备的19个原生槽位、物品ID、可读链接及采集时间；空槽位单独显示，名称未缓存时显示物品ID。槽位映射沿用已取证的库存API范围，远程槽与本服特殊装备形态仍须实机核对。

Builds拥有本插件的穿戴构筑观察快照，独立 `YiboBuildsForeverDB`／schema1。Vault库存快照继续由Vault拥有；本版不消费或改写Vault数据，不把Builds快照注册为第二库存权威，也没有跨业务私有读取。Core只提供角色标识、物品解析和公共UI。

不加载MoP天赋／雕文结构、附魔／宝石／专业增强静态目录，不提供换装、插宝石或学习操作。天赋树、专精、传承、完整构筑及增强判断分别取证后另行适配，不从API存在推定已支持。

## 采集、保存与失败行为

进入世界后合并事件，读取 `GetInventoryItemID("player",slot)` 与 `GetInventoryItemLink`。只允许本人GUID，要求IsLoggedIn明确为true，两遍扫描19槽位一致且角色未变才整体提交。链接通过Core.ItemResolver:Parse校验物品ID；nil链接配合明确ID时保留ID，nil ID与nil链接共同表示候选空槽。读取异常、secret值、链接与ID不一致及扫描中换装全部保留旧快照并标记错误。

初次进入世界或普通背包事件得到全空时不覆盖；手动刷新或本人装备变化事件、双遍一致后才确认全空。这只是对过渡期的保护，真实全空、卸下最后一件和登录未就绪情形仍须客户端验证。

监听PLAYER_EQUIPMENT_CHANGED、UNIT_INVENTORY_CHANGED(player)、BAG_UPDATE_DELAYED，排队扫描0.3秒合并；退出世界取消排队。GET_ITEM_INFO_RECEIVED仅刷新名称展示，不写业务事实。物品详情使用Core.ItemResolver:GetInfo，动态名称保持客户端API原文；不自建加载轮询或无限重试。

库范围 `{target="Forever",projectID=18,scope="current-character",rulesetState="unknown"}`；按Core GUID关联，快照返回副本。未来schema、错误范围、非法或不完整19槽存档在写入前拒绝；不导入Mists库。新会话读取旧快照时显示“上次快照”，不冒充本次读取。Core清理v2按GUID删除，取消本人的待采集任务，回放保留时间有效的新观察；未来时间不受回放保护。默认MoP清单被强制加载到Forever时停止其初始化与事件注册。

## Core公共能力审查

最低API13，并检查localization:1、item-resolver:1、character-name-format:1、character-identity:1、characters:1、character-cleanup:2、account-view:2、account-entry:2、account-preview-characters:1、account-character-admission:1、account-surface-budget:2及实际方法。当前配套Core Forever0.2.0；版本或能力不足时明确提示升级并在业务建库前停止，无平行本地回退。

本次接入CAP-001名称格式化、CAP-003公共物品解析／信息、CAP-004统一窗口／滚动／字段／同源悬停／入口、CAP-007当前GUID、CAP-009语言、CAP-010清理。无输入或跨业务查询需求，CAP-002／005／008在本目标不适用；未触及的Mists接入范围不扩大。没有新Core契约。CAP-011专业档案本版未消费，仍待评估。

主窗口与预览使用同一Store副本、角色准入及绘制；19行按视口复用，字段仅“装备部位／物品”。字段显隐、三通道入口和角色管理由Core托管；独立入口三通道默认关闭。诊断保留三字母主命令 `/ybb`，全工作区SLASH注册已搜索，仅同插件历史发行快照重复；没有新增别名。`/ybb`打开页面，`/ybb scan`确认读取，`/ybb status`输出状态。

## 实机清单与发布状态

用户暂后测试，本轮不要求立即提供样本。已有联接会共享本次源码；新增TOC需完整重启客户端，再确认Builds0.1.0并用 `/ybb` 打开。

1. 对照原生角色窗口的部位与物品，检查双戒指／双饰品／主副手和本服远程槽；确实空槽与未采集提示区分。
2. 更换、卸下、重新装备，检查自动刷新；名称缓存延迟与物品ID占位恢复。
3. 关闭重开、RL、完整退出重登，分别检查历史快照与重新采集状态；当前GUID与MoP存档隔离。
4. 字段隐藏、角色排除、悬停同源、入口组合、屏幕边界与四语言模式。
5. Core不足升级提示、MoP相关实机回归及最终Forever包安装验证。

银行、邮件附件、拍卖行、公会银行保持待实机；Crafting配方读取失败等待0.1.1报告定位，均未被本轮Builds模拟覆盖。统一发布结论见[无限服台账](../../Docs/无限服适配与发布验收台账.md)。
