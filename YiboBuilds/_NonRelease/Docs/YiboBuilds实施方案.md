# YiboBuilds 实施方案

> 状态：已完成，已通过 MoP Classic 实机验收
> 最近验证：2026-09-19，主要功能与完整验收清单均已确认可用
> 目标客户端：MoP Classic（`## Interface: 50504`）
> Core 依赖：YiboCore Public API v5（`## RequiredDeps: YiboCore`）
> 关联设计记录：[LOGO_DESIGN.md](../../LOGO_DESIGN.md)

## 1. 目标与边界

YiboBuilds 是账号范围的构筑查看器。首版记录并展示每个角色的系统双天赋槽位、当前激活状态、已选天赋、雕文和完整装备快照；装备快照包含宝石与附魔。

首版只解决“保存并查看角色实际构筑”，不制作配装模拟、天赋模拟、装备方案库、历史变更时间线或正式服兼容层。后续可在不改变已有快照语义的前提下增加当前背包装备等构筑维度。

### 已确认的产品语义

- 每个角色有稳定的 `primary`（主）和 `secondary`（副）系统天赋槽位；未开启双天赋时 `secondary` 为空。
- `lastActiveSlot` 只记录角色最近一次由插件观察到的激活槽位，不是保存键。
- 每个槽位独立保存天赋、雕文、观测装备和已确认装备。登录后可同时更新主副槽位的专精、天赋和雕文；只为当前活动槽位读取穿戴，绝不迁移或覆盖另一个槽位的装备快照。
- “已确认装备”是玩家明确归属给某一天赋槽位的构筑装备，才是跨角色默认展示的装备来源。
- “观测装备”是插件在登录、装备变更、专精切换和登出时取得的当前穿戴，只用于核对，绝不覆盖已确认装备。

## 2. Core 接入边界

YiboCore 继续独占账号窗口壳、标签导航、角色目录、窗口尺寸、滚动、Broker/小地图入口生命周期及入口设置。YiboBuilds 只拥有构筑业务数据、采集规则、矩阵投影和单角色业务内容。

- 用 `AccountView:RegisterPage()` 注册 YiboBuilds 业务标签页。该页嵌入 Core 既有账号窗口与标签导航，不创建插件自己的标题栏、关闭按钮、窗口位置或第二个窗口壳。
- 用 `AccountView:NotifyPageChanged(pageID)` 通知构筑快照变动。
- 业务 SavedVariables 保存在 `YiboBuildsDB`；不得写入或迁移到 `YiboCoreDB`。
- 独立 Broker/小地图入口由 Core 创建和注销，默认不显示；玩家可在 Core 的“显示与入口”中选择不显示、仅 Broker、仅小地图或两者显示。
- 独立入口启用后，左键打开 YiboBuilds 业务页；悬停显示本方案的账号矩阵；右键打开 Core 管理的入口设置。
- 页面、入口、主表字段、悬停字段与角色排序仍由 Core 统一设置工作台保存和渲染；YiboBuilds 不创建第二套设置窗口。

## 3. 数据模型

以下为语义模型。字段名可在实施时调整，但不得改变主/副槽位、观测/确认快照和数据所有权。

```lua
YiboBuildsDB = {
  schemaVersion = 1,
  characters = {
    [characterID] = {
      identity = { name = "", realm = "", classFile = "" },
      lastActiveSlot = "primary", -- "primary" | "secondary"
      slots = {
        primary = {
          specialization = {},
          talents = { -- 固定六层；每层只保存一个已选项
            [1] = { spellID = 0, name = "", icon = 0 },
          },
          glyphs = { major = {}, minor = {} },
          observedEquipment = EquipmentSnapshot,
          confirmedEquipment = EquipmentSnapshot,
          updatedAt = 0,
        },
        secondary = nil, -- 未开启双天赋时为 nil
      },
    },
  },
}

EquipmentSnapshot = {
  capturedAt = 0,
  reason = "login", -- login | pre-spec-change | post-spec-change | logout | confirm
  slots = {
    [inventorySlotID] = {
      itemLink = "",       -- 保留随机属性、宝石、附魔等物品链接信息
      itemID = 0,
      icon = 0,
      appearance = { sourceID = 0, icon = 0 }, -- 可选；用于幻化外观，实施前验证 MoP Classic API
      gems = { { itemLink = "", itemID = 0, icon = 0 } },
      enchant = { enchantID = 0, spellID = 0, name = "", icon = 0 },
    },
  },
}
```

### 3.1 装备范围

保存全部可装备栏位：战斗装备、主手/副手/远程栏位、饰品、衬衣与战袍都在快照中保留。衬衣和战袍在主界面以较低视觉权重呈现，不与战斗装备、宝石和附魔争夺注意力。

### 3.2 数据有效性

- 没有成功采集过的内容不是零值，必须呈现为“未记录”或“无此槽位”。
- 已确认装备与观测装备分别带采集时间和原因。
- 物品尚未在本机缓存时，可先显示保存的图标/名称并请求物品数据；原生 Tooltip 数据可用后再显示。不得拼装或伪造物品 Tooltip。
- 每次 schema 变动要提供显式迁移；迁移失败时保留旧数据并显示可诊断状态，不静默清空构筑。

## 4. 采集与保存流程

### 4.1 自动采集

自动采集只更新专精、天赋、雕文、`lastActiveSlot` 和观测装备；永不覆盖 `confirmedEquipment`。

| 时机 | 动作 | 写入目标 |
|---|---|---|
| 登录 / 进入世界 | 建立角色基础快照、读取主副两套构筑及当前穿戴 | 两套槽位的专精、天赋和雕文；当前槽位的观测装备 |
| 专精切换后（经事件稳定后） | 重新读取主副两套构筑及当前穿戴 | 两套槽位的专精、天赋和雕文；当前槽位的观测装备 |
| 天赋、雕文或专精相关事件 | 合并并去抖后刷新；学习雕文同时监听 `USE_GLYPH` 与 `SPELLS_CHANGED` | 两套槽位的专精、天赋和雕文；当前槽位的观测装备 |
| 登出 / 退出 | 将内存中已经取得的事实写入 SavedVariables | 当前活动槽位和可用观测数据 |
| 玩家确认装备 | 立即重新读取当前穿戴 | 所选槽位的观测装备与已确认装备 |

退出阶段禁止依赖异步物品查询或延迟回调；只持久化已采到的内存数据。

### 4.2 确认装备交互

在单角色页、当前选择的主/副槽位下提供“确认/更新此构筑装备”操作。

- 第一次确认：直接保存当前穿戴为 `confirmedEquipment`。
- 已有确认快照：先显示覆盖确认，明确角色、槽位、旧快照时间和将要写入的当前装备；确认后才替换。
- 该操作不是装备方案管理器：首版每个槽位只保留一份已确认构筑装备。
- 自动观测快照始终保留为核对线索，不能替代玩家确认。

## 5. 账号悬停矩阵

悬停是多角色总览，采用角色为行、构筑字段为列的固定宽度矩阵；最多显示 20 名满足业务准入且有构筑快照的角色。无数据角色、调试文字和装饰说明不进入矩阵。

### 5.1 当前 / 备用专精投影

矩阵左上使用全局两态切换：

| 模式 | 每个角色显示的槽位 |
|---|---|
| 当前 | 该角色 `lastActiveSlot` 指向的槽位 |
| 备用 | 该角色另一系统槽位 |

因此“当前”矩阵始终是所有角色最近使用的构筑；“备用”矩阵始终是其未使用的另一套构筑。未开启双天赋或没有可用备用快照的角色，显示明确空状态而不是复用当前数据。

### 5.2 预览列

1. 角色；
2. 专精图标与全名；
3. 天赋第 1–6 层；
4. 大雕文第 1–3 槽；
5. 小雕文第 1–3 槽；
6. 装备确认状态与确认时间提示。

“当前专精 / 备用专精”是标题栏内的单个两态按钮；当前投影显示目录中每名角色最近使用的专精，备用投影显示该角色的另一系统专精。它不占用矩阵列。每个天赋层只显示玩家最终选择的一项。天赋和雕文单元格均为“图标 + 完整本地化名称”，列宽至少容纳五个中文字符；悬停其图标或名称时显示游戏原生技能/雕文 Tooltip。

## 6. 单角色业务页

业务页位于 Core 统一账号窗口，采用“一名角色、一套构筑、一个工作台”的信息架构：

```text
┌ Core 角色目录 ┬──────── 主/副槽位切换、快照状态 ────────┐
│ 角色分页/选择  │                                            │
│                │  装备人偶及装备栏位  │  天赋六层已选结果 │
│                │  宝石与附魔可悬停    │  大/小雕文        │
│                │                                            │
│                │  确认/更新此构筑装备                       │
└────────────────┴────────────────────────────────────────────┘
```

- 左侧使用 Core 角色目录；角色较多时由 Core 分页，不让业务内容出现横向滚动。
- 顶部主/副切换选择稳定系统槽位，并显示它是否为最近活动槽位、是否有观测/确认装备及各自时间。
- “原型 / 幻化”置于装备区顶部中央。工具栏在装备区与构筑区分界处提供“收起构筑 / 展开构筑”；收起时隐藏天赋与雕文并把装备区扩展至可用宽度。
- “确认 / 更新此构筑装备”固定在业务主内容底部，独立于构筑区的展开状态。按钮和顶部状态明确显示“暂无装备快照 / 装备未保存 / 装备有更改 / 装备已保存”；只有未保存或有更改时可操作。
- 中央围绕角色剪影排列完整装备栏位；MoP Classic 只显示主手和副手两个武器栏。远程武器也归入主手；两个武器栏置于人偶正下方中央，保留少量间隙，主手宝石与附魔在左侧、副手在右侧。所有装备格可悬停。
- 人偶标题栏提供一个两态按钮“原型 / 幻化”：`原型` 显示装备的原始外观，`幻化` 显示已应用的幻化外观。它只改变人偶渲染，不改变物品、宝石、附魔、Tooltip 或已确认装备快照的事实语义。每个装备栏位可选保存幻化外观标识；实施前须验证 MoP Classic 是否可为离线角色稳定解析该标识，无法可靠解析时明确显示不可用状态而不伪造外观。
- 装备格旁或下方显示紧凑、独立的宝石图标与附魔标记。宝石使用原生物品 Tooltip；附魔使用游戏原生效果/法术 Tooltip；装备使用原生物品 Tooltip。
- 右侧使用等高双列：左列为六层已选天赋，右列为六个雕文槽位（大雕文 1–3 后接小雕文 1–3），两列都按单行“图标 + 全名”向下排列。压缩两侧行高，使它们恰好填满装备工作台的有效高度；不再把大/小雕文拆成并列小列。
- 构筑内容使用等宽的天赋、雕文双列，并以至少 28px 的自适应列间距区分两组内容；页面自然宽度按等宽布局收紧。天赋与大型雕文图标均为 56px；“当前”雕文以 60:46 尺寸比例、金色和青绿色图标框区分前三个大型、后三个小型雕文，六行与天赋层级等高；雕文名称使用完整的行内宽度，只有非通用专精在名称下方以次级文字显示。天赋名称可占用图标右侧至列分界线之间的完整宽度。“所有”保留文字与图标并列的“大型雕文 / 小型雕文”分类切换，并以可滚动目录展示完整列表；目录内容会为滚动条预留右侧安全宽度。切换只改变该业务内容区，不扩张 Core 窗口、不制造横向滚动，也不改变矩阵投影。
- 天赋区只显示六层的已选结果；不展示每层未选候选，也不提供模拟或编辑。
- 窄屏时由 Core 将窗口扩展至安全边界后再做纵向重排；不允许横向滚动、裁切控件或把标签与操作控件拆开。

## 7. 设置、入口与诊断

- 默认仅保留 Core 的 Broker/小地图入口；YiboBuilds 独立入口默认关闭。
- 若玩家开启独立入口，入口的位置和显示方式完全由 Core 的“显示与入口”页管理。
- 矩阵预览字段使用 `settings.previewColumns`；默认保证角色、专精、六层已选天赋、六个雕文与装备确认状态一致可见。当前/备用专精通过标题栏两态按钮切换，不作为字段。后续由 Core 逐列控制显示/隐藏。
- YiboBuilds 的业务设置页只放确有必要的业务设置和“数据与缓存”；任何删除构筑缓存的动作放在该分区末尾，展示明确风险文案并要求确认。
- 开发诊断只通过插件 Slash 命令触发。实现前必须全工作区搜索 `SLASH_*`，确认一个未占用的三字母命令；不保留旧别名，诊断不占用 Broker 或小地图常规交互。

## 8. 实施里程碑

1. **插件骨架与 Core 注册**：建立 `.toc`、SavedVariables、API v5 检查、业务页及可选入口注册；确认三字母 Slash 命令唯一。
2. **稳定快照模型**：实现 `primary` / `secondary` 数据迁移、构筑事实采集、活动槽位更新及空状态。
3. **装备采集与确认机制**：实现全栏位物品链接、宝石、附魔、观测快照、切换边界采集和确认覆盖对话框。
4. **账号悬停矩阵**：实现当前/备用投影、固定列、完整本地化名称、20 角色限制和字段设置接入。
5. **单角色构筑工作台**：在 Core 标签页内实现角色目录协作、主/副切换、原型/幻化人偶切换、原生 Tooltip、等高的天赋/单列雕文区、雕文目录展开滚动和确认按钮。
6. **设置、诊断与迁移**：接入 Core 设置工作台、缓存删除确认、诊断命令和 schema 迁移路径。
7. **实机验收与发布准备**：已完成。2026-09-19 已在 MoP Classic 完成下列验收并确认可用。
