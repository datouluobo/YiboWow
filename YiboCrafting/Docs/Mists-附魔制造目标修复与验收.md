# Mists 附魔制造目标修复与验收

日期：2026-10-24。代码基线：Crafting 1.2.1 / Hub 0.6.0；本次修复尚未发布，客户端待验。

附魔配方的制造产物为对应附魔卷轴。用户截图确认：任一专业角色和指定角色配置均出现空产物列表，无法保存。原目录生成器只提取 createdItemIDs，遗漏固定客户端数据中永久附魔效果（effect 53）的 effectItemType 卷轴 ID。

## 目录与目标行为

- 生成器从固定 build 5.5.4.70032 候选的 effects 提取附魔卷轴，与既有创建物品产物去重合并。319 条卷轴映射已补齐，目录版本更新为 mop-5.5.4.70032-r5，重新触发原有学习状态扫描；总目录仍为 5275 条。所有映射使用本目标的静态证据，运行时由 Crafting 独立拥有。
- 示例：7418 → 38679（初级生命）；13620 → 38802（钓鱼）；104427 → 74724（玉魂）。对应选择器显示卷轴，单产物自动选中。
- 任一已学角色、指定已学角色均可选择实际制造次数或持有成品；实际制造读取成功施法计数，持有读取 Core Contracts 发现的库存来源，产物 ID 为卷轴 ID。库存变化不增加制造次数，成功施法也不证明背包持有卷轴。
- 数据中没有卷轴的个人戒指附魔继续按成功施法次数建目标，不构造虚假物品 ID。未学与未知角色不自动获得执行资格。
- action.targets 1.2 方法及返回结构保持兼容；已有物品目标的身份、角色基线与多产物合法性校验保持原契约。目录依然是 provisional，不能据此声明配方可取得或全目录实机验收通过。

## 迁移与 Core 审查

迁移单元为 Mists 制造目标来源和配方静态目录，分别归入 Mists/GoalTargets.lua、Mists/RecipeCatalog.lua。根目录旧文件保留为空操作兼容文件；TOC 只加载新路径。生成器输出、非发布物品反查索引和测试引用已同步。Forever 清单不加载这两个模块。

CAP-001 角色显示、CAP-003 ItemResolver、CAP-004 Theme 与入口、CAP-007 角色身份、CAP-009 owner 语言继续复用现有公开接口；无物品时不查询 ItemResolver。最低 API13 / localization:1 / business-item-actions:2 不变，无新增 Core 能力或并行实现。角色、存档 schema 和安装目录身份不变。

## 2026-10-24 实机反馈与服务器范围

用户反馈当前添加目标已正常；截图包含添加成功提示。对应操作的添加流程记为实机通过，卷轴物品、实际制卷与两种完成条件继续待验，不外推其它角色或范围。

制造目标的执行范围新增服务器约束：任一已学角色目标必须确认 `conditions.realmScope`，取值为 `realm:<Core角色目录中的服务器名>` 或 `all`。目标编辑器默认选当前登录角色的服务器，保存后保持固定，不跟随窗口顶部浏览范围或后续登录角色改变。只有明确选择所有服务器才跨服。指定角色目标的服务器由该角色身份确定。

候选角色、施法完成、库存来源调用和目标标记均按已保存范围处理；标题附服务器名以区别同配方的不同范围目标。服务器范围进入目标身份，允许同配方分别为两个服务器创建目标；明确所有服务器沿用原账号目标身份形式。角色基线保持原有开始时间语义，范围变化不重置历史制造计数。

Hub 的账号目标标记经公开 Normalize 契约获取当前候选范围，避免读取旧快照造成跨服或新角色标记错误；每批查询按目标复用结果。共享目标管理完整职责移入 `YiboTaskHub/Common/Goals.lua`，旧根路径为空操作文件，TOC 与测试的直接和间接加载同步更新。没有业务插件名分支或数据库跨插件访问，Core 的 Contracts、角色目录和统一控件继续复用，最低版本不变。

## 2026-10-25 制造计数事件补修

用户截图显示已获得“附魔护腕－超级智力”卷轴，但“制造1”目标仍为待核实。对应目录 Spell104389 → Item74703，任务创建与服务器范围已显示正常；该次制造完成验收失败，不能标为实机通过。只读检查保存文件时，文件时间为00:05，早于截图制作时间约00:07，因此不能用其磁盘计数推定截图制作后的内存状态。

代码检查发现原施法监听取可变参数最后一项作为法术ID；[Classic客户端生成接口](https://github.com/Gethe/wow-ui-source/blob/classic/Interface/AddOns/Blizzard_APIDocumentationGenerated/UnitDocumentation.lua)的 UNIT_SPELLCAST_SUCCEEDED 载荷为 unitTarget、castGUID、spellID、可选castBarID。尾部castBarID会被旧代码误认成配方法术，造成漏计或误计其它目录法术。改为固定读取第三项spellID，尾部字段不参与业务判断；支持原三项载荷与四项载荷，保持仅计玩家成功施法及原有角色／服务器／基线约束。

EnchantGoals 新增回归先在旧代码失败，修复后通过：尾部为0、尾部恰为另一配方法术ID、非玩家、缺法术ID均覆盖。新增 `_NonRelease/TaskGoalIntegration/CraftingCastSpec.lua` 使用实际 Core Events／Contracts、Crafting来源和Hub缓存／Snapshot／Observe，验证一次带castBarID的制作后：正确配方计数+1、来源变更使缓存失效、指定与服务器内任一角色两种目标均保存完成历史、任务行移除且重复读取不恢复。此前只有简化载荷的离线测试不足以覆盖本次问题。

本次仅修正已迁移的Mists目标运行模块及相关测试；Core公开调用、版本要求、目录和存档身份不变，不涉及新增公共能力接入。旧目标与历史保留，不以当前库存代替过去制造证据，不写WTF修补旧计数。

修复经目录联接可在游戏 `/reload` 后使用。实机待复验：保留截图目标，再制造一次同配方卷轴，确认一次制造完成后任务消失、目标历史为完成；重载与重新登录保持完成。此前漏记的制造次数缺少可回放证据，无法自动追补。本次补修尚未实机通过或发布。

## 2026-10-25 完成后的来源标记

用户两张截图确认：制作卷轴后Hub任务行已正常移除，该次计数与Hub完成清理记为实机通过；Crafting配方与角色格的绿色目标标记仍保留，来源标记同步验收失败。
