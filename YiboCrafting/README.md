# YiboCrafting

![YiboCrafting 图标](Media/YiboCraftingIcon-v2-128.png)

> 状态：1.2.0 / Core API13 待游戏验收与发布。首版交付账号配方查询界面，采用固定来源目录 r4，显示最近快照的已学 / 未学 / 待确认；跨插件只读查询后续交付。目录覆盖与取得来源仍允许按新证据修正。
>
> 当前发布门、逐专业目录计数及具体游戏操作见[首版发布验收](Docs/YiboCrafting-首版发布验收.md)。全部适用公共能力及不适用接口见[Core API13 完整接入清单](Docs/Core-API13-完整接入.md)。

1.0.8 搜索仅使用配方名称、目录产物名称、物品 ID 与已缓存的产物名称，不批量请求缺失物品资料；新资料事件仅在与搜索相关时合并刷新。未缓存的产物仍可按配方名或物品 ID 搜索。中键默认直接添加数量 1：名称／已学角色格为制造一次，产物为持有一件；多产物无法唯一选择时直接打开配置。目标管理可修改数量与执行范围。目标配置、提示和状态文本使用 Crafting 自有中英文资源，经 Core localization:1 / API13 查询；整体运行要求 Core1.12.0 / API13；版本、能力不足或 Core 未就绪时停止初始化并给出升级／就绪提示。

行动中心增强要求 YiboCore API v13 或更高版本，以及支持执行范围字段的 TaskHub。配方名称添加制造次数目标；产物图标添加持有成品目标（库存判断通过 Core 调用 Vault，未安装时保持待核实）。默认执行范围为任一已确认学会该配方的相关专业角色，任一角色独立达到数量即全局完成，各角色数量不相加；也可改为指定角色。矩阵仅“已学”单元格支持指定角色添加。添加按钮由 Core 跟随实际鼠标焦点显示，产物按钮放在图标右侧预留区。Core 设置为中键或 Ctrl＋左键时，正常按钮隐藏，缺参数时提供临时补充入口；右上角按钮模式下悬停即显示。

阶段 0 已备好[只读客户端探针](../_NonRelease/YiboCraftingStage0Probe/README.md)和[验证记录](_NonRelease/Docs/Stage0-客户端验证记录.md)。正式账号页加载[临时运行时目录](RecipeCatalog.lua)：5275 条目录项覆盖 12 个专业；其中目标客户端候选、角色样本与旧 MoP/AtlasLootClassic/ATT 来源按 ID 交叉对账。另有 54 条旧 CTM 配方历史映射、8 条专业动作/研究/战斗技能单列，以及 3 个历史技能候选（含 1 个不在目标 build 专业候选集内的珠宝加工来源记录）保留在审计元数据中，不混入普通配方行。附魔武器：暴政经人工核对后纳入目录。目录由[离线生成器](../_NonRelease/YiboCraftingStage0Probe/Tools/generate_runtime_catalog.py)从固定候选与来源差异表生成，逐 ID 检查 5337 条候选已归入当前配方、边界动作或历史配方；它仍不证明 DB2 候选筛选或客户端目录完整，也不证明配方当前可取得。角色登录时，插件按已确认拥有的专业分批查询 `IsPlayerSpell`，为当前目录版本保存每条配方法术的正/负状态快照；矩阵可显示“已学 / 未学 / ？”。这只证明目录中列出的配方法术在该角色是否已知，不证明目录没有漏项。旧版专业列表仍用于补充产物和分类，不再承担负向判定；探针仍为独立非发布插件，正式插件不依赖它。

当前加载代码还包括 `RecipeStateScanner.lua`。依赖 YiboCore 1.12.0 / API13，初始化检查名称、轻量身份、标准输入、物品解析、账号页／入口／高度、角色清理、连接和主动添加等实际能力（完整列表见接入清单），SavedVariables 为 `YiboCraftingDB`（schema v2）。专业窗口扫描只在本人窗口、Core 已确认当前角色及专业时执行；接口异常和部分列表不会清空已确认配方。配方状态快照独立按当前角色专业数据与目录版本生成；快照失败或 API 返回非布尔值时保留上次快照。分类优先取客户端专业列表标题，再由分类补全表补充；未保存分类时显示待分类。Core 删除角色缓存时清理对应 Crafting 数据。Core API v9 `business-services:1` 已提供通用 Service；Crafting 尚未发布配方查询 Service。

账号页提供“配方 / 专业”两种视图。配方视图以角色为列展示目录候选及角色学习记录；专业视图按专业列出目录候选和历史已学项，并在详情区展示配方信息和角色状态。两种视图支持搜索、角色和状态筛选；配方视图另可筛选专业，选定专业后可按客户端分类筛选。角色筛选按职业显示角色名，两个视图的工具栏都把角色筛选放在专业筛选之前。搜索输入短暂停顿后更新，按回车立即更新；结果列表只绘制当前可见行。首次进入为“配方”，上次所选视图保存在 `YiboCraftingDB.settings.viewMode`。

配方列表由候选目录与角色缓存合并；目录外的历史已学记录仍可见。匹配当前目录版本的 `IsPlayerSpell` 快照可让目录内条目显示“已学”或“未学”；缺少快照或目录版本变化时显示“？/待确认”。候选目录仍未证明完整，目录外漏项不在矩阵中。详情列出候选来源交叉参考提示。角色列超过屏幕安全宽度时分页。产物名称搜索依赖目录/缓存的产物物品 ID 和客户端物品资料；未缓存名称时仍可按配方或物品 ID 搜索。页面使用 YiboCore 的窗口、服务器范围和入口设置。配方详情仅列出拥有对应专业的角色；配方名称和产物图标分别显示游戏配方法术与物品 tooltip。

配方视图选择专业时，同时筛选角色列和角色下拉选项，只显示 Core 已确认拥有该专业的角色；专业快照未确认时，有该专业正向已学缓存的角色也可显示。状态筛选、自然宽度和分页使用相同角色范围。选回“全部专业”恢复当前 Core 范围内全部角色；无符合角色时仍可浏览目录候选。

角色列头复用 Core 的共享角色表头：优先短名并使用职业色，全服务器范围显示服务器第二行，悬停显示完整原名身份。下拉与详情角色名复用 `Characters:FormatName`。整体最低要求 Core1.12.0 / API13，并检查 `character-name-format:1`、`item-resolver:1` 等实际能力；不足时登录提示升级并停止初始化。本次显示与版本检查的离线验证通过，游戏内显示仍待验收。

配方与专业模式采用同一窗口宽度，按配方矩阵的有效角色列计算；专业模式在该宽度内保持三栏布局。配方详情仅列出有相应专业的角色；角色列表只绘制可见行，滚动时复用现有行。仅悬停配方名称显示客户端的配方法术 tooltip；已有产物物品 ID 时，悬停产物图标显示客户端物品 tooltip。角色状态矩阵无配方 tooltip；已学状态在页面矩阵与详情栏查看，不在 tooltip 中重复列出。

YiboCrafting 的目标是成为账号级专业与制造能力索引，记录各角色已学配方并回答“哪个角色能制造什么”。当前版本通过 YiboCore 统一账号工作台展示候选目录及 API 状态快照；全量正式目录、只读配方查询 API 及 YiboBuilds 等插件集成尚未实现。游戏内正/负样本已确认 `IsPlayerSpell` 对两个裁缝配方给出 true/false 区分；游戏截图已证明三态显示，1.2.0 的双语显示、入口、性能与交互回归仍待验收。

详细范围、数据语义、阶段计划及验收边界见 [YiboCrafting 产品边界与开发路线图](Docs/YiboCrafting-产品边界与开发路线图.md)。

全量目录、扫描完整性、确认未学状态与查询 API 的后续工作顺序见[后续实施计划](Docs/YiboCrafting-后续实施计划.md)。


## 行动中心主动添加（2026-10-10 工作树）

配方及角色格可添加制造次数或持有目标；成功施法只证明次数，不证明产出件数。持有经Core调用Vault背包评估；重新执行与复制重设角色计数起点。

整体最低要求为 Core API13；版本或能力不足时停止初始化。角色 ID 迁移同步保留来源自己的制造计数和目标起点。

实际契约、自动化与客户端待验收范围见 [实施与验证](../Docs/行动中心-主动添加实施与验证.md)。

本轮扫描优化：普通列表更新复用同会话结果；登录、打开专业、新学配方与法术变化重新查询。最后一次扫描统计只留在内存，不形成第二份业务数据库。离线验证覆盖事件合并、失败保留、取消和目录版本变化。

1.2.0 的 Broker、小地图、内置条均复用 Core 窗口中的账号矩阵预览；只纳入有业务快照的角色，使用同一配方快照、筛选与学习状态，并按可用高度限制行数。预览字段保存在 settings.previewColumns，由 Core 统一设置配置；无独立摘要窗口。主页面和预览共用 Core 角色范围／排序、列切片和状态判断。设置业务内容嵌入 Core 工作台，语言不另存于业务库。
