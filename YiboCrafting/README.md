# YiboCrafting

![YiboCrafting 图标](Media/YiboCraftingIcon-v2-128.png)

> 状态：首版账号配方页与专业页已接入 YiboCore。当前版本可浏览已记录的配方和角色专业；配方目录覆盖与扫描完整性仍在持续完善。

阶段 0 已备好[只读客户端探针](../_NonRelease/YiboCraftingStage0Probe/README.md)和[验证记录](_NonRelease/Docs/Stage0-客户端验证记录.md)。客户端样本支持“本人专业窗口可确认已学配方 ID”，但目录覆盖率和完整扫描能力仍待验证。正式插件当前只追加这种正向事实，缺失配方始终为未知；不会建立完整扫描基线，也不会生成“确认未学”状态。探针仍为独立非发布插件，正式插件不依赖它。

当前加载代码：`YiboCrafting.toc`、`Namespace.lua`、`Store.lua`、`Collector.lua`、`CategoryCatalog.lua`、`AccountPage.lua`、`Bootstrap.lua`。依赖 YiboCore API v6，SavedVariables 为 `YiboCraftingDB`。扫描只在本人专业窗口、Core 已确认当前角色及专业时执行；接口异常和部分列表不会清空已确认配方。分类优先取客户端专业列表的标题；未保存分类的旧缓存，可由目标构建 `5.5.4.69934` 的技能类别 ID 和本机游戏专业窗口观察缓存中的分类名称补齐。生成目录仅含法术 ID、分类名，不含角色或账号数据。两者均无结果时保留待分类，分类不作为已学证据。Core 删除角色缓存时清理对应 Crafting 数据。

账号页提供“配方 / 专业”两种视图。配方视图以角色为列展示各配方的学习状态；专业视图按专业列出已记录配方，并在详情区展示配方信息和角色状态。两种视图支持搜索、角色和状态筛选；配方视图另可筛选专业，选定专业后可按客户端分类筛选。角色筛选按职业显示角色名，两个视图的工具栏都把角色筛选放在专业筛选之前。搜索输入短暂停顿后更新，按回车立即更新；结果列表只绘制当前可见行。首次进入为“配方”，上次所选视图保存在 `YiboCraftingDB.settings.viewMode`。

配方记录来自客户端能够确认的已学配方。目录覆盖率与完整扫描能力仍在完善，因此未记录配方不会出现在列表，未确认的角色状态显示“待确认”，不代表未学。角色列超过屏幕安全宽度时分页。产物名称搜索依赖已采集的产物物品 ID 和客户端物品资料；旧记录可能需要重新打开角色的专业窗口以补充映射。页面使用 YiboCore 的窗口、服务器范围和入口设置。配方详情仅列出拥有对应专业的角色；配方名称和产物图标分别显示游戏配方法术与物品 tooltip。

配方与专业模式采用同一窗口宽度，按配方矩阵的有效角色列计算；专业模式在该宽度内保持三栏布局。配方详情仅列出有相应专业的角色；角色列表只绘制可见行，滚动时复用现有行。仅悬停配方名称显示客户端的配方法术 tooltip；已有产物物品 ID 时，悬停产物图标显示客户端物品 tooltip。角色状态矩阵无配方 tooltip；已学状态在页面矩阵与详情栏查看，不在 tooltip 中重复列出。

YiboCrafting 是账号级专业与制造能力索引，记录各角色已学配方，并回答“哪个角色能制造什么”。它通过 YiboCore 统一账号工作台展示数据，并为 YiboBuilds 等插件提供只读配方查询能力。

详细范围、数据语义、阶段计划及验收边界见 [YiboCrafting 产品边界与开发路线图](Docs/YiboCrafting-产品边界与开发路线图.md)。
