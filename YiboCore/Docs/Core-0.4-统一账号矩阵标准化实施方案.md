# Core 0.4 统一账号矩阵标准化实施方案

## 目标

将所有接入 `YiboCore` 的账号矩阵收敛到一套可测量的角色身份、表头、底纹、当前角色、分页、滚动与窗口尺寸契约。业务插件保留业务数据和矩阵方向，不再维护私有几何与视觉壳。

## 已确认的产品决策

|主题|统一规则|
|---|---|
|字号与行高|正文 16、辅助 14、元数据 12；主行 28、预览行 26、普通表头 28、双行角色表头 34、图标/分组行 32。|
|角色为列|Core 以“四个汉字的 assist 实测宽度 + 表头左右保护间距 + 栅格容差”生成稳定等宽；角色名完整显示，服务器第二行可截断并由 tooltip 补全；顶部无职业图标。|
|角色为行|单服务器由 Core 测量“四字名 + Core 左右保护间距”；所有服务器改测完整“角色名-服务器名”；仅行头图标时加 16px。|
|当前角色|青绿色 1px 整行/整列框，无角标；列框由 Core 裁切至可见表头与数据 viewport。|
|底纹|所有数据行交替底纹；角色为列或多字段矩阵叠加极浅偶数列底纹。|
|表头|普通表头 toolbar/muted；角色名职业色、服务器 muted；accent 不作常规标题色。|
|滚动|真实纵向溢出才显示；16px 动态沟槽内居中 14px 滑轨；无溢出不占位。|
|分页|到安全宽度后才列分页；初次与结构改变后定位当前角色页，手动翻页不被数值刷新打断。|

## 架构边界

`YiboCore.UITheme` 提供 token、表头、身份列测量、底纹、当前角色框与滚动条；`YiboCore.UI.AccountView` 提供安全尺寸、当前角色页定位和统一分页器。业务页面仅报告业务列、可见角色、当前角色列标识与真实内容尺寸。

业务插件不得自行创建滚动条、分页器、当前角色外框、角色身份列补偿间距、职业图标列宽或表头颜色。例外必须先修改权威契约，不允许永久本地补丁。

## 迁移范围

|页面|现状|迁移重点|
|---|---|---|
|YiboAltoBoss|角色为行 / Boss 为列|移除本地固定表头色与角色列框锚定，接入角色行头布局。|
|YiboCurrency|货币为行 / 角色为列|移除角色名动态列宽和私有工具栏分页，改用 Core 等宽列与表头分页器。|
|YiboQuestBlocker|任务为行 / 角色为列|删除私有预览/滚动补偿和当前列框锚定，使用 Core 分页与裁切。|
|YiboReputation|声望为行 / 角色为列|移除 44/48 本地角色列档和监控预览私有列底纹，接入统一列宽与底纹。|
|YiboTodo|角色为行 / 项目为列|保留业务图标格；角色身份列、边距和 iconRow 高度由 Core token 接管。|
|YiboLegendary|角色为行 / 目标为列|保留业务目标投影；统一行高、表头色、底纹和滚动沟槽。|

## 风险与验收

字号和行高上调会减少同屏行数并改变分页容量；必须先实现 Core 度量，再逐页迁移并在 1280×720 至超宽屏、单/多服务器、2/10/20/21+ 角色、刚好容纳/真实溢出下验收。任何页面不得依赖缩放修复布局。
