# Yibo UI 视觉系统与页面准则

> 适用范围：`YiboCore`、已接入 Core 的业务插件，以及后续新增的账号视图页面、Broker/小地图悬停预览和设置页。
>
> 本文是实施准则。业务插件提供数据、业务状态和页面布局意图；`YiboCore` 提供并维护统一的视觉 token、基础控件、表格/矩阵状态语义和入口生命周期。

## 1. 目标与原则

- **先比较，再展开**：账号视图首先帮助玩家判断“哪个角色下一步该做什么”。
- **统一壳，不同业务布局**：所有页面继承 Core 的窗口、导航、颜色、控件和状态语言；业务数据可以采用表格、矩阵或摘要，不强制同一种布局。
- **高密度但可扫读**：每一列、每一种颜色和每一条线都必须帮助比较或决策。
- **文字、形状与颜色共同表达状态**：不可只依赖颜色表达当前角色、完成、拒绝、错误或可行动。
- **预览是主表的投影**：Broker 和小地图悬停复用主窗口的同一份数据、行渲染器、状态颜色与角色筛选；只按配置隐藏列。

## 2. Core 与业务插件的职责

### YiboCore 必须提供

- 主题 token：颜色、字号、行高、间距、边框、透明度和状态色。
- 基础控件：按钮、危险按钮、输入框、分段单选、**自建复选框**、工具提示。
- 页面标题区、工具栏、设置分组、表格表头、标准数据行、分组行、矩阵表头和矩阵单元格。
- 当前角色、悬停、选中、禁用、完成、拒绝、错误、计时和空状态的统一视觉语言。
- 角色身份渲染、文字截断和完整文本悬停提示。

### 业务插件只能提供

- 业务数据、业务状态到 Core 状态语义的映射。
- 页面标题、说明、可用筛选项、列定义和业务操作。
- 在不违背本文规则时选择“角色为行”“业务对象为行”或其它业务适配布局。

业务插件不得复制 Core 的颜色表、按钮工厂、勾选框、表格行、矩阵单元格或 Broker/小地图入口逻辑。

## 3. 主题与状态

### 3.1 品牌语言

- 基调为深青黑表面、青绿色线条和青绿色主强调，保持当前 Core 风格。
- 青绿色只用于：当前页、主操作、键盘/鼠标焦点、可行动状态和关键正向信息。
- 红色只用于：危险操作、错误和拒绝；不得用于当前角色或普通悬停。
- 职业色仅用于角色身份辨认，不替代完成、选中或可行动状态。
- 页面不得使用渐变、玻璃拟态、装饰卡片或无业务意义的阴影。

### 3.2 线条

- 所有边框和分隔线均为 **1px**；不得以加粗边框代替层级。
- 外框、区域分隔、表格分隔、矩阵格线使用同一色相的不同强度 token，而非页面自行设定 RGBA。
- 矩阵格线必须弱于文字和状态填充；格线用于定位，不能比数据更显眼。

### 3.3 状态表达

每个交互控件必须有默认、悬停、焦点、激活/选中、禁用和错误/危险状态。完成、拒绝、计时、未知和空值必须同时具有文字和颜色/形状差异。

**禁止使用 WoW 原生复选框。** 所有复选、字段显示、筛选和设置开关均使用 Core 自建控件，并共享相同的边框、勾选标记、状态填充、间距和焦点反馈。

## 4. 尺寸、间距与文字

### 4.0 窗口尺寸与锚点

- 账号窗口默认锚定 `UIParent` 左上角（`16, -80`），自动适配时向右、向下展开。
- 手动调整的尺寸按页面保存；Boss、任务屏蔽、概览和设置页不得互相继承一个过大的窗口尺寸。
- 首次进入页面或恢复自动适配时，窗口按该页的首选尺寸显示；矩阵页优先在常见 1600 宽屏完整显示全部可见列。
- 只有当屏幕安全宽度确实不足时，矩阵才允许局部横向滚动；不得通过压缩文字或裁切列伪造“一页显示”。

### 4.1 间距尺度

只使用以下基础间距：`4 / 8 / 12 / 16 / 20 / 24`。

| 场景 | 规则 |
|---|---|
| 主窗口内容边距 | 20 |
| Broker/小地图预览内容边距 | 16 |
| 标题到说明 | 8 |
| 说明到工具栏或首个数据区 | 16 |
| 工具栏到表格 | 12 |
| 相邻控件 | 8 |
| 表格单元格左右内边距 | 8 |

不得在业务页面直接引入 `18`、`29`、`34`、`42` 等孤立间距；若确有必要，先新增并说明 Core token。

### 4.2 字号与行高

| 层级 | 字号 | 使用场景 |
|---|---:|---|
| 窗口/页面标题 | 16 | 顶栏标题、页面标题 |
| 区域标题 | 14 | 设置分组、数据区标题 |
| 表头与正文 | 12 | 表格、矩阵、按钮、说明 |
| 辅助文字 | 11–12 | 服务器、状态说明、悬停辅助信息 |

| 密度 | 高度 | 使用场景 |
|---|---:|---|
| 紧凑 | 24 | 矩阵状态格 |
| 标准 | 28 | 表格数据行、角色身份行、设置控件 |
| 可操作 | 32 | 强交互行、分组行 |
| 双行任务 | 44 | 仅用于明确允许两行的长任务名称 |

文字默认单行。超出时截断并提供悬停完整文本；不得因为个别文本长度让同一表格的行高随机变化。

## 5. 角色与服务器显示

### 5.1 一般规则

- 角色名按客户端实际字体进行**像素测量**，不可按“汉字数量”直接设定宽度。
- 角色名的视觉下限为“2 个汉字加左右留白”，约 48–52px。
- 按当前账号全部有效角色中最长角色名决定常规宽度；筛选、排序、切换 Boss 或服务器范围不得导致列宽跳动。
- 建议角色名上限约 112px；超过上限使用省略号并在悬停中显示完整角色名。
- 英文、重音字符等均按真实渲染宽度处理，不把中文长度规则错误套用到其它文字。

### 5.2 角色名作为第一列

角色名作为表格或矩阵的第一列时，**必须单行显示**。跨服务器信息使用紧邻的独立“服务器”列：

```text
角色          服务器      行动
天堂双影      克罗米      —
天堂图腾      莫格莱尼    计时
```

- 单服务器范围可隐藏“服务器”列；跨服务器范围必须显示。
- 服务器文本允许截断并通过悬停显示完整文字。
- 不得在第一列中把角色名和服务器名上下排列。

### 5.3 角色名作为矩阵顶部表头

角色名作为矩阵顶部表头时，可使用两行身份块：

```text
天堂双影
-克罗米
```

- 第一行为角色名；第二行仅在需要区分服务器时显示，格式固定为 `-服务器`。
- 表头预留两行高度，避免切换到跨服务器数据时布局跳动。
- 服务器名过长时第二行截断，悬停显示完整身份。

## 6. 表格与矩阵

### 6.1 标准数据表

- 适用于角色档案、传说之路等“业务对象字段较长”的页面。
- 使用 Core 标准表头、交替行、当前角色行和滚动容器。
- 表头、正文、筛选、搜索和排序控件遵循本文字号、行高和间距。
- “行动”是可执行下一步时，应提高文字对比与权重，但不得脱离全局主强调色。

### 6.2 Boss 周常：角色为行

Boss 周常采用转置矩阵：**角色为行，Boss 为列**。

```text
角色 | 服务器 | 行动 | 奥尔多斯 | 四天神 | 纳拉克 | 乌达斯塔 | 炮舰 | 怒之煞
```

- 原因：当前角色数量通常多于 Boss 数量，转置可消除顶部角色名过密和无意义压缩。
- 角色与服务器为固定左列；Boss 表头固定在顶部。
- 角色行使用标准 28 高；Boss 状态格使用紧凑 24 高。
- 若 Boss 数增长，横向滚动仅作用于 Boss 状态区，不能挤压角色和服务器列。
- 单元格始终显示“已击杀 / 未击杀 / 计时 / 未知 / —”等文字状态，颜色只是辅助。

### 6.3 任务屏蔽：任务为行

任务屏蔽保持：**任务名为第一列，角色为顶部列**。

- 原因：任务名远长于角色名，转置会造成更严重的第一列阅读问题。
- 顶部角色身份按 5.3 的两行表头规则显示。
- 任务名称默认单行截断；仅明确需要显示完整任务名的行使用固定 44 高双行样式。
- `—`/空状态、已拒绝、全局拒绝和角色拒绝使用统一的文字、图标/形状及颜色组合。
- 顶部角色列过多时保留任务名和全局列，横向滚动仅作用于角色状态区。

## 7. Broker 与小地图悬停预览

- 默认只显示该业务有效角色，最多 20 名；不显示无数据角色、调试文本或装饰文本。
- 悬停预览是正式账号视图的列投影：数据、角色筛选、状态文字和颜色必须与主窗口一致。
- 预览列由 `settings.previewColumns` 控制；完整窗口和预览的任务、目标、行动内容必须完全一致。
- 预览优先展示可帮助玩家立即决策的列，不机械保留“行动”列，也不复制主窗口的筛选和批量操作控件。
- 高列数矩阵在预览中优先投影为行动摘要；只有用户明确启用矩阵字段时才展示对应矩阵列。

## 8. 设置页

- 设置页只能使用 Core 的自建复选框、单选组、按钮、输入框和分组标题。
- 入口模式（不显示 / 仅 Broker / 仅小地图 / 两者都显示）必须作为一个清晰的单选组，而不是四个无关联按钮。
- “主表字段”和“悬停预览字段”并列显示；预览字段仅可选择已经启用的主表字段。
- 重置布局、放弃任务等不可逆或高影响操作使用统一危险样式，并在需要时确认。
- 业务专属设置与统一入口/字段设置分区，避免将插件说明、入口模式和危险操作混在同一视觉层级。

## 9. 新页面实施与验收清单

新增或迁移业务页面前，逐项确认：

- [ ] 页面通过 Core 注册，并复用 Core 窗口和入口生命周期。
- [ ] 未复制颜色、按钮、复选框、表格/矩阵单元格或悬停框实现。
- [ ] 仅使用 Core 间距、字号、行高、边框和状态 token。
- [ ] 表格列、文字截断、悬停完整文本和滚动策略已经定义。
- [ ] 角色作为第一列时为单行，跨服务器时使用独立服务器列。
- [ ] 角色作为矩阵表头时，跨服务器身份块遵守两行规则。
- [ ] 状态不只依赖颜色，并具有文字与形状/图标区分。
- [ ] Broker/小地图预览复用主窗口数据与渲染逻辑，只按预览列隐藏内容。
- [ ] 主窗口、Broker 预览和小地图预览在同一业务数据下核对过一致性。
- [ ] 窄窗口与高列数数据下，固定列、固定表头与横向/纵向滚动符合本文规则。

## 10. 迁移优先级

1. 在 Core 提取并公开主题 token、自建复选框和基础表格/矩阵组件。
2. 迁移设置页和角色档案，使其成为标准控件与标准数据表样板。
3. 将 Boss 周常迁移为“角色为行、Boss 为列”的 Core 矩阵样板。
4. 将任务屏蔽迁移为“任务为行、角色为列”的 Core 矩阵样板。
5. 将 Broker/小地图悬停预览改为页面组件的列投影，并逐页验证一致性。
