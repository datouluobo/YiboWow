# Yibo UI 视觉系统与交互语义准则

> 状态：全系列权威视觉与交互语义基线。
>
> 适用范围：`YiboCore`、所有接入 Core 的业务插件、账号主窗口、统一设置工作台、Broker / 小地图账号悬停预览，以及 Yibo 自建控件。
>
> 关联文档：[Yibo 窗口、尺寸与响应式布局规范](./Core-0.3-窗口尺寸与溢出契约.md) 负责字号数值、行高、间距、列宽、窗口尺寸、锚点、分页、滚动和整体缩放。本文件只定义视觉与交互语义，不重复维护尺寸数字。

## 1. 文档权威性与变更规则

1. 颜色、状态、控件、身份表达和交互语义必须先在本文件中定义，再进入 Core token 和业务实现。
2. 修改视觉或交互规则时必须同步修改本文件；不得只为某个业务插件建立永久特例。
3. 若统一语义不能覆盖实际业务，应停止实现并重新讨论，再修改统一规则。
4. 业务插件不得复制 Core 的颜色表、按钮、复选框、表格行、矩阵单元格、提示或入口交互实现。
5. 本文件只说明 token 的用途；所有影响几何测量的具体数值以尺寸规范为唯一来源。

## 2. 产品目标与设计原则

1. **先比较，再展开。** 账号视图首先帮助玩家发现角色差异并决定下一步行动。
2. **统一壳，不同业务布局。** 所有页面继承 Core 的窗口、导航、视觉 token、控件和状态语言；业务数据可以选择适合自己的表格或矩阵方向。
3. **高密度但可扫读。** 每一列、颜色、图标和分隔线都必须服务比较或决策。
4. **状态不只依赖颜色。** 颜色、文字与图标/形状共同表达完成、拒绝、错误、计时、未知和可行动。
5. **当前角色不抢占全局。** 当前角色应可识别，但账号比较始终是主任务。
6. **预览是主表投影。** Broker 和小地图账号预览复用主窗口的数据、角色准入、状态语义和格式化，只按设置投影字段。
7. **一致性优先于装饰。** 同一动作、状态和控件在所有插件中使用同一种视觉与交互方式。

## 3. Core 与业务插件职责

### 3.1 YiboCore 必须提供

- 主题 token：颜色、字号角色、间距角色、边框、透明度和状态色。
- 基础控件：按钮、危险按钮、输入框、分段单选、自建复选框、提示和确认。
- 页面标题区、工具栏、设置分组、表格表头、标准数据行、分组行、矩阵表头和矩阵单元格。
- 当前角色、悬停、选中、禁用、完成、拒绝、错误、计时、未知和空状态的统一视觉语言。
- 角色身份渲染、文字截断和完整文本提示。
- Broker / 小地图入口及账号预览的创建、定位、显示和关闭生命周期。

### 3.2 业务插件只能提供

- 业务数据及其到 Core 状态语义的映射。
- 页面标题、说明、筛选项、列定义和业务动作。
- 业务字段的显示名称、内容格式和默认投影意图。
- 在统一规则下选择“角色为行”“角色为列”或其它更适合比较任务的布局。
- 通过注册接口提供业务设置，不创建第二套设置窗口壳。

## 4. 品牌视觉语言

### 4.1 基调

- 采用深青黑表面、青绿色线条和青绿色主强调，延续 Yibo 系列识别。
- 青绿色只用于当前页、主操作、焦点、可行动状态和关键正向信息，不作为无意义装饰。
- 红色只用于危险操作、错误和拒绝，不用于当前角色或普通悬停。
- 职业色只用于角色身份辨认，不替代完成、选中或可行动状态。
- 背景、面板、工具栏和数据行使用同一色相体系中的分层 token，不允许业务页面自行发明接近但不同的颜色。

### 4.2 禁止项

- 不使用渐变文字、装饰渐变、玻璃拟态或无业务意义的阴影。
- 不使用装饰卡片堆叠代替信息结构。
- 不用大面积高饱和色表达普通非激活状态。
- 不使用粗侧边色条作为通用强调方式。
- 不以动画作为理解业务状态的前提。

## 5. 线条、表面与层级

- 外框、区域分隔、表格分隔和矩阵格线统一使用 Core 线条 token。
- 线条粗细及所有具体尺寸由尺寸规范定义；业务插件不得加粗边框制造层级。
- 矩阵格线必须弱于文字和状态填充，只用于帮助定位。
- 标题栏、导航、工具栏、数据区和危险区通过表面 token 区分，不通过额外装饰框堆叠。
- 弹出层级统一为：普通窗口 → 对话窗口 → 原生提示。账号悬停预览不得覆盖原生 `GameTooltip`。

## 6. 文字层级与内容规则

### 6.1 字号角色

- `title`：窗口标题和页面主标题。
- `section`：设置分组和数据区标题。
- `body`：表格正文、矩阵状态、按钮和输入。
- `assist`：服务器、辅助说明和次要状态。

具体字号、行高、截断和单/双行高度以尺寸规范为准。

### 6.2 文字使用

- 同一界面使用统一字体家族，不为标题或业务状态引入装饰字体。
- 状态文字优先使用玩家可以直接理解的短语，如“已击杀”“未击杀”“计时”“未知”“—”。
- 辅助文字必须保持足够对比度，不能用过暗文字换取视觉轻盈。
- 表格文字默认单行；截断后必须能通过原生提示看到完整内容。
- 不得为了适应列宽而删除影响决策的任务、目标、行动或身份信息。

### 6.3 窗口标题文案

账号主窗口和对应账号悬停预览使用同一标题内容，不为悬停窗口追加无实际信息的说明。

完整标题格式：

```text
{插件技术名} {版本} · {页面名称}
```

例如：

```text
YiboAltoBoss v2.1 · Boss 周常
YiboLegendary v1.8 · 传说之路
YiboReputation v1.0 · 声望总览
```

- 页面名称面向玩家，属于最高优先级标题信息。
- 插件技术名用于准确识别安装模块，优先级低于页面名称。
- 版本号在空间充足时显示，空间不足时最先省略。
- 不添加“账号预览”“账号角色预览”“多角色状态”等统一框架已经表达的后缀。
- 关于页面继续承担子插件和同作者插件展示，不作为当前安装插件版本信息的唯一入口。
- 标题或业务图标的原生提示始终提供完整插件技术名、版本和页面名称。

标题身份使用以下完整状态，不使用省略号截断页面名称：

|级别|显示内容|
|---|---|
|0|业务图标 + 插件技术名 + 版本 + 页面名称|
|1|业务图标 + 插件技术名 + 页面名称|
|2|业务图标 + 页面名称|
|3|页面名称，省略业务图标|
|4|省略业务图标和全部标题文字|

- 标题栏右侧功能按钮需要空间时，按 `0 → 1 → 2 → 3 → 4` 依次降低标题身份。
- 不缩小标题字号、不让标题换行、不显示半截页面名称。
- 标题身份完全省略时，标题栏空白表面的原生提示仍显示完整窗口身份。
- 功能按钮移入独立功能行后，标题栏恢复级别 0，不保留之前的降级状态。
- 设置工作台标题固定为“Yibo 设置”，当前设置页面名称放在内容区标题中。
- 确认和编辑窗口使用“动作 + 对象”，例如“删除角色缓存”“添加自定义目标”，不重复添加 `Yibo ·`。

## 7. 状态语义

### 7.1 通用状态

每个状态必须同时具有明确文字和至少一种非文字视觉差异：

|状态|文字要求|视觉要求|
|---|---|---|
|当前|保留真实业务值|当前行/身份标记，不替换业务状态色|
|选中|显示选中对象原文|选中表面与焦点边框|
|完成|明确显示完成含义|成功色或完成图标|
|可行动|显示下一步行动|主强调色与较高文字权重|
|计时|显示剩余或计时状态|计时色及对应文字|
|拒绝/阻止|显示拒绝来源或状态|危险/阻止色及图标或形状|
|错误|提供可理解的错误说明|危险色和错误标记|
|未知|明确写出未知|中性状态，不伪装为空值|
|空值|使用统一占位符|中性低强调，不与未知混淆|
|禁用|保留标签并说明不可用|低强调表面和文字|

### 7.2 状态一致性

- 同一状态在主窗口、悬停预览和设置说明中使用同一文字、颜色与格式。
- 职业色、当前角色色和业务状态色不能互相覆盖；角色身份与业务状态分别表达。
- 悬停和选中不得改写语义文字颜色，只改变控件边界或表面。

## 8. 控件规范

### 8.1 交互状态

所有交互控件必须定义：

- 默认
- 悬停
- 焦点
- 激活/选中
- 禁用
- 加载
- 错误或危险

### 8.2 基础控件

- 所有按钮使用 Core 共享工厂和统一形状。
- 关闭按钮是轻量窗口操作，不使用危险实心按钮样式。
- 危险按钮只用于删除缓存、放弃或不可逆操作，并配合确认。
- 禁止使用 WoW 原生复选框；字段显示、筛选和设置开关统一使用 Core 自建复选框。
- 入口模式使用一个清晰的分段单选组，不表现为互不相关的多个按钮。
- 输入框、按钮、复选框和单选组不得由业务插件重新定义颜色、边框或反馈。

### 8.3 提示与反馈

- 文字截断、按钮含义和字段说明使用原生 `GameTooltip`。
- 数据加载优先保持稳定布局并显示明确状态，不使用遮挡整个页面的装饰动画。
- 动效只用于状态变化与操作反馈，持续时间短，并提供无动画等价行为。

## 9. 角色与服务器身份表达

### 9.1 角色作为数据行

- 角色名与服务器作为相邻但独立的信息角色。
- 单服务器范围可隐藏服务器列；所有服务器范围显示服务器列。
- 当前角色使用身份标记或当前行表面，不覆盖职业色与业务状态。

### 9.2 角色作为顶部矩阵列

- 单服务器范围只显示角色名。
- 所有服务器范围显示角色名和 `-服务器`。
- 服务器属于辅助身份信息，视觉权重低于角色名。
- 单行/双行高度、截断和范围切换尺寸行为以尺寸规范为准。

## 10. 表格与矩阵

### 10.1 标准数据表

- 适用于角色档案、传说之路等字段内容较长的页面。
- 使用 Core 标准表头、数据行、交替行、当前角色标记和数据视口。
- “行动”列只有在提供真实下一步时才提高权重，不机械高亮空行动。
- 空状态应解释缺少数据的原因和下一步，而不是只显示“无数据”。

### 10.2 矩阵

- 矩阵方向必须帮助玩家比较，不以已有代码结构作为理由。
- Boss 周常优先采用角色为行、Boss 为列。
- 任务屏蔽等长任务对象页面可以任务为行、角色为列。
- 固定身份/任务区与分页、滚动和尺寸顺序由尺寸规范统一管理。
- 每个状态格始终显示文字状态，颜色只是辅助。

### 10.3 分页视觉

- 列分页必须清楚显示当前页、总页数和前后页操作。
- 固定身份/任务区在翻页时保持不变。
- 翻页后焦点和当前角色标记保持可识别。
- 不使用难以发现的隐藏手势代替分页控件。

## 11. Broker 与小地图账号预览

### 11.1 内容投影

- 账号预览只显示具有该插件业务快照且满足准入条件的角色。
- 不显示调试文本、重复说明、无数据角色或纯装饰内容。
- 预览字段由插件设置中的 `settings.previewColumns` 控制。
- 预览字段只能投影主表已有字段；任务、目标和行动内容必须与主窗口完全一致。
- 默认字段优先帮助玩家直接作出决策，不机械保留“行动”列。
- 高列数矩阵优先投影为行动摘要；用户需要更多字段时按尺寸规范使用列分页。

### 11.2 标题栏与功能语义

- 悬停标题栏允许利用右侧空间放置少量上下文功能，不固定增加第二行。
- 只有服务器范围功能时，服务器按钮右对齐放在标题栏；标题身份按第 6.3 节自动降级。
- 存在服务器范围以外的业务预览模式时，通用功能进入一条独立功能行，标题栏恢复完整身份。
- 列分页放在数据表头右侧，不进入通用功能行。
- 悬停窗口不显示设置、排序、添加、删除、编辑、放弃、批量操作或诊断按钮。
- 功能按钮不能为了适应宽度缩小字号、压缩点击区域或覆盖标题。

服务器范围优先使用完整名称按钮。空间不足时直接改为：

```text
[当前服务器名] [其它 ▾] [所有]
```

- 不使用单字或前缀缩写服务器名。
- 中间控件选中其它服务器时显示该服务器完整名称，而不是继续显示泛化的“其它”。
- 完整按钮、选择器和独立功能行的选择顺序及显示前测量规则以尺寸规范为准。

### 11.3 入口交互

- 左键打开统一框架中的对应业务页面；右键进入 Core 管理的入口设置。
- 探针和诊断只通过插件 Slash 命令触发，不占用常规入口交互。
- 锚点、角色数量、分页、滚动、功能行和关闭宽限以尺寸规范为准。

## 12. 统一设置工作台

- 所有依赖 Core 的插件使用同一个设置工作台，不创建第二套标题栏、关闭按钮、滚动条或位置存档。
- 左侧导航顺序固定：Core 常规设置在前，随后按插件技术名字母序排列业务插件。
- Core 常规设置包含“窗口”“角色与排序”“显示与入口”。
- 业务插件设置页按适用情况依次提供“页面与入口”“显示与排序”“业务设置”“数据与缓存”。空分区不显示，但顺序不得改变。
- 页面与入口、主表字段、预览字段和角色排序由 Core 渲染和保存。
- 主表字段和预览字段并列表达；预览字段只能选择已启用的主表字段。
- 破坏性动作位于“数据与缓存”末尾，使用明确风险文案和统一确认。
- 设置工作台的尺寸、两栏降级和滚动规则以尺寸规范为准。
- 未来业务插件独立缩放属于 Core 通用设置能力，不由业务插件创建自定义缩放控件。

## 13. 无障碍与可读性

- 正文和辅助文字必须与所在表面保持足够对比度。
- 状态不能只依赖红绿差异；文字与图标/形状必须同时存在。
- 焦点状态在深色表面上清晰可见。
- 交互热区遵循共享控件 token，不因视觉紧凑而难以点击。
- 动画不是理解内容或完成操作的前提。
- 放大显示属于未来的最终显示能力；100% 基线本身必须可读、完整并通过尺寸验收。

## 14. 新页面实施检查清单

- [ ] 页面通过 Core 注册并复用统一窗口和入口生命周期。
- [ ] 未复制颜色、按钮、复选框、表格行、矩阵格或悬停框实现。
- [ ] 所有颜色和状态来自 Core token。
- [ ] 所有字号、行高、间距、列宽和窗口尺寸引用尺寸规范与 Core token。
- [ ] 状态同时具有文字和非文字差异。
- [ ] 角色身份与业务状态没有互相覆盖。
- [ ] 矩阵方向能够解释其比较优势。
- [ ] 主窗口与账号预览复用同一数据、准入、状态和格式化逻辑。
- [ ] 预览只投影字段，不复制编辑和批量操作。
- [ ] 标题使用统一文案和身份级别，不追加“账号预览”等冗余后缀。
- [ ] 服务器范围使用完整名称或统一选择器，没有插件私有缩写。
- [ ] 只有服务器功能时优先使用标题栏右侧；存在其它预览模式时只增加一条功能行。
- [ ] 列分页控件清楚可见，横向滚动未被当作默认方案。
- [ ] 设置内容进入统一工作台，危险操作位于正确分区。
- [ ] 同一业务数据下核对过主窗口、Broker 预览和小地图预览的一致性。

## 15. 实施优先级

1. Core 统一主题 token、基础控件和状态语义。
2. 设置工作台和角色档案作为标准控件与标准数据表样板。
3. Boss 周常作为角色为行的矩阵样板。
4. 任务屏蔽作为任务为行、角色列分页的矩阵样板。
5. 传说之路和声望迁移到共享表格、状态和预览投影。
6. 所有页面按尺寸规范完成 100% 显示验收后，再实现业务插件独立缩放。
