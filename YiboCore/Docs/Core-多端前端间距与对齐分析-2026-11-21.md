# YiboCore 多端前端间距与对齐分析

2026-11-21 · 适用于熊猫人之谜（MoP）、无限服（Forever）和正式服（Retail）· 本轮为前端分析，截图验收待执行。

优先修正表头与文字的位置，再缩减固定区的无效留白，最后整理格线：先消除相邻边框叠加、嵌套边框和描边贴边形成的多重线，再调弱普通格线。文字偏心主要影响观感，数据视口之前的固定高度直接决定首屏能看到几行，多重线会让 1 单位的格线在截图里变粗、变花。保留现有深青黑与青绿识别，普通数据行先按主表 `28`、悬停 `26`、正文 `16` 比较。所有尺寸为源码中的 UI 单位，截图的实际像素与字形受客户端字体和 UI 缩放影响。本文记录观察和验收建议，尺寸定义与视觉语义沿用两份现行规范。 [窗口尺寸与溢出契约](Core-0.3-窗口尺寸与溢出契约.md) · [UI 视觉系统与页面准则](UI视觉系统与页面准则.md) · [Core 主题](../UI/Theme.lua)

## 优先级 3 · 多重格线、底纹与强调色

历史 MoP 仓储截图中，角色选择框、页签、品质边框和物品图标同时抢占视觉注意力。清晰的线框也会放大文字偏心。完成对齐后先处理多重线，再降低普通矩阵格线和常规控件边框的存在感。

### 3.1 多重格线

Core 表头已按「每格只画右线和底线」实现，相邻表头不会重复画同一条边界。但多个数据页的行、格仍使用四边 `edgeSize = 1` 的 Backdrop，紧贴排列时相邻两条边会叠成一条 `2` 单位的粗线。

| 类型 | 源码观察 | 处理方向 |
| --- | --- | --- |
| 相邻行边框叠加 | Core 角色档案的每行都用四边边框，行距等于行高、间隔为 `0`，上一行底边与下一行顶边紧贴。 | 普通行改为只画底线，或只用斑马底纹不画行框。整表外框由容器统一画一次。 [角色档案行](../UI/AccountPages/CharacterArchive.lua) |
| 行框内嵌格框 | AltoBoss 的行带四边边框，行内的击杀状态格自身也有四边边框（普通 `matrixLine`，已击杀 `success`）。 | 同一层级只保留一种边界：状态格保留语义边框时，所在行不再画竖向格线；普通格靠底纹和列间隔区分。 [AltoBoss 行与状态格](../../YiboAltoBoss/Mists/AccountPage.lua) |
| 容器框与行线重合 | MoP 专业矩阵的容器有 `matrixLine` 边框，行内另画 `rule`；仓储的行与格也同时设置边框。首行、末行、首列、末列与容器框可能重合。 | 规定容器框负责外边界，行线、格线只画内部分隔，首末边不再重复画。 [MoP 专业矩阵](../../YiboCrafting/AccountPage.lua) · [仓储页](../../YiboVault/StoragePage.lua) |
| 表头底线接数据行顶边 | Core 表头自带底线，若下方第一行带四边边框，会在表头下沿叠出双线。 | 表头底线作为表头与正文的唯一分界，第一行不画顶边。 [Core 表头](../UI/Theme.lua) |
| 强调描边贴着格线 | 当前角色描边向内缩 `1` 单位，贴在行框或格框内侧，形成「格线＋强调线＋相邻格线」的平行线组。 | 当前角色描边显示时，被覆盖的普通格线隐藏或让位，或描边改为占用格线位置，保证只看到一条强调线。 [当前角色描边](../UI/Theme.lua) |
| 列底纹边缘接格线 | 偶数列叠加 `0.36` 透明度的列底纹，若同时画竖向格线，底纹边缘与线并排，形成软硬两条边。 | 有列底纹的矩阵不画普通竖线，列与列之间只靠底纹交替区分。 [列底纹](../UI/Theme.lua) |

统一规则建议写入 Core 主题并由各页复用：**一条边界只由一个元素画一次**。容器画外框，表头画右线和底线，数据行只画底线，状态格的语义边框优先于普通格线。业务页不再自建四边行框，迁移按「触及即迁移」逐页进行。

### 3.2 1 单位线的像素对齐

`lineWidth = 1` 是 UI 单位，源码中未对格线做像素吸附。WoW 中每个 UI 单位对应的物理像素约为「屏幕高度 ÷ 768 × UI 缩放」：`1280×720` 缩放 1 时约为 `0.94`，`1920×1080` 约为 `1.41`，`2560×1440` 约为 `1.88`。非整数时，同一页面的线可能有的 1 像素、有的 2 像素，或在小于 1 时变淡、断线，看起来像粗细不一的多重线。

线宽换算、像素吸附和缩放变化后的刷新统一由 Core 控制，业务页只调用 Core，不自行换算、不保留本地回退。具体设计见 [像素线宽统一控制实施方案](Core-像素线宽统一控制-实施方案-2026-11-21.md)。截图时注意区分「源码画了两条线」与「一条线被渲染成 2 像素」。

### 3.3 弱化与保留

去重之后，再降低普通矩阵格线和常规控件边框的存在感，保留轻底纹帮助跨列扫读。物品品质边框、当前角色框、焦点与选中状态保留足够辨识度。状态需要同时能从文字或符号读出。 [MoP 仓储截图](../../YiboCore%20for%20MoP/Screenshots/03-Account-Inventory.png) · [Core 线条与状态准则](UI视觉系统与页面准则.md)

### 分辨率与缩放

每端按三档取样，覆盖中文和英文代表页：

| 分辨率 | 定位 | 重点检查 |
| --- | --- | --- |
| `1280×720` | 较小视口 | 首屏行数、角色列是否过早分页、底部操作是否可见。每 UI 单位不足 1 像素，检查格线变淡或断线、小字号字形是否完整。 |
| `1920×1080` | 常用基准 | 作为前后对照的主基准，记录全部关键间距。 |
| `2560×1440` | 高分辨率 | 窗口扩展到安全边界后的最大宽高、完整矩阵是否不再分页、末列右侧与底部是否留下大片空白。每 UI 单位接近 2 像素，检查 1 单位线粗细是否一致、双线是否被放大。 |

每档至少取客户端默认 UI 缩放一张。`2560×1440` 另取一张玩家常用的较小 UI 缩放，因为这时有效像素比例又会变回非整数。

每组附客户端 build、插件版本、页面、主窗或悬停、分辨率与 UI 缩放。图上至少能辨认表头上下边、首末行和最右列，并附上首屏完整行数及关键间距。检查多重线时，用原尺寸截图或按整数倍放大查看，不用缩放后的预览图判断线宽。验收通过依据是字形完整、表头与正文对齐、固定区随内容变化、末列可读、任一边界只看到一条线，以及格线弱于文字和状态。 [现有尺寸验收矩阵](Core-0.3-窗口尺寸与溢出契约.md) · [MoP／Retail 设置实机记录](../../YiboBeastPaths/Docs/1.9-维护面板迁入设置页-20261114.md)
