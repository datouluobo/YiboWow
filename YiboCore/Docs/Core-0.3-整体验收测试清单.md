# YiboCore 0.3 整体验收测试清单

> 本清单只验证 YiboCore 平台能力。除专门的模拟注册器外，不改动、不要求加载真实业务插件。

## 测试前准备

- 使用全新的 `YiboCoreDB` 完成一轮测试，再使用含旧窗口和入口设置的存档完成一轮回归。
- 准备一个仅用于测试的模拟插件；它应先调用 `YiboCore:RegisterAddon`，然后注册页面和可选入口。
- 至少准备两名已记录角色，其中一名在 Core 设置中隐藏。

## A. 基线与兼容

- [ ] 仅加载 YiboCore：`/yco` 能打开账号总览，`/yco settings` 能打开设置。
- [ ] 不加载业务页面时，概览、角色档案、设置、Core 小地图入口均正常。
- [ ] Core 默认 Broker 存在时左键打开总览、右键打开设置；Broker 缺失时插件不报错。
- [ ] 旧存档中的窗口位置、尺寸、角色隐藏、Core 小地图位置和页面设置可以读取。

## B. 注册与冲突仲裁

- [ ] 未调用 `Core:RegisterAddon` 的模拟插件注册页面时被拒绝，错误指出未注册插件。
- [ ] 两个插件注册同一 `pageID` 时，第二次被拒绝，原页面仍正常。
- [ ] 业务页面使用 `overview`、`characters`、`settings` 或 `YiboCore` 等保留 ID 时被拒绝。
- [ ] 入口绑定不存在页面时被拒绝。
- [ ] 插件 A 的入口绑定插件 B 页面时被拒绝。
- [ ] 重复 `entryId`、Broker 名称或小地图 Frame 名称时被拒绝且不会覆盖已有入口。
- [ ] 已登记的 page、entry、broker 与 minimap-frame 资源冲突会在注册时拒绝，且不会覆盖已有资源。

## C. 入口生命周期

- [ ] 模拟业务入口默认模式为“不显示”，不会新增 Broker 或小地图图标。
- [ ] 分别切换为仅 Broker、仅小地图、两者都显示；Core 默认入口始终不受影响。
- [ ] 业务小地图图标可拖动，重载后仍保持自己的位置；不同 `entryId` 的位置互不覆盖。
- [ ] 关闭业务小地图模式后图标立即隐藏。
- [ ] 关闭 Broker 设置后显示“重载界面后生效”的语义；重载后不再注册新的 Broker 入口。
- [ ] 注销业务页面后对应小地图图标隐藏，Broker 不再响应点击或悬停。
- [ ] 重新注册同一插件、页面和入口后不会生成重复图标或重复 Broker。

## D. 主窗口与悬停预览

- [ ] Core 默认入口悬停显示概览预览，而不是只显示当前角色。
- [ ] 业务快捷入口左键进入其目标页面，右键进入该页面的 Core 设置。
- [ ] 业务页面仅在 `previewEnabled = true` 时允许显示预览；禁用页面不会弹出预览。
- [ ] 主窗口和同一业务的 Broker/小地图预览拥有相同的可见角色范围；隐藏角色不出现。
- [ ] 业务 `previewColumns` 改动后，窗口业务数据不变，预览仅改变列显示。
- [ ] 快速从入口移入预览再移出时不闪烁、不提前关闭；预览渲染失败时不会影响主窗口。

## E. 概览行动

- [ ] 模拟两个页面各返回 4 条行动；概览中每页最多显示 3 条，总数最多显示 8 条。
- [ ] 行动按 priority 降序排列；同优先级时按业务标题、角色/行动标题稳定排序。
- [ ] 业务回调返回的行动 table 没有被 Core 修改（尤其没有被写入 `pageID`）。
- [ ] 概览行动点击能打开其页面；页面被禁用或注销时不会报错。
- [ ] `GetSummary` 或 `GetActions` 抛错时，其它业务页面、概览和入口仍可使用，聊天框诊断包含页面和插件名而不泄露业务数据。

## F. 设置与诊断

- [ ] Core 通用设置只管理窗口、角色范围与 Core 入口。
- [ ] 业务设置页显示页面开关、独立入口模式、主表字段和（可用时）预览字段。
- [ ] 业务专属设置仍由业务回调打开，Core 不写入业务 SavedVariables。
- [ ] `/yco` 打开账号总览，`/yco settings` 直接进入统一设置工作台。

## G. 最终回归门槛

- [ ] 分别在无 Broker 库、有 Broker 库、`/reload` 后完成 A–F。
- [ ] 使用新存档和旧存档各完成一次 A–F。
- [ ] 角色数为 1、2、20、超过 20 时，窗口与预览均无 Lua 错误且滚动正常。
- [ ] 记录测试期间出现的 Lua 错误为 0；若有错误，必须先修复并重新执行受影响分组。
- [ ] 确认本轮改动路径仅在 `YiboCore/**`，没有业务插件文件进入变更集。
