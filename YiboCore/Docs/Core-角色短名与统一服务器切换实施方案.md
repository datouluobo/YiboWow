# Core 角色短名与统一服务器切换实施方案

> 状态：已确认的改造基线  
> 影响范围：`YiboCore`、所有已接入 Core 的业务插件；首个落地页面为 `YiboReputation` 的声望总览。  
> 本文补充现有 Core 账号视图、角色排序和页面范围契约；发生冲突时，以本文的角色短名与服务器切换规则为准。

## 1. 已确认的产品决策

1. 角色名不做自动截取。把所有角色截成前几个字会在同前缀角色中失去身份意义，例如多个“天堂…”角色都会变成“天堂”。
2. Core 提供玩家维护的**自定义短名**；业务插件可声明表头/列表使用完整名或短名优先。
3. 所有业务插件使用同一套服务器切换交互：在由 Core 管理的业务入口账号视图顶部，显示服务器按钮与“所有服务器”按钮。点击即切换该账号视图的角色范围。
4. 服务器范围是 Core 的统一账号视图状态，不由每个插件重复保存或重复绘制。业务过滤仍归业务插件。
5. 声望总览的紧凑矩阵仅显示精确当前值、`—` 和 `?`；不得使用 `5.9k` 这类缩写，也不显示“崇/敬/尊/友”等等级简称。完整等级、分子/分母、数据状态和时间在 tooltip 中呈现。
6. 角色分页是窄屏或极多角色时的回退，不是常规浏览方式。先通过短名、窄等宽列和精确短值提高同屏容量。

## 2. 职责边界

| 事项 | YiboCore | 业务插件 |
| --- | --- | --- |
| 角色真实名称、服务器、职业、角色 ID | 保存、迁移、提供查询 | 只读使用，不复制身份事实 |
| 自定义短名 | 保存、校验、编辑 UI、统一读取接口 | 声明某一列/列表使用完整名或短名优先 |
| 服务器按钮 | 生成、排序、绘制、选择状态、持久化、角色集合过滤 | 不自行实现；只接收筛选结果 |
| “所有服务器” | 统一提供且作为范围复位 | 不复制同义按钮 |
| 业务角色准入 | 在 Core 排序与范围流程中调用插件回调 | 定义 `HasCharacterSnapshot` 或等价业务准入 |
| 业务筛选 | 提供范围之后的角色集合 | 定义并保存，例如声望的“未满 / 已监控 / 搜索” |
| Broker / 小地图入口 | 创建、注销、左/右键语义及入口设置 | 注册摘要与目标页面，不处理入口生命周期 |
| tooltip | 提供容器与标准身份信息能力 | 提供业务详情内容与状态解释 |

Core 不接管 Boss、任务、声望等业务快照，也不推断业务上的“可显示”含义；它只负责可信角色身份、通用范围与统一入口交互。

## 3. Core：角色短名能力

### 3.1 数据模型

短名写入 `YiboCoreDB` 的角色显示偏好，以稳定 `characterID` 为键；不得用名称或“名称-服务器”作为键。

```lua
characterDisplay = {
  [characterID] = {
    shortName = "暴风", -- nil 或空字符串表示未设置
  },
}
```

- 原始 `character.name`、`character.realm` 和旧键别名不变。
- 删除 Core 角色档案时，随该角色的显示偏好一并删除；不得影响其它角色或业务快照。
- 迁移只新增字段，不对历史角色名生成猜测式短名。

### 3.2 公共读取接口

```lua
Core.Characters:GetDisplayName(character, "full")
Core.Characters:GetDisplayName(character, "short")
Core.Characters:SetShortName(characterID, value)
```

语义：

- `full`：返回真实角色名；跨服务器身份块仍由调用处以真实服务器名补充。
- `short`：有自定义短名时返回短名；未设置时回退真实角色名，**绝不截取**。
- `SetShortName`：去除首尾空白；空值清除短名；拒绝控制字符与不可渲染内容；返回可供设置页显示的校验错误。

短名可以重复，但 Core 设置页必须标出当前账号范围内的重复项，并显示其完整“角色名—服务器”身份。重复仅为警告，不自动拼接服务器名、不偷偷改写玩家输入。

### 3.3 Core 设置工作台

在 `角色与排序` 下新增“角色名称”页/分区，作为唯一短名管理入口：

1. 每行显示职业色真实角色名、服务器、当前短名输入框和清除操作。
2. 短名为空时明确显示“将回退完整名”，不预填截断值。
3. 发现重复短名时就地提示相关角色；不阻止保存。
4. 角色排序仍以已有排序规则为准；短名只影响显示，不影响身份、排序键、业务缓存键或服务器归属。

## 4. Core：统一服务器切换

### 4.1 统一交互

Core 在每个已注册业务页面的账号视图顶部渲染同一种服务器范围条：

```text
[当前服务器]  [其它有准入角色的服务器]  [所有服务器]
```

- 当前登录角色所在服务器排在第一位；其它服务器按 Core 的稳定服务器排序；“所有服务器”永远最后。
- 只为该业务页面**有业务准入角色**的服务器生成按钮，空服务器不出现。
- 一个服务器只有一个按钮，按钮文案使用完整服务器显示名；不在不同插件中变更名称或顺序。
- 所有按钮使用 Core 的常规/选中/悬停/禁用视觉状态，业务插件不得自绘同类控件。
- 选择结果在当前账号视图中立即生效；所有服务器是明确的复位项。

这里的“Broker 中直接切换”指由 Core 管理的业务 Broker 入口打开的账号视图中可立即操作的范围条。入口本身仍遵循统一语义：左键打开该业务页面，右键打开入口设置；不把右键或悬停改造成插件私有的服务器切换协议。

### 4.2 状态与过滤顺序

服务器选择保存为 Core 的统一账号视图状态，例如：

```lua
accountView = {
  selectedRealmScope = "realm:<realmKey>" | "all",
}
```

切换后 Core 用以下固定顺序构建 `context.characters`：

1. 排除被 Core 隐藏的角色；
2. 调用业务插件的角色准入；
3. 根据已选服务器或“所有服务器”过滤；
4. 应用 Core 的当前角色置顶与有效排序；
5. 将稳定有序结果传给业务页面与同一业务的入口预览。

业务页面不得再次按服务器或名称重排 `context.characters`。业务插件自己的条件只在此集合之上过滤业务行/数据，不能创建另一套服务器状态。

### 4.3 业务接入契约

业务插件注册页面时继续提供角色准入回调；范围条无须插件声明服务器列表：

```lua
HasCharacterSnapshot = function(character)
  return Addon:HasUsableSnapshot(character)
end,

header = {
  characterNameMode = "short", -- 或 "full"
}
```

Core 从准入结果中派生服务器按钮和 `context.characters`。若业务插件没有任何准入角色，Core 不显示空服务器条，页面显示该业务自己的空状态。

## 5. 子插件显示名使用规则

| 场景 | 默认模式 | 原因 |
| --- | --- | --- |
| 矩阵角色表头 | `short` | 保持等宽窄列，提高同屏角色数 |
| 角色目录、排序、短名设置 | `full` | 身份管理不能依赖玩家昵称 |
| 详情页、tooltip、删除确认 | `full` + 服务器 | 必须可精确识别角色 |
| 普通角色列表 | 由插件声明，默认 `full` | 列宽允许时优先保留真实身份 |
| 紧凑账号预览 | `short`，tooltip 补全 `full` + 服务器 | 兼顾空间与可辨性 |

使用短名的表头和紧凑列表都必须提供 tooltip：真实角色名、服务器、职业、等级及短名（若已设置）。短名不是角色身份的替代物。

## 6. YiboReputation 落地

### 6.1 页面结构

声望总览的顶部顺序固定为：

```text
Core 服务器范围条
声望搜索 | 全部 | 未满 | 已监控 | 全部折叠
固定角色表头（短名优先）
声望树矩阵
```

- 服务器条完全由 Core 生成；`YiboReputation` 删除任何自建服务器范围和持久化逻辑。
- 搜索、`全部 / 未满 / 已监控`、折叠属于声望业务工具栏，仍保留在服务器条下方。
- 先由 Core 按服务器筛选角色，再由声望页面按业务条件决定可见声望行。

### 6.2 窄列与单元格

- 每个角色列等宽，目标为 44–52 UI 单位；不得为完整角色名或某一个数值临时扩张。
- 角色表头采用 `characterNameMode = "short"`；未设置短名时可裁切**绘制结果**并以 tooltip 补足身份，但不得把裁切文本保存成短名或当成消歧方案。
- 正文与表头字号提升到可稳定辨读的等级，行高同步增加；密度通过更短内容而非缩小字体获得。
- 正常声望单元格只显示精确当前值，如 `12345` 或 `5900`，不使用 `5.9k`；文字着色沿用声望色。
- `—` 表示不适用/不可用；`?` 表示需要重扫。两者必须有 tooltip 说明具体原因。
- 崇拜即表示满值，不再添加“已满”符号或额外等级简称。
- tooltip 显示完整等级、精确分子/分母、特殊声望说明、数据状态与更新时间，例如“崇敬 12345 / 21000”。

### 6.3 溢出回退

当 Core 已采用短名、最小安全列宽后，仍无法在安全宽度内显示当前范围角色：

1. 首选保持声望名称列与角色表头固定，并只让角色状态区横向滚动；
2. 在极窄屏或角色数异常多时，启用 Core 提供的角色列分页；
3. 分页不改变 Core 的服务器范围、角色排序或 tooltip 身份信息。

常规显示不主动分页，也不因角色名长短改变列宽。

## 7. 非目标与禁止项

- 不向业务插件暴露可各自绘制的服务器按钮 API。
- 不为每个业务插件各存一份服务器选择。
- 不自动从角色名截取前 N 个字作为短名。
- 不用 `5.9k` 等数值缩写换取列宽。
- 不用纯颜色热力图、等级单字或“已满”标记替代声望数值。
- 不将短名写回业务插件 SavedVariables、业务缓存键或排序键。
- 不改变 Broker 右键入口设置和左键打开业务页的既有统一语义。

## 8. 实施顺序

1. **Core 数据与 API**：新增短名存储、迁移、读取/写入接口与重复检测。
2. **Core 设置**：在“角色与排序”实现短名管理页，完成校验与身份提示。
3. **Core 范围条**：从业务准入角色动态生成服务器按钮；实现全局选择状态、过滤顺序和页面刷新。
4. **Core 预览同步**：使同一业务的 Broker/小地图预览复用已选服务器范围与 `context.characters`。
5. **Core 列工具**：提供统一表头的 `full`/`short` 名称模式，以及窄屏角色列滚动/分页基础能力。
6. **YiboReputation**：接入短名表头与 Core 范围条；重排工具栏；调整精确数值、`—`、`?` 和详情 tooltip；提高字号与行高。
7. **其它业务插件**：删除重复服务器范围控件/状态，改为声明角色准入和显示名模式。
8. **验收与迁移**：验证跨服务器、无短名、重复短名、无业务快照、窄屏及入口预览的一致性。

## 9. 验收标准

- [ ] Core 设置页可为任意缓存角色设置、修改和清除短名；真实名称和服务器未改变。
- [ ] 没有短名时，短名优先接口回退完整名，不产生自动截断或错误消歧。
- [ ] 重复短名被清楚提示，且 tooltip 仍可精确区分完整角色身份。
- [ ] 所有 Core 业务页面的服务器范围条位置、按钮顺序、选中态和“所有服务器”语义一致。
- [ ] 某服务器没有某业务插件的准入角色时，该业务页面不显示该服务器按钮。
- [ ] 切换服务器后，主页面和同业务 Broker/小地图预览使用相同角色范围和排序。
- [ ] 子插件没有独立保存服务器清单、选择状态或复制服务器按钮。
- [ ] 声望总览角色表头优先显示短名，列宽不随角色真实名称长度跳动。
- [ ] 声望数值保持精确显示，不出现 `k` 缩写、等级简称或额外“已满”符号。
- [ ] 声望 tooltip 能解释 `—`、`?` 和完整“等级 + 当前值 / 上限”详情。
