# Core 内置 LDB 与信息条实施方案

> 日期：2026-10-02。  
> 状态：方案文档已完成，功能尚未实施。  
> 已确认方向：Core 内置 LDB，提供由用户控制开启的 Yibo 信息条；小地图、外部 Broker、内置条支持自由组合；信息条总开关控制各入口的内置条设置。  
> 本文的具体布局、接口名称与第一版外观属于实施建议，尚未通过游戏内验收。

## 1. 目标与范围

Core 统一管理三处入口：小地图按钮、供 Bazooka 等展示插件使用的外部 Broker 数据源、Core 自带信息条。业务插件只注册一次入口，提供图标、目标页面和业务预览；Core 负责展示、交互、配置和生命周期。

第一版信息条只展示 YiboCore 与已注册的 Yibo 业务入口。沿用 Core 主题和现有悬停预览，不增加业务数据缓存或摘要排版。

内置 LDB 始终加载；信息条默认关闭。是否开启信息条由用户明确选择，与是否安装外部展示插件无关。

## 2. 当前代码基线

| 位置 | 当前行为 | 改造重点 |
|---|---|---|
| `UI/Entry.lua` | 四状态 `none / broker / minimap / both`；同时管理小地图与 Broker | 改为三项独立选择，抽出共用交互与预览生命周期 |
| `Data/Database.lua` | Core 默认两者显示，业务入口保存于 `pageModes` | 新增规范化入口配置与信息条总设置 |
| `Data/Migrations.lua` | 当前迁移注册至版本 10，包括 Core 四状态迁移 | 实施时在最新迁移版本之后新增迁移 |
| `UI/AccountView.lua` | 自行归一化 Core 四状态与旧入口字段 | 调用统一配置读取接口，避免多处初始化覆盖 |
| `UI/AccountPages/SettingsWorkbench.lua` | 单选入口位置；部分控件直接写 `pageModes` | 三处独立选择、总开关联动、统一通过 Entry API 保存 |
| `YiboCore.toc` | 可选依赖外部 `LibDataBroker-1.1`，未内置库 | 添加库文件、加载顺序与信息条模块 |

当前 Broker 关闭逻辑会让已注册数据源停止响应，但无法保证外部展示插件立即隐藏图标。Core Broker 从初始关闭切换为开启时，也需补齐即时创建路径。

## 3. 两层控制模型

### 3.1 信息条总开关

`bar.enabled` 决定整条是否启用。关闭后：

- 立即隐藏信息条及其按钮，关闭由该条触发的预览，停止相关临时拖动和观察逻辑。
- 保留 Core 与所有业务入口的内置条选择、位置和外观设置。
- 设置表中的全部“内置条”勾选控件禁用，但保留勾选状态可见；说明文字为“启用内置信息条后可调整”。
- 信息条外观、锁定及位置操作禁用，总开关始终可操作。
- 小地图、外部 Broker、账号页面显示、业务设置和悬停字段设置仍可正常调整。

开启后恢复这些控件，并按已保存的每个入口选择重建展示。不得通过关闭总开关批量清空选择，也不得通过勾选业务入口自动开启总开关。

### 3.2 每个入口的三处选择

Core 与每个已注册业务入口分别保存 `minimap / broker / builtinBar` 三个布尔值，支持全部八种组合。

| 总开关 | 该入口 builtinBar | 内置条实际展示 | 该入口控件 |
|---|---|---|---|
| 关闭 | 关闭 | 不展示 | 未勾选、禁用 |
| 关闭 | 开启 | 不展示，保留选择 | 已勾选、禁用 |
| 开启 | 关闭 | 不展示 | 未勾选、可操作 |
| 开启 | 开启 | 满足入口有效条件时展示 | 已勾选、可操作 |

入口有效条件包括：已注册、未注销、目标页面可解析且满足现有页面可用规则。配置意图与运行时实际展示分开保存；插件暂未加载或目标页不可用时，不清除用户选择。

有效展示判定为：`bar.enabled AND channels.builtinBar AND entryAvailable`。小地图和外部 Broker 的有效性不受 `bar.enabled` 影响。

### 3.3 账号页显示与入口

账号页显示和入口配置分别保存。切换账号页显示不得隐式改写入口选择。实施前核对现有页面启用、目标页解析和点击规则，确保实际显示的入口可打开有效目标；页面不可用时隐藏内置条按钮并保留其配置。

仅有字段设置、没有独立入口的页面（例如角色档案）继续只显示适用控件，三处入口位置显示“—”。

## 4. 设置工作台

所有设置放在 `Core 常规设置 → 显示与入口`，保留固定导航与业务插件技术名字母序。

页面顺序建议为：通用悬停选项、信息条启用与外观、Core 与业务页面入口表。

### 4.1 总开关与信息条设置

首先提供“启用内置信息条”开关，并显示启用状态及已选择入口数。外观设置使用紧凑两栏，可折叠：锁定位置、重置位置、图标大小、图标间距、显示名称。

总开关开启但没有选中可用入口时，不显示空白条。设置页提示“尚未选择入口，请在下表勾选内置条”。不自动选中全部业务插件。

### 4.2 入口表

移除重复的“独立入口”说明列，将原入口位置单选下拉改为三项勾选：

| 页面 | 账号页显示 | 小地图 | 外部 Broker | 内置条 | 页面选项 | 主表字段 | 悬停字段 |
|---|---|---|---|---|---|---|---|
| Core | — | 可选 | 可选 | 受总开关控制 | 悬停页面 | — | — |
| 业务页面 | 可选 | 可选 | 可选 | 受总开关控制 | 适用的布局选项 | 适用字段 | 适用字段 |

“主窗口打开时仍显示悬停”移至通用悬停选项，避免 Core 行与业务行的“显示”列含义不同。

禁用态同时使用控件灰显和说明，不能只降低文字透明度；即使禁用也能看清原来是否勾选。切换总开关后即时刷新所有相关控件，不更改表格位置、行顺序或玩家当前查看位置。

宽屏使用上述直接勾选列；窄屏按可用宽度将入口三项作为完整语义组放到该行第二行，字段控件也按组换行。不得出现横向滚动、裁切或标签与控件分离。

## 5. 信息条呈现与交互

- 一个可移动、可锁定的紧凑横向条，使用 Core 现有主题、图标资产和字体规则。
- Core 在首位，业务入口按插件技术名字母序排列；同插件有多个入口时使用稳定的入口 ID 次序。
- 第一版默认图标模式，可开启名称；首版建议图标 24px、间距 6px，作为可调参数，实际尺寸需原生与 NDui 环境验收。
- 默认位置在屏幕安全范围内；解锁后通过独立拖动把手移动，避免业务图标点击与拖动冲突。保存锚点和偏移。
- 按实际内容计算宽度，到屏幕安全边界后自动换行；不裁切入口或依赖水平滚动。极端入口数量超过安全高度时使用分页，分页只影响入口按钮。
- 分辨率、UI 缩放改变及重载后重新限制位置和尺寸，保证把手、图标与设置操作可达。
- 左键打开对应业务页面；Core 左键打开统一账号框架。右键统一打开 Core 的显示与入口设置，可定位对应入口行。
- 悬停复用现有账号快照、角色准入、预览列和窗口。支持由图标移入可交互预览、延迟关闭以及快速切换不同入口。
- 同时展示小地图、外部 Broker、内置条时，仍只维护一个当前预览所有者；关闭信息条只关闭由信息条拥有的预览，不误关另两处刚触发的预览。
- 第一版不新增每图标 OnUpdate 数据扫描；按钮刷新由入口注册、注销、配置和必要尺寸事件驱动。

## 6. 架构与接口

### 6.1 内置库

加入上游 LibStub、CallbackHandler-1.0、LibDataBroker-1.1，在入口模块之前按依赖顺序加载。通过 LibStub 的版本注册机制与其他插件共存，不覆盖已加载的较新库。保留授权与上游来源，发行打包验证库文件齐全。

LDB 提供数据源，外部展示插件提供信息条。Core 内置条直接消费 Core 入口注册表，独立于外部 Broker 数据源是否注册或停用；仅选择内置条时不得被迫向外部展示插件发布入口。

上游参考：https://github.com/tekkub/libdatabroker-1-1

### 6.2 统一入口服务

建议新增以下接口（名称以实施时统一接口审查为准）：

| 接口 | 职责 |
|---|---|
| `GetEntryChannels(entryID)` | 返回三处选择，统一解析 Core 与业务入口 |
| `SetEntryChannel(entryID, channel, enabled)` | 校验、保存并更新对应展示与设置状态 |
| `GetBuiltinBarSettings()` | 读取总开关、位置及外观 |
| `SetBuiltinBarEnabled(enabled)` | 更新总开关和运行状态，保留入口选择 |
| `GetEntryAvailability(entryID)` | 判断目标可用性，区分保存选择与有效展示 |
| `HandleEntryClick(entryID, mouseButton)` | 统一左键、右键目标 |
| `ShowEntryPreview(entryID, anchor, source)` | 统一悬停并标记来源与所有者 |
| `GetBuiltinBarEntries()` | 获取有效且选中内置条的稳定排序列表 |

设置页不直接写 SavedVariables。三处展示使用相同的目标页面解析、点击行为和预览逻辑。`EntryBar` 负责布局与按钮，不解释业务状态。

业务插件继续通过现有 `RegisterBusinessEntry` 接入。保留现有 `defaultMode` 和 `legacyIDs` 的注册兼容语义，在 Core 内转换为规范配置；如果提供新的 `defaultChannels`，明确它仅作为尚未保存选择的默认值，并进行校验。旧调用方搜索完成后再决定是否提高 Core API 或新增能力版本。

### 6.3 生命周期

注册或恢复入口时更新三个展示；注销时隐藏小地图和内置条按钮，使外部 Broker 停止交互并清理该入口拥有的预览。总开关关闭时内置条不创建新的可见按钮，注册数据和用户选择仍保留。

Core Broker 与业务 Broker 的创建、恢复、停用必须走一致路径，补齐登录时未注册、之后即时开启的场景。

LDB 不提供标准数据源注销接口。关闭已注册的外部 Broker 时立即停止回调，但外部条是否隐藏由其自身决定；设置页需说明可能要在外部条隐藏或重载。下次重载只注册选中的外部入口。不得破坏 LDB 内部表以模拟删除。

## 7. 配置结构与迁移

建议保存于 `YiboCoreDB.settings.accountView.entry`：

```lua
{
    channelsVersion = 1,
    coreChannels = { minimap = true, broker = true, builtinBar = false },
    businessChannels = {
        -- [entryID] = { minimap = false, broker = true, builtinBar = false },
    },
    bar = {
        enabled = false,
        locked = true,
        point = "TOP", relativePoint = "TOP", x = 0, y = -16,
        iconSize = 24, spacing = 6, showNames = false,
    },
    -- 保留现有小地图角度、业务位置、Core 悬停页和通用悬停偏好。
}
```

迁移映射：

| 旧模式 | minimap | broker | builtinBar |
|---|---|---|---|
| none | false | false | false |
| broker | false | true | false |
| minimap | true | false | false |
| both | true | true | false |

- 升级保留现有两处入口选择，信息条总开关与全部新增选择为关闭。
- 新安装仍默认只显示 Core 的小地图与外部 Broker；业务入口依注册默认值，内置条默认关闭。
- 一次性迁移旧 `coreMode`、`pageModes` 与旧别名；保留角度、位置和悬停配置。
- 新配置已存在时优先读取新配置，不允许旧归一化代码或默认值重新覆盖显式 false。
- 迁移须先区分字段缺失与用户关闭。注意数据库默认值在迁移前应用，不能提前填充新 channels 而使旧选择失去迁移机会。
- 尚未加载插件的旧入口配置也迁移或保留待注册解析，不只遍历当前已注册入口。
- 旧字段作为迁移来源保留，运行时只有新结构作为配置真值；本方案不承诺旧版本回退会识别第三处入口。
- 迁移重复执行不改变结果。参数异常进行有界归一化，位置始终钳制到安全屏幕范围。

## 8. 文件级实施顺序

1. 搜索所有四状态读写与入口调用方，加入库、规范配置和一次性迁移；核对默认值应用顺序。
2. 改造 `Entry.lua` 共用交互、有效性与生命周期，补齐即时 Broker 创建；替换 `AccountView.lua` 重复归一化。
3. 新增 `UI/EntryBar.lua`，完成总开关、稳定排序、布局、拖动、预览所有者和屏幕约束。
4. 改造设置工作台，完成总开关对每个内置条控件的联动，以及窄屏语义组布局。
5. 更新 TOC、README、入口 API 文档与发布测试清单。同步修订项目入口规范，使其明确包含三处入口和两层控制。
6. 完成下面的测试后再确定发布版本；业务插件仅在接口审查发现调用不兼容时做必要修改。

## 9. 验收要求

### 配置与迁移

- 四种旧模式正确迁移；缺失字段、旧别名、未加载业务插件、显式 false 与重复迁移均保持选择正确。
- Core 与至少两个业务入口验证全部八种组合；三处互不强制开启或关闭。
- 总开关关闭时，所有内置条控件禁用且原勾选可见；重新开启后原选择与条布局恢复。
- 关闭总开关后仍能调整小地图、外部 Broker、账号页及业务设置。
- 关闭期间的业务注册、注销、重载不会自动打开信息条或丢失选择。

### 入口与预览

- 仅内置条时，未选择外部 Broker 的对象不被注册；仅外部 Broker 时不显示内置按钮。
- Core 与业务入口从初始关闭切换开启后即时生效；外部对象停用限制有准确说明。
- 同时启用三处入口，左键目标、角色筛选、字段、状态与行动数据一致。
- 图标间快速悬停、移入预览、移出关闭、主窗口打开时悬停符合现有设置。
- 信息条关闭、入口移除、页面不可用时无悬挂预览；不会误关其他入口拥有的预览。
- 页面显示开关与入口配置保持独立，实际显示按钮的点击目标始终有效。

### 布局与环境

- 原生环境与 NDui 环境分别验证字体、透明图标、层级、点击区域、战斗中的开关和拖动。
- 不装外部信息条也能显示内置条；与 Bazooka 同时使用时分别遵循各自选择。
- 与其他插件加载的 LibStub、CallbackHandler、LDB 共存且不重复创建同名对象。
- 零入口、一个入口、全部现有入口、长名称与屏幕安全边界下布局可用。
- 设置窄屏无横向滚动和裁切；总开关切换不改变导航、表格顺序或查看位置。
- UI 缩放、分辨率变化与重载后信息条位置可达，位置、锁定和外观设置保存正确。
- 打包包含全部库、授权与模块；没有新增逐图标业务轮询或重复扫描。

## 10. 完成标准

用户能够先决定是否启用整条，再为 Core 和每个业务入口独立选择三处展示。关闭整条会暂时禁用内置条相关设置并保留选择。三处入口共用既有业务预览与目标解析，且升级不改变原有小地图和外部 Broker 配置。
