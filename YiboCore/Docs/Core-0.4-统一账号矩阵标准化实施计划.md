# Core 0.4 统一账号矩阵标准化实施计划

## 阶段 1：Core token 与共享构件

1. 更新 `UI/Theme.lua` 的字号、表格行高、矩阵边距与 16px 滚动沟槽 token。
2. 增加 Core 角色行头布局/测量接口，统一四字名、16px 职业图标与保护间距。
3. 更新 `CreateMatrixHeader`、`SetMatrixHeader`、`SetCharacterHeader`：普通表头 muted，角色名职业色，服务器元数据 muted。
4. 将当前角色列框创建、锚定与可见 viewport 裁切封装为 Core API，删除角标语义。
5. 让 `CreateScrollFrame` 以 16px 沟槽容纳居中的 14px 滑轨，并确保真实溢出前后不压缩数据列。

## 阶段 2：AccountView 尺寸与分页

1. 更新页面度量与安全宽度计算，使用新行高、边距、沟槽和角色列宽。
2. 将“当前角色页定位”纳入首次展示与结构变化流程；保留用户手动页码直到下一次结构变化。
3. 保证统一分页器位于数据表头右侧，固定列/表头与数据使用同一列度量。
4. 为角色为列/多字段矩阵提供共享偶数列底纹入口；分组行不参与行奇偶计数。

## 阶段 3：业务页面迁移

按 `YiboAltoBoss`、`YiboQuestBlocker`、`YiboCurrency`、`YiboReputation`、`YiboTodo`、`YiboLegendary` 的顺序迁移。每页完成后删除本地几何常量、当前角色框锚定、滚动条沟槽、分页控件、表头色和重复底纹，只保留业务列定义与数据渲染。

## 阶段 4：验证与文档闭环

1. 为 Core 共享算法补充 Lua 级测试：列宽、当前角色页定位、溢出阈值、沟槽释放和边界裁切。
2. 对每个页面及其 Broker/小地图预览执行权威验收清单 H。
3. 在 1280×720、1600×900、1920×1080、2560×1440 与超宽屏进行截图核验。
4. 重新运行 Lua 语法检查和既有业务 smoke tests；所有受影响页面零 Lua 错误后才进入发布清单。

## 完成标准

- 所有矩阵视觉与几何均由 Core token/API 产生，业务插件无私有补偿实现。
- 主窗口、Broker 预览、小地图预览在同一数据下角色准入、顺序、字段、状态、分页和当前角色标识一致。
- 无真实溢出时没有滚动条或空沟槽；有真实溢出时最后一列不被压缩。
