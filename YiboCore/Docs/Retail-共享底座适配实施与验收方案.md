## 1. 已确认范围与完成边界

- 本次审查全部共享底座，不仅审查 YBP 当前调用链；适用的多端共用逻辑本次完成适配，避免不同目标维护平行实现。
- 客户端差异集中在目标适配层，共享实现消费稳定契约。正式服专属能力只实现 YBP 首期所需内容；专业、装备、专精、日历等其它正式服目标能力暂不实现。
- “共享实现完成”与“目标能力可用”分别登记；不能因为 Lua 可加载或 API 名称存在就声明该目标提供能力。纯通用能力应统一实现并验证；依赖目标采集器的能力由目标实际实现决定。
- 共享改动回归 Mists、Forever，保持既有公开契约、各目标存档身份及已支持行为。不得为精简 Retail 删除其它目标正在使用的能力。
- 本轮不实现 YBP 宠物采集、存档、业务页面或路线拥有判断，不提高 YBP 现有依赖要求。用非发布消费者夹具验证 Core 接入契约，真实 YBP 集成验收留给业务阶段。

本轮完成条件：共享模块清单逐项审查完毕，适用改造与目标隔离完成，Retail 所需公共能力可用且通过对应验证，受影响旧目标完成回归，必要安装与恢复证据齐全。代码完成、离线通过、客户端通过、可发布、已发布分别记录。

## 3. 共享底座全量审查清单

实施时按当前两份真实目标 TOC 的并集、XML／间接引用及公开调用方建立逐文件清单；同时核对未直接进入当前清单的公共模块。每项记录共享职责、目标依赖、消费者、适配结果和验证，不能只抽查首个消费者。

| 职责单元 | 现有主要位置 | 必须完成的审查与适配 |
| --- | --- | --- |
| 启动、就绪、事件 | `Bootstrap.lua`、`Runtime/Events.lua`、目标入口 | 产品校验先于写库及对外业务注册；事件按目标支持情况注册；重复初始化与晚就绪不重复生效；失败不发布成功就绪 |
| 能力、插件注册、连接 | `Runtime/Capabilities.lua`、`Registry.lua`、`Contracts.lua` | 保持契约兼容，区分能力注册与业务就绪；版本、冲突、晚注册、注销及失败语义一致 |
| 存档与迁移 | `Data/Database.lua`、`Migrations.lua`、`DomainStore.lua`、`Util/Defaults.lua` | 目标身份与存档一致；异常／超前 schema 停止；保留各目标已有数据和迁移路径 |
| 角色与范围 | `Data/Characters.lua`、`CharacterCleanup.lua`、`Util/CharacterSort.lua`、`LevelFilter.lua` | GUID、跨服务器同名、轻量快照隔离、短名、隐藏／排序、范围与清理所有者；Core 目录不限定猎人 |
| 数据域与兼容门面 | `Runtime/DataDomains.lua`、`Data/Profile.lua`、`Data/Domains/`、`Data/Fields/` | 分离通用分发／状态／字段机制和目标采集；不支持域不注册、不投影假值；保留已支持目标兼容形状 |
| 公共资源与输入 | `Runtime/Resources.lua`、`ItemResolver.lua`、`UI/Theme.lua`、`Input.lua`、各 Picker／确认与业务操作组件 | 分清通用控件与目标原生 API；通用部分统一验证，目标特有解析／操作仅按实际需要接入，不空报能力 |
| 账号页、字段、布局 | `UI/AccountView.lua`、`Runtime/Fields.lua`、`ArchiveFields.lua`、`UI/AccountPages/` | 页面生命周期、角色准入、自然宽度／安全边界、统一分页／滚动、无数据与动态字段；通用机制不含宠物判断 |
| 设置与玩家入口 | `Runtime/SettingsRegistry.lua`、`EntryConfig.lua`、`Commands.lua`、`UI/Entry.lua`、`EntryBar.lua`、设置工作台 | 单一窗口壳、固定导航、技术名字母序、三通道八组合、幂等注册及注销、位置恢复、无横向滚动 |
| 语言、目录与状态 | `Runtime/Locale.lua`、`Locales/`、`Data/AddonCatalog.lua`、`Runtime/AddonStatus.lua` | owner 语言资源、格式参数一致、动态名称原文；目录目标过滤，不将安装／启用误报为业务可用 |
| 库、媒体、构建引用 | `Libs/`、实际资源引用、TOC／XML、`Tools/ReleaseProfiles.psd1` | 核对依赖与目标支持；迁移后引用闭合、资源完整、旧文件覆盖只执行适用链 |

共享稳定逻辑不复制到三个目标目录；新增归档按需进入 `Common/`，既有清晰共享路径可保留。客户端专用 API、事件、规则与目录归入 `Mists/`、`Forever/`、`Retail/`；迁移以完整职责单元为边界，先保持行为验证，再调整功能。

能力矩阵至少分别记录：共享实现是否完成、三个目标是否实现／验证、接口最低版本、消费者和证据。所有共享单元必须有结论；正式服暂缓项要记录具体目标依赖和原因，不能成为遗漏共享逻辑的占位项。

## 4. Retail 加载、存档与初始化设计

遵守[目标与发行标识规范第 2.1 节](../../Docs/多版本目标与发行标识规范.md)及[多版本开发规则](../../Docs/多版本开发规则.md)。

- 源清单采用已实测识别的唯一 `YiboCore_Mainline.toc`；源码默认 TOC 继续 Hint。单目标安装包把所选 Retail 清单输出为 `YiboCore/YiboCore.toc`，只包含本目标必需文件。
- 目标策略拟集中于 `Retail/Target.lua`。实际产品常量、Interface、后缀识别和清单优先级在正式服采证后登记；不直接照抄 YBP 旧 Mainline 清单的 Interface。
- `YiboCore` 技术名、安装目录保持稳定。Retail 为新目标，独立表名拟采用 `YiboCoreRetailDB`，实施时核对历史兼容情况并固定；不读取、复制或迁移 Mists／Forever 表。WTF 文件名仍随插件技术名为 `YiboCore.lua`。
- 新目标以真实 GUID 关联角色；GUID 未就绪时等待，不能用名字或服务器短名替代身份。账号范围是本客户端本地已观察目录，不承诺跨账号同步。
- 写库、迁移、采集与业务注册前验证实际目标及存档目标戳；共享 Mists 默认策略也须明确核对，不能仅排除 Forever 后就将其它客户端视为 Mists。
- 审查 `Core:Initialize()` 的重复调用与失败处理，确保就绪发布发生在必要初始化成功后。重复加载／事件／就绪通知不重复注册页面、入口、订阅或消费者。
- 目标版本独立维护；API13 是现有契约基线，不代表新的目标已通过兼容验证。最终 Retail 版本、最低 Core API／能力、是否新增契约在实现审查后明确，不能由目标名或版本号推算。

## 5. 面向后续 YBP 的公共支持契约

优先验证既有接口；以下为需求映射，不是新增 API 声明，也不是 YBP 已接入记录。

| 需求 | 已有公开契约候选 | 本轮 Core 验证 |
| --- | --- | --- |
| 当前角色与跨服目录 | `characters:1`、`character-identity:1`；`Characters:GetCurrent/Get/GetAll({identityOnly=true})` | GUID 晚到、同名不同服、只读身份投影与复制隔离、目录恢复 |
| 名称与统一角色管理 | `character-name-format:1`、`character-cleanup:2`；公开格式化及清理所有者接口 | 显示名不作身份；排序／隐藏／短名一致；消费者只清理自己拥有的数据 |
| 窗口与准入 | `account-view:2`、`account-character-admission:1`、`account-surface-budget:2` | 由消费者按“猎人且有兽栏快照”提供业务准入，Core 不存宠物过滤规则；跨服务器集合可展示 |
| 入口与预览 | `account-entry:2`、`builtin-entry-bar:3`、`account-preview-characters:1` | Core 创建与注销三通道入口，左右键语义一致；消费者提供同源业务快照与预览 |
| 设置、输入与语言 | 现有设置注册接口、`basic-input:1`、`localization:1` | 统一工作台、owner 资源、语言切换后重载、输入焦点与隐藏清理；无控件需求时不强加输入依赖 |
| 就绪与变化通知 | `Core:IsInitialized()`、`Core:CheckAPIVersion()`、能力检查、`CORE_READY` 与公开事件 | 缺失／旧版／缺能力停止依赖功能；晚就绪、重复通知、注销与清理 |

实施时将实际方法和最低版本固定到接口记录；候选能力不机械全部变成 YBP 强制要求。现有公共接口不足时，仅扩展有真实需求的通用契约，并同步接口文档与 CAP 台账。

Core 不建立宠物数据域、不读取 YBP SavedVariables、不保存宠物快照，也不判断宠物来源、颜色或是否拥有。业务阶段由 YBP 保存以 Core 角色 ID 关联的快照；没有兽栏快照的猎人不展示。Core 目录中没有对应业务快照，不能推断角色未拥有宠物。

YBP 后续继续采用可选依赖：路线独立运行，兽栏须检查 Core 就绪及最低 API／能力，缺失或版本不足时明确提示，不创建本地替代窗口。既有基础路线独立语言兼容例外按 YBP 文档保留；兽栏使用 Core 会话语言。此边界实施时须同时核对仓库依赖规范并明确登记可选增强适用范围，不将整插件改为强依赖。

本轮非发布消费者夹具仅验证注册、晚就绪、角色准入、布局及清理契约，不持久化真实宠物数据。真实兽栏采集与时效规则由 YBP 阶段验收；没有跨业务消费需求时不增加宠物 Service／Provider。
