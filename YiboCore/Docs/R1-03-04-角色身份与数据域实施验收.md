## 身份边界与兼容性

- `Core.Client` 是Core内部边界，不是业务Service或新增公开能力；业务插件继续使用Characters等已有公开契约，不直接绑定Client实现。
- 内部 `ReadGUID` 返回GUID／状态；`ReadNameRealm` 返回显示名与服务器；`ReadCharacter` 返回原生GUID、名称、服务器、职业token、等级及观察时间；`ReadIdentity`、`ReadLocation` 返回对应域数据／状态。读取失败返回nil及非known状态，不创建猜测值。
- Mists允许会话首次真实GUID出现前使用既有legacy身份；真实GUID出现后，临时丢失GUID不再新建fallback行。只将legacy身份提升为GUID，已有真实GUID不会因为同名同服而替换为另一个GUID。Forever继续等待真实GUID，不建立名字别名或导入旧角色。
- 原生姓名、职业、等级或时间不可读时，原角色记录、lastSeenAt和已有快照保持不变，等待适用事件恢复；不填UNKNOWN职业／1级等临时事实。
- 读取保留多返回值和nil槽位；职业使用原生第二返回值token。identity v1的race／faction保留既有原生第一返回值形状，不改写历史文本，也不趁迁移将种族显示名批量变为技术token。
- 同名跨服、同名同服不同GUID保持独立；显示短名／服务器名称不作为角色身份键。轻量身份副本仍不复制无关domain，原缓存只读约定保持。
- AccountView仅将无当前角色时的服务器显示回退改为消费Client边界；其它UI原生差异继续留待R1-06。

## 数据域读取与失败语义

公开API仍为13，`data-domains:1`、`domain-store:1`等能力版本不变。本次修正失败路径，保留有效收集器调用与直接DomainStore提交的既有接口。

| Collect结果 | 分发行为 |
| --- | --- |
| table＋known，或table且省略state | 作为成功快照提交；空table明确表示已确认的空快照，可替换旧值 |
| nil／部分table＋unavailable、not-yet-scanned、error或stale | 只更新状态，保留上一份域数据；忽略此次部分数据及其changedKeys，不制造“字段被删除”通知 |
| nil／非table＋known | 视为error，保留旧值并显示Core中英文诊断；不能把没有快照解释成成功空表 |
| 非法state（包括false）或Collect抛错 | 视为error，保留旧值；仅nil state采用默认known |

DomainStore的nil保留与显式空table替换机制未变；修复的是分发层把nil变成空table，以及失败table被当新值提交的问题。直接调用DomainStore:Commit的现有显式数据语义没有改写。

旧档案投影仅在known时写入新值和observedAt；失败只更新availability，保留旧值／旧时间。特别覆盖了只有v4 profile、尚无domain记录的历史角色：第一次失败不会清掉profile，专业字段仍可展示旧值；随后成功确认空专业会清空，下一会话失败也不会让旧专业复活。

Domain.updatedAt继续表示数据／状态变更时间，revision在数据与状态均不变时不增加；它不是所有成功读取的独立采集时间。Forever专业已有data.observedAt语义保留。YBP未来仍须拥有自身随身／兽栏分组采集时间，不能拿此变更时间替代。

Mists专业首次空返回不当成卸除，缺名称／等级等部分读取不提交；两端均仅在SKILL_LINES_CHANGED等已声明完整条件下确认空专业。装备／专精／位置／身份的失败不会以空值覆写历史。

## 字段与事件契约

- 字段ID、主表／预览设置身份和格式保持稳定：Mists维持10个原有静态字段，Forever维持9个、不注册装等。旧专业槽位解释移到Mists配置，Forever仅依据权威skillLineID，不按Mists槽号猜测。
- 第二主专业的明确空槽不再从密集profession列表误取副专业；旧profile无primaryProfessions时，优先按记录slot解释，保留最早无slot快照的既有兼容读取。
- DataDomains的域版本、重复ID拒绝和owner契约保持；Lifecycle在启动时合并域事件，晚注册域／旧Profile收集器可订阅其原生事件。旧收集器false事件项继续有效但不订阅，非法事件容器在注册前拒绝。
- 角色身份由pending恢复时，只补采当前原生事件未处理的Core自有域，内部reason为character-ready；当前事件正常负责的域不重复采集，不重发CORE_READY，也不主动轮询其它owner的域。其它owner仍仅由其声明的原生事件触发。
- 不新增宠物域、业务Provider或Retail采集器。Mists仍无profession-profile能力标记，Forever仍有profession-profile:1；没有通过补标记消除目标契约差异。
