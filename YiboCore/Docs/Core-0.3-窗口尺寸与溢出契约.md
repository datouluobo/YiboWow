# YiboCore 0.3：窗口尺寸与溢出契约

> 状态：设计基线；本文件先定义跨页面共同规则，后续实现只能按本契约落地。
>
> 适用范围：YiboCore 的普通账号窗口、业务页面、Core 管理的 Broker / 小地图悬停预览。业务插件不得自行修改账号窗口壳的尺寸。

## 1. 目标

账号页应在切换时优先完整展示“当前可见且可操作”的内容，而不是维持无意义的大空白。窗口不能超过安全屏幕区域；达到上限后，只有实际溢出的数据区域可以滚动。工具条、列头、主要操作和页面导航始终可见。

本契约特别覆盖两类页面：

- **矩阵页**：Boss、任务屏蔽等；宽度主要随角色列增长，高度主要随业务行数增长。
- **列表/设置页**：角色档案、概览、设置等；高度主要随条目数增长，宽度通常固定。

## 2. 基本原则

1. **先测量、后布局。** 页面在已得出角色准入、可见字段、范围和筛选结果后，报告尺寸需求；Core 再决定窗口尺寸。不得由页面根据猜测的父级宽高反向堆叠布局。
2. **正常页完整优先。** 在安全屏幕上限内，普通账号窗口应采用页面的首选尺寸，避免因历史尺寸留下大块空白或不必要的滚动条。
3. **预览克制优先。** 悬停预览只显示正式页的字段投影，先限制至 20 名有效角色，再受独立预览上限约束；预览不得为了消除滚动而吞占游戏画面。
4. **不压缩语义。** 到达宽度上限后，不能通过缩小字体、挤压状态按钮或隐藏任务/角色名称来伪造“无滚动”；应改为数据区横向滚动。
5. **滚动局部化。** 水平滚动只属于矩阵数据区，垂直滚动只属于内容区。页面标题、筛选、表头、底部主操作和 Core 导航不得跟随滚动。
6. **用户优先。** 用户手动调整后的窗口尺寸是明确偏好；自动布局只能在不低于页面最低可用尺寸的前提下使用它，不能在每次刷新时强行重设。

## 3. 尺寸状态与切换规则

Core 保存一个普通窗口布局状态：

```lua
accountView.layout = {
    mode = "auto", -- auto / manual
    width = 1120,
    height = 650,
}
```

- `auto`（默认）：进入页面、切换页面、字段/范围/角色集合变化后，Core 按该页面的首选尺寸调整窗口。
- `manual`：用户拖动尺寸把手后进入。切换页面时保留用户尺寸；若它小于新页面的 `min`，仅增大到 `min`，不主动缩小。
- “重置窗口布局”恢复位置并把模式重设为 `auto`；设置页应显示当前模式及“恢复自动适配”动作。
- 业务数据频繁刷新（如任务日志事件）只允许在同一帧合并测量；**不得**在 `manual` 模式中改变普通窗口尺寸。
- 若自动尺寸因角色/字段变化而变小，Core 应只在页面稳定刷新后一次性收缩，不在鼠标悬停、编辑框输入或滚动期间收缩。

## 4. 页面尺寸报告契约

每个业务页可选实现：

```lua
GetLayoutMetrics = function(context)
    return {
        minWidth = 760,
        preferredWidth = 1120,
        minHeight = 430,
        preferredHeight = 520,
        horizontalOverflow = "matrix", -- none / matrix
        verticalOverflow = "content",  -- none / content
    }
end
```

约定如下：

- `minWidth` / `minHeight` 是保持关键控件可用的下限，不能以小字体或重叠计算。
- `preferredWidth` / `preferredHeight` 是当前数据无滚动（或仅保留设计上必要滚动）时的尺寸。
- 没有实现时，Core 使用当前默认尺寸 `1120 × 650` 和全局下限 `760 × 430`，保证旧页面兼容。
- 页面只报告内容需求，不包含 Core 左侧导航、顶部栏、边框和安全边距；Core 统一计入窗口壳开销。
- 矩阵页按“固定业务列 + 可见角色列 × 最小列宽”计算宽度；列表页按最长必要字段与固定控件计算宽度。
- 高度只计算当前页面实际呈现的行、工具条、分组、空状态和底部操作；禁止为可能出现的未来数据预留高度。

## 5. Core 尺寸计算

普通窗口的候选尺寸为：

```text
目标宽高 = 页面 preferred 尺寸 + Core 窗口壳开销
```

随后 Core 使用安全范围裁切：

```text
minWidth  = 760
minHeight = 430
maxWidth  = 屏幕宽度 - 32
maxHeight = 屏幕高度 - 80
```

`auto` 模式使用 `clamp(页面 preferred, min, max)`；`manual` 模式使用 `clamp(max(用户尺寸, 页面 min), min, max)`。

若显示器小于全局最低尺寸，屏幕安全上限优先；窗口缩至可见范围，页面按局部溢出规则承载其余内容。

当首选尺寸超过安全上限时：

1. 先固定 Core 窗口、页面工具条、表头和底部操作；
2. 为发生溢出的轴预留滚动条沟槽；
3. 仅让声明的 `matrix` 或 `content` 子区域滚动；
4. 表头必须和矩阵内容共享横向偏移，不能出现列头与单元格错位。

## 6. 悬停窗口尺寸与定位

悬停窗口是正式页面的只读投影，不是缩小版主窗口，也不得继承普通窗口的手动尺寸。它使用独立的尺寸状态，每次打开根据当前锚点、角色集合和预览字段重新测量。

业务页可选实现新的 `GetHoverMetrics(context)`：

```lua
GetHoverMetrics = function(context)
    return {
        minWidth = 420,
        preferredWidth = 900,
        minHeight = 150,
        preferredHeight = 320,
        horizontalOverflow = "matrix", -- none / matrix / content
        verticalOverflow = "content",  -- none / content
    }
end
```

未实现时，Core 兼容既有的 `GetPreviewSize(context)`；两者都没有时使用 `820 × 360` 的安全回退。

`GetHoverMetrics` 与兼容的 `GetPreviewSize` 返回的是**整个悬停 Frame**的尺寸，必须包含 Core 顶栏、页面表头、内容区和必要间距；不要只返回业务行的内容高度。普通页的 `GetLayoutMetrics` 则仍只报告页面内容尺寸，由 Core 另行加上窗口壳开销。

悬停窗口受以下硬规则约束：

- 预览角色数最多 20 名；先运行与正式页完全相同的角色准入和字段筛选。
- 每次打开按 `preferred` 测量，并裁切到 `min … 屏宽 - 32` 和 `min … 屏高 - 80`；极小分辨率时以屏幕安全范围为最终上限，绝不越界。
- 定位顺序固定为：锚点下方 → 锚点上方；若右侧越界则右对齐锚点。Core 负责这一策略，页面不得自行设置预览锚点。
- 超出悬停上限时，优先保留任务/目标和当前行动字段；页面不得在悬停中显示编辑、筛选、添加或放弃等操作控件。
- 若仍发生溢出，只允许悬停内容区滚动；矩阵表头必须与内容保持同一横向偏移。不得扩展到屏幕外，也不得遮挡锚点的交互区域。
- 同一锚点内容未改变时，宽高不得在鼠标移入/移出期间重算；业务数据变更只在下一次 `ShowPreview` 或合并刷新时生效，避免闪烁。

## 7. 页面实现规范

- 页面首次 `Refresh` 前不得读取不稳定的 `GetWidth()` 作为数据列数依据；列数来自 `context.characters` 和可见字段。
- 每个可滚动矩阵必须把列宽、表头 X 坐标和单元格 X 坐标复用同一套度量函数。
- 页面在内容为空时报告紧凑的空状态高度，而不是默认整窗高度。
- 页面不得直接调用 Core 窗口的 `SetSize`、修改 Core 保存的 `width/height`，或保存私有窗口尺寸。
- 添加、删除、筛选或范围变更后调用 `context:Refresh()`；Core 负责在刷新完成后安排一次尺寸测量。

## 8. 验收矩阵

每个接入页面至少验证：

|场景|期望|
|---|---|
|概览 → 列表 → 矩阵切换|自动模式按各页内容伸缩，无大块空白；导航与工具条稳定|
|2 名角色、8 行任务|任务页高度贴合内容，数据区无垂直滚动|
|15 名角色、8 行任务|角色列完整显示或仅矩阵横向滚动；表头与单元格严格对齐|
|矩阵行数超出屏幕|仅矩阵内容垂直滚动，筛选、列头和底部操作常驻|
|用户手动放大窗口后切页|窗口保持用户尺寸，不被自动缩回|
|用户手动缩小后进入宽矩阵|窗口至少恢复到最低可用尺寸；更宽部分由矩阵横向滚动承载|
|Broker / 小地图预览|不显示编辑控件；尺寸不越界；与正式页角色和字段一致|

## 9. 当前落地顺序

1. 在 Core `AccountView` 实现尺寸状态、测量调度、`GetLayoutMetrics` 回退值和局部溢出容器。
2. 先为 Boss 周常、任务屏蔽补齐页面度量函数和共享矩阵滚动偏移。
3. 再接入概览、角色档案、设置和传说之路；每完成一个页面执行第 8 节验收矩阵。
4. 所有业务页迁移前，不改变其业务数据、角色准入或预览字段归属。
