# Yibo 窗口、尺寸与响应式布局规范

> 状态：全系列权威尺寸基线。
>
> 适用范围：`YiboCore`、所有接入 Core 的业务插件、统一账号主窗口、统一设置工作台、Broker / 小地图账号悬停预览，以及 Yibo 自建的确认和编辑窗口。
>
> 关联文档：[Yibo UI 视觉系统与交互语义准则](./UI视觉系统与页面准则.md) 负责颜色、状态、控件和交互语义；本文件负责所有会影响几何测量、屏幕占用、分页和滚动的数字及规则。两份文件不得重复维护同一项数值。

## 1. 文档权威性与变更规则

1. 所有窗口尺寸、字号、行高、列宽、间距、锚点、分页、滚动阈值和安全区域规则，必须先存在于本文件中，再进入 Core token 和业务实现。
2. 修改任一尺寸约束时，必须同步修改本文件；不得只在单个插件中添加特殊处理。
3. 如果统一规则不能覆盖实际场景，应停止实现并重新讨论规则。确认后修改统一规范，不以业务插件永久例外绕过。
4. 兼容代码只能用于旧接口或旧数据迁移，必须有明确移除目标，不能形成第二套尺寸逻辑。
5. 本文件、Core token、页面度量接口、设置项和验收清单必须保持一致。
6. 业务插件不得直接设置统一窗口尺寸、保存私有窗口尺寸或复制 Core 的锚点、分页和滚动实现。

## 2. 设计目标

1. **100% 正常显示。** 所有窗口首先在 100% 显示比例下完成设计和验收，不依赖缩放修复布局。
2. **完整展示优先。** 正常数据量下优先一页完整显示，不出现横向或纵向滚动。
3. **左上角稳定。** 主窗口切页时尽量保持左上角不变，只改变右边缘和下边缘。
4. **不压缩语义。** 不通过缩小字体、挤压状态、裁掉身份或隐藏用户已启用字段伪造“完整显示”。
5. **分页优于横向滚动。** 宽度不足时先优化布局和列分页，横向滚动仅为最后兜底。
6. **滚动局部化。** 必须滚动时，只允许实际溢出的数据区滚动；标题、工具栏、表头、固定身份区和底部主要操作保持可见。
7. **预览复用主表。** 账号悬停预览复用主窗口的数据、准入、字段格式和状态判断，只改变投影字段与可用视口。

## 3. 单位、尺寸组成与度量口径

### 3.1 统一单位

- 所有尺寸使用 WoW UI 逻辑单位。
- 屏幕可用尺寸统一读取 `UIParent:GetWidth()` 和 `UIParent:GetHeight()`。
- 不得把 `GetScreenWidth()` / `GetScreenHeight()` 返回的物理像素与 Frame 逻辑尺寸混算。
- 所有文字宽度必须在字体、字号和 UI 缩放已经确定后，使用客户端实际字体测量。

### 3.2 窗口组成

```text
窗口尺寸 = Core 固定壳 + 页面固定区 + 数据视口
```

- **Core 固定壳**：外框、标题栏、导航、通用边距。
- **页面固定区**：页面说明、范围切换、筛选工具栏、表头、底部操作区。
- **数据视口**：真实业务行和业务列，可在必要时分页或滚动。

### 3.3 三种尺寸

每个页面必须区分：

- `minimum`：关键控件仍可正常使用的最小尺寸。
- `natural`：当前真实内容完整显示所需尺寸。
- `maximum`：当前窗口类型和安全屏幕区域允许的最大尺寸。

`natural` 只计算当前可见字段、角色、行、工具栏和空状态；禁止为未来可能出现的数据预留空白。

### 3.4 统一报告口径

- 主窗口和悬停预览都只报告**页面内容尺寸**。
- Core 根据表面类型添加主窗口壳、悬停壳或设置工作台壳。
- 业务插件不得使用 `+178`、`+47`、`+110`、`+160`、`+230` 等经验常数估算 Core 壳。
- Core 固定壳应由真实锚点和共享 token 测量。

建议统一接口：

```lua
GetSurfaceMetrics = function(context)
    return {
        minContentWidth = 582,
        naturalContentWidth = 942,
        minContentHeight = 150,
        naturalContentHeight = 383,
        fixedLeftWidth = 250,
        fixedTopHeight = 74,
        horizontalOverflow = "paginate", -- none / paginate / content / matrix
        verticalOverflow = "content",    -- none / content
    }
end
```

- `fixedLeftWidth` 声明列分页或最终横向滚动时不可移动的身份/任务区。
- `fixedTopHeight` 声明纵向滚动时不可移动的工具栏和表头区。
- `GetPreviewSize`、旧 `GetHoverMetrics` 和依赖显示后回测的 `GetMeasuredHeight` 只作为迁移接口；普通表格和矩阵迁移完成后不得继续维护两套估算。

## 4. 权威尺寸 token（100% 基线）

### 4.1 间距

只使用 `4 / 8 / 12 / 16 / 20 / 24`：

|场景|数值|
|---|---:|
|主窗口内容边距|20|
|账号悬停预览内容边距|16|
|标题到说明|8|
|说明到工具栏或首个数据区|16|
|工具栏到表格|12|
|相邻控件|8|
|单元格左右内边距|8|
|悬停窗口到入口图标|8|

### 4.1.1 表格边距与滚动条沟槽

- 每个页面的内容矩阵（含表头与全部可见数据行）必须使用 Core 定义的**四向矩阵边距**，不得由业务插件以独立常量、历史偏移或“看起来合适”的空白替代。四向值是方向性 token，而非“所有方向永远相等”的隐含规则；当前基线如下：

|表面|上|右|下|左|
|---|---:|---:|---:|---:|
|主窗口、无前置页面控件的矩阵|20|20|20|20|
|账号悬停预览、无前置页面控件的矩阵|16|16|16|16|

- 页面标题、说明、筛选/工具栏属于矩阵外的明确固定区。它们存在时，矩阵上边距改为固定区之后的标准间隔：说明到首个数据区 `16`，工具栏到表格 `12`；左、右、下仍分别使用该表面的矩阵边距 token。隐藏、空白或无控件的固定区不得占用矩阵上方空间。
- 页面有常驻底部操作区时，矩阵下边距为矩阵到操作区的 `12`，操作区到底边仍为该表面的下边距 token；不得既保留已隐藏操作区的高度，又额外添加底部空白。
- 矩阵外框以“表头首像素至最后一个可见数据行的末像素”为准；表头、分页器、滚动条沟槽和内容滚动视口都必须纳入同一次尺寸测量。窗口自然宽高必须从该外框与四向边距推导，不能沿用上一页面、上一范围或隐藏控件的尺寸。
- 数据表无论是否可滚动，最后一列右侧均保留该表面类型的右边距；最后一行下方使用对应的下边距。
- `16`px 是纵向滚动条沟槽，不是常驻右侧留白。仅当真实内容高度超过数据视口时，Core 才把这 `16`px 计入窗口自然宽度，并将滚动条放入该新增沟槽。
- 因此无滚动条时，数据区不会为隐藏滚动条缩窄；有滚动条时，数据列保持原有语义宽度，窗口优先向右扩展 `16`px。达到安全宽度上限后，才按本规范的分页/紧凑列宽顺序处理。
- 滚动条必须位于窗口内的专用沟槽，不得覆盖最后一列，也不得绘制到窗口边框以外。

验收时逐页检查：无前置控件时四边都命中对应 token；有前置控件时仅上边按上述固定区间隔变化；隐藏滚动条不占沟槽，有真实滚动条时窗口增加沟槽而矩阵列宽不变。

不得在业务插件中引入孤立间距；确有必要时先新增 Core token 并更新本文件。

### 4.2 字号

以下数值与当前 Core 主题 token 对齐：

|token|字号|用途|
|---|---:|---|
|`title`|18|窗口标题、页面主标题|
|`section`|16|区域标题、设置分组标题|
|`body`|16|表格正文、矩阵状态、按钮、输入|
|`assist`|14|服务器、辅助说明、次要状态|

- 同一语义在主窗口、设置工作台和账号悬停预览中使用同一字号 token。
- 不得由页面为塞入更多列而局部缩小字号。
- 文字默认单行；超出时截断并提供完整文本提示。

### 4.3 行高和控件高度

|token|高度|用途|
|---|---:|---|
|`compact`|26|紧凑矩阵状态格|
|`standard`|30|标准数据行、角色身份行、设置控件|
|`action`|34|强交互行、分组行|
|`double`|46|明确允许双行的任务或身份块|
|`title`|48|标题区域的设计基线；实际共享壳按统一边框取整|

- 同一表格的行高固定，不因个别长文本随机变化。
- 双行必须使用明确的双行行型，不得临时自动换行。
- 计算时统一取整，避免刚好放满时产生 1px 伪滚动范围。

## 5. 屏幕安全区域

### 5.1 主窗口

主窗口安全边距：

- 左：16
- 右：16
- 上：80
- 下：32

安全矩形必须同时约束窗口尺寸和位置，不能只计算“屏宽减 32”。

### 5.2 悬停窗口

悬停窗口安全边距：

- 左右：16
- 上下：16
- 与 Broker / 小地图图标间距：8

### 5.3 极小屏幕

- 屏幕安全范围小于页面最低尺寸时，安全范围拥有最终优先级。
- 固定区保持可用，数据视口承担分页或滚动。
- 分辨率、游戏 UI 缩放或显示器变化后，下一次打开窗口时重新计算安全区域。

## 6. 账号主窗口

### 6.1 锚点和切页

1. 默认锚定 `UIParent` 左上角 `(16, -80)`。
2. 页面切换时保持窗口左边缘和上边缘坐标不变。
3. 自动尺寸变化只调整右边缘和下边缘。
4. 新页面超出安全区域时，才允许向左或向上进行最小量纠偏。
5. 安全纠偏是临时显示位置，不覆盖用户保存的原始锚点。
6. 切回较小页面时优先恢复原始左上角锚点。
7. 只有用户主动拖动窗口后，新的左上角才成为保存位置。

### 6.2 固定壳

- 标题栏高度固定，不因页面、标题或数据量变化。
- 左侧导航宽度固定，页面切换时不得变化。
- 页面固定区和底部主要操作不得进入数据滚动区。
- 主窗口全局最低宽度为 `760`，包含 Core 导航与窗口壳。
- 不再对所有页面使用统一 `430` 高度下限；每页按真实固定区和行数报告最低高度。

### 6.3 自然宽度

标准表格：

```text
内容边距 + 固定列 + 当前可见业务列 + 列线 + 必要沟槽
```

矩阵：

```text
固定身份/任务区 + 当前可见矩阵列的语义宽度 + 分组间距
```

- 角色名、任务名、目标名和服务器名按真实字体测量。
- 每种列同时具有自然宽度和语义下限，只能压缩到语义下限。
- 普通数据量下优先完整显示；宽屏也不得因角色数增加而无限吞占游戏画面。
- 主窗口先以安全区域宽度约 `80%` 作为软上限；确有必要时可扩展到硬安全上限。
- 页面切换时按新页面重新计算，不继承前一宽页面的空白宽度。

### 6.4 自然高度

```text
Core 标题栏 + 页面固定区 + 实际可见行 × 固定行高 + 分组间距 + 内容边距
```

- 空状态、少量数据和大量数据必须产生不同自然高度。
- 最后一行下方只保留标准内容边距，不保留无用途的深色空白。
- 超过安全高度后只缩短数据视口；标题、工具栏、表头和底部操作保持可见。
- 纵向滚动条仅在真实内容高度超过数据视口时显示；出现时按 4.1.1 为窗口新增沟槽，不以压缩最后一列或制造常驻空白作为代价。

### 6.5 自动尺寸稳定性

- 默认使用自动适配。
- 页面、角色集合、字段集合、范围或行集合变化时允许重新测量。
- 普通业务值刷新若未改变行列集合，不改变窗口尺寸。
- 一次刷新全部完成后再提交一次尺寸变化，不得边创建行边缩放。
- 页面切换只允许一次尺寸提交，不得连续跳动。
- 若未来恢复用户拖动尺寸，必须按页面保存；没有可见拖动手柄时不保留名义上的手动模式。

## 7. 角色身份与服务器行数

### 7.1 角色作为左侧数据行

- 角色名始终单行。
- 单服务器范围可以隐藏服务器列。
- 所有服务器范围使用独立服务器列，不把服务器叠在角色名下方。

### 7.2 角色作为顶部矩阵列

单服务器范围使用单行：

```text
天堂双影
```

所有服务器范围使用双行：

```text
天堂双影
-克罗米
```

- 单服务器不预留空白第二行高度。
- 范围切换完成后只执行一次表头和窗口高度调整，并保持主窗口左上角锚点。
- 服务器过长时第二行截断，悬停显示完整身份。

## 8. 表格、矩阵、分页与滚动

### 8.1 统一度量

- 每个矩阵只有一套列度量结果，表头和单元格共享。
- 固定列与数据格共享纵向偏移。
- 如果最终允许横向滚动，表头和数据格共享横向偏移。
- 滚动条沟槽只在真实纵向溢出时计入自然宽度；出现时扩展窗口以保持数据列宽，消失时恢复标准内容边距。

### 8.2 宽度处理优先级

所有插件统一按以下顺序处理：

1. 一页完整显示，不出现滚动。
2. 根据数据特征选择更合适的矩阵方向。
3. 使用真实文字测量消除无意义空白。
4. 在语义下限内使用紧凑列宽。
5. 将适合摘要的低优先级信息组合为统一摘要列，但不擅自隐藏用户启用的信息。
6. 将窗口扩展到安全区域软上限，必要时扩展到硬上限。
7. 使用统一列分页或字段分组。
8. 只有分页仍无法合理表达时，才允许数据区横向滚动。

横向滚动是全系列最后兜底，不得成为任何插件的默认布局。出现横向滚动需求时，必须先重新检查矩阵方向、字段组织和分页设计。

### 8.3 角色数量

- 20 名是“无滚动完整展示目标”，不是角色数量上限。
- 有效角色不超过 20 名时，默认完整显示全部角色。
- 超过 20 名后仍保留全部有效角色，不得静默截断。
- 角色为行时，超过 20 名后允许数据区纵向滚动。
- 角色为列时，超过 20 名后优先使用列分页；仍不得默认启用横向滚动。
- 主窗口和账号悬停预览使用相同的角色准入集合。

### 8.4 页面方向基线

- Boss 周常优先采用“角色为行、Boss 为列”，使宽度随相对稳定的 Boss 数量变化，高度随角色数量变化。
- 任务屏蔽等长任务名页面可采用“任务为行、角色为列”，固定任务/全局列，角色区使用列分页。
- 新页面必须先说明行列方向如何服务比较任务，不能让尺寸系统替不合理的数据方向兜底。

## 9. Broker / 小地图账号悬停预览

### 9.1 内容规则

- 账号预览是主页面的只读字段投影，不是缩小版完整窗口。
- 不显示设置、排序、添加、删除、编辑、放弃或批量操作。
- 显示所有符合业务准入且有有效快照的角色；20 名以内以无滚动完整显示为目标，超过 20 名后允许数据区纵向滚动或列分页。
- 数据、角色准入、状态文字、颜色、数值格式和字段内容与主窗口一致。
- 预览不保存尺寸、不允许拖动缩放、不继承主窗口尺寸。

### 9.2 四象限锚点

预览首次显示时，直接根据入口图标中心相对 `UIParent` 中心的位置选择锚点和展开方向：

|图标位置|预览窗口锚点|展开方向|
|---|---|---|
|左上|`TOPLEFT`|向右、向下|
|右上|`TOPRIGHT`|向左、向下|
|左下|`BOTTOMLEFT`|向右、向上|
|右下|`BOTTOMRIGHT`|向左、向上|

- 不使用“先定位、越界后镜像”的策略。
- 悬停期间锚点不翻转、不镜像、不跳到屏幕中央。
- 最大可用宽高按所选方向到对应安全边缘的真实剩余空间计算。
- 空间不足时缩短数据视口、分页或纵向滚动，不改变展开方向。
- 图标恰好位于中线时选择可用空间更大的一侧；空间相同时使用固定方向，防止重复悬停跳动。
- Broker 与小地图使用完全相同的定位算法。

### 9.3 尺寸和生命周期

- 自然宽度只计算实际预览字段，不计算主表全部字段。
- 普通预览默认不依赖横向滚动；字段过多时列分页优先。
- 20 名以内且屏幕允许时完整显示；超过 20 名或屏幕高度不足时缩短数据视口。
- 鼠标从入口移动到预览时保留 `150–250ms` 关闭宽限。
- 同一次悬停期间业务刷新不得改变窗口宽高；下一次打开再应用新尺寸。

### 9.4 标题栏与功能组响应式布局

悬停窗口不固定增加功能行。Core 必须在窗口显示前，根据内容自然宽度、锚点方向的可用宽度、标题身份和功能组共同选择布局。

#### 9.4.1 只有服务器范围功能

只有服务器范围功能时，服务器按钮优先放在标题栏右侧：

```text
[图标与标题]                         [服务器按钮组]
```

处理顺序固定为：

1. 使用完整服务器按钮，并按视觉准则定义的标题身份级别依次降低标题占用。
2. 标题图标和文字全部省略后，仍放不下完整服务器按钮时，直接改用三控件服务器选择器。
3. 服务器选择器仍放不下时，才将服务器功能组移动到独立功能行。
4. 功能组移动到独立行后，标题栏恢复完整的最高级标题身份，不继承之前的省略状态。

三控件服务器选择器固定为：

```text
[当前服务器名] [其它 ▾] [所有]
```

- 第一个按钮固定为当前登录角色所在服务器。
- 中间按钮包含账号内其它服务器；选中某个其它服务器时，中间按钮直接显示该服务器完整名称并保留下拉箭头。
- 最后一个按钮切换所有服务器范围。
- 当前服务器不在“其它”菜单中重复出现。
- 账号只有一个有效服务器时隐藏整个服务器范围组，因为当前服务器与所有服务器结果相同。
- 禁止用单字、最短前缀或其它方式缩写服务器名称；不得生成 `[莫]`、`[克]` 等短名按钮。

#### 9.4.2 存在其它功能组

悬停窗口除服务器范围外还存在预览模式等其它功能组时，所有通用功能组使用一条独立功能行：

```text
标题栏：[完整图标与标题]
功能行：[服务器范围]                         [预览模式]
```

- 独立功能行固定最多一行，不换行、不横向滚动。
- 服务器组先尝试完整服务器按钮；放不下时直接改用三控件服务器选择器。
- 不在完整名称和选择器之间插入服务器缩写状态。
- 列分页与具体数据表关系更紧密，放在表头右侧，不进入通用功能行。
- 悬停窗口最多承载一个服务器范围组和一个业务预览模式组；更多操作必须进入主窗口。
- 如果选择器加一个业务预览模式组仍无法在一行内显示，保留服务器范围和完成当前预览所必需的模式，将其它操作移至主窗口，不增加第二条功能行。

#### 9.4.3 标题与按钮宽度优先级

- 功能按钮使用自然宽度，不因冲突缩小字号或压缩点击区域。
- 标题身份按视觉准则定义的级别完整切换，不使用半截文本或省略号标题。
- 标题身份可以完全让位于服务器按钮，但服务器按钮仍不得覆盖标题区域或窗口边界。
- 按钮移入独立功能行后，标题栏重新使用完整身份。
- 功能行不存在时不保留空白高度；出现时必须在窗口显示前计入自然高度。

### 9.5 显示前测量与性能

Core 使用轻量布局模型在 `Show()` 前完成计算；可以复用已创建但尚未显示的窗口壳和控件，不要求在创建任何 Frame 前完成。

计算顺序：

```text
构建角色、服务器和功能组模型
→ 选择四象限锚点并计算该方向的安全空间
→ 测量业务内容自然尺寸
→ 测量各级标题身份
→ 测量完整服务器按钮和三控件选择器
→ 决定标题栏或独立功能行
→ 计算最终窗口尺寸和列分页
→ 一次性显示
```

性能规则：

- Core 使用一个隐藏的共享文字测量对象，不为每个候选状态创建临时 FontString。
- 文字宽度缓存键至少包含字体 token、文本、游戏 UI 缩放和客户端语言。
- 标题各级宽度、服务器完整名称宽度、服务器选择器宽度和业务功能组宽度都应缓存。
- 只有服务器集合、页面、功能组、字体、游戏 UI 缩放、客户端语言或入口象限变化时重新计算。
- 普通业务数值、状态文字颜色和鼠标在预览内部移动不触发布局重算。
- 一次刷新内合并全部测量，只提交一次最终尺寸，禁止窗口显示后连续改变标题、宽度或功能行。

## 10. 统一设置工作台

- 设置工作台采用稳定尺寸，不随业务设置页切换而伸缩。
- 最低尺寸：`820 × 560`。
- 自然尺寸基线：约 `960 × 720`。
- 最大尺寸：当前屏幕安全区域。
- 空间不足时只缩短右侧内容区；左侧导航、页面标题、底部状态和关闭操作保持可见。
- 只有右侧内容区允许纵向滚动；设置页禁止横向滚动。
- 两栏内容在宽度不足时改为单栏，不以横向滚动维持两栏。
- 响应式换行的最小单位是完整语义组：标签、说明、控件和紧邻状态必须一起换列或换行；不得把说明与其按钮、下拉框或输入控件拆开。
- 长列表优先使用表格、分页或“展开更多”；字段详情一次只展示当前选择插件，避免在同一页并列展开全部插件的字段矩阵。
- 切换设置页时窗口位置和尺寸稳定；滚动位置按页面独立保存或回到顶部。

## 11. 普通提示、确认和编辑窗口

- 文字截断、按钮说明等普通提示使用原生 `GameTooltip` 自动测量，不纳入账号预览尺寸体系。
- 确认框必须完整显示风险文本和确认/取消按钮，按钮不得进入滚动区。
- 小型编辑窗口按内容自然尺寸显示，且不得超过安全宽度的 `50%` 和安全高度的 `60%`。
- 二级窗口相对主窗口定位，主窗口关闭时一并关闭。

## 12. 未来业务插件独立缩放

缩放功能在本轮 100% 尺寸规范完成并验收后实施。本节只定义边界，不授权当前实现用缩放修复页面。

1. 100% 是唯一设计和计算基准。
2. 所有窗口必须先在 100% 下满足尺寸、锚点、分页、空白和安全区域要求。
3. 每个业务插件未来可以保存独立缩放值；Core 内部页面和统一设置工作台使用 Core 自身缩放值。
4. 主窗口和该插件的账号悬停预览使用同一个插件缩放值。
5. 未设置时回退到 100%，不建立隐式全局继承。
6. 缩放只作用于布局完成后的最终 Frame 显示比例。
7. 缩放不参与字体 token、文字测量、列宽、行高、自然尺寸、可见行列数、分页结果、滚动阈值和页面方向计算。
8. 缩放不由 Core 自动修改，也不能成为处理溢出的手段。
9. 非 100% 缩放造成的最终视觉尺寸变化，不反向触发布局重算或重新分页。
10. 非 100% 缩放后的屏幕边界处理方式，在缩放功能实施前另行讨论；不得反向改变本轮 100% 设计结果。

## 13. 尺寸稳定性

- 同一账号有效角色集合中，角色列宽使用稳定测量结果；筛选、排序和服务器范围变化不应无理由跳动。
- 标题过长时截断并提供原生提示，不挤压右侧控制区。
- 同一锚点、字段和角色集合未改变时，重复打开应得到相同尺寸。
- 业务插件不得直接调用统一窗口的 `SetSize`。
- 所有尺寸变化由 Core 在刷新提交阶段统一执行。

## 14. 验收矩阵

每个业务页面及其账号悬停预览至少验证：

|场景|期望|
|---|---|
|2、10、20 名角色|一页完整显示，默认无滚动|
|21 名及更多角色|保留全部有效角色；角色为行时允许纵向滚动，角色为列时优先列分页|
|0、1、8、20、50 行业务数据|高度贴合真实内容；达到安全上限后只滚动数据区|
|单服务器|顶部角色身份单行，无空白第二行|
|所有服务器|顶部角色身份使用“角色名 / -服务器”双行|
|最少字段与全部字段|真实测量；宽度不足时先分页，横向滚动仅最后兜底|
|页面连续切换 10 次|左上角稳定，无尺寸累积、二次跳动或空白继承|
|内容刚好放满|不出现伪滚动条|
|Broker 位于四个屏幕象限|预览朝屏幕中心展开，不镜像、不跳到中央|
|只有少量服务器按钮|按钮位于标题栏右侧；标题按级别降级，不额外增加功能行|
|服务器按钮较多|标题全部省略后仍不足则改用 `[当前服务器名] [其它 ▾] [所有]`，不生成服务器缩写|
|服务器范围加业务预览模式|使用一条独立功能行；完整服务器按钮放不下时改用选择器，功能行始终保持一行|
|功能组移入独立行|标题栏恢复完整图标、插件技术名、版本和页面名称|
|`1280×720`、`1600×900`、`1920×1080`、`2560×1440`、超宽屏|窗口不越出安全区域，固定区始终可用|
|游戏 UI 缩放高、中、低三档|使用逻辑单位重新测量，表头和数据保持对齐|
|100% Yibo 显示比例|所有页面独立通过验收，不依赖未来缩放功能|

## 15. 实施顺序

1. Core 统一尺寸 token、屏幕安全矩形、页面度量口径和刷新提交时机。
2. 统一主窗口左上角稳定策略、悬停四象限锚点、标题身份级别和服务器选择器。
3. 迁移页面壳估算常数和旧度量接口。
4. 为矩阵提供固定区、列分页、垂直滚动和最终横向兜底的共享组件。
5. 依次迁移 Boss 周常、任务屏蔽、传说之路、声望、角色档案、概览和设置工作台。
6. 全部页面在 100% 下通过第 14 节验收后，再设计和实现业务插件独立缩放。
