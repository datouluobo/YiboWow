# YiboCore 像素线宽统一控制 · 实施方案

2026-11-21 · 状态：已确认并实施（代码完成、离线通过，三端实机待验）· 来源：[多端前端间距与对齐分析](Core-多端前端间距与对齐分析-2026-11-21.md) 第 3.2 节 · 接口：[API-v14-像素线宽](API-v14-像素线宽.md)

## 1. 目标与边界

- 让 Yibo 系列所有 1 线宽的格线、分隔线和描边，在任意分辨率与 UI 缩放下都只占 **1 个物理像素**，且同一页面内粗细一致。
- 像素换算、吸附和缩放变化后的刷新统一由 Core 负责，业务页只声明“这里要一条几像素的线”，不自行换算，也不保留本地回退。
- 不改变布局尺寸：列宽、行高、外边距和沟槽仍使用 UI 单位，只有线宽和线的位置换成按像素计算。
- 与第 3.1 节“一条边界只画一次”配合：本能力同时提供按边选择的像素边框，用于替换四边 `edgeSize = 1` 的 Backdrop。
- 不包含：格线配色调整（第 3.3 节）、图标与品质框的视觉重绘。

## 2. 现状

| 项目 | 观察 |
| --- | --- |

| Core 内部用线 | 表头右线与底线、当前角色行与列描边（4 处入口）、按钮、下拉菜单、信息条、账号窗口与菜单、角色档案行。 |
| 全仓库四边 1 线框 | 非探针源码中 `edgeSize = 1` 共 69 处、35 个文件，其中 Core 约 24 处，其余在业务插件。 |
| 像素相关接口 | 正式源码未使用 `GetPhysicalScreenSize`、`PixelUtil`、`SetSnapToPixelGrid` 或 `SetTexelSnappingBias`。 |
| 缩放事件 | 三个目标的 `Target.lua` 均已声明 `DISPLAY_SIZE_CHANGED`、`UI_SCALE_CHANGED`；`EntryBar` 已用 `Core.Events:Register` 监听。 |
| 窗口缩放 | Core 窗口未单独 `SetScale`，有效缩放来自 UI 缩放和父级链。 |

## 3. 换算规则

WoW 以屏幕高度 768 为 UI 坐标基准。对任一区域：

```
每 UI 单位像素数 = 物理屏幕高度 ÷ 768 × 区域有效缩放
N 像素对应的 UI 单位 = N × 768 ÷ 物理屏幕高度 ÷ 区域有效缩放
吸附 = round(值 × 每 UI 单位像素数) ÷ 每 UI 单位像素数
```

| 分辨率 | UI 缩放 | 每 UI 单位像素 | 1 像素线的 UI 单位 | 现状（1 UI 单位）实际渲染 |
| --- | --- | --- | --- | --- |
| 1280×720 | 1.00 | 0.94 | 1.067 | 不足 1 像素，变淡或断线 |
| 1920×1080 | 1.00 | 1.41 | 0.711 | 1 或 2 像素交替 |
| 1920×1080 | 0.80 | 1.13 | 0.889 | 多为 1 像素，偶有 2 像素 |
| 2560×1440 | 1.00 | 1.88 | 0.533 | 多为 2 像素 |
| 2560×1440 | 0.71 | 1.33 | 0.750 | 1 或 2 像素交替 |

计算使用“区域自身的有效缩放”，与 YiboReputation 悬停命中计算的做法一致，避免嵌入缩放父级时出错。

## 4. Core 设计

### 4.1 目标适配层（各端 `Surface.lua`）

客户端差异集中在目标适配层，共用逻辑只消费稳定契约：

| 新增 surface 方法 | 返回 | 说明 |
| --- | --- | --- |
| `ReadPhysicalScreenSize()` | `width, height` 或 `nil, "unavailable"` | 绑定 `GetPhysicalScreenSize`；值必须为正整数，否则按不可用处理。 |
| `ReadPixelSnapSupport()` | `{ grid = bool, bias = bool }` | 检测纹理是否支持 `SetSnapToPixelGrid` / `SetTexelSnappingBias`。 |

在 `Runtime/Client.lua` 的 surface 方法列表中登记这两项。三个目标是否真正提供这些接口以阶段 0 探针结果为准，不按客户端名称推断；尤其无限服 `Interface: 16001` 必须单独实测。

### 4.2 Theme 公共接口

放在 `UI/Theme.lua`，不新增文件，因此三个目标 TOC 不变。

| 接口 | 作用 |
| --- | --- |
| `Theme:GetPixelSize(region, pixels)` | 返回 `pixels`（默认 1）个物理像素在该区域的 UI 单位长度。 |
| `Theme:SnapToPixel(region, value)` | 把偏移量或尺寸吸附到该区域的像素网格。 |
| `Theme:CreatePixelRule(parent, orientation, options)` | 创建一条水平或竖直线；`options` 含 `pixels`、`color`、`layer`、锚点。返回的纹理已登记，缩放变化时自动刷新。 |
| `Theme:CreatePixelBorder(frame, options)` | 按 `sides = { top, right, bottom, left }` 只创建所需边，替代四边 Backdrop 边框；同一 frame 重复调用只更新、不重复创建。 |
| `Theme:SetPixelBorderColor(border, color)` / `SetPixelBorderShown` | 状态切换（选中、击杀、焦点）只换颜色或显隐，不重建。 |

语义约定：

- `Theme.Table.lineWidth` 的含义从“UI 单位”改为“物理像素数”，默认仍为 `1`。因为只有 Theme 内部读取，不影响业务插件。
- 当前角色描边的内缩量改为 `GetPixelSize(owner, lineWidth)`，与 3.1 中“描边占用格线位置”一起实现。
- 需要强调的语义边框（焦点、选中）可用 `pixels = 2`，同样由 Core 换算。

### 4.3 吸附策略

1. **首选：纹理吸附**。线纹理创建时调用 `SetSnapToPixelGrid(false)` 和 `SetTexelSnappingBias(0)`，由 Core 自行按像素设定线宽与偏移。这是正式服原生界面绘制像素线的常见做法，可避免引擎二次吸附带来的 1/2 像素跳动；各端实际效果以探针对照图为准。
2. **接口不可用时：Core 布局吸附**。只在 Core 管理的矩阵布局中，对行的纵向起点、列的横向起点和线的锚点偏移调用 `SnapToPixel`。行高和列宽的 UI 单位不变，只是相邻行在像素上可能相差 1，肉眼不可见。
3. **物理分辨率不可读时**：线宽保持当前的 1 UI 单位，并在 Core 诊断信息中记为 `pixel-metrics: unknown`。这是 Core 内部的目标差异处理，保持现有行为，业务插件不感知。

具体走哪条路径按目标登记，由阶段 0 探针结果决定。

### 4.4 刷新与生命周期

- Core 维护一个弱引用表，登记所有像素线与像素边框，记录其像素数与方向。
- 监听已声明的 `UI_SCALE_CHANGED`、`DISPLAY_SIZE_CHANGED`，统一重算并刷新；同一帧内多次事件合并为一次。不使用 `OnUpdate` 轮询。
- 账号窗口与悬停预览在 `OnShow` 时按当前有效缩放刷新一次，覆盖父级缩放在隐藏期间变化的情况。
- 重复调用创建接口不得产生重复纹理或重复登记；frame 回收复用时沿用已有边框对象。

### 4.5 版本与能力声明

- `Core.API_VERSION` 提升为 `14`，注册能力 `pixel-line:1`。
- 台账新增 **CAP-013：像素线宽与像素边框**，记录 Core 实现状态、接口文档、最低版本及各插件接入状态；业务插件初始状态为“待评估”。
- 另写接口文档 `YiboCore/Docs/API-v14-像素线宽.md`，说明输入输出、默认与失败行为、各目标吸附路径和刷新语义。

## 5. 迁移范围与顺序

### 阶段 0 · 三端探针（非发布）

在 `_NonRelease/` 下新建独立探针目录，目录名与命令按《非发布探针命名与组织规范》确定，注册 Slash 命令前搜索全工作区 `SLASH_*` 确认未被占用。探针记录：

- 三端 `GetPhysicalScreenSize`、`SetSnapToPixelGrid`、`SetTexelSnappingBias`、`PixelUtil` 是否存在，以及返回值。
- `UIParent:GetEffectiveScale()` 与公式结果是否一致。
- 绘制对照图：同一位置并排画“1 UI 单位线”和“1 像素线”，各放在整数与小数偏移上。
- 修改 UI 缩放和窗口分辨率时，`UI_SCALE_CHANGED` 和 `DISPLAY_SIZE_CHANGED` 是否触发、触发几次。

覆盖分析文档的三档分辨率，每档包括默认缩放和一档较小缩放。实机操作由用户执行，我提供测试清单与截图要求。

### 阶段 1 · Core 自身（保持行为，只换线）

1. 实现 4.1–4.4，提升版本与能力号。
2. 迁移 Core 内部全部用线：表头右线与底线、4 个当前角色描边入口、按钮、下拉菜单、信息条、账号窗口与菜单、角色档案行、设置工作台等 Core 内的约 24 处 `edgeSize = 1`。
3. 角色档案行同时按 3.1 改为只画底线，外框交给容器。这是 Core 内唯一同时改变边的数量的位置，单独提交，便于对照截图。

### 阶段 2 · 业务插件（触及即迁移）

业务插件不一次性全量迁移。按分析文档的优先级，在处理对应页面的间距或多重线问题时，将该页面的四边线框迁到 `CreatePixelBorder` / `CreatePixelRule`，并同步做 3.1 的去重：

| 顺序 | 插件与页面 | 原因 |
| --- | --- | --- |
| 1 | YiboAltoBoss `Mists/AccountPage.lua` | 行框与状态格框嵌套 |
| 2 | YiboCrafting `AccountPage.lua`（MoP）与 `Forever/AccountPage.lua` | 容器框与行线重合，表头对齐问题同页处理 |
| 3 | YiboVault `StoragePage.lua`、`Forever/AccountPage.lua` | 行框与格框叠加 |
| 4 | YiboReputation `Forever/AccountPage.lua`、`AccountMatrixView.lua`、`MonitoredPreview.lua` | 主窗与同源悬停一起验收 |
| 其余 | Builds、Todo、QuestBlocker、Mail、TaskHub、BeastPaths 等 | 后续修改到对应页面时迁移，作为台账库存 |

每个接入插件按规范提高最低 Core 要求到 API 14 / `pixel-line:1`；版本不足时提示升级 Core，停止该页面的初始化，不保留本地 `edgeSize = 1` 回退。迁移只换线框实现与边的数量，不改布局尺寸，并同步核对受影响目标的 TOC、XML 与构建引用。

## 6. 验证

### 6.1 离线

在 `YiboCore/_NonRelease/Tests/` 新增规格测试：

- 换算：三档分辨率 × 缩放 `0.64 / 0.71 / 0.80 / 1.00 / 1.15` 的结果与第 3 节公式一致；`pixels = 2` 正好是 2 倍。
- 吸附：吸附后的值乘以每 UI 单位像素数为整数。
- 不可用路径：物理分辨率读不到或为非法值时，返回 1 UI 单位，状态为 `unknown`，不抛错。
- 幂等：重复创建同一边框不新增纹理；`sides` 只创建所请求的边。
- 刷新：模拟两个缩放事件只刷新一次；回收的弱引用对象不会被访问。
- 版本：`CheckAPIVersion(14)` 与 `HasCapability("pixel-line", 1)` 为真。

构建经过统一构建器的目标、Interface、引用和包内容校验。

### 6.2 客户端（由用户执行）

- 三端按分析文档的分辨率与缩放表取样：角色档案、专业矩阵（MoP）、声望主表（无限服），各取主窗和悬停。
- 原尺寸截图或整数倍放大检查：所有普通线都是 1 像素，同页没有 1/2 像素混杂，720p 下没有断线。
- 游戏中修改 UI 缩放，不重载，窗口打开状态下线宽立即更新；关闭再打开后仍然正确。
- 线变细后会显得更弱，按第 3.3 节复核对比度；如需调整配色，另作为 3.3 的改动处理，不在本能力中顺带修改。

## 9. 实施记录（2026-11-21）

与方案的差异：

- 吸附路径先只实现“按像素换算线宽与内缩”和“读不到时回退 1 UI 单位”两条；纹理吸附开关（`SetSnapToPixelGrid` / `SetTexelSnappingBias`）和矩阵行列起点吸附暂不启用，`SnapToPixel` 已提供但 Core 布局未调用，等探针 D/E 对照结果再决定。因此 `ReadPixelSnapSupport` 未加入 surface，探针直接记录这两个方法是否存在。
- 除 `CreatePixelRule` / `CreatePixelBorder` 外，新增 `ApplyPixelRule`（已有纹理设为像素线）和 `ApplyPixelBackdrop`（直接替换四边 `edgeSize = 1` Backdrop，保留原有颜色调用），使 Core 内部迁移不改变控件结构。
- 刷新合并用 `C_Timer.After(0)`；有效物理高度才缓存。
- 未加入“账号窗口 `OnShow` 时刷新”：Core 窗口不单独 `SetScale`，有效缩放只随 UI 缩放变化，已由 `UI_SCALE_CHANGED` 覆盖；若探针或实机发现隐藏期间缩放变化未触发事件，再补此项。
